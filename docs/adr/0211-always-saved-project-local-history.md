## 问题

2026-11-25 来信：用户整合数据时把**整个项目文件夹**挪了位置，重新打开后「找不到原来绘制好的图了，得重新画」。
维护者同日的判断：**不能把按 ⌘S 当作留住工作的必要动作**——这个时代的软件应当始终可保存、可回溯。

### 实测现状（隔离数据目录 + 真实页面，2026-11-25，origin/main `f22cd8e5a`）

| 情况 | 现在 | 图 | 修改 |
| --- | --- | --- | --- |
| 整夹挪走，没按过 ⌘S | 新路径是空白排版；只有「排版」菜单最底下一条「…项目 projA」→「仍然打开」能救；换了 origin（桌面换端口，#715）就**零入口** | 本机在 | 本机在 |
| 整夹挪走，按过 ⌘S | 排版随 `tavottofile/` 走，但启动落空白，要自己去「打开排版…」找 | 在 | 在 |
| 挪回原位 | 自动恢复 | 在 | 在 |
| 只挪脚本（项目内） | 只剩旧快照；双击报「找不到这个脚本的文件（{{script}}）……」（占位符漏填，#2215 修）；运行新位置的脚本另起一张图，旧修改带不过去 | 快照 | 旧面板上，永远重渲染不了 |
| 只挪数据 | 0106 指认弹窗，指一次就接上 | 在 | 在 |

两条关键事实：

1. **项目文件夹里其实已经有历史。** 没按 ⌘S 时，时间线的自动节点（停顿 15 s 且距上个节点 ≥ 2 分钟）也写进
   `<项目>/tavottofile/versions/<docId>.vx/`，信封里带着图内修改，另有缩略图。所以挪走的文件夹里有截至最后一个节点的图——
   只是界面不会去那里找：项目身份是绝对路径的哈希（`app._project_id`），归属与「上次开着哪份」记在本机按路径作键的
   `state/layout-sessions.json` 与前端 `tavotto.docIndex` 里，新路径一律判成「别的项目」。
2. **新路径每次加载都新建一份空白排版，并在用户项目里留一个只有 `open` 节点的空 `.vx` 目录**（加载 5 次多 5 个；
   `App.tsx` `markWorkspaceOpenedAfter` → `markMoment('open')`，`allowEmpty:true`）。

按路径失联的本机状态（随文件夹走的只有 `tavottofile/`、`tavotto_registry.json`、时间线）：

| 状态 | 键 | 处置 |
| --- | --- | --- |
| 排版归属与「上次开着」 | `layout-sessions.json`，归一化绝对路径 | 第一期：项目内证据优先；第二期：工作副本在项目里，不再依赖它 |
| 改指表 | `config.json` `projects[<绝对路径>].input_remap`，规则里也是绝对路径 | 第一期：随认领迁移——指向旧项目内的规则换成新根，项目外的原样 |
| 运行配置 / 输入转录 | `runconfigs/`、`inputtranscripts/`，路径 sha256 | 随认领迁移 |
| 渲染缓存 / 烘焙覆盖 | `cache/engine/`、`baked_overrides/`，项目 id | 丢弃重建（派生物） |
| 「记住此项目和此 Python」 | 运行许可 | **不迁移**，照旧重新确认（0021 §7.1：项目移动后重新确认） |

## 裁决

### 原则

用户做过的每一处编辑，在不按任何键的情况下，都要在**项目文件夹自己的**存储里留下可恢复、可回溯的记录；
挪文件夹、复制给别人、换电脑、换端口之后，打开项目就是上次的样子。本机数据目录只做崩溃缓冲与只读项目的退路。

### 维护者 2026-11-25 拍板的四项

| # | 问题 | 裁决 |
| --- | --- | --- |
| 1 | 实时形态：一个 ZIP 文件还是一个目录 | **目录**。实时写 ZIP 每改一下重写整个文件、写一半崩溃坏全部、同步盘上单个大文件易冲突；0140 否决「整份历史一个文件」是同一理由。发给别人时一键打成 `.tavotto` ZIP |
| 2 | 放在哪 | **`tavottofile/` 里**，每份排版一个目录，不弄乱用户文件夹 |
| 3 | ⌘S 的新含义 | **给这一版起名字**（0101 命名节点：永不自动清理）。不再有「未存进项目」这个状态 |
| 4 | 旧版 Tavotto 遇到新形态 | **明确提示需要更新**，不尽力打开、不静默改写 |

### 第一期：从项目自己的历史找回（正确性修复）

1. **打开项目时先问项目自己**：后端列出 `<项目>/tavottofile/versions/*.vx` 里有内容的排版（最近一个非空节点、画布数、时间），
   作为恢复候选的一个证据来源，接进现有 `projectDocs.planRestore` / `confirmRestored` 流程，不另起一套；前端索引与
   `layout-sessions.json` 都没有记录时也能出候选。挪走、复制、换电脑、换 origin 统一走这一条。
2. **候选怎么用**：本机自动保存槽位里有同一个 docId 且比项目节点新 → 用本机那份（它包含节点之间的修改），并把归属改到当前项目；
   只有项目节点 → 从最近节点恢复（一条可撤销的历史）。**多份候选不猜**（0027 §5）：列出来，用户选。
3. **复制与移动分开**：旧路径仍在 = 复制。不转移旧项目的归属；当前项目用项目内节点恢复出**新 docId** 的一份，两边互不影响。
4. **不再留空目录**：空白排版不打 `open` 节点（`allowEmpty` 只留给确实有内容的时刻）；已留下的只有一个空 `open` 节点的 `.vx` 不进候选。
5. **本机设置随认领迁移**：改指表、运行配置、输入转录按上表处置；运行许可不迁移。
6. **只挪脚本**：脚本缺失（`source_missing` / `script_source_missing`）时，项目里有**内容字节完全相同**的脚本 → 给一个按钮「接到 scripts/plot.py」；
   有多个、或只有同名但内容不同的 → 列出来让用户选，也可以手动指认。接上后改注册表登记、面板身份不变，图内修改保留。不按文件名或修改时间自动接。
7. 界面只复用现有位置（恢复候选、属性栏那行灰字、错误卡的主按钮），一句话，不加横条；截图过 agy 再给维护者看。

### 第二期：工作副本住进项目（#243 / R-07 的处置）

- 自动保存（防抖、`atomicio` 原子写）直接写 `tavottofile/<排版>/layout.json`；本机 `layouts/_autosave/` 降为崩溃缓冲，写盘成功即清。
- **修订 0096 §三**：「自动保存不写项目文件」的理由（用户没按保存，项目里的文件就变了）被本 ADR 的原则取代——项目里的排版本来就该是最新的。
  代价如实记：git / 同步盘里会看到 `tavottofile/` 频繁变化；合作者正在读的文件会变。
- **外部修改**（git pull、另一台电脑、同步盘回写）：沿用 0024 的修订号判据；自动写入撞上外部修改时不覆盖，进现有冲突裁决，本机缓冲保住这边的版本。
- **写不进去时的退路**：只读项目、只读卷、没开项目、playground、Codex 内嵌画布 → 写本机（与今天相同），界面一行灰字说明「这个文件夹只读，修改存在本机」。
- **⌘S**：给当前状态存一个命名节点（就地小框起名，与 ⌥⌘S 合并）；关闭保护、保存状态胶囊不再有「未存进项目」。
- 旧数据迁移：`tavottofile/<名>.json` 与 `versions/<docId>.vx` 读兼容；首次写入时迁进新目录（处置见下面「第二期形态拍板」③，取代原写的「旧文件冻结不删」）。

#### 第二期形态拍板（维护者 2026-11-26「都按推荐」）

实现前核实：已发布的 v0.21.3 `api_layouts` 只对 `tavottofile/`、`canvases/`、`layouts/` 做**不递归**的 `glob("*.json")`，
`GET /api/layouts/<名>` 只读 `<名>.json`——目录形态的排版对它**不可见、也不提示**；它在同名下另存会生出一份与目录分叉的 `<名>.json`。
它打开 `schema` 超出自己认识范围的排版时走现成的「版本太新」结局（`tooNewSchema` → `schema_too_new` 提示 + 「检查更新」）。

| # | 问题 | 裁决 |
| --- | --- | --- |
| ① | 排版目录名 | **`tavottofile/<名>.tavotto/`**，`layout.json` 在里面。与第三期交换形态同形：打包 = 把这个目录压成同名 ZIP，不再迁第二次 |
| ② | 旧版怎么「明确提示需要更新」（裁决 4） | 目录旁留一个**占位** `tavottofile/<名>.json`：只有一个旧版不认识的 `schema` 与指向目录的标记，没有画布内容。旧版照常列出「<名>」、打开即「版本太新，请更新」；新版认得占位，不当排版列出，读写都走目录 |
| ③ | 已有的旧 `<名>.json` | 首次写新目录时**原样搬进目录留底**（目录内一个只读的旧文件副本），原处换成②的占位。不冻结在原处——否则旧版会静默打开一份过时的图，与裁决 4 相反 |
| ④ | 没起过名的新排版写到哪 | 用**画布名**（默认「排版一」）作目录名，重名加序号；用户在「打开排版…」里改名 |

旧版在占位上另存（「仍然覆盖」）会把占位换成一份旧格式排版：新版据修订号把它当**外部修改**进现有冲突裁决，不静默覆盖任何一边。

第二期分三个 PR：**后端存储**（目录读写、占位、迁移、只读退回）→ **自动保存写进项目**（本机槽位降为崩溃缓冲；写不进时一行灰字）→
**⌘S = 起名字**（⌘S 与 ⌥⌘S 同开现有命名小框；去掉「未存进项目」状态与提示）。界面改动截图过 agy 后给维护者看。

### 第三期：排版目录与 `.tavotto` 容器同形

排版目录（实时形态）与 `.tavotto`（交换形态）是**同一棵树**，后者只是前者打成 ZIP（另可选带数据、脚本、来源证明、预览）：

```
tavottofile/figure_1.tavotto/      # 目录（实时）；打包后同名 .tavotto 为 ZIP
├── package_manifest.json          # 容器版本、能力要求、资源校验
├── layout.json                    # 当前权威文档（schema 3/4）
├── history/
│   ├── index.json                 # 版本索引、当前 HEAD（= 0140 的 index.json）
│   ├── revisions/                 # 版本节点与父版本引用（= 0140 的不可变信封，加 parent）
│   ├── snapshots/<sha256>.json    # 完整检查点，内容寻址去重（= 0140 D3）
│   ├── operations/                # 可选：分段编辑事务；必须落在检查点之间，坏一段只丢一段（0140 否决「只存 diff」的理由）
│   └── thumbs/
├── assets/  scripts/              # 现有命名空间
├── data/                          # 可选，不强制
├── provenance.json                # 可选
└── preview/fallback.pdf           # 可选
```

- **与合同 #1921 的冲突要在合同里改，不另起一套**：现合同只认 `assets/` 与 `scripts/`、清单键闭集、`version == 1`。
  `history/`、`data/`、`provenance.json`、`preview/` 与新清单键需要 `PACKAGE_VERSION = 2`；按 #1920 单一存储，schema 3/4 照旧由 `layout.json` 的 `schema` 区分。
  这份修订与 #1877（外部贡献者的 RFC）对齐后再接代码。
- **旧版结局（裁决 4）**：容器 v2 的包，现役读取端按 `version` 拒绝并提示「需要更新 Tavotto」。已发布的 v0.21.x 只看 `layout.json` 的 `schema`、
  静默忽略多出的成员——它会打开当前排版、看不到历史；它的打包端不接收包文件，不会把历史改写掉。这一档如实写进发行说明，不宣称旧版会提示。
  旧版看不见 `tavottofile/<名>.tavotto/` 目录里的实时排版（已核，见「第二期形态拍板」）；它看见的是旁边的占位 `<名>.json`，打开即「版本太新」。

## 不做

- 不把运行许可、解释器信任随项目迁移（0021 §7.1）。
- 不按文件名 / mtime 自动认领或接回（0027 §5）。
- 不在项目里放「项目身份标记」文件来认亲：文件夹内容是外来的，不能凭它继承别的项目的本机设置；候选只来自项目内的历史与用户的选择。
- 不用 SQLite 或单文件 ZIP 做实时存储（0140 §一 的否决理由，同步盘上的损坏源）。

## 验收

- 第一期：真实页面 e2e——整夹挪走（没按 ⌘S）后打开即是上次的图、修改在；复制场景两边各自独立；换空 localStorage 仍能找回；
  加载 N 次项目里不新增空 `.vx`；只挪脚本时「接到 …」一步接回且修改保留；指认过的数据规则随项目迁移；运行许可仍要重新确认。
- 第二期：不按任何键、杀进程重开，最后一次编辑在项目里；只读项目退回本机且有那行灰字；外部修改不被自动写入覆盖。
- 第三期：目录 ↔ ZIP 往返字节一致；v2 包在现役读取端以外的旧构建上的表现与本节描述一致。
