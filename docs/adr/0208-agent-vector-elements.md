## 问题

维护者 2026-11-24 的三句话：

- 「我们现在已经设计了应用内类似 illustrator 的矢量编辑能力，那 Agent 有没有能够利用上这些矢量编辑器的工具，帮助用户在组图上进一步添加矢量元素。甚至说可不可以更进一步，让 Agent 拥有直接通过 Tavotto 画插画肌理图的能力」；
- 随后更正：「我说的是机理图，科研示意插画」；
- 「Agent 往组图上加矢量元素这个过程，我们要能够做的足够精确和智能，不能 Agent 画完连原图都对不齐。你要以一个更高更深层次的视角去考虑这个问题」。

**现状**：两条 Agent 线都碰不到排版。插件的 17 个工具以「单张图的会话 + 脚本 patch」为单位（0192）；改图助手的工具集只有读写文件与 `check`（0147）；
0199 §十三 写着「排多张图要等 MCP 能读写排版文档再说」。ADR 0185 的矢量对象（`path`、组、蒙版、渐变……）全在排版文档里，由前端编辑。

**真正的难点是精度，不是工具数量。** 模型看到的是一张位图，凭眼睛给出的毫米坐标误差以毫米计；组图里的对齐却是 0.1 pt 级的事（0199 §六 的验收口径）。
「当时对齐」也不够：脚本重跑、拖动图、一键排版之后，图里的坐标轴会移动，事后画上去的箭头就指歪了。所以**精度不能交给模型**，只能由 Tavotto 用图的真实几何保证，
并且要**一直**保证；模型的长处是理解「这里该标什么、指向哪里、讲什么机理」，就让它只做这一半。

## 2026-11-24 实证（决定的依据）

| 查了什么 | 结果 | 对设计的影响 |
| --- | --- | --- |
| 四段典型机理图 SVG 过 `rendercore.svgimport.import_svg` | 渐变、`use`、裁剪、嵌套组都落成 `path` / `text`；**`marker`（箭头头）记为 `unsupported`**，按现约定整段 SVG 当图片；`<tspan>` 的上标被抹平（`Ca²⁺` 变成 `Ca2+`，粗体铺满整行）；同时带 `filter` 与 `pattern` 的那段整段拒绝（这次没拆开测，分不出是哪个触发的） | SVG 只能当「画异形轮廓」的辅助入口；箭头、文字、连线必须是原生对象 |
| 「标注跟着图走」 | 没有存下来的绑定：拖动时按几何包含现算（`web/src/lib/annotationScale.ts` `annotationsInside`），整个在图框里的标注跟着平移并按比例缩放字号线宽 | 现在没有办法让标注「指向图里某个点」并一直指着；新的锚点要和这条现有规则分清谁管谁（§六） |
| 后端对排版对象的校验 | 没有。`validate_document` 只查骨架；对象 id 只由前端 `lib/id.ts` 生成 | Agent 交来的对象是不可信输入，后端要补对象级校验，且与前端判据同源 |
| 后端写排版 | `POST /api/layouts/<name>` 有基于内容哈希的冲突检查，但**只在带 `base_revision` 时才查**；时间线有 `POST /api/versions/<doc_id>` | 插件写排版必须强制带基线；写之前可以先留一版 |
| 0181 的「一个窗口编辑」 | 是浏览器窗口之间的协商（`doc-held` / 接管），**另一个进程（插件）看不到** | 插件不能靠它判断「桌面正开着」，只能靠冲突检查（§五） |
| 图的几何 | manifest 元素有 `bbox`（图幅比例，y 向下）；坐标轴的框取自 `ax.get_position()`（绘图区本身，不含刻度文字）；坐标轴元素带可编辑的 `xlim / ylim / xscale / yscale` | 坐标轴框可以直接当锚点；数据坐标的换算以 worker 里 matplotlib 自己的变换为准（§二），不在外面重写刻度换算 |
| 成品字号 | 0203：`inspector.observe_pdf()` 能从导出的 PDF 里量出每段文字的有效字号 | 字号核对可以在成品上独立量（§四） |

## 决定

### 一、分工：Agent 说「画什么、挂在哪、和谁什么关系」，Tavotto 算「在哪里」，再用另一条路量

借 TikZ 的思路（科研作者画机理图最常用的精确工具，靠的是锚点与相对位置，而不是绝对坐标）：

- Agent 交的是**场景描述**：元素是什么（文字 / 箭头 / 连线 / 括号 / 形状 / 路径 / 示意图元），锚在哪个对象的哪个点上，与别的元素是什么关系（在右边 2 mm、
  与谁左对齐、在两者之间、包住这几个）。
- Tavotto 用一个**确定性的求解器**（不调模型）把它解成毫米坐标；再在**导出管线算出来的几何**上量一遍（§四，不拿求解器自己的数验自己），过了才出方案；
  没过就把量到的事实与可照抄的下一步交回 Agent。
- **凡是与图有关的位置，Agent 不写绝对毫米。** 绝对坐标只在「示意图框」（§七）的自身坐标系里允许，那里没有可以对不齐的东西。

### 二、读：给 Agent 一张「图的几何场景」

新工具 `tavotto_layout_scene`（插件）/ 同名任务工具（改图助手）返回当前画布的结构化场景，**全部是可引用的短号 + 画布毫米**：

- 画布与每张图（`panel`）：框、缩放；
- 每张图里的坐标轴：绘图区框、`xlim / ylim / xscale / yscale`、是否翻转；带 gid 的元素（曲线、柱、散点集合、图例、轴标题、刻度文字、子图标签）的角色、标签与毫米外框；
- 已有的标注对象；
- **空白区**：每张图的绘图区里，减去**数据元素**（角色闭集直接用已有的 `engine/interference.py` `DATA_ROLES`：line、errorbar、scatter、fill、patch、collection、linecoll、image、bar_series、stem_series，不另立一份）的几何与文字元素（`TEXT_ROLES`：刻度文字、轴标题、图例、子图标签）
  之后剩下的矩形区域。坐标轴底色、网格线、轴线不算占位（不按像素统计，否则绘图区里永远没有空白）；
- **样式记号**：图里的字体族、刻度文字 / 轴标题字号、轴线线宽、系列配色（复用 0185 色板的「图内配色」），以及当前期刊的最小字号 / 线宽；
- **场景指纹**：排版的 `base_revision` + 每张图这次渲染的指纹。落地时任一项变了（文档被改、脚本重跑出了新图），方案作废，回 `scene_stale` + 「重新读场景」；
- 一张预览图，**把短号直接标在图上**（视觉定位：模型看到的东西与它能引用的号一一对应）。

**锚点用哪份几何**（2026-11-24 查清，§十三 第 3 项）：manifest 的 `bbox` 是 `get_window_extent` 加上「太薄的边撑到可点击的最小像素」（`_padded_bbox`），散点的 `bbox`
可能只是数据范围、不含标记大小，刻度文字是不带留白的字形框。所以方位点优先取元素的 `geometry`（真实轮廓路径：曲线、柱、散点的每个标记都有），没有 `geometry` 的
（文字、图例）才用 `bbox`，并且不用 `_padded_bbox` 撑过的那一份（锚点要贴着墨迹，不要贴着点击热区）。场景回包里每个锚点标出它取自哪一份。

**坐标链**：图幅比例 → 图的毫米 → 画布毫米，要把图在画布上的缩放、**裁剪**、**翻转**、**旋转**都算进去。首期只支持「缩放 + 裁剪」的图；翻转或旋转过的图回 `panel_transformed`，
不出场景里的子元素（只给它的外框），不猜。

**数据锚点以 matplotlib 为准**：数据点 → 图幅位置由 worker 用这根坐标轴自己的 `transData` 算（线性、对数、symlog、日期、分类轴都自然对），算不了（3D、极坐标的部分情况、
变换报错）回 `anchor_unresolvable`。这是 worker 协议上新的一条只读命令（2026-11-24 查清，§十三 第 4 项）：照 `docs/rules/backend/worker-protocol-and-lifecycle.md` 与 ADR 0003——在 `wireproto.py` 的命令闭集里加一项
（如 `transform_points`），像 `*_existing` 那样作用在已建好的图上、不重跑脚本、不改状态（与 `export` / `preview_png` 同样「状态中性」），走 `REQUEST_TIMEOUT`；
Rust 的 `workerd/` 同步加；用例进 `tests/test_worker_protocol.py` / `test_worker_roundtrip.py`。不用 manifest 的 `xlim / xscale` 在外面重算（非线性轴算不对）。

体积守 `docs/rules/plugin/result-budget-and-session-state.md`：元素按角色截断，截掉的给计数（`elided`），预览图单独一项。

### 三、写：场景描述的闭集

一次调用交一批元素（0192 的评测说明调用越少越好）。每个元素：

- `kind` ∈ `text`、`arrow`、`connector`、`bracket`、`box`、`shape`、`path`、`svg`、`glyph`（§七）、`graph`（§七）；
- **锚点**（闭集）：图 / 坐标轴 / 带 gid 的元素的 9 个方位点（`nw`…`se`、`center`）；**数据点** `{axes, data: [x, y]}`（§二）；刻度位置；
  本批里先声明的元素（按局部名字引用，像 TikZ 的 node 名）；已有的标注对象；
- **关系**（闭集）：`at` + 偏移 mm；`right_of / left_of / above / below` + 间距；`align`（左 / 右 / 上 / 下 / 水平中线 / 竖直中线）；`distribute`；
  `between`；`connect`（从锚点 A 到锚点 B，走直线 / 直角折线 / 弧线，自动绕开数据元素与文字）；`fit`（括号或框包住一组元素，加内边距）；
- **样式只用记号或显式值**：`size: "tick_label" | "axis_label" | <pt>`、`stroke: "axis_line" | <pt>`、`color: {series: "WT"} | "#hex"`；
  不写时取图里的记号，保证与原图一致。

求解是一次拓扑排序后的约束传播（不是通用约束求解器）：环、互相冲突的约束、引用不存在的东西，一律整批不落地，回结构化原因（哪个元素、哪两条约束）和 `next`。

### 四、量过才交：用另一条路量

求解之后、出方案之前，引擎把「原排版 + 新对象」交给**导出管线**（RenderCore 的几何，`geometry.path_segments` 与对象变换，和真正导出 PDF 同一条路）算出新对象的实际轮廓，
再拿它和**图本身的真值**比，不拿求解器的输出验求解器。判据写法照 `docs/rules/repo/predicate-subject.md`，量不了记 unknown，不冒充通过：

1. **锚点残差**：新对象的锚点位置（导出几何）与 worker 给的真值（坐标轴框、gid 外框、`transData` 算出的数据点）之差 ≤ 0.1 pt；
2. **对齐残差**：声明了对齐的几个对象，导出几何上的对应边之差 ≤ 0.1 pt；
3. **不遮数据**：与数据元素（§二 的角色定义）的几何重叠为 0；箭头允许尖端伸进数据区，伸进多少待定（拟 1.5 mm）；显式写了 `over_data: true` 的例外，并在结果里列出来；
4. **不压字**：与刻度文字、轴标题、图例、子图标签、已有标注都不重叠；
5. **不出界**：在所属图或画布之内；
6. **期刊字号**：把方案结果导出成 PDF，用 0203 的 `observe_pdf()` 量新文字的实际字号（含上下标），不低于期刊下限；现有预检的 `font-too-small` 等规则同时照常生效（只覆盖 `text`）；
7. **期刊线宽**：新对象的描边宽度不低于期刊下限。2026-11-24 查清（§十三 第 2 项）：**现有预检对画布上的箭头 / 形状 / 路径没有任何线宽检查**——`line-width-below-min`
   只读 manifest 里图内的线宽，画布对象进预检时只带 `{id, type, rect_mm, hidden}`（`web/src/lib/preflight.ts`）；字号检查只覆盖 `text`，不含路径文字 `pathText`。
   所以要新增一条预检规则（两侧求值器 + `tests/golden/preflight_vectors.json` 对拍），本 ADR 的核对直接复用它；规则对谁生效见 §十二 第 7 项；
8. **与原图一致**：字体族与图里一致，字号 / 线宽落在声明的记号上。

没过：不写文档，回量到的事实（哪项、差多少、和谁重叠）与 `next`。过了：回方案 + 渲染预览图，Agent 看图做语义上的自查（「箭头是不是指向我要说的峰」），
几何正确性由数字保证，不靠看图。

**科学性（七问第 1、4 问）**：

- 标注不能冒充数据：除 `arrow / connector / bracket` 的端点外，元素不得以数据坐标落在绘图区里冒充数据标记；
- **统计标注不由 Agent 编**（维护者 2026-11-24 定）：显著性星号、p 值、n 这类文字只能来自用户的话或脚本 / 数据里有的结果；来源不明的进「需要你确认」，不落地；
- 不改图里任何数据元素；这条工具只加对象（数据指纹不变）。

### 五、落地：只用已有对象类型；一次方案、一次提交、一步撤销

- 结果**只用现有对象类型**（`text / arrow / shape / path` 与组），外加 §六 的 `anchor` 字段；导出端不认识新东西。
- 后端补一份**对象级校验**（类型、必填字段、有限数、`groupPath` 末项 = `groupId`、尺寸上限），与 `web/src/types/document.ts`（`isKnownObject`、`readPath` 的缺省）
  同源，登记进 `docs/rules/repo/same-origin-pairs.md`；对象 id 由后端按 `lib/id.ts` 同一格式生成（`o_` / `g_` + 8 位）。
- **桌面（改图助手）**：方案交给前端，走 0206 的修改方案卡（看过再应用），前端一次 commit。0206 没落地之前的退路：与一键排版一样一次 commit + 一步撤销 + 结果胶囊。
- **无头（插件）**：本 ADR 定义一个排版写入口（0199 §十三 的多图排版以后复用它，不另开一套）：
  - 必须带 `base_revision`（场景回包里给），冲突 409 → `next` = 重新读场景；
  - 写之前经 `POST /api/versions/<doc_id>` 在时间线（0101）留一版，「一步撤销」= 回到这一版；
  - 写根照 0141：只写项目的 `tavottofile/`；
  - **插件可以直接写**（维护者 2026-11-24 定：「也允许插件直接写」），缺省打开。
  - **桌面正开着同一份排版时**（2026-11-24 查清，§十三 第 1 项）：桌面端没有文件监听，只在**下一次写盘**时按内容哈希发现冲突，**任何一条路都不会悄悄丢改动**：
    - 插件写的是项目里的排版文件（`tavottofile/<名>.json`）；桌面的自动保存只写自己的自动保存位置，不碰这个文件，所以不会把插件写的内容盖掉；
    - 桌面下一次 ⌘S / 「存进项目」时收到 409，弹出带冲突分支的保存对话框（`web/src/store/projectSave.ts`），内存里的改动还在，只有用户选「覆盖」才会盖掉插件写的内容；
    - 自动保存位置若被改（不是本 ADR 的写法），自动保存停写、顶栏「别处有改动」；「重新加载」先把本窗口的改动放进恢复槽位再读盘（`documentStore.reloadFromDisk`），可以一键恢复。
  - **缺口**：⌘S 撞上冲突时，用户今天只能在「覆盖（丢掉插件加的东西）」与「另存」之间选，桌面画布上也看不到插件刚加的东西。所以第 2 期一起做：
    冲突对话框认出「磁盘那份比我多出的只是一批带 `anchor` 的新对象」时，多一个主按钮「把 Agent 加的并进来」（一次 commit、可撤销，之后照常保存）；其余冲突照旧走 0096 / 0181。
    另外，桌面开着这份排版时最好不用等到 ⌘S 就知道：插件进程与桌面不一定是同一个后端，通知走哪条路（桌面对项目排版文件做变更检查，或插件经桌面的后端写入）在第 2 期定；
    能通知时在顶栏胶囊说一句「Agent 往这份排版里加了 N 个元素」+「并进来」。
- SVG 入口（`kind: svg`）只经 `import_svg`；`unsupported` 非空时**不落地、也不当图片**，回原因码与 `next`（如「去掉 marker，箭头改用 `arrow`」）。

### 六、一直对齐：锚点第一期就存下来（维护者 2026-11-24 定：A，先提示、后自动重新对准）

- **A（选定）**：`ObjectBase` 加可选字段 `anchor`（`{to: <图 id>, ref: <gid> | "axes:<gid>" | {axes, data}, point, offset_mm}`），**第一期就随对象写进去**：
  - 第一期只做**提示**：图被拖动 / 缩放、脚本重跑之后，按新几何算一遍锚点位置，和对象现在的位置差超过 0.1 pt 就在问题栏列一条「这个标注可能已经没对准它指的地方」，
    带一个「重新对准」按钮；锚点目标不见了列「标注找不到它指的元素了」。
  - 后一期做**自动重解**。这里不必在前端重写数据坐标换算：拖动 / 缩放只是对图整体做仿射，前端按仿射挪锚点即可；脚本重跑的新位置由 worker 的 `transData` 在渲染时给出。
  - **与现有「整个在图框里就跟着走」的分工**：带 `anchor` 的对象不再走 `annotationsInside` 那条（不平移、不按比例缩放），只按锚点重解；不带 `anchor` 的照旧。这样不会被挪两次。
    带 `anchor` 的文字字号不随图缩放（它锚的是期刊字号，图缩放后字号该不该变由期刊规范管，不由图的缩放比例管）。
  - 旧构建不认识 `anchor` 时照旧显示、按旧规则跟着走（字段原样保留，`structuredClone` 不丢字段）。
- **B（未选）**：只落最终坐标，跟随沿用今天的规则。便宜，但脚本重跑、图内坐标轴移动后会悄悄指歪，正是维护者说的「对不齐」。

### 七、机理图（科研示意插画）——高级版

**归属**（维护者 2026-11-24 定：「机理图进高级版」）：示意图框、语义图元 `glyph`、通路图 `graph` 进高级版，0193 §一 的功能键闭集加 `mechanism-diagram`；
按 0198，图元库与通路布局放闭源组件，开源侧只做操作闭集校验与 §四 的核对（与 0199 一键排版同一分工）。免费用户的工具列表里也有这两种 `kind`，
调用回结构化的 `pro_required`（一句话 + 「了解高级版」），不当成错误。**§一–§六 的「给组图加矢量元素」免费**。

画在一个**示意图框**里（一个带框的组，可以单独占一个子图位置，也可以放在图旁边），框内用自身坐标系。三层，由精确到自由：

1. **语义图元 `glyph`**（参数化、确定性生成 `path`，后端 Python 实现，黄金用例看护）：作用箭头（激活 →、抑制 ⊣、间接 = 虚线、转位、结合）、
   细胞膜（双层）、细胞 / 细胞核 / 囊泡 / 线粒体、受体 / 离子通道、DNA 双链、蛋白团块、磷酸化标记 P 等。箭头的语义约定拟参照 SBGN Activity Flow，
   **出处要先读原文再写进 `docs/sciviz/sources.md`，没读之前不引用**。
2. **通路图 `graph`**：Agent 给节点、边（带语义）和大致的层次 / 方向，引擎用分层布局 + 直角走线排好（确定性，不调模型），再按 §四 量一遍。
3. **自由轮廓 `path` / `svg`**：异形的、图元库没有的东西，Agent 写路径或 SVG，过 §五 的严格导入。

示意图框与组图之间的连线（「这块示意对应 b 图的这个峰」）照样用 §三 的锚点与 §四 的核对。

样式统一由 Tavotto 管：字体与原图一致，配色缺省 Okabe-Ito（0185 推荐色板），线宽分层（轮廓 / 连线 / 细节三档，取期刊下限之上）。
给模型的机理图画法只经 `engine/sciviz_guidance.render()` 取，新增一节，条目按 `basis` 标注，不在提示词里另抄。

`svgimport` 顺带补两处（单独的 PR，0189 的安全边界不放松）：简单三角 `marker-end / marker-start` 换成路径的 `headEnd / headStart`；`<tspan>` 的上下标与局部粗细
保留下来（文字对象怎么表示局部样式要先查清现有能力，再定）。`filter` 与 `pattern` 分开各测一次，确认是谁被拒。

### 七之二、可编辑性：画出来的东西要像人画的一样好改

维护者 2026-11-24：「我们的重点要放在其生成的机理图就要像人画的一样非常易于编辑。每个图形都是独立的，拆组后可以单独移动的，形状是易于编辑的。并且最好有智能的分组和命名。……现在的大多数 Agent 生成的机理图不具备可编辑性，只能简单拖动，但是想编辑其中的某个元素几乎不可行。」

**这是机理图最重要的验收项，排在「好看」前面。** 下面每一条都是在 Tavotto 里与导出到 Illustrator 之后都要量的硬性标准：

1. **一个看得见的东西 = 一个对象**：一个受体、一支箭头、一个细胞核各自是独立对象，不把几个看起来分开的形状并成一条路径；复合路径只用来表示「带洞的形状」
   （如环形、膜上的孔）。核对：每个对象的各子路径在画面上是连在一起的（不连的拆开）。
2. **拆组后外观不变、可以单独挪**：组只负责「归在一起」，不承载外观——组上不放变换、不放不透明度、不放剪切（真要蒙版的地方单独标成剪切组，并在名字里说明）；
   变换与不透明度落在每个对象自己身上。核对：把整个机理图全部拆组后逐对象比较渲染结果，与拆组前逐像素一致；Illustrator 里「取消编组」到底后同样核一次。
3. **形状好改**：能用参数对象的用参数对象，带参数的图元保留参数，自由路径过路径质量核对（下面三档）；描边保持描边，不转轮廓；文字保持文字。
4. **智能分组**：按语义分层，像设计师整理图层那样——
   - 顶层是示意图框（如「信号通路示意」），下面按生物结构或叙事分块（「细胞膜」「胞质信号」「细胞核」），再下面是单个元件；
   - 标签与它标注的东西放在同一组（「受体 EGFR」组里是受体形状 + 文字），挪受体时字跟着走，拆组后又能各自挪；
   - 连接两个元件的箭头归到「流程」那一层，不塞进任何一端的组里；
   - 不留只有一个成员的组；层级不超过 4 层；叠放顺序 = 背景 → 结构 → 箭头 → 文字。
5. **智能命名**：每个组和对象都有名字，名字 = 角色 + 身份，用户界面语言（「受体 EGFR」「激活箭头 EGFR→RAS」「磷酸化标记 P」），同类自动加序号；
   不出现「路径 12」「组 3」。Agent 在场景描述里给出语义（它知道这是什么），引擎按规则生成最终名字并保证唯一；图元自带缺省名字。
   核对：没有无名对象、没有无名组、同一层里没有重名。

上面 2、4、5 条对 §一–§六 Agent 在组图上加的元素同样适用（例如「标注 b 图峰值」一组：箭头 + 文字）。

**为什么要这样**：今天的生图 / 写 SVG 的 Agent 产出要么是位图，要么是一整块合并的路径和压平的组，只能整体拖动。Tavotto 的长处是对象模型与导出都在自己手里——
把「像人画的一样好改」做成可量的核对，是别的工具给不了的。

可编辑性的三档：

维护者 2026-11-24：「SVG 是不是对于 Tavotto 以及 illustrator 而言就丧失了可编辑性。那些形状很难以精细地手动调整。」

SVG 导入后在 Tavotto 里是原生的 `path` / `text`（不是图片），**能编辑，但不一定好编辑**：模型写的 SVG 常见几百个锚点、变换被压平、没有分组和名字，
用户想把细胞膜弯一点、把受体挪高一点，得拖几十个点。所以可编辑性按三档看，Agent 的产出一律往上靠：

1. **参数对象（最好）**：箭头、连线、括号、框、矩形、椭圆、文字一律用原生对象，改参数就行（端点、头型、线宽、圆角、字号）。能用参数对象的地方不许用路径。
2. **带参数的图元**：`glyph` 生成的路径在对象上保留生成参数（`glyph: {kind, params, version}`），属性栏按参数改（膜的长度与弯曲、脂质个数、受体高度……），
   改参数 = 按同一 id 重新生成。用户手动拖过它的锚点之后参数脱钩（标「已手动修改」，不再按参数重生成，不覆盖手改）；字段旧构建不认识时原样保留，只当普通路径。
3. **干净路径**：自由轮廓（`path` / `svg`）要过**路径质量核对**才落地——锚点落在极值点与拐点、平滑点两侧手柄共线、没有零长段与重合锚点、每个子路径的锚点数有上限
   （拟「可见拐角数 × 2 + 8」，用真图校准）、闭合形状真的闭合。不过就回 `next` 让 Agent 用更少的锚点重写；后端不偷偷简化（简化内核只在前端，0185 §三）。

另外两条：

- **命名与分组**：每个元素带 `name`（「细胞膜」「受体」「信号箭头」），按语义成组（0191 的嵌套组），用户在图层里一眼找得到、一次选中一整块；
- **带到 Illustrator**：见 §七之三。

### 七之三、导出到 Illustrator 精修

维护者 2026-11-24：「我们机理图也要保证 illustrator 这些编辑器的适配性，用户很可能还希望导出到 illustrator 中精修」。

**2026-11-24 真机实证**（本机 Adobe Illustrator 2025；ExtendScript 打开文件后逐层读出图层、组、名字、剪切、文字段与字体、填充类型，不保存关闭。
样张两类：「基线」= 今天的导出管线对同一组对象的输出；「样张」= 手写的候选写法）：

| 项 | 基线（今天的导出） | 候选写法与 Illustrator 的结果 |
| --- | --- | --- |
| 组 | 前端导出前就拍平（`web/src/lib/exportPayload.ts` `toExportObjects` 不发 `groupPath`）；SVG 里每个对象外面还套 1–2 层没有名字的组 | SVG 嵌套 `<g>` → Illustrator 里原样是嵌套的组 ✓；**PDF 的 `q … Q` 嵌套不成组**（全部平铺） ✗ |
| 名字 | 不导出，图层里全是无名对象 | SVG 的 `id` → 对象名 ✓，中文 `id` 也行（「细胞膜」「受体」原样）；`_` 显示成空格；**`data-name` 被忽略**；**PDF 的可选内容组（图层名）被忽略**，只有一个「图层 1」 |
| 剪切蒙版 | 复制到每个被裁对象上：8 个对象 = 8 个各自独立的剪切组 | SVG 组上一个 `clip-path` → 一个剪切组 ✓ |
| 渐变 | SVG：可编辑的渐变 ✓；**PDF：变成「非原生对象」**，不能当渐变改 ✗ | SVG 线性渐变（含带透明度的色标）→ 可编辑渐变 ✓；PDF 用着色图案或 `sh` 都是非原生对象 ✗ |
| 描边 / 复合路径 | 描边仍是描边、线宽对 ✓ | 复合路径（`fill-rule="evenodd"`）在 SVG 与 PDF 里都是复合路径 ✓ |
| 文字 | 是可改的文字 ✓，但按字体回退拆成几段（「Receptor 」「受体」两个文字框） | 一个 `<text>` 只用一个字体族时是一个文字框 ✓ |
| 字体 | SVG 写 `'Liberation Serif', 'Times New Roman', …`：**Illustrator 只认第一个字体族**，本机没有 Liberation，被替换成一个不相干的本机字体 ✗ | 第一个字体族写成本机有的字体（`Times New Roman`、`Arial`）→ 正确对上 `TimesNewRomanPSMT` / `ArialMT` ✓ |
| 上下标 | — | `baseline-shift="super"`、`baseline-shift="33%"`、`dy` 三种写法**都被拆成单独定位的文字框**，不保留「上标」属性；同一个 `<text>` 的几段落在一个以它命名的组里 |

**结论：给 Illustrator 精修只能走 SVG。** PDF 进 Illustrator 丢组、丢名字、丢图层、渐变变成不能编辑的对象；PDF 继续当投稿成品。

**决定**（对所有画布的 SVG 导出生效，不只机理图；免费，导出质量不是高级版功能）：

1. **组原样导出**：导出载荷带上组树（`groupPath`），IR 按组嵌套（`ir.Group`），SVG 每个组一个 `<g>`；去掉每个对象外面没有作用的包装组。
2. **名字写进 `id`**：名字是合法 XML 名字时原样用（中文可以），空格换成 `_`（Illustrator 显示回空格），以数字或标点开头的加前缀，重名加序号；没有名字的不写 `id`。
   不用 `data-name`（实测被忽略）。
3. **剪切组只写一次**：剪切组里的对象放进同一个带 `clip-path` 的 `<g>`，不再把蒙版复制到每个对象上。
4. **第一个字体族写真实字体**：`font-family` 的第一个写用户机器上有的等价字体（Liberation Serif → Times New Roman、Liberation Sans → Arial、Liberation Mono → Courier New，
   与 Liberation 的字宽一一对应），中文按平台写系统字体（macOS：Songti SC / Heiti SC；Windows：SimSun / Microsoft YaHei；中文这几个名字 Illustrator 能否对上还没实测，实现时先跑探针），后面照旧列回退。
   **这会改变所有带文字的 SVG 导出的字节**（黄金用例要重生成），浏览器与其他编辑器里的显示不变或更好；维护者 2026-11-24 同意：「做」。
5. **每个文字对象写成一个 `<text>`**；有上下标或字体回退的，几段落在一个以对象名命名的组里（Illustrator 只能这样读，实测三种上标写法都一样）。
   2026-11-24 查清（§十三 第 5、7 项）：文字对象本来就支持上下标与局部粗斜（`^{…}` / `_{…}`、`\textsuperscript{}`、`$…$`，`richtext.py` ↔ `web/src/lib/richText.ts` 同源）；
   导出 SVG 时普通上下标每段一个 `<text>`（`svgwriter` 按段写），进 Illustrator 是同一组里的几个文字框、**都还能改字**；**`$…$` 公式则写成路径**，进 Illustrator 是复合路径、
   不能改字（实测「Ca$^{2+}$」的「2+」与「ΔG = −RT ln K」都是曲线）。所以 **Agent 写化学式、离子、单位一律用 `^{…}` / `_{…}`，`$…$` 只留给真正的数学公式**；
   §四 的核对里加一条：文字对象用了 `$…$` 而内容只是上下标时，回 `next` 让 Agent 改写。
6. **参数带不过去，形状带得过去**：图元的生成参数（§七之二）是 Tavotto 自己的东西；带过去的是干净路径与分组。要改参数就在 Tavotto 里改完再导出。
7. 导出对话框里要不要点明「给 Illustrator 精修选 SVG」、怎么说，截图稿过 agy 再定。

**验收**：

- 自动：导出的 SVG 的 `<g>` 树与文档的组树一致、名字一个不少、剪切组里蒙版只出现一次、`font-family` 第一项在映射表里；没有组也没有文字的文档导出逐字节不变。
- **真机**：把这次的探针脚本整理进 `scripts/dev/illustrator_probe.jsx`（ExtendScript，只读：打开、读结构、不保存关闭），每期改导出的 PR 在装了 Illustrator 的 Mac 上
  对同一组样张跑一遍，结果（组树、名字、剪切组数、渐变类型、字体名）贴进 PR。Windows 上的 Illustrator 与 Inkscape、Affinity Designer 另跑一次。

### 七之四、导出 `.ai`

维护者 2026-11-24：「实际上我们也可以支持导出 .ai 文件，这样最能适配 illustrator」。

**三条路，2026-11-24 在本机 Illustrator 2025 上实测**（同一份 §七之三 的样张，同一个只读探针）：

| 路 | 做法 | 组 | 名字 | 剪切组 / 渐变 | 文字 |
| --- | --- | --- | --- | --- | --- |
| 现代 `.ai` 自己写 | PDF + Illustrator 私有数据（`AIPrivateData`，PGF） | — | — | — | — |
| 旧版 `.ai`（AI 7） | vectorcraft `vectorcraft-cli convert … --ai-version 7`（`crates/eps/src/legacy_ai/`，MIT OR Apache-2.0） | 在 ✓ | **全丢**（格式只给图层起名）；中文图层名变成 `???` | 在 ✓ / 可编辑渐变 ✓，但渐变形状上的描边丢了 | **含中文的文字被转成轮廓**（30 段曲线，不能改字）；另一份里文字框读不出内容；透明度变成不透明 |
| Illustrator 自己另存 | 用户的 Illustrator 打开 Tavotto 导出的 SVG，另存为 `.ai`（脚本 `IllustratorSaveOptions`） | 在 ✓ | 在 ✓（与 SVG 完全一样） | 在 ✓ / 在 ✓ | 中文文字仍是文字 ✓ |

- 现代 `.ai` 的私有数据没有公开规格，也没有开源写出器；**不带私有数据的 `.ai` 就是改了扩展名的 PDF**，Illustrator 按 PDF 导入（§七之三：丢组、丢名字、渐变变非原生对象）。不做。
- 旧版 `.ai` 对中文用户是倒退（名字、中文文字都保不住），**不做**。
- 真正的 `.ai` 只有 Illustrator 自己写得出来；它从我们的 SVG 另存出来的 `.ai` 与 SVG 的结构逐项相同。所以 **`.ai` 的保真度上限 = 我们 SVG 的保真度**，
  功夫全部花在 §七之三 的 SVG 上。

**决定**（维护者 2026-11-24 选 A）：精修走 SVG；在此之上给装了 Illustrator 的用户一个省事的入口——

- **A（选定）**：导出对话框 / 机理图的右键菜单里「在 Illustrator 中打开」：导出 SVG 后直接用本机 Illustrator 打开，用户在 Illustrator 里按需存成 `.ai`。
  只调系统的「用某个应用打开文件」，不驱动 Illustrator 的脚本；没装 Illustrator 时不出现这一项。
- B（未选）：「导出为 .ai（需要本机装有 Illustrator）」：在后台用 Illustrator 的脚本接口把 SVG 另存为 `.ai`。要驱动第三方应用、要处理 Illustrator 的版本 / 授权 / 弹窗，
  失败面大，不推荐首期做。

### 八、两个宿主，一个引擎

## 后果

- 正面：精度由几何与测量保证，与模型强弱无关；换更好的模型只会让「画什么」更好，不会让「画在哪」变差。锚点存下来之后，脚本重跑、一键排版也不会让标注悄悄指歪。
  插件与改图助手共用一个引擎、一个写入口，与 0199 §十三、0206 是同一套「只算不写 → 看过再应用」的契约。
- 代价：引擎要新写求解与核对；worker 协议多一条查询；后端第一次有对象级校验，要和前端一起改；`anchor` 改变了一部分标注的跟随规则。
- 风险：空白区按 manifest 的角色认数据元素，角色认错（例如把画数据的 `fill_between` 认成装饰）会让标注压到数据上——角色闭集与 manifest 同源，认不出的元素一律当数据占位。

## 修订（2026-11-25，第 2 期：意图核对、排版写入口）

1. **意图核对**（维护者 2026-11-25 同意推进）。第 1 期保证「引擎准确做了描述里写的」，不保证「描述就是用户要的」——
   偏差出在 Agent 把用户的话翻成描述那一步，任何语言都省不掉这一步。所以每批方案多一项**复述**：
   - **只从求解结果生成**（`engine/layoutannotate.describe`）：每个锚点实际落到了什么——元素的名字（脚本 `label=`）与角色、
     子图与坐标轴、数据坐标——不回放 Agent 的输入。锚点全落在**有名字**的元素上、数据点都量到了，`intent` 为 `describable`；
     否则 `unnamed`（复述只说得出 gid / 坐标，Agent 没法拿用户的原话去比，如实告诉用户）。

2. **写入口**（`engine/layoutannotate.py`，插件与以后的改图助手共用，插件只翻译）：
