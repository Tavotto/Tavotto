# ADR 0217：插件会话与桌面排版的图内修改同步——一份真值、按条合并；建议待办卡在窗口里出同一张

日期：2026-11-28 · 状态：**Accepted**
相关：[0214 建议待办卡](0214-suggestion-todo-card.md)（第 3 期 3b 的底座）、[0208 排版标注](0208-agent-vector-elements.md) 第 2 期 ③ /
[0212 矢量编辑](0212-agent-vector-editing-tools.md) §二（Agent 写排版、桌面「并进来」）、[0211 始终保存](0211-always-saved-project-local-history.md)、
[0094 写回事务](0094-script-writeback.md) §零、[0083 目标身份](0083-override-target-identity.md)。

## 问题

插件（Codex / Claude Code）改图内修改，改的是 MCP 会话里那份 `Session.patches`；桌面改的是排版文件里子图的 `panel.overrides`。两份互不相干：
用户在桌面拖好了图例，再让 Agent「按你的建议改」，Agent 是在没拖过的那份上改的；Agent 改完，桌面看不到。0214 第 3 期 3b（窗口里出同一张待办卡）
建在这上面必然对不上——维护者 2026-11-28 选「做完整版：先同步，再出同一张卡」。

## 决定

### 一、一份真值：排版里的 `panel.overrides`

- 插件会话**绑定**到一份排版里的一个子图后，不再自己存一份 patches：每次调用读那个子图此刻的 `overrides`，写的时候写回那个子图（`write_canvas`：
  文档锁、修订号核对、撤销留存、原子替换，与 0208 / 0212 写排版同一条路）。没绑定的会话照今天的行为（会话自己那份），什么都不变。
- 脚本仍是真值，照 0094 §零：同步只动排版里的图内修改，**任何路径都不写用户脚本**。
- 读到的修改带 `identity`（0083）原样保留；全量列表语义不变（列表里没有的键 = 恢复脚本原值），所以写回整份列表，不发增量。

### 二、绑定

- `tavotto_open_figure` 多一个可选 `layout`（排版名）+ `panel`（子图 id 或短号 `P1`）。不给时：这张图在项目所有排版里**只出现在一个子图**就自动绑；
  出现在多个子图 = 不绑，回包 `binding: {state: "ambiguous", candidates: [...]}`，Agent 问用户是哪一个再带上重开；一个都没有 = 不绑（`state: "none"`）。
- 不能绑的子图与 `_layout_measure` 同一口径：按冻结快照合成的（`figureSnapshot` / `figureOrigin`）、运行时素材、没有登记脚本的。
- 绑定那一刻：会话的修改 = 子图的修改。会话里如果有没导出的草稿（0192 第 2 条）且与子图不同，**子图赢**，草稿另存一份、回包如实说
  「你上次在会话里的修改没进排版，已经以排版里的为准」（`draft_superseded`）。
- `lockedGids`（用户锁住的元素）里的元素，插件的修改照桌面规矩不改，进 `rejected`（`locked`）。

### 三、桌面 → 插件：每次调用先读

- 绑定的会话在每次调用前（与 `@_synced` 同一个入口）比一次排版修订号：变了就重读那个子图的 `overrides`、按新列表重渲染同一个会话，回包带
  `layout_sync: {reason: "desktop_changed", changed: [...有界]}`。桌面里撤销（⌘Z）也就是插件下一次读到的状态，不另算。
- 子图被删了 / 排版被删或改名：会话解绑，回包说清（`binding.state: "lost"`），之后照没绑定的会话用。

### 四、插件 → 桌面：写回 + 桌面按条并进来

- 绑定会话的 `tavotto_apply_overrides` / `tavotto_suggest_apply` / `tavotto_normalize_figure` 等写修改的工具：渲染通过后把整份列表写回子图
  （`base_revision` = 本次调用读到的修订）；写之前排版又变了 → 拒绝（`layout_changed`），Agent 重读再改，不在别的底子上套。
- 工具说明写明：绑定后这些工具**会改用户的排版文件**（只改这个子图的图内修改）；回包带 `layout_written` 与撤销凭据（共用 0208 的撤销留存，
  每份排版最近 20 步，「中间没被别人写过」才能撤）。
- 桌面「并进来」（0208 ③ / 0212 §二，`planAgentMerge`）扩一格：**子图的 `overrides` 按 `(gid, prop)` 逐条三方合并**——
  Agent 改的那几条、桌面这边从基线起没动过 → 换成 Agent 的；同一条两边都改了 = 冲突。合并结果一次 commit，⌘Z 一步撤回。
- **冲突时桌面赢**：桌面那份不动、不弹覆盖 / 另存，插件那次写入在桌面并入时整笔不并（排版文件改回桌面那份的下一次自动保存），
  插件下一次调用读到桌面那份、回包说清「用户在桌面也改了 X，你那次修改没进排版」（`layout_sync.reason: "desktop_won"`）。
  （0212 的矢量对象冲突照旧走覆盖 / 另存；只有图内修改这一格桌面直接赢——用户的手比 Agent 的建议优先。）
- 规范化合同（[0051](0051-preserving-normalization.md)）：桌面改到合同范围以外的条目 = 合同解除、验收作废（与 `user_authorized` 解除同一处置），回包如实说。

### 五、窗口里的待办卡（0214 3b）

- 绑定会话出的建议方案（`tavotto_suggest_plan`）的底子就是子图此刻的修改，`base.target` 记子图的 `fileId`（桌面口径），另记 `agent.panel`。
- 桌面发现：与「并进来」同一个节奏（窗口回到前台 + 每 60 秒）问 `GET /api/change-plans?agent=1`（新，只列这个项目、6 小时内、没应用过的
  Agent 方案）；打开的排版里有对得上的子图、修改也对得上（指纹一致）就在助手面板出同一张待办卡，标「来自 Codex」之类的来源（文案过 agy）。
  不推送：打包版桌面不收插件主动发来的请求（只认受限令牌），轮询不用新开口子。
- 桌面上点「改这 N 项」：图内待办照 0214 写进文档（一次 commit）；**脚本待办不在桌面做**，卡上那几行写「交给 Codex 改」，
  勾着的交回插件（`suggest_status` 的 `chosen` 带它们，宿主照 3a 自己改脚本）。「＋ 再加一条」在 Agent 来源的卡上不出现（加的那条要 Agent 想）。
- 桌面应用的结果另记一格（`agent_applied: {by: "desktop", keys, at}`，不复用脚本方案的 `applied`），`suggest_status` 回 `by: "desktop"`；
  插件这边的会话下一次调用经第三节读到新修改。两边都点了：先落定的那次算，后一次 `suggest_plan_applied`。

### 六、不做

- 不做插件 ↔ 桌面的实时推送；不做跨项目、跨机器；不同步脚本修改（脚本本来就在磁盘上，两边各自按 `script_revision` 发现）；
  不让插件改冻结快照合成的子图。

## 分期（PR）

1. ADR（本文）。
2. 绑定 + 桌面 → 插件（第二、三节）：`open_figure` 的 `layout` / `panel`、自动绑、每次调用先读、解绑；插件测试 + 真 worker 往返。
3. 插件 → 桌面（第四节）：写回、`planAgentMerge` 按条合并、冲突桌面赢；前端测试 + 金样向量（若合并有后端镜像）。
4. 窗口里的待办卡（第五节）：列表端点、桌面轮询、Agent 来源的卡、`agent_applied`、`suggest_status` 带桌面结果。预览先给维护者看、过 agy。

## 维护者裁决（2026-11-28）

1. 同一条图内修改两边都改了：**桌面赢**，不弹窗，Agent 下一次调用被告知。
2. 绑定后插件**直接写排版**、不再问（可撤销、从不改脚本），同 0208 §十二 第 4 条。
3. **只出现在一个子图时自动绑**；多个子图时 Agent 问用户；一个都没有照今天的用法。
4. 1.0 收敛纪律：**算在 0214 的豁免里**，不单独记。
