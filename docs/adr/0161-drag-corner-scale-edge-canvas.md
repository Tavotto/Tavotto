# ADR 0161：拖角改图、拖边改画布——单图留白与排版裁剪共用一套停靠点

日期：2026-11-02 · 状态：**Accepted**（用户 2026-11-02 在「画布拖边 · 交互演示」页上同意三点，并说「就按你的推荐开始实现」）
相关：[0028 原图规格](0028-original-output-spec.md)、[0098 savefig 的裁切框就是图幅](0098-savefig-frame-is-the-figure.md)、
[0051 保留原图的规范化](0051-preserving-normalization.md)、[0128 智能对齐](0128-smart-alignment.md)；
`docs/rules/frontend/canvas-objects-and-workspace.md`、`docs/rules/frontend/workflows-and-original-spec.md`。

## 动机

用户来信：「调整画布大小时，里面的图不变……或者导出时加一个图片紧凑的选择」。

- **单图编辑**里拖图的四条边改的是 `figure.size_mm`：图按新图幅重新出图，文字 pt 不变，绘图区被拉伸 / 挤压。
  用户想要的「画布变大、图不变」（加留白放标注、把画布扩到栏宽）没有入口；单图导出的页面恒等于图幅，留白也带不出去。
- **多图排版**里拖面板的边是非等比拉伸（把字和点压扁），拖角是视觉缩放（图内 pt 按比例折算，预检照折算后的查）。
  叠在图上的 a / b 字母、箭头不跟着缩。
- 「紧凑导出」要的是「裁到内容」，而 matplotlib 自己就有这个框（`get_tightbbox`）。

## 裁决

一条手势语法，两个模式各自的「图」：

| 手势 | 单图编辑（改图本身） | 多图排版（摆放成品图） |
|---|---|---|
| 拖角 | **等比改图幅**（`size_mm` override，松手后重新出图，文字 pt 不变）；⇧ 自由比例；⌥ 关栏宽吸附；吸附量的是**导出宽 = 图幅 + 左右留白** | 整张图**等比视觉缩放**（现状），图内 pt 折算显示在胶囊里，低于期刊下限只变色提示（不吸回）；**「连同标注」默认开**：与这张图相交的标注按同一锚点、同一比例缩放位置、尺寸、字号、线宽 |
| 拖边往外 | **扩充画布**：图不动，那一边加留白；画布宽吸附栏宽 | 只能退回图边（页面本身就是画布，不给单张图加留白） |
| 拖边往里 | 先收留白 → 停在**图边** → 停在**内容边缘（紧凑）** → 按住 ⌥ 才继续裁进内容 | 同一组停靠点，作用在面板裁剪（`panel.crop`）上 |
| 排版里改图幅本身 | — | 双击进图内后走单图规则，排版层不再加第三种手柄 |

胶囊（`ContextBar`）在这类拖动期间**不再隐藏**，改为显示这一下拖动的含义（「扩充画布 · 右 +6 mm」「等比改图幅 · 86 → 120 mm · 文字保持 8 pt」
「缩放 92% → 75% · 图内文字 7.4 → 6.0 pt」「紧凑 · 已到内容边缘，按住 ⌥ 继续会裁掉内容」）；不拖时显示数值与「贴合内容」「去掉留白 / 取消裁剪」。
其余手势（移动、旋转、普通对象缩放）的「拖动即藏」不变。

## 数据与协议

### 1. 单图留白 `FigureDocument.framePad`

`{ l, t, r, b }`（mm，负值 = 裁进图幅），挂在**画布**上（模式按画布判、`openFastEdit` 一张图一张画布）。缺席 = 全 0，与今天逐字节相同。
只在单图编辑里有意义：第二张图进来变排版时保留不用，删回一张原样回来（与 `page` 的处理同一个道理）。
**不写回脚本**：写回原始文件改的是 `.py` 与它的 savefig 产物，留白只在 Tavotto 的导出里生效；胶囊上的 ⓘ 说这一句。

图幅变了（拖角、属性栏图幅、AI 改图）时：处在「紧凑」停靠点上的那几边**保持紧凑**（按新的内容边缘重算），其余边的 mm 不变。
判据是 `framePadTight?: ('l'|'t'|'r'|'b')[]`，由手势 / 「贴合内容」写，不从数值猜。

### 2. 内容边缘：manifest 的 `figure.ink_bbox`

引擎在出 manifest 时取 `fig.get_tightbbox(renderer)`（matplotlib 自己 `bbox_inches="tight"` 用的同一个框，**不加 pad**），
换成相对图幅的分数（y 向下，与 `bbox` 同一套），放在 `gid == "figure"` 元素上。加字段协议：缺席（旧后端）= 没有「紧凑」停靠点，
拖边照样能扩 / 收，只是不停在内容边缘，「贴合内容」按钮置灰。前端读它只经 `exactPanelManifest`（ADR 0017）。

### 3. 导出：`original.pad_mm`

单图原图口径的请求加可选 `original.pad_mm: [l, t, r, b]`。缺席或全 0 → 载荷与今天逐字节相同。有值时后端走「原图 + 标注」那条
RenderCore 合成路径（`_export_produce_original_annotated`，没有标注也走它）：页面 = 图幅 + 留白，面板落在 `(l, t)`，
负值由页面裁掉。位图源的像素密度、EPS 内嵌、产物验收的尺寸都按页面算。前端 `singleAnnotatedDocument` 同一份规则生成预览与
`original.objects` 坐标（标注以页面左上为原点）。检查（栏宽等）按页面宽判。

### 4. 排版的边 = 裁剪

面板四条边的手柄从「非等比拉伸」改为裁剪（写 `panel.crop`，与裁剪工具同一字段、同一撤销标签）；往外到「未裁剪」为止。
已经被拉伸过的老面板（宽高比 ≠ 原图）照原样显示，不迁移。角柄语义不变（等比，⌥ 反转锁定），只加「连同标注」。

## 不做的

- 不加「导出紧凑」开关：单图的「贴合内容」就是它；排版导出本来就按页面。
- 不做整页缩放（用户 2026-11-02 确认要的是单图缩放）。
- 留白不进写回、不进脚本、不改 savefig。

## 1.0 豁免

扩大产品能力，登记在 `docs/1.0-release-readiness.md` §1.8。默认开；逃生口：不拖边就与今天相同，`framePad` 缺席即旧行为。

3. 前端排版：边 = 裁剪（停靠点）、「连同标注」、胶囊拖动中显示。
