# ADR 0161：拖角改图、拖边改画布——单图留白与排版裁剪共用一套停靠点

日期：2026-11-02 · 状态：**Accepted**（用户 2026-11-02 在「画布拖边 · 交互演示」页上同意三点，并说「就按你的推荐开始实现」）
相关：[0028 原图规格](0028-original-output-spec.md)、[0098 savefig 的裁切框就是图幅](0098-savefig-frame-is-the-figure.md)、
[0051 保留原图的规范化](0051-preserving-normalization.md)、[0128 智能对齐](0128-smart-alignment.md)；
`docs/rules/frontend/canvas-objects-and-workspace.md`、`docs/rules/frontend/workflows-and-original-spec.md`。

## 动机

用户来信：「调整画布大小时，里面的图不变……或者导出时加一个图片紧凑的选择」。

- **单图编辑**里拖图的四条边改的是 `figure.size_mm`：图按新图幅重新出图，文字 pt 不变，绘图区被拉伸 / 挤压。
  用户想要的「画布变大、图不变」（加留白放标注、把画布扩到栏宽）没有入口；单图导出的页面恒等于图幅，留白也带不出去。
- **多图排版**里拖面板的边是非等比拉伸（把字和点压扁），拖角是视觉缩放（图内 pt 按比例折算，预检照折算后的查）。
  叠在图上的 a / b 字母、箭头不跟着缩。
- 「紧凑导出」要的是「裁到内容」，而 matplotlib 自己就有这个框（`get_tightbbox`）。

## 裁决

一条手势语法，两个模式各自的「图」：

| 手势 | 单图编辑（改图本身） | 多图排版（摆放成品图） |
|---|---|---|
| 拖角 | **等比改图幅**（`size_mm` override，松手后重新出图，文字 pt 不变）；⇧ 自由比例；⌥ 关栏宽吸附；吸附量的是**导出宽 = 图幅 + 左右留白** | 整张图**等比视觉缩放**（现状），图内 pt 折算显示在胶囊里，低于期刊下限只变色提示（不吸回）；**图内标注跟着缩**（2026-11-04 修订，见文末）：整个落在这张图里的标注按同一锚点、同一比例缩放位置、尺寸、字号、线宽 |
| 拖边往外 | **扩充画布**：图不动，那一边加留白；画布宽吸附栏宽 | 退回图边；~~到图边为止~~（2026-11-06 修订：没裁剪过的图从图边继续往外 = 改图幅，文字 pt 不变，见文末）。页面本身就是画布，不给单张图加留白 |
| 拖边往里 | 先收留白 → 停在**图边** → 停在**内容边缘（紧凑）** → 按住 ⌥ 才继续裁进内容 | ~~同一组停靠点，作用在面板裁剪（`panel.crop`）上~~（2026-11-09 修订：没裁剪过的图往里 = 缩小图幅、文字 pt 不变，按住 ⌥ = 裁剪，见文末） |
| 排版里改图幅本身 | — | ~~双击进图内后走单图规则~~（从未实现：模式只由画布图数决定）；2026-11-06 修订：沿用边柄，不加第三种手柄，见文末 |

胶囊（`ContextBar`）在这类拖动期间**不再隐藏**，改为显示这一下拖动的含义（「扩充画布 · 右 +6 mm」「等比改图幅 · 86 → 120 mm · 文字保持 8 pt」
「缩放 92% → 75% · 图内文字 7.4 → 6.0 pt」「紧凑 · 已到内容边缘，按住 ⌥ 继续会裁掉内容」）；不拖时显示数值与「贴合内容」「去掉留白 / 取消裁剪」。
其余手势（移动、旋转、普通对象缩放）的「拖动即藏」不变。

## 数据与协议

### 1. 单图留白 `FigureDocument.framePad`

`{ l, t, r, b }`（mm，负值 = 裁进图幅），挂在**画布**上（模式按画布判、`openFastEdit` 一张图一张画布）。缺席 = 全 0，与今天逐字节相同。
只在单图编辑里有意义：第二张图进来变排版时保留不用，删回一张原样回来（与 `page` 的处理同一个道理）。
**不写回脚本**：写回原始文件改的是 `.py` 与它的 savefig 产物，留白只在 Tavotto 的导出里生效；胶囊上的 ⓘ 说这一句。

图幅变了（拖角、属性栏图幅、AI 改图）时：处在「紧凑」停靠点上的那几边**保持紧凑**（按新的内容边缘重算），其余边的 mm 不变。
判据是 `framePadTight?: ('l'|'t'|'r'|'b')[]`，由手势 / 「贴合内容」写，不从数值猜。

### 2. 内容边缘：manifest 的 `figure.ink_bbox`

引擎在出 manifest 时取 `fig.get_tightbbox(renderer)`（matplotlib 自己 `bbox_inches="tight"` 用的同一个框，**不加 pad**），
换成相对图幅的分数（y 向下，与 `bbox` 同一套），放在 `gid == "figure"` 元素上。加字段协议：缺席（旧后端）= 没有「紧凑」停靠点，
拖边照样能扩 / 收，只是不停在内容边缘，「贴合内容」按钮置灰。前端读它只经 `exactPanelManifest`（ADR 0017）。

### 3. 导出：`original.pad_mm`

单图原图口径的请求加可选 `original.pad_mm: [l, t, r, b]`。缺席或全 0 → 载荷与今天逐字节相同。有值时后端走「原图 + 标注」那条
RenderCore 合成路径（`_export_produce_original_annotated`，没有标注也走它）：页面 = 图幅 + 留白，面板落在 `(l, t)`，
负值由页面裁掉。位图源的像素密度、EPS 内嵌、产物验收的尺寸都按页面算。前端 `singleAnnotatedDocument` 同一份规则生成预览与
`original.objects` 坐标（标注以页面左上为原点）。检查（栏宽等）按页面宽判。

### 4. 排版的边 = 裁剪

面板四条边的手柄从「非等比拉伸」改为裁剪（写 `panel.crop`，与裁剪工具同一字段、同一撤销标签）；往外到「未裁剪」为止。
已经被拉伸过的老面板（宽高比 ≠ 原图）照原样显示，不迁移。角柄语义不变（等比，⌥ 反转锁定），只加图内标注跟着缩。

## 不做的

- 不加「导出紧凑」开关：单图的「贴合内容」就是它；排版导出本来就按页面。
- 不做整页缩放（用户 2026-11-02 确认要的是单图缩放）。
- 留白不进写回、不进脚本、不改 savefig。

## 1.0 豁免

扩大产品能力，登记在 `docs/1.0-release-readiness.md` §1.8。默认开；逃生口：不拖边就与今天相同，`framePad` 缺席即旧行为。

## 实施

1. 引擎：`figure.ink_bbox` + `original.pad_mm`（含 EPS、产物验收）。
2. 前端单图：`framePad` 持久化、拖边 / 拖角手势、胶囊、导出接线。
3. 前端排版：边 = 裁剪（停靠点）、图内标注跟着缩、胶囊拖动中显示。

## 修订 2026-11-04：去掉「连同标注」开关，图内标注按位置自动跟随

用户反馈：「连同标注」只管拖角缩放，拖着图移动时标注从来不跟，开不开都一样，名字让人以为移动也带着走。
用户裁决：**去掉开关；标注在图内时跟着图移动和缩放，在图外时独立**。

- 「在图内」= 标注看得见的盒（旋转过的取外接框）**整个落在**面板此刻的可见框里，且未锁定、未隐藏；
  成组的标注要整组都满足（只带走半个组等于拆组）。压在图边上、伸到图外的标注不跟——原先「相交即跟」作废。
  判据唯一出处 `lib/annotationScale.annotationsInside`。
- 移动：鼠标拖动与方向键微调共用 `draggableSelection`，它经 `withFollowers` 给每张移动的面板补上图内标注，
  同一事务、同一条历史；历史标签按用户选中的个数说。只拖标注本身时面板不跟。
- 缩放：多图排版拖角时照旧按同一固定点、同一比例缩放（非等比那一帧留在原处）；单图编辑拖角改图幅，不涉及。
- `uiStore.scaleWithAnnotations` 删除；老用户本机偏好里残留的这一键读入时被忽略。

## 修订 2026-11-06：排版里从图边往外拖 = 改图幅

用户反馈（v0.21.0）：选中排版里的子图往下 / 往右拖，想把图加宽，却只得到「到图边 · 右未裁剪」。原裁决写的「双击进图内后走单图规则」
没有成立过：模式由画布图数决定（`settleMode`），双击进图内后仍是排版，所以排版里没有不压扁文字的加宽办法。用户裁决：**拖动改变图幅，文字大小不变。**

- 没裁剪过的面板，边已在图边上，指针继续越过吸附半径 → 改被拖那一维的 `figure.size_mm`（与单图拖角、属性栏「图幅」同一条 override），缩放比不变，所以文字 pt 不变；另一维不变，对边不动。
- ~~往里拖仍是裁剪，语义与停靠点不变~~（2026-11-09 修订，见下）；同一下拖动可以往返，松手落在哪边算哪边。
- 拖动中只放虚线预览框，不写文档；松手丢掉裁剪事务、`setFigureFrame` 一次（一条历史 + 一次渲染），新图回来前留虚线框。只拖到吸附半径内或 Esc / pointercancel 不改图幅。
- 权威同单图（`figureFrameFacts`，只认精确 manifest）。裁剪过的图停在图边，胶囊说「取消裁剪后才能改图幅」：`panel.crop` 是相对图幅的分数，图幅一变裁剪框就得重算，这一步不混进同一个手势。没有可编辑 `size_mm` 的图同样停在图边并说明。
- 旋转 / 翻转过的面板、角柄语义不变。图内标注不跟着动（页面位置不变）；压到相邻子图由用户自己摆，不做避让。

## 修订 2026-11-09：排版里往里拖也 = 改图幅；⌥ = 裁剪；文字放不下时提示等比缩小

用户反馈：往外拖按原字号重新出图，往里拖却是裁剪，贴到内容边缘就停住——图只能变大不能变小。用户裁决（2026-11-09）：
**往里拖也重新出图；拖到文字撑不下时提示，是否等比缩小文字；按住 ⌥ 拖边 = 裁剪；等比缩小只缩到刚好放得下。**

- 没裁剪过、`size_mm` 可编辑的面板：不按 ⌥ 时两个方向都改被拖那一维的 `figure.size_mm`（`planEdgeGrow`，`outMm` 可负，钳到引擎的 min / max），缩放比不变，文字 pt 不变。
- 按住 ⌥ = 裁剪（停靠点照旧；⌥ 本身已表示「要裁」，所以同时放行越过内容边缘，不再另设一道闸）。拖动中按 / 松 ⌥ 即时切换，松手落在哪种算哪种。
  裁剪过 / 图幅不可编辑 / 旋转翻转过的面板，边柄语义不变（只裁剪）。
- 「文字放不下」= 新图回来时，被拖那一维上元素探出图幅的量比拖之前**新增**了超过容差（逐元素判据就是预检「元素超出图幅」，同一份 `drawnFigureRect`）。
  只在缩小后、新图回来那一刻量一次；原来就压边的部分不算。
- 提示走通知轨的带按钮 toast（不挤页面）：「文字放不下了，要等比缩小吗？」+「缩小到 N%」。点了 = 页面上的框不动，按「刚好放得下」的图幅出图
  （被拖那一维 = 现在 + 新增探出量，不超过拖之前的长度；另一维同比放大），再整体等比缩进框里：文字只缩必要的那部分。一条历史、一次渲染。
  matplotlib 布局不是严格线性，估短了新图回来再量一遍、再问一次；超出引擎上限就不提示。提示挂着时撤销或改过图幅，按钮什么都不做。
