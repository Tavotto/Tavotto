日期：2026-11-21 · 状态：**Proposed（草稿：先定契约与计量口径；额度数字、模型、成本比例等维护者拍板，见 §十二）**

## 问题

高级版的第一项权益是「内置 AI」：买了高级版的用户不用自己去申请模型的 API key，打开就能用改图助手、AI 修复、数据出图。
这件事要同时满足四条：

1. **模型密钥不能离开我们的服务器。** 仓库是 AGPL，客户端里的任何东西都会被拆出来；打包进应用的密钥迟早会被拿去白嫖。
2. **花多少要算得清、管得住。** 模型按 token 收费，各家价格差几十倍；一次改图从几万到几十万 token 不等，失败的那次往往最贵（§三实测）。
   收入是固定的（年度 ¥168），成本是浮动的，必须有上限、有熔断，而且要能不发版就调。
3. **所有用户当小白。** 额度用完、网关不通、令牌过期，都不许把用户卡在报错上；自带 key 的免费路径永远照旧可用。
4. **永久免费承诺不动。** 改图助手、AI 修复、数据出图本身都是免费功能（用户自带 key 或订阅登录）。`hosted-ai` 卖的只是「我们替你付模型的钱」，
   不许在这些功能里加任何权益判断（0193 §一）。

## 决定

### 一、范围

- **算进内置 AI 的**：Tavotto 自己发模型请求的路径（都经 `engine/agent_runner/wires.post_json`）：
  - 改图助手 `figure_edit`（`/api/ai/run`，含「按期刊修正」这一情景）；
  - AI 修复 `fix_environment`（`/api/ai/fix`，`fixsession` 进程内循环）；
  - 数据出图「理解列」（`/api/ai/data-figure/propose` → `ai_data_roles`，单轮结构化调用）；
  - 「转成可编辑」`convert`（`/api/ai/convert`、`/realign`）：**是否算进、单列上限，待维护者定**（单次上限 80 万 token，是其他任务的 2 倍）。
- **不算的**：Codex / Claude Code 订阅登录（`sub:codex` / `sub:claude`）、用户自填的任何连接——这些照旧走用户自己的账，网关不出现。
- 一键排版（0199）没有模型调用，与本 ADR 无关。
- **内置 AI 是一条连接，不是一个开关**：在「连接 AI」列表里多一条「Tavotto 内置」（只有 `license.has("hosted-ai")` 时出现）。
  执行器路由照旧（ADR 0170 / 「界面不出现执行器」）：用户选了它就用它，选了自己的 key 就用自己的。功能代码里没有任何 `has()` 判断——判断只在这条连接是否出现。

### 二、计量单位：后台记成本，界面显示额度

- **账本单位 = 成本**，记「微元」（百万分之一人民币，整数）。每次请求结算：
  `成本 = 未命中缓存输入 × 输入价 + 命中缓存输入 × 缓存价 + 输出 × 输出价`（价格表在配置里，§七；美元计价的上游按配置里的固定汇率折算）。
  不用 token 记账：模型之间价格差几十倍，换模型、降价都只改价格表。
- **界面只显示比例**：设置里一条细进度条「本月内置 AI 已用 37%」，用到 80% 时一行灰字。不显示 token、不显示钱。
  （「大约还能改 N 次」需要按任务类型估，口径不稳，第一版不做。）
- **周期**：每张授权的权益期内，每 30 天一个额度周期，从该次购买的开始日起算；周期结束余额清零（不结转）。通行证叠加时周期首尾相接。
- **每档每周期的额度**写在配置里（§七），本 ADR 不写数字；三种时长通行证用同一个每月额度，课题组每份一样。

### 三、实测：每类任务花多少

（2026-11-21，开发机实测，全部是**服务端报的用量**，不是字符估算。）

**AI 修复**：`scripts/eval/fix_compat` A 组，`opencode-go/deepseek-v4.1-flash`，11 题各 1 次（2 题本来就出图、不叫模型），数据取 sidecar 执行追踪：

| 结局 | 题数 | 输入 token / 次 | 其中命中缓存 | 输出 token / 次 | 轮数 |
|---|---|---|---|---|---|
| 修好 | 1 | 91.6k | 87% | 1.5k | 10 |
| 模型认输（`gave_up_not_fixed`） | 5 | 62k–165k | 80–92% | 2.0k–5.9k | 6–13 |
| 撞预算上限（`fix_failed:budget`） | 2 | 609k–622k | 92% | 15.1k–15.4k | 19–25 |
| 权限拦下 | 1 | 207k | 87% | 8.7k | 14 |

**改图助手**：`scripts/dev/taf_bench.py --real codex --model gpt-6.2-sol --effort medium`，12 个改图场景各 1 次（`FB-S02/S04/S06/S09/S11`、`C01/C02`、`V01/V06`、`T05/T06/T07`；
选了的 3 个画图场景 `FB-D*` 本轮没跑起来，另补），12 个全部 `completed`，用量取 Codex 的 `turn.completed`：

| | 最小 | 中位数 | P90 | 最大 |
|---|---|---|---|---|
| 输入 token / 次 | 94k | 161k | 205k | 212k |
| 其中命中缓存 | — | 141k（总体 86%） | 178k | 181k |
| 输出 token / 次 | 273 | 492 | 601 | 1,025 |
| 耗时 | 29 s | 33 s | 41 s | 45 s |

口径提醒：这是经 **Codex CLI** 量的，输入里含 Codex 自己的系统提示与工具定义，内置执行器的输入应当更少；Codex 报的输出可能不含推理 token。
所以它适合当**上界**用；托管模型选定后要用内置执行器（`--real builtin`）重测。

**按候选模型折算一次的成本**（价格取 `ai_pricing.TABLE`，2026-11-10 核对；美元，未含汇率）：

| 模型 | 改图（中位） | 改图（P90） | 修复（认输的典型一次 ~10 万） | 修复（撞 60 万上限） |
|---|---|---|---|---|
| Haiku 5.5 | $0.004 | $0.005 | $0.004 | $0.018 |
| gpt-5-mini | $0.010 | $0.012 | $0.014 | $0.057 |
| gpt-5 | $0.048 | $0.061 | $0.067 | $0.28 |
| Sonnet 5.5 | $0.060 | $0.076 | $0.075 | $0.31 |
| DeepSeek Flash（官方 API，高峰价） | $0.008 | $0.010（思考模式多出 4k 输出时 $0.015） | $0.006–0.012（实测 6 次） | $0.034–0.039（实测 2 次） |

DeepSeek 价格取官方定价页（2026-11-21 核对，`deepseek-flash` = DeepSeek-V4.1-Flash-1017）：缓存命中 $0.006 / 未命中 $0.30 / 输出 $1.20 每百万 token（高峰），
非高峰半价（工作日 UTC 01–04、06–10 点以外都是非高峰）。它的修复成本是**实测用量直接算的**，不是折算。
DeepSeek Flash 的成本里，未命中缓存的输入占 55–80%——缓存命中率每降 10 个点，一次改图的成本涨约 60%，网关不改写请求前缀这一条对它最要紧。

**数据出图「理解列」**：没有实测，按代码上限给**上界**：每次最多 2 个请求，输入 ≤ 4 万字符（约 1–1.5 万 token），输出 ≤ 2000 token；结果缓存 30 天。

由此得出三条设计约束：

1. **失败最贵**：撞上限的两次是修好那次的 6–7 倍。所以每类任务在内置 AI 下要有**比自带 key 更紧的上限**（§五），不能沿用 `FIX_LIMITS` 的 60 万。
2. **九成输入命中缓存**：成本主要看缓存价。选模型时看「缓存价 × 0.9 + 输入价 × 0.1」，不看标价；网关必须把缓存命中原样透传给上游（不改写请求前缀）。
3. **样本少、单一模型**：每题 1 次、只有 DeepSeek（另一组 gpt-6-luna 11 题全过、轮数更少）。定额度前要用**候选的托管模型**每题跑 ≥ 3 次，取 P50 / P90。

### 四、架构：客户端 → 网关 → 上游

```
引擎（内置执行器 / fixsession / ai_structured）
  └─ wires.post_json ──(授权令牌 + 设备签名 + task_id)──▶ AI 网关（我们的服务器，持上游密钥）
                                                           ├─ 验令牌、验设备签名、读授权台账（0193 §六）
                                                           ├─ 额度账本：任务放行 → 请求预扣 → 按实际用量结算
                                                           └─ 按配置路由到上游模型 ──▶ 模型服务商
```

- **上游密钥只在网关的环境变量里**，客户端拿不到任何上游密钥。
- **只认内置执行器**：网关不接受普通的 `Authorization: Bearer <key>`。每个请求必须带
  `X-Tavotto-License`（授权令牌）、`X-Tavotto-Task`（§五的任务号）、`X-Tavotto-Ts`、`X-Tavotto-Sig`（设备私钥对 `方法 | 路径 | sha256(请求体) | ts | task_id` 的 Ed25519 签名，同 0193 的设备密钥）。
  所以这条连接不能被塞进 Codex / Claude Code / 别的软件当通用模型代理用。
- **签名在哪做**：`ai_providers.builtin_conn` 对内置连接返回 `auth: "tavotto-device"`；`wires.post_json` 遇到这种 auth 时调用 `license` 模块的签名函数逐请求加头（今天 `post_json` 只发静态头，这是唯一要改的传输层代码）。
  子进程执行器（`tavotto-cli agent-run`）不拿设备私钥：签名经父进程的本地回调完成（与 `check` 工具走 stdin IPC 同一条路），私钥不出主进程。
- **协议**：网关对外只说一种协议（OpenAI Chat Completions 兼容 + `usage` 字段），模型名固定写 `tavotto-auto`；网关按配置选上游（§七）。客户端不知道、也不需要知道用的是哪家模型。
- **可达性**：国内节点 `ai.tavotto.cn`（与 `license.tavotto.cn` 同一 CloudBase 环境）；海外节点以后再加，**两边共用同一份账本**（只有一个写入点，海外节点转发记账请求）。
- **网关回权威用量**：每个响应带 `X-Tavotto-Charged`（本请求结算的微元）、`X-Tavotto-Remaining`（本周期剩余比例，0–1，两位小数）。
  客户端的执行追踪把网关回的成本当作权威值记下（`ai_pricing` 对网关地址本来就算不出价格）。

### 五、按任务放行，按请求结算

一次改图是一个**任务**：最多 24 轮 × 2 次 Agent 调用，几十个请求。只按请求扣，会在任务做到一半时余额见底、白花一半钱还没结果。所以：

1. **开任务**：功能开始前 `POST /v1/ai/task {kind}`（`kind ∈ figure_edit | fix | data_roles | convert`，闭集）。
   网关核权益、核余额 ≥ 该类任务的**放行线**（配置，默认 = 该类 P50 成本），回 `{task_id, ceiling}`。
   `ceiling` = 该类任务的**单任务上限**（配置，按 P90 定）。余额不足放行线 → 回 `quota_exhausted`（§八）。
2. **请求**：每个请求带 `task_id`。网关先按「请求体估算输入 + `max_tokens` 全额输出」预扣，转发，再按上游回的实际 `usage` 结算、多退。
3. **任务内透支**：放行之后，这个任务可以一直用到 `ceiling`，即使周期余额中途变成负数——**不在任务中途掐断**。周期余额最多被一个任务透支一次 `ceiling`，下个周期不补扣。
4. **任务到顶**：任务累计到 `ceiling` 时，网关对下一个请求回 `task_budget_exhausted`；引擎把它当作已有的「预算用完」结局处理（`fix_failed:budget` 同一条路），不报新错误。
5. **幂等**：同一 `task_id` + 请求序号重放不重复扣；任务 30 分钟无请求自动关闭。
6. **失败扣不扣**：**待维护者定**（§十二）。草案：照扣——模型的钱已经花了；靠收紧 `ceiling` 控制失败的损失，而不是退款。

### 六、单任务上限（内置 AI 专用，比自带 key 紧）

内置连接下，`Limits` 由网关在开任务时下发（`ceiling` 换算成 token 上限 + 轮数上限），引擎照用；自带 key 时完全照旧。
草案数字按 §三的实测待定，原则：**P90 的成功任务放得下，撞上限的失败任务尽早停**。

### 七、后台调控：一张配置表，一分钟内生效

网关每 60 秒读一次配置（CloudBase 数据库一个集合，只有维护者能写），不发版、不重新部署：

| 配置项 | 用途 |
|---|---|
| `plans`：每档每周期额度（微元） | 涨价、促销、补偿 |
| `kinds`：每类任务的放行线、单任务上限、是否开放 | 收紧失败成本；临时关掉某一类 |
| `prices`：上游模型 → 输入 / 缓存 / 输出单价、币种、汇率 | 服务商调价 |
| `routes`：`tavotto-auto` → 上游（主 + 备），可按任务类型分 | 换便宜模型、上游故障切换 |
| `breaker`：全局每日花费两档阈值 | 超第一档：全部改走最便宜的上游；超第二档：内置 AI 暂停到次日 |
| `overrides`：按授权号单独调额度 / 封停 | 处理滥用、给反馈问题的用户补额度 |
| `kill`：总开关 | 出事时一键关停，客户端回到「用你自己的 key」 |

另外两道保险：每家上游在服务商后台设月度花费上限（我们的代码出 bug 也刷不爆）；每台设备每分钟请求数、每个授权每天不超过周期额度的 1/5（防一天刷光）。
报警：熔断第一档、单个授权单日花费异常、上游连续失败，发企业微信（沿用现有通道）。

### 八、额度用完、网关不通：不卡人

- `quota_exhausted` / `task_budget_exhausted` / 网关不可达 / 令牌失效：一律不弹窗、不报红字。改图助手和 AI 修复的失败卡上，
  用现有的胶囊给两条路：**「改用我自己的 key」**（打开连接设置，自带 key 永远免费）、**「下个周期再用」**（显示刷新日期）。
- 已经放行的任务不会因为周期余额用完被掐断（§五.3）。
- 免费功能完全不受影响。

### 九、隐私

- 走内置 AI 时，用户的脚本片段、截图、数据摘要会经过我们的网关转给上游模型商。**网关不存请求与回复内容**，只记：
  授权号的哈希、任务类型、上游模型、token 数、成本、耗时、结果码。保留 90 天。
- 用自带 key 时一个字节都不经过我们。
- `docs/privacy.md` 新增「内置 AI」一节，写明以上与上游模型商的名字；**措辞待维护者点头**。

### 十、部署与可行性（测试模式先验）

- 首选：CloudBase HTTP 云函数（Web 函数）`ai-gateway-test`，与 `license-api-test` 同一测试环境、同一份授权台账。
  Web 函数默认支持 SSE；一个连接的时长受函数最大运行时间限制。
- **上线前必须在测试环境实测两件事**，任一不满足就改用 CloudBase 云托管（容器）：
  1. 单次请求时长：一轮输出 8k–32k token 的请求要 1–5 分钟。引擎今天是非流式请求，网关对上游用流式、对客户端在 JSON 前发空白字符保活（JSON 允许前导空白），确认网关层不会在 60 秒断开；
  2. 请求体大小：`check` 工具一次最多 4 MiB 图片，base64 后约 5.4 MiB，并且在多轮对话历史里重复出现——实测上限，必要时客户端先把图上传到云存储、请求里只带地址。

### 十一、上线开关与步骤

- `hosted_ai.PRODUCTION_LIVE = False`：在网关正式部署并验通之前，正式安装里看不到「Tavotto 内置」连接、零网络。另有 `TAVOTTO_NO_HOSTED_AI=1` 逃生口。
- 步骤（每步先报合并大队长，再由维护者本人批准）：
  1. 测试网关 + Stripe 测试授权，跑通「开任务 → 请求 → 结算 → 到顶 → 额度用完 → 改用自己的 key」；
  2. 候选托管模型每类任务每题 ≥ 3 次实测，维护者定额度；
  3. 正式网关、正式上游密钥、服务商花费上限；
  4. 隐私声明这一节上线；
  5. 翻开关。

### 十二、待维护者拍板

1. 托管哪家 / 哪几个上游模型（国内、海外各一个？）；
2. 成本占收入的比例（草案按年度 ¥168 → 每月 ¥14，留一半给模型 ≈ 每月 ¥6–7 / 人；实测后再给档位）；
3. 失败的任务扣不扣额度（草案：扣，靠单任务上限控损失）；
4. 「转成可编辑」算不算进内置 AI；
5. 隐私声明「内置 AI」一节的措辞；
6. 豁免是否按 0193 延伸登记 §1.8。

## 后果

- 引擎改动集中在三处：`ai_providers` 多一种内置连接、`wires.post_json` 逐请求签名、引擎处理两个新的结局码；功能代码零权益判断。
- 新的服务端组件（网关 + 账本 + 配置）有持续成本与运维面；熔断与服务商上限是硬兜底。
- 额度数字不进代码：调价、促销、补偿都是改配置。
