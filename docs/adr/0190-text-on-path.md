# ADR 0190：路径文字——一行字沿自带的路径排开，落字只在后端

## 问题

ADR 0185 能力矩阵「路径文字」（●）：科研图里偶尔要把标签贴着曲线写（拟合曲线旁的方程、弧形箭头上的说明、圆周上的样品编号）。
浏览器的 `<textPath>` 与后端导出排出来的字（HarfBuzz、同一张字体登记表）不是同一份，直接用它做画布会让画布与导出对不上。

## 决定

### 一、新对象类型 `pathText`

`types/document.PathTextObject`：一行字 + **自带的一份路径**（`subpaths`，框比例坐标，与 `path` 同一套）+ 起点（全长比例 `startOffset`，缺省 0）+
对齐（`textAlign` 缺省从起点开始 / `center` 以起点居中 / `end` 到起点结束）+ `flip`（沿反方向走，字翻到路径另一侧）。文字样式字段与 `text` 同名同义
（字号、粗斜、颜色、三个通用字体族）；只排一行（换行并成空格），没有行距、底框、下划线。导出载荷同名下划线字段（`exportPayload.pathTextExport`），缺省不发。

### 二、绑定：自带一份路径，和源对象成组

从路径 / 形状 / 箭头生成时复制它的第一条画得出的子路径（形状 / 箭头按「转为路径」的同一份几何），并把两者放进一个**新组**（一起挪、一起缩放；
双击组进去能单独改哪一个）；新组挂在源对象原来所在的组里。原来那条线照旧画着——路径文字多半是曲线旁的标签，线要留着；删了线字也在。

不采用「引用另一个对象的路径」：引用要处理被引用者删除 / 换类型 / 进出剪切组 / 跨画布复制，导出与旧构建兜底都要多一层；换来的只是「改线时字跟着改」，
而挪动和缩放成组已经覆盖。

### 三、落字只在后端

`rendercore/pathtext.py` + `plan._path_text_node`：与普通文字**同一次排字**（`typography.layout_text`，框宽给大排成一行——`break_lines` 一个字不改），
再按弧长把每个字的**中点**放到路径上：基线顺着切线，字头朝切线左法线；起点 = 比例 × 全长，再按对齐往回退半个 / 整个字串宽；开放路径越界的字不画，
闭合路径绕回。每个字一个 `ShapedText`（原点 0, 0）包在带变换的组里——IR 与 PDF / SVG / EPS 三个写入器不用认识新东西。翻转是转 180°，不是镜像
（变换行列式恒正，测试核）。

弧长：第一条画得出的子路径按 `geometry.path_segments` 的填充几何展平（直线段原样，三次贝塞尔每段按 t 等分 32 段）。前端 `lib/pathText` 用同一个展平规则，
只管起点柄画在哪、点在路径上落哪；两边对拍 `tests/golden/path_text_vectors.json`（`scripts/dev/gen_path_text_vectors.py`）。

### 三之二、离线：字默认不碰线（2026-11-16 用户追加）

基线沿字的上方（切线左法线）离开路径中心线一段「离线」`baselineOffsetPt`（pt，导出 `baseline_offset_pt`）：0 = 基线贴在线上，负 = 往线上压。
没写 = **自动**：线宽 / 2 + 0.2 em + 降部深度（主字体真实的 sTypoDescender），字最靠线的降部离描边外缘还有 0.2 em。翻面只是换到另一侧、方向倒过来，
字仍是基线朝线、字头朝外，最靠线的仍是降部，所以两种情况同一个式子（不是「字顶离线」——那要把字整个翻过线去，等于另一种排法）。

线宽取**生成时一起成组的那条线**（`lineId`，只用来取线宽）的描边宽度：那条线还在、看得见、有描边才算，否则 0；前端在载荷里发 `line_width_pt`
（`exportPayload.lineWidthOf`，画布预览、导出、转轮廓、复制为 SVG 同一个判据），后端落字时算（`pathtext.offset_pt`）。复制 / 粘贴 / 阵列 /
复制画布时线和字一起复制，副本的 `lineId` 改指副本的线；只复制字就仍指原来那条。

属性栏「起点 · 离线」同一行：离线没写时框里用占位样式显示自动值（接口 `/api/text/outline` 给路径文字另带 `auto_offset_pt`，与落字同一组脸、
同一个式子），填数 = 手动，清空 = 回到自动。`pathText` 还没有发过版，没有旧文档要迁移：没有这个字段一律按自动。

调间隙的四个入口（2026-11-16 用户追加「要能很方便地调」），改的都是同一个 `baselineOffsetPt`：
- **画布间隙柄**（`PathTextHandles.GapHandle`）：起点处沿字的上方离线那么远（就是基线所在）一个小圆点，虚线连回线上；沿法线拖它改离线，
  ⇧ 时离 0 或自动值 1.5 pt 以内就吸过去（吸到自动 = 删字段）；一次拖动一条历史；拖动中 interaction = `pathTextGap`，浮动栏让开，
  画布预览的请求只等一帧（平时歇 120 ms），字实时跟着动。
- **属性栏**：「离线」两个字是拖动改数的柄（整轮一条历史），↑↓ 0.5 pt、⇧ 2 pt（`NumberField.shiftMult`），旁边一颗只有图标的 ↺ 回到自动。
- **快捷键** ⌥⇧↑ / ⌥⇧↓（选区全是路径文字时，0.5 pt / 下，Illustrator 调基线偏移同一组键）。⌥↑ / ⌥↓ 已是细微调（0.1 mm），不占；
  选区不全是路径文字时这组键照旧是 ⇧ 大步微调。没写离线的从自动值起步（画布预览带回来的那个数，还没回来就不动）。
- 离线很大时外侧字距会拉开（字按原路径的弧长排）；改成沿平行线排列在审阅页待定。

### 四、画布与导出同源

`PathTextView` 把对象挪到原点、去掉旋转发给「文字转轮廓」接口（`/api/text/outline`；`textoutline` 认 `pathText`，路径文字每个字一段 `ShapedText`，
同色的字并成一条复合路径），照拿回来的字形轮廓画（外层 div 照常带旋转）。第一次 / 改动后等结果的那一下用浏览器 `<textPath>` 顶着，结果回来就换；旧结果在
新结果回来前留着（打字不闪）；同一份字和路径只问一次（挪位置不重新问）。`tests/test_path_text.py` 按像素核导出与转轮廓结果相同（弧线、旋转、翻转居中、
粗斜无衬线、闭合圆、上标）。

### 五、编辑

- 文字工具点在路径 / 形状 / 箭头的轮廓上（不拖，容差 = 吸附容差）= 在它上面放路径文字，起点就在点的地方，并进入就地输入（Enter / 失焦提交一条历史，
  Esc 放弃）。右键「在路径上加文字」同样。双击 / Enter 改字。
- 选中时描出路径（虚线）并给起点柄（横跨路径的短线 + 方块），拖它沿路径挪，一次拖动一条历史。属性页「路径文字」一节：内容、字号 + 粗斜、颜色、字体族、
  对齐 + 翻转、起点百分比。⇧⌘O 转轮廓照常可用。
- 镜像：上下翻只翻路径；左右翻再倒过来走（起点换成 1 − 起点、起止对齐对调），字不倒、不成反字。整组缩放字号跟着变。
- 「裁到内容」按一个字号多一点往外留（`exportCrop`）。写回脚本不带路径文字（留在画布上，不丢）。

### 六、旧版本的兜底（#1913，ADR 0185 §六）

`pathText` 是第一个真正由更新的构建写进文档的类型。旧版本（带 #1913 的判据 `isKnownObject`，已知类型只有 panel / text / arrow / shape / path）
打开带路径文字的项目时：

- 图层树里看得见，那一行显示「新版对象」占位（通用图标，不崩）；
- 画布上只画占位框、不接指针，全选与框选不收它——所以删不掉、拖不动、复制不了，文档原样保留、保存时原样写回；
- 导出（包括逐张导出）会灰掉，并说明原因（「有 N 个新版对象」），不会悄悄少画一块。

`web/src/lib/unknownObjects.test.tsx`「旧版本（#1913 的判据）打开路径文字」把本构建的已知类型退回 #1913 那一版，逐条核上面三点。兜底要先于第一次
把 `pathText` 写进文档的正式版发出去。

## 后果

- 新增 `rendercore/pathtext.py`（纯标准库）、`plan._path_text_node`；`textoutline` 的字形改成按颜色 / 模拟粗体攒成复合路径（普通文字结果不变）。
- 版本缩略图草图（`app._version_sketch`）与前端小缩略图只画路径细线；导出对话框的整版预览同样只画细线（导出文件是完整的）。
- 没做：沿路径的字距 / 基线偏移 / 「彩虹 / 倾斜 / 阶梯」效果；多行；路径文字自己的路径暂不能改锚点（双击是改字）；放不下的字没有溢出标记；区域文字。
