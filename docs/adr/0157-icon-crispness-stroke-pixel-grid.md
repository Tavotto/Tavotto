# ADR 0157：图标描边 1.5 + 吸到像素网格，小图标统一 16px

日期：2026-10-31 · 状态：**Accepted**（用户 2026-10-31 在清晰度演示页上选定「描边 1.5 + 对齐像素」，14px 档选「小图标统一改 16px」）
相关：[0052 自绘图标集](0052-in-house-icon-set.md)、[0156 图标微动效](0156-icon-micro-motion.md)；`docs/ux/ICONOGRAPHY.md` 尺寸阶梯与描边两节。

## 动机

用户：「我们的图标看上去糊糊的，没有 Claude 的高清」。对照 Phosphor（第三方逆向文档称 Claude 桌面端用这套 256 网格、描边 16）
在 2 倍屏上按实际尺寸渲染：

- 不是渲染出了问题——边缘半透明像素的占比我们并不比对方高；
- 是**线太粗**：24 网格描边 2，16px 上 1.33px、14px 上 1.17px（对方 16px 上 1px），小图标里的空隙被挤没；
- 是**边缘不落整像素**：大量 .5 坐标，在 16px 2 倍屏上边缘总跨在两个物理像素之间。

此前（2026-10-28 图标审计）用户否掉过「小图标描边加粗」——「放大后整体看上去很糊」。方向一致：变细、对齐。

演示页四版（现在 / 描边 1.5 / 描边 1.5 + 对齐像素 / Phosphor 参照）按 14 / 16 / 20px、界面样机与 4 倍像素放大并排，用户选第三版。

## 决定

1. `ICON_STROKE.regular` 2 → **1.5**，`emphasis` 2.5 → 2；路径上单独写的宽度同比缩到 ¾（`EyeOff` / `ImageOff` 挖口 6 → 4.5、
   `SquareMousePointer` 选中挖口 4 → 3、`Bold` 2.75 → 2.1）。
2. **几何吸到 0.75 网格**：`defs.ts` 末尾 `ICON_DEFS = snapVariant(RAW_DEFS…)`，`snapPathToPixelGrid` 把每条路径里落在线上的点
   （M / L / H / V / T 终点、曲线与圆弧端点）吸到 0.75 的整数倍，曲线控制点跟着各自端点平移，圆弧半径按弦长伸缩比例缩放
   （否则两段大弧拼成的整圆会鼓成柠檬形）。16px 在 2 倍屏上 0.75 单位 = 1 物理像素、描边 = 2 物理像素，边缘落在整像素上。
   几何仍按原值写，吸附只在这一处做。
3. **`ICON_SIZE.sm` 14 → 16**：0.75 网格只在 16px 上对齐，14px 上对不齐。`sm` 仍是默认档、档名保留（与 `md` 同值），
   三百多处调用方不用改；`xs` 12 与 `lg` 20 不变。
4. `SlidersHorizontal` 的轨道伸缩关键帧（ADR 0156）按吸附后的长度改写（长段 8.25、短段 1.5）。

## 看护

- `iconography.test.tsx`：吸附后的几何再吸一次不变（新几何、新图标都必须落在网格上）；尺寸 / 描边 token 的值。
- 真浏览器：全套 160 个图标 48px 形状目检（整圆、圆角没变形）+ 16px 2 倍屏放大目检。

## 后果

- 默认档图标大 2px：与 12–13px 文字并排的行里图标略大，行高不变（`IconSlot` 按行高居中）。紧凑的行如有拥挤，逐处调间距，不回退尺寸。
- 12px（xs）上 0.75 单位 = 0.75 物理像素，仍对不齐；xs 只给折叠箭头与徽标，暂不处理。→ 2026-11-01 由 [ADR 0158](0158-small-glyphs-and-solid-status-marks.md) 解决（12px 另画小号字形）。
- 想在 14px 上也锐，得另画一套几何——没做，档已统一到 16。
