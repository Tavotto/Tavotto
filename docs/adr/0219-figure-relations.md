## 问题

维护者 2026-11-28 真机试用：示例图里图例「Blank」的标记颜色与曲线不一致，改图助手没发现。维护者问「Agent 能拿到完整的科研语义吗」——拿不到。
改图助手（及插件的宿主 Agent）今天只有三样输入：

1. **元素表**（`manifest` → 方案模型的元素视图）：元素、位置、可改属性与当前值；
2. **版面事实**（`engine/figure_facts.py`，0214 修订）：位置用词、数据占格、干涉结论、数据范围对坐标范围、点数；
3. **出版规范数字**（期刊 / 默认规范、预检结论）。

三样都是**逐个元素**的事实，**缺元素之间的关系**：哪个图例项代表哪条曲线、哪组误差线属于哪个系列、哪条线看右轴、哪张色条给哪张热图。后果：

- **发现不了不一致**：图例与曲线颜色不同、同一条件在两个子图里换了颜色、两张热图色标不统一——模型只看到两个独立的颜色值，问题面板也没有这类检查；
- **改图不会联动**：用户把曲线改成红色，图例示意（脚本自己设过示意线的 `custom` 项）、误差线、另一子图里同名的系列都还是旧色，改完反而造出新的不一致。

引擎其实早就知道一部分关系，只是散在各处、没有汇成一份：图例项的 `legend_entry.source_gid`（0034）、`manifest` 里的 `ErrorbarContainer` 分组、色条反查 `mappable`、twinx / twiny 孪生簇；
`ai_figure_edit`、`figureverify`、`changeplan` 各自按 `source_gid` 现查。#2342（未合入）在写入侧先补了两处：示意线改色时同色的标记填充 / 描边跟着改；
密集曲线的标记被 `dense_curve` 拦下时绑到它的图例项 `handle_marker` 一并拦下——它是写入时的处理，**还不是比对**。

## 决定

### 一、关系层：引擎认出科研实体与关系，写成一份只读事实

- **实体**：数据系列（线 / 散点 / 柱 / 填充）、坐标轴（含孪生轴）、图例项、误差线、色条、子图、显著性标记、标注（文字与箭头）、子图编号。
- **关系**（有向、带类型）：`legend_entry → series`、`errorbar → series`、`series → axis`（双轴时看哪根）、`colorbar → mappable`、`same_condition`（跨子图同名）、
  `significance → groups`、`annotation → target`、`panel_label → panel`、`axis_label → axis`。
- **在哪认**：artist 对应只在 worker 里有，所以**在 worker 建 manifest 时认**，写成 manifest 上一份只读字段 `relations`（同 V-001 / V-002 的事实通道：worker 算事实、下游只读）。
  下游——`figure_facts`、预检、方案守卫、插件——一律只读这份，不各自再查 `source_gid`。
- **依据只有三种**：渲染几何、artist 属性、matplotlib 自带对应（legend handle 来源、`ErrorbarContainer`、`Colorbar.mappable`、twin 共享、`Annotation.xy`）。
  不读脚本、不读数据文件、不跑额外代码。
- **两档把握**（仿 `interference` 的确定 / 风险）：
  - `certain`：matplotlib 自带对应或同一 container 给出的关系；
  - `inferred`：只能靠几何或文字推断的（代理图例按标签唯一对上、星号与横线跨哪几组、箭头离哪个点最近）。
  **认不准就不认**：几个候选都对得上、或推断依据不唯一时不建这条关系（0034 的「绑错一条比不绑更坏」）。
- **结构化、有界、确定性**：实体与关系按 gid 排序；每图实体、关系、发现各有上限（超出截断并记 `truncated`）；同一份渲染 → 逐字节相同的 `relations`（它进提示词与缓存键）。
  认关系出错 / 超时 → 这一张图 `relations` 记 `status: unknown`，下游少说、不报、不显示「已通过」，不拖垮出图、出方案与预检。
- **只认这张面板自己那份渲染**（0017）：显示回退借来的 manifest 不产生发现。

### 二、关系清单与一致性检查

严重度只用 `publication.json` 已有的 `error` / `warn` / `suggestion`，每条预检 id 在 profile 登记；按七问的规则纪律：`basis: encoding` 用 `warn`、其余数据语义类用 `suggestion`，
**只有 `certain` 的发现进问题面板**，`inferred` 的只作为事实给助手。每条在实现那期 PR 里先写进 `validation-spec.md`（V-012 起），上调严重度前过「埋缺陷图集」评测。

| 关系 | 检查项 | 严重度 | 不报的情形 |
| --- | --- | --- | --- |
| 图例 ↔ 系列 | 示意线色 / 线型 / 标记形状 / 标记填充与描边 / 面色与源不同；线宽差异只作事实 | `warn`（encoding：图例指错了数据） | `follow_source` 项（按构造一致）；没有源的项（代理图例按标签对上的只给助手）；标记大小（`markerscale` 常有意放大）；脚本用整图统一的灰色示意 |
| 误差线 ↔ 系列 | 误差线颜色等于**另一个**系列的颜色；误差类型 SD / SEM / CI 能否从图内文字 / 图例 / 轴标签得知 | 颜色：`suggestion`；类型：不出 issue，照 V-004 进「需要你确认」 | 误差线与自己系列同色或中性灰 / 黑；配方已知含义（0178）时列事实不提问；图中没写就如实说「图中没写误差线代表什么」，不猜 |
| 同一条件跨子图 | 同一图例标签 / 同名系列在不同子图颜色或标记不同 | `suggestion` | 只有一个子图；标签只出现一次；同名但子图本身用颜色编码别的变量（色图映射的系列） |
| 色条 ↔ 映射数据 | 色标范围截掉了数据（饱和）；多张同标题热图色标范围不统一 | `suggestion` | 用户显式设了 `vmin/vmax` 且色条带延伸箭头（`extend`）；色图是否合适沿用现有 `discouraged-colormap` / `palette-semantic`，不另立一条 |
| 双坐标轴 ↔ 系列 | 哪条线看哪根轴（事实）；轴标签 / 刻度着色与它的系列色对不上（左轴着了右轴系列的色） | `suggestion` | 轴没着色（默认黑）；双轴本身不报（G-041 明确不做成规则） |
| 轴标签单位 ↔ 数据量级 | 缺单位；单位与量级明显不符 | 不出 issue，只给助手（只提示不断言） | 无量纲量、计数、类别轴；**不凭取值落在 [0, 1] 猜归一化**（validation-spec 登记的伪规则） |
| 显著性标记 ↔ 组 | 横线端点落不到任何一组上；星号不在横线上方 | `inferred` 为主，只给助手；评测后再议进面板 | 认不出横线与星号的配对 |
| 子图编号 ↔ 子图 | 编号跳号 / 重号、顺序与阅读顺序不符、风格不统一（大小写、括号、字号、粗细） | `suggestion` | 只有一个子图；编号是画布标注（0199 一键排版另管） |
| 标注箭头 ↔ 目标 | 箭头指向坐标范围外或空白处（离最近数据远） | `suggestion` | 文字注释没有箭头；目标是图内另一元素而非数据点 |

**数据本身的含义**（变量是什么、n、是否归一化）要读脚本 / 数据文件，触及隐私边界——**登记为后续，单独讨论，本 ADR 不做**。

### 三、出口 (a)：改图助手的事实块

- `figure_facts` 的总预算不变（`MAX_LINES = 40`、`MAX_CHARS = 4000`，提示词体积与缓存口径不变），改为**分段配额**：
  关系发现预留 ≤ 12 行 / 1,200 字，排在版面事实**之前**（今天是从头截断，排在末尾的多子图时最先被砍）；按严重度、再按 gid 排；
  一致的关系并成一句否定事实（「图例与曲线、误差线与系列已核对，没有对不上的」，同「图例没有压住数据」的用意：不让模型凭空找问题）；预留没用完的还给版面事实。
- 双轴归属这类中性事实排在版面事实之后，额度不够时先省它。
- 提示规则（并进 0214 的三分）：**提问**——指出不一致、说怎么修；**笼统的修改 / 按规范**——每处不一致列一条待办并给出修正；
  **具体的修改**——不擅改别的，但按 §五 把联动项列进同一组。插件的宿主 Agent 经现有读图工具拿到同一份事实。

### 四、出口 (b)：「问题」面板

- 判据只有引擎这一份：worker 写进 `relations` 的发现已经是结论，`preflight.py` / `preflight.ts` **只折叠、不重算**（前端不移植认关系的逻辑）。
  折叠是同源对，进 `docs/rules/repo/` 的同源对总表，golden `relation-*` 对拍，第 1 期登记。
- 每条 issue 指得出对象（主语 = 不一致的那一方，如图例项）、`detail` 写另一方，定位走 `focusObject()`（0030）。
- 一键修复：能接现有覆盖的接——图例 ↔ 系列接「让图例跟随曲线」（写 `binding: follow_source`，0034 已有），是用户点的单项按钮，
  **不进「全部修复」的批量**（守 sciviz 规则「不自动修」）；跨子图颜色、色标范围这类「该以哪边为准」的不给一键修复，交给助手方案。

### 五、出口 (c)：改图联动

- 用户（或方案模型）改一个系列的颜色 / 标记 / 线型时，方案按 `certain` 关系把联动项列进**同一组**：它的 `custom` 图例项示意（`follow_source` 的会自己跟，不列）、它的误差线、跨子图同名系列。
- 联动项在卡上是组内的子行，**默认勾上、可逐行取消**；一次 commit、一步撤销（0206）。`inferred` 关系不联动。
- #2342 的两处写入侧处理（示意线改色带动同色标记、`dense_curve` 连带拦图例标记）第 1 期改为读关系层，不再各自查 `source_gid`。
- 不另加设置项：关掉修改方案卡开关时联动不出现；整个关系层的逃生口见 §七。

### 六、隐私与安全

只读渲染结果（worker 里已有的 artist 与 manifest）；不读数据文件、不读脚本源码、不执行额外代码、不联网；发给模型的只有结构化事实（关系类型、元素名、颜色 / 线型等样式值、一句结论），不带数据点。

### 七、默认与逃生口

默认开（随 0206 修改方案卡与问题面板）。`TAVOTTO_NO_FIGURE_RELATIONS=1`：worker 不写 `relations`，事实块、预检、方案与今天逐字节相同。
没有关系发现的图，事实块、预检输出与今天逐字节相同（看护用例在第 1 期）。

### 八、分期（每期独立 PR）

1. **核心 + 图例 / 误差线 / 跨子图 + 出口 (a)(b)**：`relations` 字段与两档把握、上限与 unknown；图例 ↔ 系列（迁 #2342 两处）、误差线 ↔ 系列、同一条件跨子图；
   事实块分段配额；预检折叠与 golden、同源对登记；V 规格；真 worker 防误报用例（含 Blank 那张示例图，记下它落在哪一档）。
2. **色条、双轴、单位、子图编号**。
3. **显著性标记、标注箭头、改图联动 (c)**（联动的卡片界面先给维护者看、过 agy）。
4. **后续（另议）**：数据本身的含义。

## 后果

- 助手与问题面板第一次能说「图例和曲线对不上」；改一条线不再留下半截不一致。
- manifest 多一个字段、worker 建表多一点开销（有上限）；预检多一组同源折叠要维护。
- 发现只用于提示与方案，不改用户脚本、不自动修；误报的代价由「只报 `certain`」与图集评测压住，代价是一部分真问题（代理图例、推断的显著性配对）只在助手那里出现。

## 未做

- 数据本身的含义（变量、n、归一化）——读脚本 / 数据的隐私边界，单独讨论。
- 不做跨图（跨排版里不同图）的关系；不让模型自己建关系；不用多模态模型看图判断一致性。
