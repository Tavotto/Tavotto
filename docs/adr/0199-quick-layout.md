## 问题

维护者 2026-11-20 提出第一个高级功能：进入排版模式后，点一次「一键排版」，就得到一份好看、合规的多图版面：

- 四张图的子图边精准对齐；
- 文字、线条符合出版规范；
- 每张子图左上角打好标签。

今天用户能做到，但要手动走很多步：放进网格、逐张拖边改图幅、逐张在问题面板里按期刊修正、跨图对齐轴、加标签，而且改完一张，别的又要重对。

### 已经免费的能力（不许拦，0193 §一）

| 能力 | 出处 |
| --- | --- |
| 对齐 / 分布 / 等间距 | `actions.alignSelected` / `alignSelectedTo`，ADR 0036 / 0128 |
| 行 / 列 / 网格排列组 | `LayoutGroup {kind: row\|col\|grid, gap, cols, align, uniform}` |
| 拖边改图幅、文字 pt 不变 | `{gid: "figure", prop: "size_mm"}`，ADR 0161 |
| 拖动坐标轴 | `{gid: <axes>, prop: "position", value: [x, y, w, h]}` |
| 单图按期刊修正字号、线宽、边距 | `/api/engine/specfix`、MCP `tavotto_fix_to_journal`，ADR 0080 / 0180 |
| 一键加 (a)(b)(c) 标签 | `actions.addSubLabels`（按阅读顺序，加粗） |

**高级版收费的只是「求解」**：一次算出整版的网格、每张图的图幅与轴位置，让轴线在行列上对齐、整版宽度正好等于期刊栏宽、文字都落在规范字号上。上面这些免费能力照旧免费、不加任何判断；一键排版把它们当零件来调用。

## 决定

### 一、入口与范围

- 入口：排版模式工具栏一个按钮「一键排版」，命令面板里也有一条。没有授权时用 `PremiumLock`（#2071）置灰，悬停一句话 +「了解高级版」，不弹窗。
- 作用对象：选中了 ≥ 2 个子图就排选中的；没有选中就排当前画布上的全部子图。
- 参与求解的子图：有图内编辑入口的脚本出图（`obj.script`，与右键菜单「编辑图内元素」同一个判据）。几何由引擎在请求里自己渲染取得，不要求前端此刻已有精确 manifest（没进过图内编辑的图前端本来就没有，2026-11-20 真浏览器走查发现）。
- 位图、未旋转的 SVG / PDF 等不能改图幅的子图：只当作固定宽高比的盒子参与排位。
- 旋转或翻转过的子图：原地不动，当作障碍物。
- 选项放在按钮旁的小下拉里，默认值取自期刊库：
  - 目标宽度：单栏 / 双栏 / 整页（= 页宽）；
  - 图间距（mm）：相邻两张图**文字外沿**之间的空隙，不是图框之间；
  - 「同时按规范修文字和线条」：默认打开（维护者 2026-11-20 选 A）。关掉就只排版：不换字体、不改字号、线宽、刻度方向、图例边框。打开时胶囊里一行灰字说明按哪份规范、改了哪几类（字体、字号、线宽、刻度方向、图例边框、字重）。建议档（比如轴标题加不加粗）一律不改。
- **页面四周留白**：任何文字外沿（含标签）离页边至少 2 mm（维护者 2026-11-20 定）；用户设了安全边距就用安全边距。每张图的图框内侧再留 0.5 mm，文字外沿不贴图框（字形会略微超出测得的外框，2026-11-20 走查时「Combination」被裁就是这个原因）。
  没选期刊时用 0029 默认规范的栏宽。

### 二、算法分工：引擎编排、sidecar 求解、前端一次提交

照 specfix 端点的做法（`/api/engine/specfix`「只算不写」：在 worker 里渲染候选、回最终的全量覆盖列表，由前端一次 commit），新端点 `POST /api/pro/quick-layout/plan` 也**只算不写**：

```
前端                         引擎 engine/quicklayout.py（开源）                 Pro sidecar（闭源）
发：选区、各图 B0 全量覆盖、  1. 各图按 B0 渲染，取精确 manifest
   摆放、页面、规范全文        2. 收集输入（§四）─────────────────────────────▶ 3. quick_layout.plan：网格、size_mm、
                                                                              画布位置、轴 position、标签位置
                             4. 校验操作（§五），落成各图候选覆盖 ◀──────────── 返回操作列表
                             5. 每张图跑 specfix.plan（scale = 1）：字号、线宽按规范修
                             6. 候选渲染 → 新的精确 manifest → 回到 2（最多 3 轮）
                             7. 量验收指标（§六）
收：每张图的最终全量覆盖、    ◀ 通过：回最终方案；不通过：回 ok: false，worker 回到 B0 或作废
   各对象的新摆放、标签
→ 一次 commit
```

- **按图幅出图，不缩放图片**：求解器给每张图定 `figure.size_mm`，并让画布上的子图框与之等大（缩放 = 1）。这样文字的实际字号就是规范字号，不会因为缩放变成 7.3 pt。
- **对齐的是轴线，不是图片外框**：同一行的绘图区下边、同一列的绘图区左边对齐，靠写各图 axes 的 `position` 做到。刻度标签宽度不同造成的错位，由绘图区内边距吸收。
- **先让画布样式落好**：画布样式（ADR 0081，免费）在一张图第一次出图时才套上。点按钮后先等参与排版、还没出过图的那几张出第一张图（最多 30 秒），再让样式对齐新图，然后才记 B0、发请求。否则一键排版会抢在样式前面算完，样式随后再把轴标题改粗改大，算好的对齐与留白就不作数了（2026-11-20 走查发现）。样式是用户选的外观，规范修正只补样式没管到的（例如线宽吸附到档位）。
- **期刊修正复用 specfix**：第 5 步调现有的 `specfix.plan()` / `verdict()`（字号按角色提到规范下限、线宽吸附到规范档），不重新实现判据（`docs/rules/plugin/fix-to-journal.md`）。sidecar 只拿到修正后的几何。
  - **第 1 轮只定图幅与摆放，不写轴位置**：手写的 `position` 在 specfix 的核对里算受保护的值。先写了它，字号变大后边距没法重排，specfix 会整张拒绝（2026-11-20 实测，带色条的图）。所以轴位置从第 2 轮才写，按修正后的实际占位来算。
  - **整张修不成时逐级退让**：specfix 一次修一整张图，任何一条冲突就整张不改（实测：图例字号提上去会压住数据）。这时先按规则逐组修，某组还修不成再逐个元素修。每一步都是问题面板「逐条修复」用的同一个免费入口（`only`），各自判、各自回滚。只修「全部处理」本来会修的规则（`select(…, None)`，不含建议档），不多修。最后仍有修不成的，结果里带 `spec_not_fixed`，前端一行灰字照实说。
- **worker 热态**：与 specfix 的约定完全相同。事务结束时热态要么是 B0，要么是回给前端的那份列表，要么作废（`worker_retired`，下次按全量列表重放）。native 图（`tavotto run` 的 live Figure）照 specfix 回 `quick_layout_native_unsupported`，只当作固定盒子参与排位。
- **标签复用 `addSubLabels` 的约定**：小写字母、括号、加粗，字号与颜色取画布文字默认值。求解器只给每个标签的位置（对齐到该子图墨迹外框的左上角，整版统一偏移）。
  - 抽成共用函数时，免费的「添加子图标签」行为一字不变。
  - **重排时替换旧标签**：落在参与排版的图原来范围里（外扩 5 mm）的旧子图标签（与样式系统同一判据 `isSubLabel`），在同一次 commit 里换成新的。所以重复点不会叠标签，手加的 (a)(b) 也会落到对的位置；远处的文字不动。
  - 期刊库的 `panel_label` 今天只是自由文本信息项，首版不解析。
- **迭代**：改图幅后 tight layout 会改动刻度与标签的占位，一轮算不准，所以最多 3 轮。3 轮没达标回 `ok: false`，什么都不改。

### 三、一张图里有多个坐标轴

- **参与行列对齐的「绘图区」**：这张图里所有主坐标轴外框的并集。
  - twin 轴与宿主外框相同，去重；
  - 色条轴（`colorbar` 角色）不算主轴；
  - inset：外框完全落在另一个主轴里面的那个不算。
- **求解器移动主轴时整体平移、缩放这一组**，保持组内相对位置。各轴的 `axes.position` 按同一个仿射变换算出；组内原有的对齐关系（比如 `subplots` 的网格）不打散。
- **等比例轴**（`imshow`、`aspect='equal'`）：matplotlib 会在 `position` 框里再收缩，写了 `position` 也不一定到位。含这种轴的图**只参与排位与图幅**，不参与轴线对齐指标。结果里给一行灰字说明（§六）。

### 四、给 sidecar 的输入（0198 §三：只给数字与结构）

```json
{"cmd": "quick_layout.plan", "payload": {
  "round": 1,
  "page": {"w": 210, "h": 297, "margin": 10},
  "target": {"width_mm": 174, "gap_mm": 3},
  "panels": [{
    "ref": "p1", "kind": "figure", "box": [x, y, w, h],
    "size_mm": [w, h], "size_limits_mm": [[wmin, hmin], [wmax, hmax]],
    "aspect_locked": true, "equal_aspect": false,
    "ink_bbox": [x0, y0, x1, y1],
    "elements": [{"ref": "e3", "role": "axes", "bbox": [x, y, w, h]}]
  }],
  "fixed": [{"ref": "p5", "box": [x, y, w, h]}]
}}
```

- `ref` 是本次请求现编的短号，不是对象 id / gid（映射只留在开源侧）。
- `elements` 只给角色与外框，角色闭集：`axes`、`colorbar`、`axis-label`、`tick-labels`、`title`、`legend`、`suptitle`。**不给文字内容、不给数据、不给文件名或路径。**
- 单位：画布 mm；`bbox` / `ink_bbox` 是相对图幅的比例（y 向下，与 manifest 同）。

### 五、sidecar 返回的操作（闭集）

| op | 字段 | 开源侧落成 |
| --- | --- | --- |
| `panel.place` | `ref, x, y, w, h`（mm） | 子图对象的 `x / y / w / h` |
| `figure.size` | `ref, w, h`（mm） | `{gid: "figure", prop: "size_mm"}` |
| `axes.position` | `ref, element_ref, x, y, w, h`（比例） | `{gid: <axes gid>, prop: "position"}`（4 位小数，与手动拖轴同） |
| `label.place` | `ref, x, y`（mm） | 一个子图标签文字对象（§二 的约定） |

- 开源侧逐条校验：
  - `ref` 必须是本次请求发出去的；
  - 数值有限；
  - 图幅在 `size_limits_mm` 之内；
  - `element_ref` 必须是 `axes` 角色；
  - 子图不越出页面。
  **任何一条不过，整份方案作废**，不做部分应用。
- 未知的 op 名 = 整份作废（协议升级走 `pro_api`，0198 §三）。
- **页面随内容收紧**：一键排版的结果就是最终那张图。引擎回 `page: {w, h}` =「内容外框 + 页边距」（含固定盒子），前端在同一次 commit 里改页面尺寸。所以 `panel.place` 不受原页面大小限制，只防荒谬值（≤ 2000 mm）。
- 落成的全是现有键，所以没有授权的电脑打开、编辑、导出都一样（0198 §一）。导出 .py 时，这些键与手动编辑写出的同一批键同样对待（哪些键能写进 .py 由导出那边决定，本 ADR 不改）。

### 六、验收指标（引擎核对，过了才回方案）

在最后一轮候选渲染的精确 manifest 上量：

| 指标 | 阈值 |
| --- | --- |
| 同一行绘图区下边、同一列绘图区左边的偏差（§三 的并集；等比例轴的图不计） | ≤ 0.1 pt |
| 相邻两张图文字外沿之间的空隙 | ≥ 图间距 − 0.1 mm |
| 文字外沿（含标签）到页边 | ≥ 留白 − 0.05 mm；页宽 = 目标宽度 |
| 文字外沿到自己的图框 | ≥ 0.2 mm |
| 字号 / 线宽 | specfix 的判据全部通过（不另写判据） |
| 重叠 | 子图墨迹外框之间、标签与任何墨迹之间都不重叠 |
| 标签 | 相对各自子图框的偏移全版一致 |

- 判据代码在开源侧（`engine/quicklayout.py`），**不信 sidecar 自己报的结果**。
- 只因为图幅上下限或等比例轴达不到某一条时，方案照样回，但带上这一条的说明。前端在胶囊里用一行灰字写出（例如「图 c 太宽，栏内放不下」），不出现红字、带底色的状态块或弹窗。

### 七、应用与撤销

- 首版**不做应用前的预览**：没有现成的「带临时覆盖重渲染、不进历史」的路径（现有预览平面 `svgPreviewStore` 只改画面、不经后端），首版不新造这一层。
- 点按钮后：
  1. 前端给排版时间线打一个自动检查点（0101）；
  2. 请求 `/plan`，期间按钮显示忙碌状态；
  3. 拿到方案后用**一次** `documentStore.commit` 写入全部改动（历史里一条「一键排版」），再对每张图 `requestRender`；
  4. 胶囊显示「已排好 · 撤销」，⌘Z 同样一步撤回。
- 请求期间用户动了画布或文档：方案作废、不提交。commit 用的是请求发出时的 B0 做比对，B0 已变就丢弃方案，胶囊说「图刚刚变了，再点一次一键排版」。
- 改的都是排版文档；**不改用户脚本**。

### 八、失败与边界（全部静默回到原状）

| 情况 | 结局 |
| --- | --- |
| 没有授权 / 授权过期 | 按钮置灰（`PremiumLock`） |
| 组件还在下载 / 平台不支持 | 置灰，悬停一句话（0198 §九） |
| 少于 2 个可排的子图 | 按钮可点，胶囊说「至少要两张图」 |
| sidecar 超时、崩溃、返回不合规 | 不改任何东西，胶囊说「这次没排好，再试一次」 |
| 3 轮内没达标 | 同上 |
| 请求期间文档变了 | 丢弃方案（§七） |

### 九、授权判断的位置

- 功能键 `quick-layout` 登记进 0193 §一 的闭集（本 PR 同步改 0193）；实现 PR 把它加进 `license.FEATURES`。
- `license.has("quick-layout")` 只在两处，两处都登记进 `REGISTERED_CALLERS`：
  - 0198 的 `engine/prohost.py`；
  - 新模块 `engine/quicklayout.py`。`app.py` 里的路由只转调它，**`app.py` 本身不登记**，否则等于放行所有免费端点。
- 前端置灰只看 `/api/license/status`，不是权威判断。改前端绕过灰态也拿不到方案，因为 `quicklayout` 与 sidecar 都会拒绝。
- 免费能力的模块（`addSubLabels`、对齐、`LayoutGroup`、specfix、拖边改图幅）里不出现任何权益判断。为一键排版抽出的共用函数也放在免费模块里，不加判断。

### 十、首版不做

- MCP 工具（agent 侧的一键排版）：等桌面版上线、真机走通后另开 PR。
- 期刊库 `panel_label` 的结构化，以及按期刊切标签样式（免费期刊库的事，另开 PR）。
- 跨页排版、图注区、子图之间共享坐标轴 / 共享色条的合并。
- 自动挑选「哪种网格最好看」的多方案对比，首版只给一个方案。
- 应用前的预览（§七）。
- 各图同一角色字号拉齐到同一个值（specfix 只保证不低于规范下限）。

### 十一、界面

按钮、下拉、结果胶囊的截图稿先过 agy（温暖、人文、质感、优雅），改一轮再给维护者过目，定稿后才开实现 PR。文案一句话，不带 AI 味。

## 后果

- 正面：
  - 收费的是新增的「求解」，免费能力一个都不拦；
  - 结果是普通文档数据，过期了也不影响已有版面；
  - 判据在开源侧，sidecar 算错了不会被应用；
  - 引擎编排沿用 specfix 已验证过的「只算不写」事务形状；
  - 一步撤销，应用前有时间线检查点。
- 代价：
  - 每次一键排版要多轮重渲染，图多时会慢（首版目标是 4 张图 3 秒内出结果，真机实测后再定）；
  - 首版没有预览，靠一步撤销兜底。
  - 输入输出协议要维护版本。
- 未做（NOT_RUN）：
  - 求解器、开源侧入口 / 编排 / 核对的实现；
  - specfix 在 scale = 1、改过图幅的候选上能否与求解器的迭代收敛（只读过端点契约，没有实跑）；
  - 截图稿；
  - 真机性能；
  - 位图子图与旋转子图混排的实际效果。
