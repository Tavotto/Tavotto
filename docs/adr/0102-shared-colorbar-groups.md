# ADR 0102：共享色条的真实组——归属只认脚本声明，组是派生结构、不进文档

日期：2026-09-28 · 状态：**Accepted**（第一阶段：只覆盖显式声明的共享色条）
相关：[0081 画布跟随样式](0081-canvas-follows-style.md)（左栏的另一块）、
[0083 override 的目标身份](0083-override-target-identity.md)（成员 gid 漂移时的降级）、
细则 `docs/rules/backend/colorbar.md`「结构归属」、`docs/rules/frontend/readiness-and-left-shell.md`「元素树」

## 问题

元素树原来只有「整张图 → 子图 → 抽屉 → 元素 → 零件」，父级全靠 gid 路径推
（`roles/hierarchy.parentGid`）。`fig.colorbar(im, ax=[b, c])` 这种横跨两个子图的色条：

- 色条轴 `axes_3` 按路径挂在**整张图**下，和两个子图平级，看不出它属于谁；
- 引擎把它挂在**第一个**宿主的随行表里（`follow_map`），于是单独拖 B 会把整条共享色条
  拖走、C 留在原地；
- 想整体挪 B、C 和色条只能手工多选三次。

单宿主色条同样挂在整张图下（色条轴与子图平级）。

## 裁决

### 一、三件事分开建模

| 概念 | 回答什么 | 出处 |
| --- | --- | --- |
| **归属**（结构父级） | 挂在谁下面、面包屑怎么写 | manifest 元素的 `parent_gid` + `groups` |
| **分类**（抽屉） | 在子图里归哪一格 | 前端 `ElementTree` 的 `CLUSTERS`；色条轴与图例同进「图例与色条」 |
| **关系**（行为依赖） | 谁跟谁一起动、颜色从哪来 | 组 → 成员一起平移 / 缩放；色条 → `mappable_gid`（不是组） |

抽屉只是视图容器：不进 manifest、不可选中、不进面包屑、不参与几何。

### 二、归属只认色条自己声明的宿主

证据只有一份：matplotlib 在 `fig.colorbar(..., ax=...)` 那一刻记下的 ax 列表
`cax._colorbar_info["parents"]`（`colorbarmodel.declared_parents`，`make_axes` /
`make_axes_gridspec` 写、constrained layout 读）。它是调用参数的记录，不是从渲染结果反推的；
仓库此前已用它判多宿主（`colorbar_host_count`）。

- 声明 1 个宿主 → 色条轴 `parent_gid` = 那个子图；
- 声明 ≥2 个宿主 → 组 `group:<色条轴 gid>`，成员 = 这几个子图 + 色条轴，成员的
  `parent_gid` = 组；色条元素另报 `owner_gids`；
- **不成组、保持原样**：`cax=` 建的色条（没有声明）、宿主有一个不在元素表里、成员不在
  同一个（子）图里（`SubFigure`）、同一个子图被两条共享色条同时声明（两个组重叠，单父树
  表达不了）。位置相邻、颜色相同、norm 相同一律**不是**成组的证据。

### 三、组是派生结构，不进文档

组每次渲染由引擎从脚本重新推出（`manifest._colorbar_structure`），与元素表同一套稳定性，
不写进用户文档：

- 旧项目加载后文档一个字节不变（没有迁移、没有新字段）；树上多出组，是因为脚本本来就这么声明；
- 组上的布局操作落成**成员各自的 position override**：保存、重开、撤销、重做、写回都是
  现成的链路，不需要为组再造一份持久化；
- 成员缺失或 gid 漂移：组随脚本重新推出（缺了就不成组），成员身上的 override 由
  ADR 0083 的目标身份核对兜底。

不存第二份「组关系」的原因：它必然与脚本里的 `ax=[...]` 形成两个权威，脚本一改就分叉。
手动分组、拖拽改归属这类**用户自定**的结构才需要进文档，那是后续工作（见「不做」）。

### 四、组的交互

- 组只能从元素树 / 面包屑选中；画布上点不中它（点到的仍是子图、色条）。
- 选中组 → 画布画组框（带手柄）+ 成员细虚线；拖组里任一成员（含成员子图里的线、标题、
  图例等，按真实父级归属）= 整组平移，只点不拖 = 钻进去选中点到的那个；组框手柄 = 整组缩放。几何全部复用多选子图那一套
  （`alignEntries` 把组展开成成员 → `startElementGroupMove` / `startGroupResize` /
  `ScaleField`）：参照框是成员 position（figure 分数、bottom-origin 存储）的并集，
  平移是同一个分数位移，缩放按手柄方向钉住对边、成员线性重映射进新框。
- 选中组按方向键微调（ADR 0093）= 整组平移：`nudge.moverFor` 先 `expandGroups` 再走
  `groupMove`，与拖组里任一成员同一套；不能整体挪的组展开为空，照旧「不能移动」。
- constrained 图上每个成员（含色条轴）各自被 ADR 0100 的排版钉位钉住，组外子图不被挤动。
- 组**不能整体变换**时整组不动，原因只由 `elementGeom.groupTransformBlocked` 判：有成员落位不归
  Tavotto 管（插图、寄生轴：`resizable: false`）、有成员被锁定（成员或共享的色条元素）、有成员这一版
  拿不到可写的 position。这样的组不展开、不给手柄、组页不摆缩放，拖动 / 方向键按原因说一句，只点
  不拖照常钻进去。不「跳过不能动的、挪其余的」——那会把色条与子图拆开；与画布对象组「组内有锁定
  成员整组不动」同一条规则。
- **不变式：组的变换只有全员刚性与零两种结果。** `expandGroups` 之后的出口不许再逐个过滤成员
  （隐藏的成员照样跟着组走）；对齐 / 分布 / 等宽等高把组当一个单位（成员并集为框、成员一起
  重映射，`elementGeom.alignUnits`），不逐个成员排版。
- 多宿主色条不再进任何一个宿主的 `follow_gids`：单独拖 B，C 与色条都不动；重新布局后
  归属仍按声明推出，不会被重新挂到 B。
- 属性页选中组是**组页**（成员、颜色来源、整组缩放），不是退回「整张图」；面包屑走
  `structuralParent` 的真实祖先链，色条轴那一级不单列。

## 不做（第一阶段之外）

共享图例、共享轴标题、手动分组、拖拽改归属、按几何自动推断、智能建议；`cax=` 色条的
归属（需要在导入入口记录 owner，见下）；组级锁定与隐藏；组的方向翻转（多宿主色条翻转
仍按 `multi_host_colorbar` 不宣称）。

`cax=` 要成组，得在脚本执行时截获 `Figure.colorbar` 的调用参数（`figcapture` 的 savefig
拦截那一层）并记下 owner——那是执行入口的改动，两条入口（safe worker / native bridge）都要
同步，不在本阶段。
