# ADR 0187：外部审阅——把单图 / 排版的画面分享成一个链接，别人在网页上批，作者在应用里接着看、回复

日期：2026-11-15 · 状态：**Proposed（本 ADR 只定契约；服务端、引擎、前端各一路实现，CloudBase 环境尚未开通，真实服务与真机未验）**

隐私声明 `docs/privacy.md`「External review links」；截图稿（维护者 11-15 过目）：外部审阅界面稿 v2。

## 问题

作者改好一张图，想让导师 / 合作者看一眼。今天只能导出 PNG 发微信，对方在截图上圈一圈发回来，作者再对着截图找是哪根线、哪个字；
改了第二版又发一遍，意见散在几段聊天记录里，哪条处理过全靠记。对方多半不装 Tavotto。

## 决定

### 一、做什么

- 作者在应用里对**当前这张图或这份排版**点「分享审阅」，得到一个链接 `https://review.tavotto.cn/r/<审阅令牌>`。
- 打开链接的人不注册、不登录：第一次留言时填一个称呼（浏览器本机记住）。可以**点选元素、框选区域、写整体意见**，可以回复，可以对每个版本**提交结论**（通过 / 需要修改 + 一句说明）。
- 作者改完图点「更新到同一链接」：同一个链接多一个版本（V1、V2…），旧版本的画面与意见都保留，网页默认显示最新版、可切回旧版。
- 作者在应用里看意见、回复、标记已处理：右栏新增「审阅」页签，**只有这张图 / 这份排版真的创建过审阅才出现**；画布上的意见圆点**只在打开「审阅」页签时显示**。
- 「停止分享」立刻让链接失效（网页显示「这个链接已停止分享」），服务端删除画面与意见。

### 二、只上传画面，不上传项目

每个版本上传且只上传：

| 内容 | 说明 |
| --- | --- |
| `snapshot.png` | 当前画布的渲染结果，走现有导出管线（单图 `scope=original`、排版 `scope=canvas`），长边 ≤ 3000 px，≤ 8 MiB |
| `elements.json` | 元素位置表 `[{gid, label, bbox}]`，bbox 是画面比例坐标 `[x, y, w, h]`（y 向下）；单图取自 `manifest.build_manifest`，排版 = 每个面板一个框 + 面板内元素按面板位置换算后的框；≤ 256 KiB |
| 元数据 | 标题（默认图名 / 排版名，可改）、「给审阅者的话」（可不填，≤ 200 字） |

**脚本、数据、项目文件、文件路径、本机信息一律不传。** 元素 `label` 是图里本来就看得见的文字（轴标签、图例项），不额外暴露东西。

### 三、额度（免费版，维护者 2026-11-15 改定）

- 每台设备**每天新建 1 个链接**；每个链接**每天最多更新 5 次**。北京时间 0 点重置。暂不做付费档与账号。
- 「每台设备」= 本机首次使用时生成的 Ed25519 设备密钥（PyNaCl，私钥 0600 存 `config.data_dir()/review/device.key`），每个作者端请求带 `(时间戳, 请求体哈希)` 的签名，服务端以公钥为计数主体，时间戳偏差 > 10 分钟拒收。
- 重装换密钥能多拿额度，这是接受的代价；兜底只有按来源 IP 每天 50 个新链接的熔断（学校 NAT 后面人多，不能按 IP 卡正常用户）与全站每天总量熔断。
- 计数在服务端事务里做「未满才 +1」：`quota/new:<公钥>:<日期>`（上限 1）、`quota/update:<share_id>:<日期>`（上限 5）。init 时预占，30 分钟内没有 complete 自动退回。
- **用满不报错**：新建用满时弹选择卡「更新已有的链接 / 复制图片 / 明天再分享」；更新用满时同样给「复制图片 / 明天再更新」。剩余次数只在弹窗页脚用一行小字写。
- 永久免费承诺（官网 FAQ）：免费额度上线后只能上调，不能下调。

### 四、令牌与有效期

- 两种令牌，各 128 位随机：**审阅令牌**在链接里，**管理令牌**只在作者本机（`review/shares.json`，0600）。服务端只存两者的 HMAC-SHA256（服务端密钥），比较用常数时间；错令牌、过期、已停止一律统一 404。
- 有效期 30 天，**每次更新顺延到更新时刻 + 30 天**。到期或停止分享后，服务端删除画面、元素表、意见与结论；存储另设生命周期规则兜底。
- 审阅网页 `noindex`，不列目录；图片地址是短时效签名链接，由 `GET /v1/r/<令牌>` 每次现发。

### 五、意见的锚点与「图改过之后」

```
comment = { id, v, anchor, author, text, replies[], resolved, created_at }
anchor  = { kind: "element", gid, box } | { kind: "region", box } | { kind: "overall" }
reply   = { id, from: "reviewer" | "owner", author, text, created_at }
verdict = { v, decision: "approved" | "changes", note, author, at }   // 每版本每位称呼一条，后提交覆盖先提交
```

- `box` 永远存版本当时的画面比例坐标，所以在那个版本的快照上永远画得对。
- 应用内显示：意见所在版本 = 当前画布，或元素 `gid` 在当前画布里还在 → 圆点跟着元素当前位置走；
  `gid` 不在了（或是区域意见且画布已经变了）→ 不在画布上硬画，列表里用该版本的缩略图标出原位置，一行灰字「原位置已变化」。
- 文字一律当纯文本显示（网页与应用都不解释 HTML / Markdown），≤ 500 字；称呼 ≤ 20 字。
- 只有作者能「标记已处理」；审阅者能删除自己浏览器发出的意见（浏览器本机随机 `author_key`，只存哈希）。

### 六、服务端：腾讯云 CloudBase（维护者 2026-11-15 选定，不上现有 VPS）

- 代码在 `Tavotto/infra` 的 `serverless/review/`：云函数（Node.js）+ 文档数据库 + 云存储 + 静态托管（审阅网页）。不新增需要自己维护的服务器。
- 接口（v1，**本节是唯一出处**；`/v1/shares/*` 作者端要设备签名，`/v1/shares/<id>/…` 另要 `Authorization: Bearer <管理令牌>`）：

| 方法 · 路径 | 用途 |
| --- | --- |
| `POST /v1/shares` | 新建：`{client_share_id, kind: figure\|layout, title, note, png_bytes, elements}` → `{share_id, review_url, owner_token, version: 1, upload, quota}`；`client_share_id` 幂等 |
| `POST /v1/shares/<id>/versions` | 更新到同一链接：`{png_bytes, elements, note?}` → `{version, upload, quota}` |
| `POST /v1/shares/<id>/versions/<v>/complete` | 核对已上传对象的大小与 PNG 魔数后版本才可见；顺延有效期 |
| `DELETE /v1/shares/<id>` | 停止分享 |
| `GET /v1/shares/<id>/feed?since=<游标>` | 作者拉增量（新意见 / 回复 / 结论 / 删除） |
| `POST /v1/shares/<id>/comments/<cid>/replies` · `PATCH …/comments/<cid>` | 作者回复 · 标记已处理 |
| `GET /v1/quota` | 今天还剩几次（弹窗页脚用） |
| `GET /v1/r/<令牌>` | 审阅网页读：标题、给审阅者的话、各版本（短时效图片地址 + 元素表）、意见、结论 |
| `POST /v1/r/<令牌>/comments` · `…/comments/<cid>/replies` · `DELETE …/comments/<cid>` · `PUT /v1/r/<令牌>/verdicts/<v>` | 审阅者留言 / 回复 / 删自己的 / 提交结论 |
| `POST /v1/r/<令牌>/report` | 举报（转维护者企业微信，维护者可一键停用该链接） |

- 上传是「服务端签名 → 客户端直传存储 → complete 核对」，与 0118 / 0145 同形。
- 限流：审阅者写操作按来源 IP 每链接每小时 60 次；每个链接意见总数 ≤ 500。
- 失败码闭集：`quota_new_exhausted`、`quota_update_exhausted`、`share_gone`、`too_large`、`rate_limited`、`network`、`server`、`client_error`（与前端 `review.failure.*` 对拍）。

### 七、客户端

- `engine/reviewshare.py`：出站全走 `diagsend._send`（系统证书、不跟随重定向、响应有上限）；目的地钉死在 `REVIEW_HOSTS = {"review.tavotto.cn"}`，开发 / 验收用 `TAVOTTO_REVIEW_ENDPOINT`，设了但不合规则功能关闭、不回退内置线路。
- `engine/reviewinbox.py`：本机分享记录（share_id、管理令牌、各版本缩略图、意见副本、已读游标），锁 + 原子写，到期 + 30 天后清理；**链接到期后作者仍能在应用里看到当时的意见副本**。
- `/api/review/*`（会话认证照旧）：`capability`、`quota`、`share`、`update`、`revoke`、`feed`、`reply`、`resolve`。
- 轮询：**没有未到期的分享记录就一次网络都不发**；有记录时引擎每 30 分钟拉一次 `feed`，「审阅」页签开着时前端每 60 秒请求一次刷新。新意见 → 顶栏「分享审阅」按钮小圆点 + 通知轨胶囊（「林老师留了 2 条意见 · 查看」）。
- 逐次授权：只有用户点「生成链接 / 更新到同一链接」才上传；失败 / 取消后不自己重试。
- 逃生口：`TAVOTTO_NO_REVIEW_SHARE=1` 整个功能不出现、不联网。

### 八、界面（维护者 2026-11-15 过目的截图稿）

- 入口：顶栏导出按钮左边「分享审阅」。弹窗三态：首次（缩略图 + 一句「只上传这张图的画面，脚本和数据不出本机」+ 给审阅者的话 + 「生成链接」）、已分享（链接 + 复制 + 「更新到同一链接」+ 「停止分享」）、额度用满（选择卡）。
- 不用带底色的状态条（维护者：黄底「V1 需要修改」很丑）：应用里不显示结论条；审阅网页上的结论是一行灰色小字。

## 后果

- 正面：导师不装软件就能在图上指着说；意见和版本在一处；作者在应用里接着改，圆点直接落在元素上。
- 代价：新增一条出机数据流（隐私声明新增一节）；新增一个云端依赖与费用（CloudBase 资源点 + 流量）；用户内容公开托管在备案域名下，**内容审核义务待核实**（先上举报 + 一键停用 + 30 天自动删除）。
- 未做（NOT_RUN）：CloudBase 环境开通与域名绑定（生产动作，逐步等维护者批准）；真实服务端联调；海外访问速度；Windows / macOS 真机。
