# ADR 0212：给 Agent 一套够用的矢量编辑工具——选、改、排、路径、删，与桌面同一套几何

日期：2026-11-25 · 状态：**Proposed**（2026-11-25 维护者拍板两点：后端加 wasmtime 跑同一份 vecops.wasm；Agent 能改画布上**全部**矢量对象）

## 问题

0208 让 Agent 能往排版里**加**箭头、文字、括号、连线、外框，对齐与核对都可信。但用户 2026-11-25 要的是更进一步：
「我们还要给充足的矢量编辑工具给 Agent 使用」——Agent 要能像人一样**改**画布上已有的矢量：挪一挪、换个颜色和线宽、对齐分布、
编组命名、改路径锚点、做布尔运算、删掉不要的。只能追加的 Agent，改不了自己上一次放歪的箭头，也帮不了用户精修手画的示意图。

桌面已经有一套完整的矢量编辑器（0185，覆盖率 99.4%），它的命令散在前端的几张命令表里（`store/transformActions`、
`pathActions`、`pathfinderActions`、`groupActions`、`appearanceActions`，加上排列 / 层级 / 转为路径 / 复制），**几何内核
（vecops.wasm：布尔、偏移、轮廓化、简化）只在前端跑**。插件（无头）碰不到这些。

## 决定

### 一、工具面：五类，与桌面命令一一对应

| 类 | 能做的 | 桌面对应 |
| --- | --- | --- |
| **选** | 按 id、名字、类型、所在子图、组路径、0208 的锚点关系（「指向 P1 的那几支箭头」）、是不是 Agent 加的，选出对象 id 集合 | 选择、图层树 |
| **改** | 位置 / 尺寸 / 旋转（可写成锚点：「把箭头尖对准那个数据点」）；描边（颜色、线宽、虚线、线端、拐角、对齐、端型）、填充（纯色 / 渐变）、不透明度；文字内容、字号、字体、粗斜；圆角；锁定 / 隐藏；名字 | 属性栏、变换面板 |
| **排** | 对齐（到选区 / 关键对象 / 子图 / 画布）、按间距分布、层级（上下移、置顶底）、编组 / 拆组、剪切蒙版、复制 / 阵列、镜像、倾斜 | 排列、变换、编组命令 |
| **路径** | 加 / 删 / 转换锚点、断开、连接、平均、反转、复合路径、转为路径；布尔（合并 / 减去 / 交集 / 排除 / 分割 / 修边）、偏移、轮廓化描边、简化 | `pathActions`、`pathfinderActions` |
| **删** | 删除对象 / 组 | 删除 |

**不在此列**：图里由脚本画出的数据元素（改它们走 `tavotto_apply_overrides`，脚本是真值）；子图本身的裁剪与落位（排版层，
后续与一键排版 0199 的 Agent 工具合并考虑）。

### 二、写入：从「只追加」扩成「补丁」

- 一批编辑 = 一份**补丁**：每条只点名一个对象 id 与要动的字段（或一个命令 + 它的参数），不收整份对象、不收整份文档。
  服务端按补丁**重算**（与 0208 同一纪律：不收 Agent 算好的坐标），校验结果对象（`agentobjects` 的字段表与上下限），再核对。
- **复述**逐条说「改了谁、从什么改成什么」：对象的名字 / 类型 / 所在位置（「P1 右上那支红箭头：线宽 0.5 → 0.75 pt」），
  布尔与路径命令说参与的对象与结果的个数。复述 + 补丁的摘要照旧是写入的前提（`echo_digest`）。
- **能改什么**（维护者 2026-11-25 定）：画布上**全部**矢量对象，含用户手画的；每次复述、每次一步撤销（0208 的按文件留存）。
- 0208 第 2 期 ③ 的「把 Agent 加的并进来」扩成也认补丁：撤销留存记下每一步改了哪些 id；桌面这边没碰过这些对象时才能并，
  碰过同一个对象（同一字段或删 / 改冲突）就照旧走覆盖 / 另存，不替用户挑。

### 三、几何在哪里算：数据层进引擎、内核用同一份 wasm

- **数据层**（变换、镜像、倾斜、对齐分布、层级、编组、阵列、实时圆角、样式与文字字段、转为路径）：纯数据运算，搬进引擎
  （`engine/vectoredit.py` 一类），与前端**逐数对拍**——已有的 Python 参考实现（`scripts/dev/gen_transform_vectors.py`、
  `gen_array_vectors.py`、`gen_live_corner_vectors.py`、`gen_path_vectors.py`）升格为引擎代码，黄金用例两侧共读，登记进严格同源对。
- **几何内核层**（布尔、偏移、轮廓化描边、简化）：后端用 **wasmtime 跑同一份 `web/src/lib/vecops/vecops.wasm`**（维护者 2026-11-25 定）。
  0185 §三「后端永远不需要 pathops——几何只在一处算」的本意是「只有一份实现」，同一份逐字节重建的二进制在两边跑，这条本意不变；
  0185 修订记一笔。2026-11-25 实测：这份 wasm 没有任何导入，导出 `pathfinder / offset / outline / simplify / alloc / dealloc / out_ptr`，
  Python 里编译 0.12 s（进程内缓存编译结果）；wasmtime 51 的 wheel 每平台 8–9 MB，macOS arm64 / x86_64、Windows、Linux 都有。
  依赖只进引擎的可选组（插件无头与桌面后端用），延后 import；装不上 / 加载失败时这四个命令回 `kernel_unavailable`，其余工具照常。
- **桌面里的改图助手**（0147）不走后端算几何：直接调前端同一张命令表（选区 + 参数），结果照样过复述与方案卡（0206）。

### 四、核对：编辑之后的成品照 0208 量

改过的对象与新加的同等对待：锚点残差、不遮数据、不压字、不出页、期刊字号线宽、字体同类。**只核被这次补丁动到的对象**
（以及被它们挡住 / 挡住它们的），没动的不重新报——否则用户早就接受的一处压字会让每一次编辑都过不去。

### 五、分期（每期一个 PR，按风险档走评审）

1. 引擎数据层：选择器 + 补丁式写入（复述、摘要、只动点名字段、撤销留存记 id）+ 样式 / 文字 / 锁隐 / 名字 / 删除；
2. 变换、镜像、倾斜、对齐分布、层级、编组、阵列、实时圆角（参考实现升格 + 黄金对拍）；
3. wasmtime 内核：布尔、偏移、轮廓化、简化（与前端 `pathfinder.golden` 同一组输入，逐数对拍；打包核 PyInstaller / 受管环境 / Intel Mac）；（2026-11-26 补：轮廓化的虚线 / 端型 / 内外对齐照前端 `lib/outlineStroke` 有了 Python 版，与前端逐数对拍）
4. 路径锚点编辑：**逐点平移锚点 / 拖手柄**（原列表漏写，补上）、加 / 删 / 转换锚点、断开（剪断）/ 连接 / 平均 / 反转 / 复合路径 / 转为路径。2026-11-26 做了除「转为路径」外的全部（后者另一个 PR）：补丁操作 `move_anchors` / `move_handle` / `add_anchors` / `delete_anchors` / `convert_anchors` / `average_anchors` / `cut_path` / `join_paths` / `reverse_path` / `make_compound` / `release_compound`，纯函数 `engine/pathedit.py` 逐个对应前端 `lib/pathEdit.ts` 与 `store/pathActions.ts` 的对象级规则（剪断后多出的段各成新对象、连接两对象留最后一个的 id……），操作层 `vectoredit.py` 做严格校验与复述（锚点地址 `{sp, i}` 含义是**该操作执行时**的状态，每条复述写明「现为」各子路径锚点数）；场景 `vector_objects` 给路径的 `subpaths` 计数与有上限的 `anchors` 清单（页面 mm、已旋转）；与前端的逐数对拍 `tests/golden/path_edit_vectors.json`（驱动真的 store 动作录出）。不需要内核，不依赖 wasmtime；
5. 插件工具（`tavotto_layout_edit_plan` / `_apply`，选择器并进 `tavotto_layout_scene`）+ 「并进来」认补丁（2026-11-26 拆成两个 PR：① 工具 + 布局组清理 #2244；② 桌面并进来认补丁：字段三方合并）；
6. 改图助手接前端命令表 + 方案卡。

每期合入后重跑 0208 的评测任务集，另加编辑类任务（「把三支箭头左对齐并统一成 0.75 pt」「把两个圆合并成一个轮廓」）。

## 后果

- Agent 能精修矢量，不只是追加；插件无头与桌面里的结果是同一份几何。
- 引擎多一个可选依赖（wasmtime，约 9 MB / 平台）；内核加载失败只影响四个命令。
- 前后端多出一批严格同源对（变换 / 阵列 / 圆角 / 路径编辑），靠黄金用例看护；改前端几何时两边一起改。
- 1.0 期间按 0208 的豁免推进（同一条功能线）；若维护者认为要单独豁免，在本 ADR 状态行补记。
