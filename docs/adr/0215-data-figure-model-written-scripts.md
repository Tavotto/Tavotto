## 问题

维护者 2026-11-27：「如果我把这些数据直接扔给 Claude 和 Codex，他们都能够直接分析画图，但是 Tavotto 为什么就在这里如此受限。我们要在这里找出来原因，在最大的地方给它补齐。」
举的例子是一份 3.6 GB 的 LAMMPS 轨迹（`.lammpstrj`，595 帧 × 11.5 万原子）。

原因只有一个：**这条路上被执行的代码只能出自 Tavotto 写好的模板，模型一行分析代码都不写**（`ai_data_task.py` 模块说明：「这里不调模型……被执行的代码完全出自模板」；
0178 决定 1 与「不做：模型写 matplotlib」；0138 §四「数据出图 v1 因此不执行模型写的代码」）。连了 AI 也只让它指认哪一列是横轴 / 纵轴 / 分组（「读懂数据」）。
于是每遇到一种新数据——轨迹、两行表头、小数逗号、要先算再画的量——都得先由我们写一段规则或模板。同一天的记分表（90 张表，不连 AI）：
规则路修了一轮之后「好 + 可接受」71%，剩下 26 张画错 / 画不出，全是「读不进」或「要先整理 / 先算」的表。

维护者此前已定的方向（2026-11-18 / 11-19，原话见当时的记录）：配方与模型生成脚本两条路都做；模型在工作区内可写、工作区外只读；可以用命令行、可以联网；
摘要不够时能拿到完整数据文件；自带模型即可用；Windows 不做系统沙盒，「如果写了外部目录，用一下 hook 就好了」；「只能写在工作区内」做不到强制的地方要如实告诉用户。

## 决定

### 一、主路是「两段式」：模型写准备脚本，画图仍走配方

连了 AI 时，一次数据出图分两段：

1. **准备（模型写代码）**：模型看文件开头、抽样与摘要，自己写一个**准备脚本**（Python），把原始文件读成一张整洁的表（CSV）。
   读不认识的格式、合并两行表头、换小数点、逐帧汇总轨迹、按公式算出新的一列，都在这一段。脚本在候选区里试跑，报错喂回给模型改，有轮数上限。
2. **画图（配方）**：在准备好的那张表上，模型**选用或组合现有配方**（0178 的十二类图型），由模板生成画图脚本。
   这一段的核对原样保留：数据指纹与父进程算的期望值逐字节相等、画了多少行、哪些行没画、误差线取自哪几列。

为什么不是「模型直接写一整个 matplotlib 脚本」：现有的核对（期望指纹、`goal.rows_plotted`、没画的行）都建立在「画图脚本出自模板、调用同一份运行时函数」上，
模型自由写的画图脚本一条都用不上。两段式把「模型的自由」放在读取和整理上（用户数据千奇百怪的地方），把「可核对」留在画图上（科学上最怕画错的地方）。
这也是轨迹「先汇总成表再出图」（`ai_data_traj`）的同一个形状，并对得上维护者的原话「模板……供大模型在思考其科学性后选用」「可以进行组合或者拓展」。

**核对分三档，界面如实写**（「依据」那一句与问题面板）：

| 档 | 什么时候 | 能核对到什么 |
|---|---|---|
| A 表直接画 | 原始文件本身就是整洁的表（今天的路） | 全部：数据没变、每个数画对、哪些行没画 |
| B 准备 + 配方 | 模型写了准备脚本 | 画图这一段同 A（对象是准备好的表）；准备这一段只有**来源证明**：原文件 sha256、准备脚本的 sha256、读进多少行 / 帧、写出多少行、丢了多少行及原因（脚本必须自己报）。**「整理 / 计算本身对不对」不核实**，界面写明「这张表由 AI 写的脚本整理得到」并可一键打开脚本 |
| C 自由画图脚本 | 配方画不了的图，用户明确要 | 只有「数据文件没被改、脚本跑得出图」；数据核对结论是 unknown，界面写「未核对」 |

C 档不在第一期。

### 二、「工作区」是什么，脚本落在哪

本 ADR 里的**工作区 = 用户选的那个项目文件夹**（界面上的「项目」）。与 0194 里的「工作区」（Tavotto 自己的 `tavottofile/` 目录）不是一回事，下文不混用。

落盘照「转换成可编辑脚本」（0143）已经走通的形态，不改 Task Core 的写入放行：

- 模型的一切读写、试跑都发生在**候选目录**（Tavotto 自己的目录）里：项目文件经只读快照进来，脚本往项目里写的东西被改道到暂存区（0141 改道模式），**项目里一个字节不变**。
- 用户在界面上**采用**之后，后端才用 `scriptlock.create_script`（只新建、已存在就失败）把三样东西放进 `<数据文件夹>/tavotto_figures/`：
  准备脚本、准备好的表（CSV，开头几行 `#` 记来源文件名 / 字节数 / sha256 / 脚本名）、画图脚本。
- 原有的脚本与数据永远只读；模型只能改 / 删它自己在这次任务里新建的文件。
- 失败、取消、超限：候选目录整个丢掉，项目里什么都没有发生。

### 三、写入范围到底拦不拦得住（平台 × 连接方式）

维护者定的是「只能写在工作区内，做不到强制要如实说」。下面每一格只写三种之一：**拦得住** / **事后发现** / **不保证**；没有实测过的写「未验证」。

| | 内置循环（自带 Key、ChatGPT 账号登录） | Codex CLI 订阅 | Claude Code CLI 订阅 |
|---|---|---|---|
| 工具层的写文件 | 拦得住（路径判据只有一处 `_resolve`，realpath 必须在候选目录内） | macOS / Linux：CLI 自带系统沙盒（`workspace-write`），是 CLI 的行为不是 Tavotto 的保证；Windows：已知故障，现由 Tavotto 代写 | 只有权限规则，没有系统沙盒；钩子（PreToolUse）可拦工具层的写——**未验证** |
| 模型写的 Python 在进程内写文件 | macOS / Linux：拦得住（绊线 + 系统沙盒 `sandbox-exec` / `bwrap`）；Windows：绊线拦 Python 层的写（**Windows 上未验证**），`ctypes` / C 层绕得过 | 同左列（由 Tavotto 代跑时） | 同左列（由 Tavotto 代跑时） |
| 模型跑的命令 / 脚本起的子进程 | macOS / Linux：拦得住（`cmdsandbox` 第①档：可联网、只许写清单内目录）；**Windows：事后发现**（没有系统沙盒，只有起跑快照 + 项目指纹，查到后不自动还原、告诉用户） | macOS / Linux：靠 CLI 的沙盒；Windows：**不保证** | 三个平台都是**事后发现** |

要点，请维护者特别留意：**Windows 上「跑命令」这一格做不到拦住。**「用一下 hook 就好了」能覆盖的是 Python 进程内的写（绊线）和 CLI 工具层的写（钩子，待实测）；
命令自己起的进程往工作区外写，在 Windows 上只能事后靠快照与指纹发现。所以第一期在 Windows 上**不开「跑任意命令」**，只开「跑模型写的 Python」；
任意命令在 Windows 上要不要开、怎么告诉用户，放到第二期单独定。

读取：工作区外只读，沿用 `fixtools/readscope`（主目录 + 项目根 + 环境前缀；凭据目录硬拦 `DENY_HOME_RELATIVE` / `DENY_NAME_PATTERNS` 不放开）。

### 四、发给模型什么（隐私）

维护者 2026-11-27 亲批的那句——「「读懂数据」会把表名、列名、每列的类型和统计摘要，以及每列最多 20 条文字样本发给你连接的 AI；数据行本身不会发送。」——
**只对「读懂数据」这一步成立，不覆盖本 ADR 的路**。走这条路时模型会拿到：

- 文件开头若干行、抽样的数据行（它要看懂格式就必须看到真实的行）；模型需要时可以读工作区里文件的任意部分（维护者 11-19：「当模型需要的时候，它也要能够获得完整的数据文件」）；
- 它写的脚本的运行输出与报错（可能带数据片段、文件路径）；
- 第二期起：它跑的命令的输出；它可以联网（搜索知识、装包）。

所以：① 这条路需要**新的一句隐私说明**，措辞由维护者本人定，定之前不开；② `docs/privacy.md`「Optional AI assistant」一节要补逐项清单（这本来就是数据出图开关打开前的欠账）；
③ 大文件不进上下文——只给开头、抽样与模型自己写的脚本算出来的小结果；④ 数据里的文字可能诱导模型把内容外发（联网之后才成立），维护者 11-19 知情并仍选联网，照录为已接受的风险；
⑤ 遥测照旧不收脚本、路径、列名、图里的文字。

### 五、上限与收场

- 每次任务：轮数、token、墙钟时间、试跑次数都有上限（沿用内置循环的 `Limits` 与 Task Core 的 `Budget`；初值照转换任务：32 轮 / 80 万 token / 900 s，试跑 ≤ 6 次，实测后再调）。
- 结束原因是闭集（沿用 `agent_runner`：completed / max_turns / budget / tool_error_loop / auth / quota / refused / network / cancelled / internal）。失败不抛异常、不留半成品。
- 准备脚本的硬要求（提交前检查，不满足就不让采用）：能解析；只读原始文件；输出恰好一张表到指定位置；自己报告读了多少、写了多少、丢了多少；同一输入重跑两次输出字节相同（不许带时间、随机数）。
- 所有用户当小白：任何一种失败都落到一个明确的终态——「改用不连 AI 的办法画」（退回规则路）、「换一句话再试」、「打开脚本自己改」——不出现报错卡死。
- 花费：自带 Key 时照现有计价表在任务结束后显示本次花费；托管网关需要新增一类任务与上限，不在本 ADR。

### 六、分期（顺序请维护者定）

1. **第一期：内置循环 + 跑模型写的 Python**（自带 Key、ChatGPT 账号登录）。新工具集 `data_prepare`：读文件片段 / 抽样、新建与修改自己的文件、`run_python`（复用 `fixtools/trial.run_python`：绊线 + 禁起子进程 + 有就套系统沙盒）、`check`、`finish`。
   没有任意命令、没有联网。这一期就能接住轨迹、脏格式、两行表头、先算再画。
2. **第二期：命令行与联网**（复用 `cmdsandbox` 第①档）。macOS / Linux 先开；Windows 单独定（见第三节）。
3. **第三期：订阅登录的 Codex / Claude Code CLI 当 agent**。前提是在三个平台用真 CLI 实测写入行为（错题本 L-130），Claude 的钩子实测通过。
4. C 档自由画图脚本、托管网关任务类别：另立。

规则路（不连 AI）继续保留：没连 AI 时的兜底；它的读表与配方同时是第二段的地基。但**不再往规则路里堆新格式**——只修明显的读表缺陷。

### 七、怎么算做成

验收集（已有，在本机）：记分表里规则路「画错 / 画不出」的 26 张表，加 `.lammpstrj`、ReaxFF `species.out`、两行表头的表。
报：完成率（按同一份事先写好的期望评档）、每张表的花费与耗时、失败的终态分布、「原本画对的有没有被改坏」。
真模型只在本机跑、报实际花费；Windows Lab 与 CI 不跑官方模型。第三节里每一个「未验证」的格子在对应那一期开工前实测并回填。

## 已知盲区（如实写）

- 绊线只防「合作但有 bug」的脚本：`subprocess`、`ctypes`、C 层 `fopen` 绕得过；在 Windows 上没有验证过（8.3 短名、UNC、大小写）。
- Windows 没有系统沙盒；`run_python` 在 Windows 上只靠进程内守卫（0197 已接受的同一条风险）。
- 外部 CLI 的沙盒与写入行为是 CLI 的行为，不是 Tavotto 的保证；只在 macOS 实测过一次（风险登记 R-03）。
- 模型写的准备脚本「算得对不对」没有任何自动核对；用户能做的是打开脚本看，以及看「读进 / 写出 / 丢掉」的行数。
