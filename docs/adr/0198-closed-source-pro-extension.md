日期：2026-11-20 · 状态：**Proposed（本 ADR 只定边界与契约；开源宿主、私有仓库、服务端各一路实现，全部先在测试模式里走通）**
**1.0 收敛纪律：新增产品能力。方案四项由维护者 2026-11-20 定（「都按推荐来，先写 ADR」）；维护者 2026-11-20 确认按 [0193](0193-paid-edition-license.md) 高级版豁免的延伸登记在 `docs/1.0-release-readiness.md` §1.8（「可以继续」），同日确认首版只出桌面三平台、sidecar 不联网、推荐版本由服务端指定；入口跟 0193 的上线开关走，服务端正式模式验通前正式安装里零入口、零网络。**

## 问题

维护者 2026-11-20 定：**高级版功能闭源，代码不进公开仓库**。第一个功能是排版模式里的「一键排版」（另立 ADR）。要回答三件事：闭源代码怎么和 AGPL 的主程序配合、怎么只发给付过费的人、怎么更新。

约束：

1. **许可证**：主仓库 AGPL-3.0-only，并且已经有外部贡献者（CLA 在用，ADR 0137）。闭源代码如果和 AGPL 代码在同一个进程里互相 import，容易被认定为衍生作品。`docs/legal/LICENSING.md` 第二层：贡献者的代码只能在 CLA 授权范围内另行许可。
2. **永久免费承诺**（0193 §一）：已免费发布的能力不许出现权益判断；高级版用户做出来的东西必须是普通文档数据。
3. **所有用户当小白**：下载失败、验签失败、版本不兼容、新版起不来，都静默留在能用的状态（旧版或免费版），不报错卡住。
4. **大陆用户占多数**：下载要在大陆稳定可达。
5. **运行时可写数据只走 `config.data_dir()`**；macOS 写 .app 会破坏签名。
6. **本地挡不住改代码的人**：要防的重点是**闭源代码不被直接拿走**，以及拷到别的电脑上用不了；不追求绝对防破解。

## 决定

### 一、边界：开源宿主 + 闭源独立进程

```
开源仓库 Tavotto（AGPL）                         私有仓库 Tavotto/pro（闭源）
engine/prohost.py   下载 / 验签 / 安装 / 启停 / 回退 ◀── pro 协议（stdin/stdout JSON 行）──▶ tavotto-pro 可执行文件
/api/pro/*          会话认证照旧                                                          只做计算，不联网
web PremiumLock     置灰 / 预览 / 应用（#2071）                                            自己再核令牌 + 设备密钥
license.py          has(feature)（0193，已合入）
```

- **闭源代码只以独立进程存在**（下称 sidecar）。主程序任何进程都不 import、不 `dlopen` 闭源代码；前端 webview 里不加载任何闭源 JS / WASM。
- **sidecar 只返回数据**：请求里给它的是数字与结构（几何、字号、线宽、期刊规则、选区），它回的是**现有覆盖格式里的操作列表**（与手动编辑写出的条目同一套键）。预览由开源前端画；应用走现有写回事务 prepare → verify → commit，不新开写入路径，不跳过 verify。
- **不变量（看护见 §十二）**：凡高级版产生的结果都是普通文档数据。没有授权、授权过期、sidecar 不存在时，项目照样能打开、编辑、撤销、导出，看到的与应用当时一模一样。主程序读写文档的任何代码路径都不许依赖 sidecar 或 `license.has`。
- **宿主是通用的**：协议写进本 ADR 与 `docs/rules/backend/pro-extension.md`（实现 PR 新建），任何人都能按它写 AGPL 扩展；开源仓库自带一个开源的示例扩展（`tests/fixtures/pro_echo/`，纯 Python），用于契约测试，CI 不需要闭源代码。

### 二、许可证与著作权（前置条件，不满足不上线）

- 私有仓库里的代码**只能是维护者本人著作权的**。不复制主仓库里非维护者本人写的代码（按 `git blame` / `IP_PROVENANCE.md` 判断）；共享逻辑一律走协议，不搬代码。
- 私有仓库的第三方依赖只许用允许闭源分发的许可证（MIT / BSD / Apache-2.0 / MPL-2.0 等）；私有仓库 CI 跑许可证清单检查，出现 GPL / AGPL / LGPL 静态链接一律红。
- 开源宿主、协议、示例扩展都是 AGPL，留在公开仓库。
- **上线前由维护者找律师确认两件事**：① 现有 CLA 的授权范围；② 「AGPL 主程序 + 经公开协议通信的闭源独立进程」这种组合发行方式。这是 §十三 上线步骤的第 1 步，没确认不收第一笔钱。

### 三、pro 协议 v1

- 传输：sidecar 的 stdin / stdout，一行一个 JSON；stderr 只是日志，宿主截断后写进本地日志，不进诊断包正文。
- 信封与 worker 协议 v1 同形：`{"protocol_version": 1, "request_id", "cmd", "payload"}`；响应原样回显 `request_id`，`{"ok": true, "result"}` 或 `{"ok": false, "code", "message"}`。
- 握手：宿主启动 sidecar 后第一条必须是 `hello`，回 `{pro_version, pro_api, features: [...], platform}`。`pro_api` 是整数；宿主内置 `prohost.SUPPORTED_PRO_API`（集合），不在集合里 = 不兼容，按 §七 处理。
- 失败码闭集：`bad_request`、`unsupported`、`license`（sidecar 自己核令牌没过）、`timeout`、`internal`。宿主把任何失败都折成「这个高级功能暂时不可用」，不把 sidecar 的原话给用户看。
- 生命周期：第一次用到高级功能时由引擎拉起（不随应用启动）；单请求超时 30 秒（命令可在协议里声明更长）；空闲 10 分钟退出；崩溃后下次请求再拉起，同一会话连续崩 3 次就停用到下次启动。只按自己拉起的 PID 结束。
- **sidecar 不联网**：所有网络都由开源宿主做（§五），sidecar 的代码里不许有出站请求（私有仓库 CI 用 AST 扫描 `socket` / `urllib` / `http` / `requests` 的 import）。sidecar 只收到宿主给它的数字与结构：**不给脚本、数据文件、路径、图内文字的原文**（真需要文字时只给长度与字号，由各功能 ADR 逐条登记）。
- 各高级功能的 `cmd` 与 payload 在各自的 ADR 里定（第一个是一键排版）。

### 四、发行包

- 用 **Nuitka** 编成按平台的独立可执行文件（不发 `.py` / `.pyc`，不需要内置 runtime 或用户的 Python）。平台以 `docs/support-matrix.json` 的桌面目标为准：`macos-arm64`、`macos-x86_64`、`windows-x64`。pip / pipx / uvx 装的 wheel 与无头 Linux **首版不提供**：宿主照常工作，清单里没有这个平台就当作没有这个组件（功能保持置灰，悬停一句「这台电脑暂不支持」）。
- macOS：用与桌面版同一个 Developer ID 签名并公证（hardened runtime）。不依赖主程序 `entitlements.plist` 里的 `disable-library-validation`。
- Windows：与桌面版当前状态一致（未签名，沿用发版豁免）。**每次发高级版前在 Windows Lab 上跑一遍 Defender 扫描与启动冒烟**，Nuitka 产物容易被误报。
- 包格式：一个 zip，内含 `tavotto-pro/`（可执行文件及其目录）与 `release.json`（§五 的发布清单原文）。**不加密**：密钥终究要到客户端，加密挡不住人；完整性靠签名。

### 五、发布清单与下载

**发布清单**（在私有仓库 CI 里生成并签名，服务端只转发，不能改）：

| 字段 | 含义 |
| --- | --- |
| `v` | 1 |
| `pro_version` | 高级版版本号（与主程序版本无关） |
| `platform` | `macos-arm64` \| `macos-x86_64` \| `windows-x64` |
| `pro_api` | 这个版本说的协议版本 |
| `features` | 这个版本提供的功能键（必须在 0193 §一 的闭集里） |
| `sha256` · `size` | zip 的摘要与字节数 |
| `released_at` | 发布时刻（UTC 秒） |

- 格式与授权令牌同形：`{"payload": base64(JSON), "sig": base64(Ed25519), "kid"}`。签名用**新的一对发布密钥**（`kid` 前缀 `pro-`），不与授权令牌、期刊目录共用。私钥只在私有仓库发布任务的受保护环境里，由维护者本人放入；公钥按 `kid` 内置在 `prohost.RELEASE_KEYS`。**服务端被攻破也推不了恶意二进制**，因为它拿不到发布私钥。
- **服务端新接口**（0193 §三 接口表里加了一行指向这里；设备签名与 0193 §五 同形；`op` 用 `pro_manifest`，实现 PR 同步改 0193 §五 的闭集与 `license.OPS`）：

| 方法 · 路径 | 用途 |
| --- | --- |
| `POST /v1/pro/manifest` | `{license_id, device_pub, platform, pro_api: [...], ts, sig, op: "pro_manifest"}` → `{release, url, app_update_needed}` 或 `{state: "none" \| "revoked" \| "expired"}` |

  - 服务端按购买台账核权益，在该平台、客户端支持的 `pro_api` 范围内挑**当前推荐版本**（由维护者在服务端配置指定，不一定是最新；指定旧版本 = 全网回滚）；
  - `url` 是 COS 私有桶 + CDN 鉴权的**限时下载地址**（10 分钟有效），不在签名范围内；
  - `app_update_needed = true`：存在更新的高级版，但要求更新的主程序。
- 下载：主机钉死 `PRO_DOWNLOAD_HOSTS`。首选 `dl.tavotto.cn` 下独立的 `/pro/` 路径（与应用内更新同一个 CDN，大陆可达），**前提是 CDN 鉴权能只作用于 `/pro/`**，不波及 `/updater/latest.json` 与安装包；做不到就换一个独立主机名（如 `pro-dl.tavotto.cn`）并修订本节（见「后果·未做」）。下载走 `diagsend` 出站笼子的流式变体（主机白名单、超时、字节上限 = 清单里的 `size`）。下载完先核 `size` 与 `sha256`、再核 `release.json` 与清单逐字节一致，任何一项不对就丢掉，留在原状态。
- 联网时机：只在本机已有有效令牌、且 `license.has` 至少对一个高级功能键成立时；随 0193 的刷新一起（启动后一次、之后每天最多一次），以及激活成功后立刻一次。**没有令牌时一次网络都不发。**

### 六、本机安装布局

- 位置：`config.data_dir()/pro/`：
  - `<pro_version>-<platform>/` 每个版本一个目录；
  - `current.json`：指向当前版本与上一个版本（不用符号链接，Windows 兼容）；
  - `bad.json`：本机健康检查失败过的版本，不再自动切换到它们（服务端换了推荐版本后清空）。
- 安装：先解压到同目录下的临时目录，核对完再原子改名，最后原子改写 `current.json`。只保留当前与上一个版本，更早的删掉。整个过程持锁，与正在运行的 sidecar 互不干扰（运行中的版本目录不删）。
- macOS：预期应用自己用 HTTP 下载的文件不带隔离属性、不触发 Gatekeeper 弹窗（**未实测**，见「后果·未做」）；无论如何都要求 §四 的签名公证，宿主启动前跑一次 `codesign --verify`，不过就当作坏包。
- Windows MSIX：数据目录在 LocalCache 里（参见 #2063），能否从那里执行 exe 要在 Windows Lab 上实测（见「后果·未做」）。不行就改放 MSIX 允许执行的位置，并修订本节。

### 七、更新与回退

- 后台下载、**不打断正在用的功能**：新版本装好后，等 sidecar 下次启动（空闲退出或应用重启）时才切换。
- 切换后的健康检查：`hello` 在 10 秒内回来、`pro_api` 在支持集合里、`features` 与清单一致。不过就**静默切回上一个版本**并记进 `bad.json`；上一个版本也没有，就当作没有组件（功能置灰）。
- 主程序太旧：继续用本机已有的兼容版本；`app_update_needed` 时只在已有的更新胶囊里提示更新应用（不新加横条、不弹窗）。
- 回滚：维护者在服务端把推荐版本改回旧版即可，客户端下次刷新时下载并切换（允许降级，前提是旧版本同样有效签名）。

### 八、授权、过期与开关

- 宿主只在 `license.has(<该功能键>)` 成立时为这个功能拉起 sidecar；sidecar 自己再核一遍令牌签名、`exp` / `offline_until`、本机设备公钥（读 `data_dir()/license/`，与主程序同一个用户），不过就回 `license`。目的是让拷走的程序在别的电脑上跑不起来，不是绝对防破解。
- **过期或被撤销**：本机文件保留、不删，sidecar 不拉起，功能置灰（#2071 的 `PremiumLock`）；续费后立刻可用，然后照常检查更新。
- 0193 §一 的调用点看护：`license.has(` 只许出现在 `engine/prohost.py` 与各高级功能登记过的入口模块里；`tests/test_license_callsites.py` 的 `REGISTERED_CALLERS` 随实现 PR 加上 `prohost.py`。功能键仍是 0193 §一 的闭集，**每个高级功能在自己的 ADR 里登记一个键**（一键排版 = `quick-layout`），并同步改 0193 §一。
- 开关：**不另设上线开关**，跟 `license.enabled()` / `license.PRODUCTION_LIVE` 走；`TAVOTTO_NO_LICENSE=1` 时宿主整个不出现、不联网、不拉起。
- **测试模式与正式模式隔离**（与 0193 §三 同一条线）：
  - 发布密钥也分两把：测试发布密钥的公钥**不进**正式版的 `RELEASE_KEYS`，只在设了 `TAVOTTO_LICENSE_ENDPOINT` 时经 `TAVOTTO_PRO_TEST_RELEASE_PUBKEY` 认；测试服务端只转发测试清单。
  - sidecar 核令牌用的授权公钥**编进 sidecar 里**，不由主程序传入（传入等于让改过的主程序随便换）。所以私有仓库每个版本编两种：正式版只认 0193 的正式 `PUBLIC_KEYS`；测试版另外认测试授权公钥，并且只用测试发布密钥签名。正式安装拿不到也认不了测试版。
  - 授权密钥轮换（0193 §四 加新 `kid`）：先发一版认新 `kid` 的 sidecar 并设为推荐，等它铺开，再发认新 `kid` 的主程序，最后服务端才改用新密钥签名。旧 `kid` 在 sidecar 里保留到它签出的令牌全部过期。
- 开发：`TAVOTTO_PRO_DIR=<本地编译目录>` 直接用本地产物、跳过发布签名与下载，**只在设了 `TAVOTTO_LICENSE_ENDPOINT`（开发 / 验收模式）时认**，正式安装里设了也无效。

### 九、界面

- 不新增界面元素：功能入口的置灰、悬停一句话、「了解高级版」都用 #2071 的 `PremiumLock`；设置里的授权行（#2071 `LicenseRow`）不加高级版组件的版本号等字样（版本号只进诊断包）。
- 已授权但组件还在下载、或这个平台没有组件：入口保持置灰，悬停一句话（「正在准备，稍等片刻」/「这台电脑暂不支持」），不弹窗、不显示进度条。
- 具体文案与截图稿随第一个高级功能的 ADR 给维护者过目，先过 agy 审。

### 十、隐私与诊断

- 新增两条出机数据流：
  - `pro/manifest`：授权号、设备公钥、签名、时间戳、平台、支持的协议版本；
  - 从 §五 的下载主机下载组件（CDN 会记 IP 与时间，与应用内更新相同）。
  不发项目、脚本、数据、路径、本机信息。
- sidecar 在本机运行、不联网；它收到什么由各功能 ADR 逐条登记（§三）。
- 诊断包：只记高级版组件的版本、平台、最近一次健康检查结果；`pro/` 目录整个排除（与 `license/` 同）。
- `docs/privacy.md` 在 0193 那一节里补这两条，措辞由维护者本人确认后才合入。

### 十一、私有仓库与发布链

- 私有仓库 `Tavotto/pro`（建在 Tavotto 组织下；**建仓是维护者批准的动作**）。
- 私有仓库 CI：
  - 按平台矩阵用 Nuitka 编译；
  - macOS 签名公证；
  - Windows Lab 上做 Defender 扫描与冒烟；
  - 许可证清单检查、「不联网」AST 扫描；
  - 生成并签名发布清单，上传 COS；
  - 在服务端登记新版本（**不**自动设为推荐版本，设推荐由维护者执行）。
- 契约测试两头都跑：
  - 开源仓库：用 `tests/fixtures/pro_echo/` 测宿主的下载、验签、安装、切换、回退、超时、崩溃；
  - 私有仓库：每晚拿开源 `main` 的协议定义与固定向量跑一遍，主程序改了协议第二天就能发现。

### 十二、看护（实现 PR 要带的测试）

- `license.has(` 调用点登记（已有，扩表）。
- **「结果是普通数据」**：AST 检查文档读写、渲染、导出模块不 import `prohost` / `license`；e2e 用 `pro_echo` 应用一次结果，然后删掉 `data_dir()/pro/` 与 `license/`，重开项目做重放比对，结果必须逐字节一致。
- 发布清单验签：篡改 payload、换 `kid`、`sha256` 不符、`size` 超限、`release.json` 与清单不一致，各自都要拒收（每条手工反证一次）。
- 下载主机白名单：清单返回不在 `PRO_DOWNLOAD_HOSTS` 里的地址必须拒收。
- `TAVOTTO_PRO_DIR` 在没有 `TAVOTTO_LICENSE_ENDPOINT` 时无效。

### 十三、上线步骤

下面每一步都先报合并大队长，再由维护者本人批准：

1. 律师确认 CLA 授权范围与组合发行方式（§二）；
2. 建私有仓库、生成发布密钥（维护者本人）；

### 十四、维护者 2026-11-20 定的参数

| 项 | 定为 |
| --- | --- |
| 闭源代码的形态 | 独立进程（sidecar），不进主进程、不进前端 |
| 法律确认 | 上线前找律师核 CLA 与组合发行（§二） |
| 防护程度 | Nuitka 编成原生可执行文件；不加密，靠签名 |
| 授权过期后 | 本机文件保留只停用，续费即用 |
| 1.0 豁免 | 按 0193 延伸登记（维护者 2026-11-20 确认） |
| 首版平台 | 只出 macOS 两档与 Windows 桌面版；wheel / uvx / 无头 Linux 暂不提供（装了桌面版的电脑上，经 MCP 接入的 agent 共用同一份授权与组件） |
| sidecar 联网与输入 | 不联网；不给脚本、数据、路径、图内文字原文 |
| 推荐版本 | 由服务端配置指定，可指定旧版实现回滚 |

## 后果

- 正面：
  - 闭源代码不进公开仓库，也不进主进程，许可证边界清楚；
  - 服务端被攻破也推不了恶意组件（发布私钥不在服务端）；
  - 高级版可以单独发版、单独回滚；
  - 用户做出来的东西永远不依赖授权；
  - 开源仓库的 CI 不需要闭源代码。
- 代价：
  - 多一个跨仓库的发布链和一把发布密钥要保管；
  - 每个高级功能都要把输入输出写成协议，不能直接调用主程序内部函数；
  - Nuitka 产物体积更大，Windows 有误报风险；
  - 首版不支持 wheel / Linux。
- 未做（NOT_RUN）：
  - 开源宿主、服务端接口、私有仓库与发布链的实现；
  - 律师确认；
  - macOS / Windows 真机，Windows MSIX 执行位置与 Defender 实测；
  - 第一个高级功能的 ADR；
  - 腾讯云 CDN 能否只对 `dl.tavotto.cn/pro/` 开鉴权、不影响更新通道（§五）；
  - macOS 上应用自己下载的可执行文件是否真的不带隔离属性（§六）；
  - 超时与空闲数值（§三 的 30 秒 / 10 分钟 / 连崩 3 次、§七 的 10 秒）是起步值，按真机实测再定。
