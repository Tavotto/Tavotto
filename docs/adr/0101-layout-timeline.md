# ADR 0101：排版时间线——顶栏一键打开、缩略图预览、命名节点永不清理、关键时刻自动打点

日期：2026-09-27 · 状态：**Accepted**（用户 2026-09-27 拍板「做出真正的排版时间线，要有命名」；
同日看过第一版后再反馈两处：命名要有单独的按钮、预览改成模态对话框，见 §8）
相关：[0001 项目 / 画布 / 标签 / 对象](0001-project-canvas-tab-object.md)（时间线属于排版）、
[0023 文档落盘的唯一权威](0023-document-persistence-authority.md)（缩略图也走 atomicio）、

## 问题

排版版本早就有后端（`/api/versions/<排版 id>`，存 `tavottofile/versions/`）和一个右侧抽屉，
但用户反馈「不知道有这个功能」：入口是排版菜单里的第六项；自动检查点 5 分钟才一个；
没有「这一版我要留着」的说法——手动版本只是比自动的晚被裁，体积一紧照样会被挤掉；
「恢复前」那一版存成普通自动检查点，恰恰是最先被裁的那一档；缩略图是草图，画的是
**当前**磁盘素材，两个图内布局完全不同的节点长得一样。

## 裁决摘要

| 问题 | 裁决 |
|---|---|
| 入口 | 顶栏保存状态旁一颗时钟钮（`RotateCcwClock`，与抽屉空态同一个语义图标）；⇧⌘H；命令面板「排版时间线…」；排版菜单那一项保留并标上 ⇧⌘H |
| 命名入口 | 时钟钮旁独立的书签钮（气泡带 ⌥⌘S）→ 小浮层：名字框 + 保存，回车保存、Esc 取消，**不用先开抽屉**；⌥⌘S 与命令面板开同一个浮层；抽屉里的输入框 + 按钮保留（§8） |
| 形态 | 右侧浮板抽屉（沿用），**不做成左栏抽屉**：左栏 280–360 装不下缩略图 + 两行元数据，且时间线属于整份排版而不是某个对象；画布保持可见 |
| 预览 | 行上的「预览」钮 = **模态**预览对话框（单击行只选中、露出本行的「预览」「改名」钮——真实双击先发 click，单击就开模态的话遮罩吞掉双击，Codex #679）（约 80% 视口）：左边那一刻的大图（可缩放 / 适配，面板按那一刻的 overrides 出图），可切「并排 / 叠加」与当前对比，右边差异列表；标题「预览：时间 名字」；底部「关闭」（默认焦点）与「恢复到这里」；画布在遮罩后面不动（§8） |
| 视图 | 抽屉顶部分段控件「全部 / 命名」（§8） |
| 节点类型 | `named`（用户起名）/ `moment`（关键时刻）/ `auto` / `manual`，判据只在后端 `_version_kind` |
| 命名 | 任何节点可命名 / 改名（双击行、行上的「改名」钮或 ⋯；真浏览器的双击由 `e2e/timeline-row-actions.spec.ts` 看护）；「删除名字」变回普通节点；「把现在存为命名节点」按钮 + ⌥⌘S + 命令面板；名字必须是用户起的（空名字不存） |
| 命名节点的清理 | **永不自动清理**：条数上限不数它、字节上限不删它 |
| 命名节点超过 24 MB | **拒绝再命名**（409 `named_budget_exceeded`，磁盘零改动），已有的一条不删；列表 `budget.namedOver` 让抽屉挂一条常驻提示请用户自己删；删名字 / 删节点永远放行 |
| 裁剪顺序 | 未命名的：普通自动 → 关键时刻 → 手动；最新一条不参与（原有性质） |
| 自动间隔 | 停顿 15 s 且距上一个节点 ≥ **2 分钟**（原 5 分钟）；`VERSION_KEEP_AUTO` 40 → 60 |
| 关键时刻 | 导出交付了文件、写回成功、⌘S 存完、打开项目、离开项目（回主页 / 切项目）、恢复前 |
| 缩略图 | 前端拍节点那一刻用 canvas 合成（renderStore 里带 overrides 的 SVG + 文字 / 形状近似），240 px 长边，webp（WKWebView 退回 png）；单独存 `versions/thumbs/<排版 id>/<vid>.<ext>`，**不进时间线 JSON**；随节点删除 / 裁剪；没有的退回草图 |
| 恢复 | 先存「恢复前」关键时刻节点（**存不下来就不恢复**），再一次 `commit`：⌘Z 一步退回；落点按节点的画布身份（R-03 四分支原样） |

## 1. 入口与快捷键

快捷键查过四处：现有 `useKeyboard`、`ShortcutHelp`、原生菜单 #663 的加速键表、方向键 #671。

- **⌥⌘H 不行**：macOS 应用菜单的「隐藏其他」（#663 的 `hide_others`）。
- **⇧⌘Y 不行**：`useKeyboard` 的 ⌘Y 重做分支不看 shift（`key.toLowerCase() === 'y'`），会被它吃掉；
  macOS 的系统服务「新建便笺」也是 ⇧⌘Y。
- **⇧⌘H**：四处都没占用。浏览器里 Chrome 的「主页」、Firefox 的历史侧栏可以 `preventDefault`。
- **⌥⌘S** 存为命名节点：按 `e.code === 'KeyS'` 判（⌥ 会把 macOS 的 `key` 变成 ß），而且**排在 ⌘S
  前面**——Windows 上 Ctrl+Alt+S 的 `key` 仍是 s，排在后面就落进「保存」。排在前面不等于
  ⌘S 那样的例外：焦点在输入框 / 对话框里时与其余快捷键同一条 `yieldsCanvasShortcuts` 让位（落空，
  不落进 ⌘S），`getModifierState('AltGraph')` 为真时也落空——Windows 把 AltGr 报成 Ctrl+Alt，
  波兰语 AltGr+S 是在打 ś（Codex #679）。看护
  `web/src/hooks/timelineShortcuts.test.tsx`（每条带反向对照：⇧⌘Y 仍是重做、⌘S 仍是保存）。

Esc 逐层退：先退预览，再关抽屉（抽屉自己的 onKeyDown 与全局 Esc 同一顺序）。

## 2. 命名节点与字节上限

「永不自动清理」与「24 MB 上限」冲突时有两个答案：A 允许文件无上界增长、只挂提示；
B 拒绝再命名。选 **B**：A 的文件越大，**每一次**自动节点的追加都越慢（整份读 → 追加 →
整写），用户看到的是编辑越来越卡而不是一条提示。B 下文件有上界（≈ 上限 + 一条），
命名节点一条都不删，超限时说清楚、给出口（删名字 / 删节点永远放行）。

- 条数上限 `VERSION_KEEP_TOTAL` 只数**未命名**节点；`VERSION_KEEP_AUTO` 只数普通自动节点。
- `_save_versions` 按 `_sacrifice_order` 裁到字节上限为止；命名节点不在牺牲顺序里，所以
  裁完仍超上限只可能是命名节点本身占满了——文件照写（不删），再命名时 409。
- 列表端点的 `budget`：文件本身没超上限时直接回 `namedOver: false`、**不带** `namedBytes`
  （「没量」不冒充 0）；超了才把命名节点序列化一遍量。理由是实测：24 MB、百来个命名节点
  时那一遍约 150 ms，而列表每打开一次抽屉就调一次。
- 旧条目（没有 `named` 字段）：手动的、名字不是默认时间串的认作命名节点——用户在旧抽屉里
  敲过名字的那一版，升级不能让它变得可以被裁。自动检查点（含旧的「恢复前」）不算。

## 3. 关键时刻

一处出口 `lib/timelineCheckpoint.markMoment()`，**只有时间线在跑（`startVersionCheckpoints`
挂上了）时才打点**——单元测试里那些成功路径不会因此多发请求。打点处：

| 时刻 | 位置 |
|---|---|
| 导出 | `exportStore.applyExportJob` 进终局且 `done` / `partial`（同一作业只进一次终局） |
| 写回 | `UpdateSourceButton` 的 `runWriteBack` 成功、`SyncOverridesButton` 写回成功 |
| 保存 | 「排版写进了文件」事件（`lib/layoutSaved.ts`）：保存侧 `emitLayoutSaved()`，时间线在 `startVersionCheckpoints` 里订阅。今天的两个发出点：`runManualSave` 得到 `saved` / `clean`（`local`）、另存为画布文件成功（`LayoutDialog`，`layout_file`）；#674 的「写回项目文件 / 存进项目」见 §7 |
| 打开项目 | `projectStore.adoptNow` 进 `phase: 'open'` 之后 |
| 离开项目 | `showPicker`（回主页，#661）；`adoptNow` 从一个开着的项目**直接**切到另一个 |
| 恢复前 | `restoreNode()`，**直接 await**，不经 markMoment（它必须成功，见 §5） |

关键时刻**不去重**（服务器也不）：「导出成功」那一刻内容没变也是一件发生过的事。打完点
重新计自动间隔，免得紧跟着再拍一个一样的自动节点。

**项目与图源在调用那一刻同步取走**：`takeCheckpoint` 在第一个 await 之前取好 pj、文档、
画布身份，并启动缩略图合成（它也在第一个 await 之前取完各面板的 SVG / 素材 URL）。
离开项目那一刻紧接着就是 `setCurrentProjectId` / `renderStore.clear()`——晚一步取，
节点落进下一个项目、缩略图画的是另一个项目的同名素材。看护
`timelineCheckpoint.test.ts` 的「节点属于拍的那一刻的项目」。

**快照**（Codex #679）：节点若在完成时现拍，拍的是**此刻**的文档，而导出 / 保存 / 写回都要 await——完成时
用户可能已经换了排版或项目，也可能在同一份里接着改。这三处在发起那一刻取 `captureMoment()`（时间线上下文 =
项目代际 + 排版 id、送出去的那份文档与画布身份、面板图源；`lib/timelineCheckpoint`），完成时经
`markMoment(moment, snapshot)`（保存经 `emitLayoutSaved(via, { moment })`，必填）带过来：上下文不再是此刻的就
丢掉这个点；是的话**拍快照里那份**（缩略图也用快照时取的图源），不拍之后的样子。documentStore 的文档不可变，
留住引用就是留住那一刻。不回头给原来那一份补点——那要另起一条绕开「当前」的拍节点路径。打开 / 离开是同步调用，
不带。三处都拿得到送出去的那份文档，所以没有「只能按编辑代次丢弃」的路径。

「保存」时刻为什么是事件而不是保存侧直接调 `markMoment('save')`：写排版文件的路不止一条、
还在变，而 #674 的「存进项目」分支提前 return，挂在 `runManualSave` 末尾的打点在那条路上
永远不执行（beta 集成时发现）。事件把依赖反过来——保存侧只说「写成了」，时间线自己订阅——
所以不依赖合并顺序：新增一条保存路径 = 在它的成功分支 emit 一次。时间线属于排版，不属于
某一次保存。

## 4. 自动间隔与实测

`scripts/bench_document.py`（本 PR 给它加了时间线三项）与满载实测，Apple M 系列本机，
中位数：

| 排版 | 单条节点 | 常态文件（60 条自动） | 追加一个自动节点 | 挂缩略图 | 列表 |
|---|---|---|---|---|---|
| 100 对象 | 23 KB | 1.4 MB | 10 ms | 10 ms | 17 ms |
| 300 对象 | 69 KB | 4.2 MB | 31 ms | 29 ms | 36 ms |
| 1000 对象 | 230 KB | 14 MB | 110 ms | 104 ms | 113 ms |
| 1000 对象，**满 24 MB**（命名节点占满） | 230 KB | 24 MB | 368 ms | 190 ms | 353 ms |

- 2 分钟一次、每次一条：常见排版（≤ 300 对象）单次追加 ≤ 31 ms，远低于 issue #221 的
  250 ms 阈值；1000 对象的常态 110 ms。
- 满 24 MB 那一行**不是本 ADR 引入的**：同一场景在 `origin/main` 上实测 360 ms / 列表 201 ms
  （字节上限的注释里「100 ms 量级」是按 20 条 1.16 MB 的大文档估的，条数多、单条小时解析
  开销更大）。本 ADR 让它更常见的只有「命名节点占满」这一种情形，而那时再命名会被拒。
  列表多出的约 150 ms 就是 §2 里只在超限时才做的那一遍命名节点序列化。
- 缩略图的 PUT **不重写时间线 JSON**（有没有缩略图 = 文件在不在）：第一版把 `thumb` 字段
  记进 JSON，1000 对象时挂一张图要 188 ms——每个节点付两次整写。改成只写图文件后 104 ms
  （剩下的是为了确认节点还在而读一遍时间线）。
- 文件增长：到 `VERSION_KEEP_AUTO` 之前每个自动节点 + 一条（= 排版大小）；缩略图另存，
  实测几 KB 到十几 KB 一张。

e2e 把间隔**注入**调小（`window.__TAVOTTO_TIMELINE_TIMING__ = { debounceMs, minGapMs }`，
只认正的有限数、下限 100 ms，形状不对当没给），产品默认值不动。

## 5. 预览、恢复与撤销

- 预览是 `useTimelineStore.preview`（排版 id + 节点元信息 + 正文），抽屉关掉 / 换项目
  （`resetForNewProject` 里 `clear()`）/ 恢复完成 / 对话框关闭都会清掉。它画在模态对话框
  `TimelinePreviewDialog` 里（§8），不是第二个画布：不挂命中层、不进 documentStore、不 commit。
- 恢复 `restoreNode()`：`finishActiveGesture()` → 画布身份四分支确认（R-03，原样）→ 要切
  画布先切 → **await 存「恢复前」关键时刻节点，失败就停**（状态条说清「没恢复」）→
  `restoreLayoutVersion` 一次 commit。
- **与撤销栈的衔接**（ADR 0024 的保存生命周期不变）：恢复是 documentStore 里的一条普通
  历史，⌘Z 一步退回恢复之前；它同时是一次编辑，照常把 `saveState` 推成 dirty、由自动保存
  落盘。「恢复前」节点是**另一条**退路：撤销栈随刷新 / 换排版消失，节点不会。两条互不替代，
  也互不依赖（撤销不删节点，恢复节点不动撤销栈）。
- 顺带修掉：`restoreLayoutVersion` 以前不恢复 `layoutGroups`——对象身上的 `groupId` 指向
  那一版的组，只换对象不换组，恢复出来的对象会挂在当前排版里不存在的组上。

## 6. 缩略图

- 合成在 `lib/timelineThumb.ts`：面板取 `panelRender(...)` 的 SVG（编辑器里看到的那份，带
  overrides），根元素补上像素宽高后 `drawImage`；没有 SVG 的面板退回素材图（`panelSrc`）；
  裁剪 / 90° 旋转 / 翻转 / 透明度照做（旋转与翻转和画布共用 `lib/panelTransform` 一份，Codex #679）；文字按页面字号画、形状画轮廓；箭头头部、虚线不画。
  任何一步失败（解码、taint、编码）→ 没有缩略图，节点照拍。
- 为什么不在后端出图：每个节点一轮 matplotlib，2 分钟一次付不起；为什么不塞进 JSON：
  base64 的图会让每条节点多几十 KB、每次整写都搬一遍。
- 存放 `versions/thumbs/<排版 id>/<vid>.<webp|png>`，写入 `atomicio.write_bytes`；
  `_sweep_version_thumbs` 在每次时间线写入与每次挂图时按目录扫、删掉不属于任何留下来的
  节点的图（只认 `_VERSION_ID_RE` 的名字，别的文件不碰）——进程死在「JSON 写完、删图之前」
  留下的孤儿图，下一次写入顺手清掉。
- 真浏览器两条腿（chromium + webkit）都量过：缩略图挂得上，而且真的画进了面板（深色像素
  计数，不是白纸），`e2e/layout-timeline.spec.ts`。

- **#663 原生菜单**（未合入）：菜单栏该加两项，id 与前端动作一一对应——「显示」菜单
  `menu-timeline`「排版时间线」加速键 `CmdOrCtrl+Shift+H` → `toggleTimeline()`；「文件」菜单
  `menu-save-named`「把现在存为命名节点…」加速键 `CmdOrCtrl+Alt+S` → `startNamedNode()`；
  两份 i18n（`src-tauri/src/i18n.rs`）与 `menuActions.ts` 的分派表各加一行。
- **#674 ⌘S 保存到项目**（已合入 d85792de8，本 PR rebase 时落实）：三处写入成功点各发一次
  「排版写成了」，**写成之后立刻发、在任何后续步骤（记账、关对话框、状态条）之前**——后续步骤
  出错也不能吞掉这个点（Codex #679）：
  1. `store/projectSave.ts` 的 `writeOnce()`（⌘S 写回已绑定的项目文件）：`await saveLayout(...)`
     一返回 → `emitLayoutSaved('project_file', { moment })`，`moment` 在 `buildProject()` 那一刻取（排队之后才序列化，写出去的是那一份）；
  2. `components/LayoutDialog.tsx` 的 `doSave`（另存为 / 第一次存进项目）：同样紧跟 `saveLayout` →
     `emitLayoutSaved(toProject ? 'project_file' : 'layout_file', { moment: ctx.moment })`；
  3. `store/actions.ts` 的 `runManualSave()` 本机那一支（没开项目）：`emitLayoutSaved('local', { moment: ctx.moment })`。
     发不发看 `saveNowWithResult().wrote`（按下那一刻的内容写没写成），不看写完之后的实时 `saveState`——
     写的途中又改过的话状态照实是 dirty，内容却已经在盘上（Codex #679）。
  `ctx.moment` 是 #674 入口 `captureSaveContext()` **同一次捕获**里取的时间线快照，不另算一份。
  两者维度不同、各管各的：保存上下文（载入代次 / pj / 绑定文件）判「还要不要继续写、弹框」；时间线上下文
  （项目代际 + 排版 id）判「这一刻属于谁的时间线」——同一份排版被重新载入或改绑文件之后，节点仍属于它。
  beta 侧在 `writeBoundProjectFile` 里直接加的 `markMoment('save')` 要删掉，否则同一次保存打两个点。
- **#661 回主页按钮**（未合入）：它复用 `showPicker`，离开时刻自动就有。
- **#668 术语检查**：本 PR 新增与改写的时间线文案只用「项目 / 排版 / 画布 / 项目包」。

## 已知的近似与没做的

- 缩略图是近似（§6）；预览大图面板按 overrides 出不来时标「近似预览」（原有逻辑）。
- 「命名节点置顶」做成抽屉顶部「全部 / 命名」两个视图 + 行内书签与加重，而不是在「全部」里把
  命名节点从时间顺序里抽出来放最上面：时间线的顺序本身是信息，抽走一部分会让「这个名字前后
  发生了什么」看不出来。
- 画布的 `style` / `profile` 绑定（ADR 0081）不随恢复回退：它们是画布级设置，恢复的是内容。

## 8. 用户 2026-09-27 反馈后的两处改动

用户看过第一版（#679 第一次推送）后，接受「恢复不回退样式绑定」「缩略图是近似」，改两处：

1. **命名要有单独的按钮**。第一版的命名入口在抽屉里（输入框 + 按钮）与 ⌥⌘S（打开抽屉、
   焦点进名字框），用户要的是一步到位：
   - 顶栏时钟钮旁一颗书签钮（`Bookmark`，气泡说「存为命名节点 ⌥⌘S」），点开一个小浮层：
     名字框 + 「保存」，回车保存、Esc 取消。浮层开关是 `timelineStore.namingOpen`，书签钮、
     ⌥⌘S、命令面板共用这一个开关——**⌥⌘S 不再打开抽屉**。存失败（例如命名节点超出上限的
     409）那句话留在浮层里、名字不丢，浮层不关。
   - 「存为命名节点」的动作本体只有 `lib/timelineCheckpoint.saveNamedNode()` 一份，浮层与
     抽屉里保留的输入框共用。
   - 抽屉顶部「只看命名」开关改成分段控件「全部 / 命名」：命名节点是一个独立的视图，不是
     一个过滤条件。
2. **预览不要盖在画布上**。盖在画布上的只读层让用户「分不清自己是不是在改真东西」。改成模态
   对话框（`Dialog chrome="shell"`，宽约 80% 视口、高 80vh）：
   - 左边那一刻的大图，缩放 50%–300%（相对「适配」），「适配」一键回来；
   - 「与当前对比」沿用第一版删掉的那套能力并扩成两种：**并排**（那一刻 | 当前，两格画框）与
     **叠加**（底图 = 那一刻，半透明描边 = 当前）。「当前」取**节点所属画布**的当前内容（R-03）；
   - 右边是差异列表（第一版在抽屉的展开行里）；
   - 标题「预览：<时间> <名字>」；底部「关闭」与「恢复到这里」（主按钮）。**默认焦点在「关闭」**：
     为此给 `ui/Dialog` 加了 `initialFocusRef`（默认仍落在容器上，只给「默认动作必须安全」的
     对话框用）；
   - 恢复流程不变（§5）。

看护：`VersionDialog.test.tsx`（浮层存 / 存失败不关、「命名」视图、对话框不改排版、默认焦点、
并排两格各画各的、叠加有当前描边、差异列表、关闭）、`timelineShortcuts.test.tsx`（⌥⌘S 开浮层
不开抽屉）、`CommandPalette.test.tsx`、`e2e/layout-timeline.spec.ts`（顶栏钮命名 → 「命名」视图 →
预览对话框里画布未动、默认焦点、并排 → 对话框里恢复），每条新判据各反证一次。反证时抓到一条
空判据：并排用例第一版按整个对话框的文字判「当前那一格有现在这一段」，而差异列表里也写着
这段文字——拿掉「当前」那一格照样绿；改成判两格画框各自的内容。

### 顶栏在窄宽度下不重叠（#677 集成时发现，同日）

时间线的两颗钮（时钟 / 书签）加在顶栏左段之后，600 宽下左段内容（品牌 + 项目 + 文档名 + 两颗钮）
溢出到中间的工具组上；右段（缩放 + 适应画布 + 写回 + 导出 + 更多）本来就溢出到中间。断点定在
**900**（与保存状态文字原有的断点同一个），窄于它：

- 保存状态的文字收成一个状态点（文字留给读屏与悬停气泡）；
- 品牌只留标志；文档名按钮可收缩（与旁边的项目按钮同一副：`min-w-0 shrink` + 截断）；
- 「标注」「写回」「导出」只留图标，文字进 `sr-only`——可达名不变，e2e 里按名字找它们的用例照旧；
- 「适应画布」图标钮收起（缩放菜单里有同一条，⌘1 也在）。

看护 `e2e/topbar-narrow.spec.ts`：600 / 780 / 920 / 1024 四档宽度下，顶栏里所有可见按钮与保存状态
按画出来的盒子两两求交、不许出视口；chromium 与 webkit 两腿都跑（字宽不同）。反证：文档名按钮
去掉收缩 → 「存为命名节点 ∩ 撤销」；适应画布不收 → 「添加序号标签 ∩ 缩放」，都红。

**修订（2026-10-01，#770）**：上面这一节按旧顶栏写，原文保留作历史。界面重设计（设计稿 A1 / C11）之后，
其中点名的几样已不在顶栏：画布工具（选择 / 文字 / 标注 ▾ / 序号）与「适应」图标钮搬进画布底部的
浮动工具条（`CanvasToolbar`，窄于 900 同样只留图标）；缩放菜单搬进画布标签行最右；「写回」搬进「⋯」
菜单第一项。所以「适应画布图标钮收起」「标注 / 写回只留图标」两条现在分别是：适应钮不再收起（任何
宽度都在浮动工具条里）、写回没有顶栏按钮；上面反证里的「添加序号标签 ∩ 缩放」也不再可能发生。
§8 的 900 断点规则现在只管顶栏里剩下的元素（保存状态点、品牌标、文档名收缩、导出只留图标），
`e2e/topbar-narrow.spec.ts` 照旧守它；浮动工具条在各宽度下不出画布、不压选中浮动栏由
`e2e/canvas-toolbar.spec.ts` 守。
