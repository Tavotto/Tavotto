# 多语言（zh-CN / en-US）

界面支持**简体中文**与**英文**两档。默认仍是简体中文——老用户升级上来看到的
界面一个字都没变。

本文只写「为什么这么定」和「改动时要同步哪里」。具体 API 看
`web/src/i18n/index.ts` 的注释，检查规则看 `web/scripts/i18n-check.mjs`。

---

## 一句话版

- 组件里用 `useTranslation()`；store / lib 用 `import { t } from '@/i18n'`。
- 活得比一次渲染长的文本（撤销标签、toast、确认框）存**描述符**
  `{ key, ns?, values? }`，显示那一刻才翻。
- 用户自己的内容（项目名、画布名、文件名、脚本、图内文字、matplotlib 输出）
  **永远不翻**。
- 加了新文案就跑 `pnpm i18n:check`；它在 CI 里是硬门禁，缺翻译直接红。

---

## 语言怎么定

优先级：**用户手动选择 > 系统语言 > zh-CN**（`web/src/i18n/locale.ts` 的
`detectLocale`）。

- 手动选择存在 **`magplot.locale`** 这一个独立的 localStorage 键里。
  **不进 `.magplot` 文档、不进项目数据**：它是这台机器上这个人的偏好，跟着
  文档走会让同一份排版在别人机器上换语言。
- 规范化只看主子标签：`zh` / `zh-CN` / `zh-Hans` / `zh-TW` 全部 → `zh-CN`，
  所有 `en-*` → `en-US`，其余认不出（`null`）交给调用方兜底。繁体暂时也落到
  简体——中文界面比英文界面离它更近。
- 切换语言**不需要刷新**：`setLocale` 换 i18next 实例的语言，react-i18next
  订阅了 `languageChanged`，界面 / toast / tooltip / 无障碍名一起变。

## 资源与打包

- 八个命名空间：`common` `workspace` `project` `inspector` `dialogs`
  `errors` `ai` `shortcuts`，默认 `common`。
- **翻译资源静态 import 进 bundle**（`web/src/i18n/index.ts`），不走
  http-backend、不连 CDN。桌面版离线可用是硬要求，动态拉取会让断网时的第一屏
  是一串裸 key。
- key 一律语义化（`project.actions.create`），**不拿中文当 key**。唯一例外是
  `inspector:enum.<属性>.<取值>` 的最后一段——那是 matplotlib 自己的取值
  字面量（`->`、`*`、`upper left`），它就是 key 的一部分。

## 描述符：`UiMessage`

```ts
type UiMessage = { key: string; ns?: Namespace; values?: Record<string, unknown> }
```

撤销栈、状态 toast、确认框存的是**描述符**，不是翻好的字符串。理由：这些东西
活得比一次渲染长。存成「删除 3 个对象」之后用户切到英文，历史面板里还是中文，
而且再也换不回来了（原始参数已经被拼进字符串）。

用户自己的内容包成 `literal(text)`（`common:literal` = `{{text}}`），
让「历史条目一律是描述符」这条不变式成立，同时保证内容原样透出。

**这是运行时状态，绝不写进 `.magplot`**——文档 schema 一个字节没动。

## 复数

i18next 的复数是 key 后缀，**哪些后缀有意义由语言决定**：英文要
`_one` + `_other`，中文只有 `_other`（`Intl.PluralRules('zh-CN')` 只给一档）。

中文里写个 `_one` 不报错——它只是永远命中不了，那句译文是死的，评审时看着
还挺齐整。检查脚本与 `src/i18n/resources.test.ts` 都按 `Intl.PluralRules`
逐语言核对形态，多了少了都红。

**「单数是另一句话」的必须自己分 key**，别指望复数规则：

```ts
ids.length === 1 ? hist('deleteObject', { name }) : hist('deleteObjects', { count: ids.length })
```

写成 `deleteObjects_one = '删除 {{name}}'` 的话，中文用户删一个对象看到的是
「删除 1 个对象」——文件名没了。目前这样分 key 的有四对：
`history.deleteObject(s)`、`history.moveObject(s)`、`status.objectCopied` /
`objectsCopied`、`inspector:element.scaleAxes` / `scaleAxesMulti`。

## 什么不翻

- **用户自己的内容**：项目名、画布名、文档名、文件名、路径、脚本、图内文字、
  坐标轴标签、matplotlib 的输出。
- **诊断材料**：traceback、日志、后端报错原文、控制台输出。它们要贴进 issue，
  翻过一道就对不上日志了。
- **matplotlib 的属性名与取值**：`propLabel` / `optionLabel` 查不到翻译时
  `defaultValue` 回退成原始的 prop 名 / 枚举值。这是**开集**——脚本里能出现
  什么属性我们说了不算，回退到原文比显示一个空标签有用。

## 引擎协议里的中文

worker 的 manifest 里 `group` / `label` 是中文字符串（`engine/manifest.py`
发的，如 `子图 1`、`曲线 “v”`）。**没有改协议**，而是在前端翻：
`web/src/components/inspector/roles/registry.ts` 的 `ENGINE_GROUP` 表 +
`ENGINE_LABEL_PATTERNS` 正则，把结构部分换成当前语言，用户内容（引号里的
那截）原样带过去。

`GROUP_ORDER` 仍然按**引擎名**排序：分区顺序不该跟着界面语言变。

## 后端错误

**Python 不决定界面语言**，它也没有线索——偏好存在浏览器/桌面壳这一侧。

约定（写在 `src/magplot/app.py` 的 API 段首）：用户会看到的失败一律带
**稳定 `code` + `params`**，前端 `backendErrorText()` 按 code 查
`errors:backend.<code>` 并插参数；`error` 字段保留人可读的中文原文，作为
① 老前端与 curl 调试的回退，② 前端还不认识这个 code 时的兜底。

**code 一旦发布就不能改名**——改了等于让装着旧前端的用户看到一串裸 key。

只在请求本身畸形时才出现的校验错误（`patches 必须是数组` 这类）不给 code：
用户点不出来，给了也没人翻。

两侧看护：`tests/test_error_codes.py`（后端真发了 code、两种语言都有文案、
占位符与 params 对得上）+ `web/src/lib/backendError.test.ts`（选择逻辑）。

## 出版规范预检与 MCP 画布

预检（`web/src/lib/preflight.ts`）的规则来自 `publication.json`，**求值器有两个**：
TS 这一份服务画布与导出对话框，`engine/preflight.py` 那一份服务 Codex 的 MCP
server。两边跑同一份 golden vectors，但 `preflight.golden.test.ts` 明确写着
**只比判据、不比措辞**——所以：

- `PreflightIssue` 存的是描述符 `message: UiMessage`，`id` 才是稳定身份。
  golden vectors 与 proof report 认的都是 id；措辞怎么改都不动判据。
- proof report 的 `checks[].text` 写的是**导出那一刻界面语言的成文**（那份 JSON
  是给人读的、要随投稿留档），机器可读的部分是同一条里的 `id` / `severity` /
  `detail`。
- **MCP 画布（`web/src/mcp/McpApp.tsx`）里的预检条目不翻**：那份 payload 是
  Python 求值器经 `magplot_preflight` 返回的，Codex 那一侧不知道这个 webview
  用的是哪门语言。widget 自己的按钮、状态、标题照常走 `dialogs:mcp.*`。
  要让它也跟着界面语言，得让 Python 侧把「id + params」而不是成文发上来——
  已知的下一步，见本文末的「已知限制」。
- 发给 Codex 的对话内容（`bridge.sendMessage(...)`）同样不按界面语言改写：
  它进的是聊天记录，语言该跟着那边的对话走。

## 桌面壳

原生菜单由 Rust 在 webview 起来**之前**建（macOS 的菜单栏一直在那儿），那时
既没有 i18next 也没有页面。所以壳自己带一份文案：`src-tauri/src/i18n.rs`。

- **改菜单文案要改两处**：`src-tauri/src/i18n.rs` 与
  `web/src/i18n/locales/`。撤销 / 重做 / 导出这几条两侧必须说同一个词，
  `tests/test_desktop_i18n.py` 看护。
- 语言从哪来：上次前端报上来的那个，落在应用配置目录的 `menu-locale` 文件里；
  读不到就 zh-CN。前端在 i18n 就绪时与每次切语言时 invoke `set_menu_locale`，
  Rust 重建菜单并写回文件。
- **切语言只换显示文案**：菜单项 id（`magplot:menu` 转发的那个）与
  `CmdOrCtrl+*` 加速键一个字节不动。切成英文之后 ⌘Z 失灵的话，用户根本不会
  往语言上联想。
- `splash.html` / `error.html` 在 `tauri://` 源下，读不到 sidecar 那个源的
  localStorage，也没有 i18next——两份文案**内联在页面里**，语言由壳经
  `?lang=` 带过去，拿不到再退回 `navigator.language`。失败页尤其不能只有
  中文：用户看到它的时候正需要看懂上面写了什么。
- 新增 `#[tauri::command]` 仍要**三处同步**（build.rs / capabilities /
  generate_handler），漏了 invoke 会被静默拒绝。

### 已知限制

**MCP 画布的预检条目只有中文**：文案由 `engine/preflight.py` 生成。要修就得让
Python 侧改发 `id + params`（`detail` 里已经有全部数字），前端按 id 查
`errors:preflight.*`。挡在前面的是「同一个 id 有两种措辞」的几条
（`font-too-small` 面板版 / 画布文字版），得先给它们各自的 key。

**装完第一次打开**时，配置目录里还没有 `menu-locale`，原生菜单与启动画面按
默认档（zh-CN）呈现；前端起来后立刻重建成用户的语言。之后每次启动第一屏
就是对的。要在首启也对，需要壳去读系统语言（另加依赖）或读 sidecar 的配置
（把启动顺序倒过来），两条都比这个问题本身贵。

## 维护：加了新文案怎么办

```bash
cd web
pnpm i18n:extract   # 扫源码，把新 key 写进两份 JSON（英文留空待填）
pnpm i18n:status    # 看每种语言的完成度
pnpm i18n:types     # 重出 src/i18n/resources.d.ts
pnpm i18n:check     # 上面这些的门禁版；CI 跑的就是它
```

`pnpm i18n:check` = `i18next-cli types --ci` + `scripts/i18n-check.mjs` +
`i18next-cli lint`，查这些：

| 项 | 说明 |
|---|---|
| key 对齐 | 两种语言的 key 集合一致（按去掉复数后缀的基名比） |
| 漏翻 / 多余 | 一侧有另一侧没有 |
| 空翻译 | 空串等于没翻，界面上是个空按钮 |
| 插值一致 | 同一条 key 的 `{{变量}}` 两边必须相同 |
| 复数形态 | 按 `Intl.PluralRules` 逐语言核对，多了少了都红 |
| 用不到的 key | 资源里有、代码里找不到引用 |
| 硬编码文案 | 源码里的中文字面量（`i18next-cli lint`） |
| 类型过期 | `resources.d.ts` 没跟着 JSON 更新 |

### 为什么要自己写一个 `i18n-check.mjs`

官方 CLI 的静态提取只认 `t('a.b')` 这种字面量调用。本仓库为了少写重复前缀，
每个模块都有短助手：

```ts
const hist = (key: string, values?) => msg(`history.${key}`, values, 'workspace')
const cv   = (key: string, values?) => translate(`canvas.${key}`, { ns: 'inspector', ...values })
```

于是 `hist('setPageW')` 在官方提取器眼里什么也不是。降低检查范围（比如只扫
字面量调用）等于让门禁形同虚设，所以补了这个脚本：它认得三种助手声明形态、
`msg` / `nsMsg` / `t` / `translate`，模板串（`t(\`prop.${p}\`)`）按**前缀**
覆盖整组 key。

`i18next-cli extract --ci` 没有当成门禁：它把模板串按 key 的并集展开，会要求
一堆并不存在的组合。`types --ci` 与 `lint` 仍然照用。

### CI 接在哪

- `.github/workflows/ci.yml` 的 `frontend` job：
  `pnpm lint` → `pnpm i18n:check` → `pnpm test` → `pnpm build`。
- `scripts/build_frontend.py` 在 `pnpm build` 之前跑一次 `pnpm i18n:check`。
  **每一条把前端打进产物的路径都经过这个脚本**（release / nightly /
  desktop-tauri / 本地 `python -m build`），挂在那儿就没有哪条发布链能绕过去。
- `pnpm e2e` 里的 `e2e/i18n.spec.ts` 中英文各走一遍完整流程。

## 排版

英文比中文长。两层看护：

- `web/src/i18n/overflow.test.tsx`：紧位置（顶栏按钮、标签页、对话框按钮、
  左侧轨道）的英文**字数预算**，以及「宽度受限且不换行的文本都带截断」。
  预算是回归闸门不是审美标准——真需要更长的词就连同截图一起改上去。
- `e2e/i18n.spec.ts`：真浏览器里在 1024px（断点下限）量
  `scrollWidth > clientWidth`。jsdom 没有布局引擎，这一半只能在这儿测。

已经因此改过一处：右栏标签行原来是「三个标签页 + 带文字的常驻开关 + 关闭
按钮」，英文下要 321px 而面板宽度是 296–320px 定死的，关闭按钮被顶到面板
外面。现在图钉开关改成纯图标（状态靠填色 + `aria-pressed`，说明在 tooltip 与
无障碍名里）。
