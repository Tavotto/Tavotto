# 渐进式编辑：志愿者任务测试执行单

> 状态：执行单（P06）。**还没有跑过任何一场**——本文里的阈值、清单项都是实验前设定，不是结果。
> 范围：Tavotto 的「默认直接编辑 + 按需进入排版」这条路径，对新手与论文作者是否讲得通。
> 性质：定性任务测试，10–20 位志愿者。**小样本只给方向性判断，不宣称统计显著。**

## 1. 要回答的问题

1. 第一次打开的人，能不能在没有人提示的情况下，把一张图渲染出来、改一处、导出？
2. 「输出尺寸」是不是被理解为「这张图最终会是多大」，而不是一个要背的术语？
3. 需要排多张图的人（论文组合），能不能自己找到排版，并且来回切换时不担心「图被改了」？
4. 按出版规范导出之后，还要不要回头返工？

不回答的问题：哪种界面「更好看」、功能偏好排序、性能。

## 2. 志愿者与分层

- 10–20 位。至少各 4 位：**普通编辑组**（偶尔改图，不排版）与**论文组合组**（要把多张图排成一页投稿）；余下按报名顺序补。
- 至少 3 位是第一次听说 Tavotto 的人。用过 Origin / Illustrator / matplotlib 的不排除，但在记录表里标明。
- 同一人只参加一场；不做同一人的前后对比。
- 自愿、可随时停止；不给与结果挂钩的奖励。

## 3. 条件与对照

- **当前没有可切换的实验分支**：直接编辑与排版是同一个产品里的两条工作流（见 `docs/rules/frontend/workflows-and-original-spec.md`），没有「旧流程」可回退。因此**本轮不做对照组**，只做单臂观察，对照的是第 5 节的实验前阈值，不是另一组人。
- 如果以后有可开关的构建，再把「默认直接编辑 + 按需进入排版」与对照构建各分一半（随机分配），并在本文增补一节；本文不预设对照结论。
- 每场用**同一个构建**（记录版本号与平台），同一份随附示例项目，不让志愿者运行自己的脚本。

## 4. 任务卡

主持人只念任务卡，不解释界面、不暗示按钮位置。志愿者卡住 90 秒后，按「提示阶梯」给一次提示，并在记录表里记提示等级。

### 提示阶梯

| 等级 | 内容 |
|---|---|
| 0 | 无提示 |
| 1 | 重读任务卡 |
| 2 | 说出区域（「看看左边 / 右边 / 上边」），不指具体控件 |
| 3 | 指出具体控件 |
| 4 | 主持人代为操作（该任务记为未完成） |

**无提示完成** = 提示等级为 0。

### 普通编辑（所有人做）

| 卡 | 任务（念给志愿者） | 成功判据（主持人看，不念） |
|---|---|---|
| E1 | 「这里有一个示例项目，请让其中一张图显示出来。」 | 图在画布上渲染出来 |
| E2 | 「请把这张图的标题改大一些（或改成你想要的文字），再把改动撤销，再恢复。」 | 标题确实变了；撤销与恢复各发生一次 |
| E3 | 「请把这张图导出成一个可以发给导师的文件。」 | 磁盘上出现导出文件；志愿者能说出文件在哪 |
| E4 | 「你觉得这个文件大约会有多大（宽高）？这个大小是哪里来的？」 | 记录原话；是否提到「原图尺寸 / 期刊要求 / 画布」等（见第 5 节理解度） |

### 论文组合排版（论文组合组做；普通组选做 P1）

| 卡 | 任务 | 成功判据 |
|---|---|---|
| P1 | 「你想把两张图并排放在一页里，请试试。」 | 进入排版，页面上有两张图，对象数正确 |
| P2 | 「让两张图的左边对齐。」 | 左边缘对齐 |
| P3 | 「期刊要求单栏图宽度，请按这个要求设置并检查有没有问题。」（给出规范名称与宽度数值） | 选了规范 / 页面宽度；打开了导出前检查摘要 |
| P4 | 「请导出，然后回去再改其中一张图里的标题，再回到排版。」 | 导出完成；回到排版后两张图位置未变 |
| P5 | 「如果导出的结果有你觉得不对的地方，请告诉我，并试着改好。」 | 记录是否发生**出版后返工**（导出后又回去改并重导） |

## 5. 观察指标与实验前阈值

阈值在第一场之前冻结，**事后不许改**；改了要在报告里单列「阈值被修改」及原因。数值是对小样本的方向性判据，不是统计检验。

| # | 指标 | 怎么记 | 通过线（方向性） | 警示线 |
|---|---|---|---|---|
| M1 | 首次成功出图耗时 | 从任务 E1 念完到图渲染出来（秒，主持人秒表） | 中位数 ≤ 60 s | 中位数 > 120 s，或 ≥ 3 人 > 180 s |
| M2 | 首次修改与导出耗时 | 从 E2 念完到 E3 导出文件出现 | 中位数 ≤ 180 s | 中位数 > 300 s |
| M3 | 无提示完成率 | 各任务提示等级 0 的人数 / 参加人数 | E1、E2、E3 每项 ≥ 80% | 任一项 < 60% |
| M4 | 错误导出数 | 导出了但内容 / 尺寸 / 位置不是志愿者想要的次数（每人） | 平均 ≤ 0.5 | 平均 ≥ 1.5，或 ≥ 3 人至少 2 次 |
| M5 | 往返排版次数 | 快速编辑 ↔ 排版切换次数（观察 + 事后问「你知道自己在哪个模式吗」） | 论文组合组 P4 之后无人表示「担心图被改了」 | ≥ 3 人表示担心或迷路 |
| M6 | 出版后返工次数 | P5 中导出后又回去改并重导的次数 | 平均 ≤ 1 | 平均 ≥ 2 |
| M7 | 对「输出尺寸」的理解 | E4 原话编码：A 正确（原图尺寸 / 规范要求）；B 模糊（「差不多」「不知道」）；C 错误（以为是屏幕大小等） | A ≥ 60%，C ≤ 10% | C ≥ 25% |

结果判读规则（实验前定）：

- 全部指标在通过线以内 → 「方向正确，值得继续」。
- 任一指标触及警示线 → 「该处需要改，改后再测小样本」，不得写成「失败 / 成功已证实」。
- 其余情形 → 「无明确方向，保留」。
- 样本 ≤ 20，**所有百分比都附原始人数**（如 7/10），不报置信区间、不报 p 值。

## 6. 场次流程（每场 25–30 分钟）

1. 说明（2 分钟）：测试的是产品不是你；可随时停；不录制屏幕、不收文件。
2. 同意（1 分钟）：口头同意并在记录表勾选。
3. 背景问卷（2 分钟）：三问——用过哪些作图工具；每周改图频率；是否投稿过论文。
4. 任务（15–20 分钟）：E1–E4；论文组合组再做 P1–P5。
5. 收尾（3 分钟）：两个开放问题——「最卡的地方是哪里？」「你以为会发生什么，实际发生了什么？」。
6. 主持人在 5 分钟内补全记录表。

## 8. 隐私与数据边界

- 只收**手工观察表**里的内容：场次编号、任务时间、提示等级、计数、志愿者的**口头原话摘录**。
- **不收**：文件名、路径、脚本内容、图像内容、屏幕录像、截图、姓名、联系方式（报名联系方式由招募渠道自己保管，不与观察表放一起）。
- 志愿者用的是 Tavotto 随附的示例项目；不让他们打开自己的项目、不运行自己的脚本。
- **不扩遥测**：不为这次测试新增任何事件或属性，也不要求志愿者开启诊断上传。产品里已有的匿名用量统计按其自己的同意设置，不作为本研究的数据来源。
- 观察表只存在主持人的本地设备上，报告里只出现汇总与匿名化原话。研究结束后按志愿者要求删除其场次记录。

## 10. 报告写法

- 先写方向性结论，再给原始计数；不写「显著」「证明」。
- 每个警示线触发项写：现象（志愿者原话）、可能原因、建议改动、改后是否再测。
- 明确列出「本轮没测到的」：真机、embedded 宿主、窄窗口、非中英文语言。
