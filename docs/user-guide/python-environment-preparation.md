# 运行前的「准备」：Tavotto 怎么处理脚本要用的库

这篇写给不懂 Python 的科研用户。你不需要知道「环境」「包」是什么就能用 Tavotto；这里只解释：你在右下角看到的那张小卡片在说什么、什么时候要你点一下、为什么有时候它说「还没法确定」。

先说三个词：

* **库（包）**：别人写好的程序，你的脚本用 `import` 引进来用，比如画图用的 `matplotlib`、读 Word 用的 `python-docx`。脚本里没有它，就跑不起来。
* **Python 环境**：一套装好了 Python 和一批库的地方。你电脑上可能有好几套：Tavotto 自带的一套、你项目文件夹里自己建的一套（文件夹常叫 `.venv`，是「虚拟环境」的缩写）、Anaconda 里的几套。
* **安装**：把缺的库下载下来放进某一套环境里。

## 一、打开项目的时候，Tavotto 做了什么、没做什么

打开项目后，Tavotto 会**读一遍你的脚本文件**，看它们引用了哪些库、哪些是你自己写的文件（比如同目录下的 `utils.py`）。这一步**只读文件，不运行你的脚本，不启动任何 Python，不联网，不装任何东西**。

读完之后，右下角会出现一张卡片：一句话，加至多一个主按钮。更多说明收在「详情」里，默认折起来。

你自己写的 `utils.py` 这类文件，Tavotto 认得出它是「你的文件」，**永远不会**去网上找一个叫 `utils` 的包来装。

## 二、卡片上的五种状态

| 卡片上的话 | 意思 | 你要做的 |
| --- | --- | --- |
| **可以运行了** | 脚本要用的库都有，可以直接跑 | 点「运行」 |
| **用项目里自带的那套运行？** | 你的项目文件夹里有一套自己的 Python 环境，而且它已经装齐了脚本要的库；用它就不必另外安装 | 点「用它」。想用别的，在 设置 → 项目 →「Python 解释器」里更换 |
| **要先安装缺少的组件** | 缺的库是 Tavotto 认识、也信得过的（比如 `docx` 对应 `python-docx`） | 看一眼卡片上那一行「装什么 · 装到哪」（比如「python-docx · 装到 Tavotto 目录」），点「安装」 |
| **有 N 个库要你确认包名** | 脚本用了一个 Tavotto 不认识的库，它**不会自己猜**该装哪个包 | 点「确认包名」，核对（或改）输入框里的名字，再确认 |
| **有 N 个库的来源还没法确定** | Tavotto 查不清这个库是从哪来的，所以**不动它** | 展开「详情」看原因；可以点「仍然运行」，或改用你自己的 Python 环境 |

默认情况下，运行脚本时 Tavotto 会自己检查并用上**能跑的那一套**环境（优先你项目里自带的），不会反复问你「用哪套」。只有在它需要你拿主意的时候，卡片才会问。

## 三、「安装」到底装到了哪里

点「安装」之后，库会装进 **Tavotto 为这个项目单独准备的一套环境**里。它和下面这些**互不影响**：

* Tavotto 软件自带的那套 Python——**永远不会被改动**；
* 你自己电脑上的 Python、Anaconda——不会被改动；
* 你项目里自己的 `.venv`——不会被改动（除非你明确选了装进去，那时卡片上那一行会写「装到你电脑上已有的那套」，并说明装坏了不能完整回滚）。

安装前，卡片上那一行会写清**装什么、装到哪**。你点的「安装」就是对这件事的授权：它装的就是你看到的那些，装不一样的东西会被拦下，要你重新确认。

装完后 Tavotto 会再检查一遍：库真的装上了、脚本要用的东西能用、绘图功能没坏。**检查没过，这套新环境不会启用**，原来的还是原来的。

> 例外：如果你明确选了「装到你电脑上已有的那套」（比如项目里的 `.venv`），安装是直接在那套环境里进行的，没有「新环境」可以不启用。检查没过时，pip 可能已经改动了那套环境，装进去的包也可能已经能被导入；Tavotto 会如实告诉你「可能已发生部分修改」，但不能把它完整恢复原样。

## 四、什么时候要你「确认包名」

有些库的名字，Tavotto 没法替你定。比如脚本里写了 `import mystery_lib`，但 `mystery_lib` 不在 Tavotto 认识的名单里：它可能是网上某个包，也可能是你实验室内部的库，甚至只是个拼错的名字。

这时 Tavotto 的做法是：

1. **不猜、不自动装。**
2. 卡片说「有 N 个库要你确认包名」。
3. 你点「确认包名」，会看到每个库一个输入框，里面预先填了一个**建议的名字**（通常就是库名本身）。**这只是个建议，不是 Tavotto 核实过的**：你可以改成你确定的包名，也可以加版本，比如 `lab-tools>=2.1`。
4. 点「核对包名」，进入确认页。页面会明白地写：**这几个包是你指定的，未经可信来源核实；确认后才会安装。** 每个包旁边有「用户指定，未经核实」的标记。
5. 你点「确认并安装」才会真的安装。

装完以后 Tavotto 会再核对一次：**你确认的这个包，真的提供了脚本要用的库吗？** 如果你填错了包名——比如装上的包里根本没有脚本要的库，或者脚本要的库是顺带被别的包拉进来的——核对会失败，框里会说「装完后核对发现，装上的包和你确认的计划不一致」，详情里写「包名可能填错了」。这时（装在 Tavotto 为你准备的环境里时）**不会启用**这次装的东西，你可以返回去改名字再试，输入框里的内容还在。如果你选的是装进自己已有的环境（比如项目 `.venv`），装错的包可能已经留在那套环境里、也能被导入，Tavotto 会提示「可能已发生部分修改」，需要时请自己用 pip 卸掉。

> 一个小提示：如果同一个脚本既缺 Tavotto 认识的库、又有要你确认包名的库，会分两步：先装认识的（一次「安装」），装完后再出现「确认包名」。两种信任程度不同，所以分开问。

## 五、为什么有时候说「还没法确定」

「还没法确定」表示：Tavotto 看到脚本用了一个库，但**没有可靠的依据**说它该怎么装，所以选择不装、也不替你猜。常见的原因（都写在卡片「详情」里，每条一句话）：

* **暂时查不清它是从哪来的**：这个库在你的环境里能找到，但没有留下「它是哪个包」的登记信息（比如是手工复制进去的）；
* **好几个包都能提供它**：比如 `cv2` 可以来自好几个不同的包，Tavotto 不替你挑；
* **它是你本机上正在开发的库**：Tavotto 没法在新环境里照样装出一份；
* **它是从本地文件或网址装的**：Tavotto 没法照原样再装；
* **它是用 Conda 装的**：用 pip 不一定能装到同样的东西；
* **它已经装了，但导入时出错**：再装一遍也没用；
* **Tavotto 不认识它，不知道该装哪个包**。

「还没法确定」**不代表脚本一定跑不起来**。如果这个库在你正在用的环境里本来就能用，点「仍然运行」就能跑——Tavotto 只是不替你做决定。如果跑不起来，再回来看「详情」，或者用下一节的办法换一套你自己的 Python 环境。

## 六、怎么选你自己已有的环境

如果你有一套自己装好了所有库的 Python 环境（项目里的 `.venv`、Anaconda 里的某一套，或者你平时一直在用的 Python）：

1. 打开 **设置 → 项目**，找到「Python 解释器」一栏，点「更换…」；
2. 选你的那一套。选好之后 Tavotto 会先**检查**它能不能跑 Tavotto 的绘图功能，通过才会记下你的选择；
3. 之后脚本就用它运行。**采用你自己的环境不等于安装**——Tavotto 不会往里装任何东西，除非你在卡片上明确授权。

> **检查和读文件不一样**：打开项目时的「读一遍脚本」不运行任何东西；但你点「检查」某套环境时，Tavotto 会**真的启动那套 Python，并加载脚本要用的库**。加载一个库，就会运行这个库自带的初始化代码。所以检查是需要你明确点一下的，而且 Tavotto 不会声称它「没有任何副作用」。

## 七、常见问题

**为什么 Tavotto 不直接帮我装所有缺的库？**
装库会往你的电脑上放第三方程序。Tavotto 的原则是：只装它**能确认来源**的，装之前让你看清装什么、装到哪，并且只装到它自己为你的项目准备的环境里。

**我的脚本文件名是中文（比如 `数据.py`），行不行？**
行。Tavotto 按 Python 自己的规则认出它是你的文件，不会拿去网上找包。

**装不上、或者装完说「核对失败」，我的原有文件会被改吗？**
你的脚本和数据文件不会被改。环境方面：装在 Tavotto 为你准备的环境里时，新环境没检查通过就不启用，原来的环境不动；如果你明确选了装进自己已有的环境（比如项目 `.venv`），安装是直接在那套环境里做的，失败时可能已经部分改动、不能完整回滚，Tavotto 会如实提示。
