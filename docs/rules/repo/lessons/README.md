# 错题本：犯过的错与做对的事

> 由根 `AGENTS.md`「任务路由」点名：改哪一层，动手前读这个目录里那一层的文件（`repo.md` 放跨层的，
> 改跨层规则、门禁或工作流时也读它）。
> 写入只走每日复盘：会话里踩到的坑写进维护者本机的复盘收件箱，由夜审合成一个 PR 改这里——
> 并行 PR 不直接改这里（同一文件多 PR 必撞）。格式、体积与脱敏由 `scripts/dev/lessons.py` 解析、
> `tests/test_lessons_format.py` 看护。

## 怎么用

- **Seen 只数不同的日子。** 同一条在 3 个不同日子出现，就升级：规则写进对应层的细则（照细则的
  「规则 + 为什么 + 看护用例」写法，并点名 `L-xxx`），这里那条压成标题一行的指针。
- 升级之后再犯，在细则里补证据，不回到这里重新计数。
- 每层一个文件，上限 16 KiB：一个 agent 读的就是一份，上限按读的单位定。
- 条目点名的代码已不在、或已有门禁拦住、或 60 天没再出现且细则里已有同义规则：夜审直接删，在 PR
  正文列出。原文留在提交历史里。
- 这是公开仓库：不写机器地址、账号、人名、反馈包编号、本机路径。证据只写 PR 号与提交号；
  用户反馈写「一份用户反馈」。

## 条目格式

```text
### L-007 一句能照做的规则（≤ 60 字）
- 类: 别这样            # 或「照这样」（做对了、值得照抄的）
- 触发: scripts/ci/, tests/test_gate*   # 从 diff 能读出的路径；通用纪律写 *
- Seen: 2026-10-31, 2026-11-02
- 为什么: 一段。发生了什么、代价是什么。
- 证据: #1587, #1604

### L-008 已升级的条目只留这一行 → docs/rules/<层>/<主题>.md
```

## 触发：按改动文件只看命中的条目

每条未升级的条目带一个「触发」，列出「改到这些路径时这条才相关」。路径条目沿用
`.github/judge-paths.json` 的写法，逗号分隔：

- 以 `/` 结尾 = 目录前缀（含子目录）：`scripts/ci/`
- 以 `*` 结尾 = 同一目录下的文件名前缀（不含子目录）：`tests/test_gate*`
- 其余 = 精确路径：`.github/workflows/ci.yml`
- 不支持别的通配（`**`、`?`、`[ ]`）。路径宁具体勿宽：能定到文件或子目录就别写整个 `src/`。
- 特殊值 `*`（单独出现）= 任何改动都适用的通用纪律（例如「验证结论取自退出码」）。要克制：条数有上限，
  默认不列出。已升级的指针条目不写触发（规则在细则里，由层的速查表指路）。

看护用例判：未升级条目必须有触发；每个路径条目至少匹配一个 `git ls-files` 里的文件（匹配不到 =
空转，多半是文件改名后没跟上）。

```text
python3 -I scripts/dev/lessons_for_diff.py                 # origin/main...HEAD 的改动文件
python3 -I scripts/dev/lessons_for_diff.py --paths-file f  # 每行一个路径；- 读标准输入
python3 -I scripts/dev/lessons_for_diff.py --all --why     # 另列通用条目，并附「为什么」
```

输出每行「编号、层文件、标题」，只列命中的条目；评审与动手前读这几条，不必通读各层。夜审新增条目时
同时写触发（路径取证据 PR 改到的文件，再收窄到真正相关的目录或文件）。

编号跨文件唯一、只增不复用，下一个可用编号看 `python scripts/dev/lessons.py --stats`；文件内按编号排。
