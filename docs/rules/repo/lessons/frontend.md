### L-068 对比度门禁要同时看 axe incomplete，零违规不等于达标
- 类: 别这样
- Seen: 2026-08-26
- 为什么: 整行可点的 absolute 覆盖层让 axe 算不出背景色，对比度进 incomplete 而非 violations；颜色改成明显不达标仍绿。要自算 WCAG 比值并变异验证。
- 证据: #130

### L-069 跨两次 evaluate 传节点要带身份，不能只传选择器字符串
- 类: 别这样
- Seen: 2026-09-15
- 为什么: axe 生成的选择器几秒后重新 querySelector，DOM 已变就指到别的元素；只在 Windows 腿暴露，两次重跑同样红，不是 flaky。解析后先核对身份。
- 证据: #354, #356

### L-074 别拿 elementsFromPoint 判「这点下面画着什么」
- 类: 别这样
- Seen: 2026-09-03
- 为什么: 命中测试受 pointer-events 与 overflow 影响；Radix 开 Dialog 时 body 变 pointer-events:none，同一采样点从 13 个元素塌成 2 个，同批节点在有无模态下给出两个结论。要按几何自己排绘制顺序。
- 证据: #210

### L-075 额度算到 0 再传下游前，先确认 0 是「零」还是「无限」
- 类: 别这样
- Seen: 2026-09-03
- 为什么: 共享 90 s 截止期的剩余为 0 时传给 Playwright 的 timeout:0 读作不设超时，预算用完的那一刻门禁从立即失败变成永远等；用 Math.max(1, 剩余)。timeout=None、limit=0、maxsize=0 同族。
- 证据: （迁移自维护者记录，无编号）

### L-076 e2e 里别把断言包在 if (await loc.count()) 里
- 类: 别这样
- Seen: 2026-09-07
- 为什么: 控件被改名或收进折叠区后 count() 为 0，整段断言安静不执行，用例照绿，报告与「跑过并通过」一样。分支条件改由独立来源给出，或在天天跑的用例里钉住锚点存在，或加 count>0 断言。
- 证据: #299

### L-077 rebase 过拖动/命中的 PR，合并态本机跑相关 e2e，量位移的 e2e 关吸附
- 类: 照这样
- Seen: 2026-08-26, 2026-09-26
- 为什么: 两个分支各自绿、合起来红且只有真浏览器看得见：NumberField 同值提交拦截 × e2e 写入等于初值；图内吸附让「拖动中改倍率不跳位」稳定红 6-9 px。仅 merge_group 才跑的套件，PR 绿不代表绿。
- 证据: #127, #575, #591

### L-078 测试/e2e 取元素别用「第一个匹配」的 role、aria-label 或文案
- 类: 别这样
- Seen: 2026-09-07, 2026-11-03

- 证据: #296, #1678

### L-083 弹层里 Esc 用例按「对话框还在不在」分支，不按气泡开没开

- 证据: #330

### L-084 核对 axe 给的选择器要带身份快照，对不上按已消失处理

### L-145 接入本机大清单时，清单到达后再测常用交互与重复渲染的成本
- 类: 别这样
- Seen: 2026-11-05

### L-153 会改 worker cwd 的 e2e，先等应用退出再删临时项目
- 类: 别这样
- Seen: 2026-11-07
- 为什么: macOS 允许删除进程的当前目录，本机浏览器用例全绿；Windows 上 worker 仍占着 cwd，清理报 EBUSY，打包 CI 两个场景加重试都红，多一轮返修。清理顺序按 Windows 的占用语义写，本机是 macOS 时打 full-ci 看 Windows 腿。
- 证据: #1800

### L-155 改界面行为前在 web/e2e 里搜被改的文案与锚点，钉旧行为的一并改
- 类: 别这样
- Seen: 2026-11-11
- 为什么: 失败卡主按钮从「再试一次」改成别的，jsdom 用例全改了，PR 没碰 e2e 所以 PR 上不跑 posix-e2e；一条钉着旧按钮的 e2e 在合并队列里红，被连踢三次，前两次还被当成机器故障重排；同日改工作目录默认行为的 PR 又因一条钉旧流程的 e2e 被踢四次。改行为前 grep 被改的 data-* 与文案，命中的 spec 一起改、PR 上跑一次。
- 证据: #1828, #1846

### L-158 给失败配出口按错误来源列全产出路径，断言钉死结构化码不放兜底码
- 类: 别这样

- 证据: #1859

### L-161 判改动有没有落盘看保存结果，dirty 清了不算
- 类: 别这样
- Seen: 2026-11-13
- 为什么: 两窗口接管时让出方保存失败，「拿回来编辑」仍按 dirty 为假、摘要相同判成没有改动，重新加载把这个窗口没存进去的改动丢掉、也不进恢复；自动保存写完本地兜底就清 dirty，磁盘请求还没成功。评审报 P1。丢弃前的保护判断带上 save_error / conflict 这类未成功的持久化状态，用例先摆一次保存失败再走丢弃路径。
- 证据: #1870
