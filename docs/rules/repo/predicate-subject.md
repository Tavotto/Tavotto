# 判据的主语（写判据之前）

> 原文出自根 `AGENTS.md`「判据的主语」一节（2026-09-17 指导文档治理时迁出，正文逐字未改）。
> 这里是这套方法的**唯一全文**；根 `AGENTS.md` 只留四问与三条配套的一句话版本。写门禁 / 断言 / 反证之前读这里。

写门禁 / 断言最常犯的错**不是实现写错，是判据问错了主语**——它量的不是你以为
的那个对象，于是恒真或恒假。**跑测试发现不了：它一直是绿的。** v0.9 发版当天
同一形状出现十几次，之后又在 Windows 路径、轮询计数、备份存档、FD 检查、泄漏
断言的归属、性能判据的维度上照原样复发——这是个会连着犯的家族，不是一次失误。

**动键盘之前先把主语说出口：谁的、哪个进程、哪个时刻、哪个维度。** 四问哪一条
答不上来，就先答上来再写。

| 判据问成了 | 该问的 | 漏掉的那一问 |
| --- | --- | --- |
| `ulimit -n` 有多大 | **runner 服务**的限制有多大 | 谁的 |
| 这个文件里有没有裸 Request | **所有**起实例的脚本里有没有 | 谁的 |
| 登录 shell 的 PATH | **服务进程**的 PATH（systemd → `.path` → `.env`，后面的赢） | 哪个进程 |
| 父进程解码对不对 | 子进程**编码**对不对（管道有两端） | 哪个进程 |
| `/api/version` 通不通 | **带认证的**端点通不通（公共端点没就绪时也通） | 哪个时刻 |
| 缓存键含不含这一维 | 缓存**热**了之后再读还含不含（先摆状态才首读的话永远量不到） | 哪个时刻 |
| 有没有写 `text=True` | 语义上是不是真的文本模式（给了 `encoding` / `errors` 就是） | 哪个维度 |
| 源码里有没有这个名字 | 有没有真实**调用**（定义、注释、docstring 都满足子串） | 哪个维度 |

配套三条：

- **判源码结构用 AST，不用子串。** 注释满足它、函数定义满足它、目标写成变量又
  匹配不到，每补一个洞露出下一个；要 `ast` 的真实 Call 节点 + 一层可达性，
  剪掉 `if False:` 那种死分支。最高发的入口是**判据匹配到了散文**——包括自己的
  注释、自己的 docstring、自己在告诉用户「去跑这条命令」的那句 `printf`。
  因此判据尽量写成**正面形式**（「必须出现 `> x.log 2>&1`」而不是「不许出现
  `2>/dev/null`」），否定断言会被解释它的那句话咬到。
  再犯（#1603，2026-11-02）：启动顺序与诊断字段用源码子串断言，把 `run_once()` 调用注释掉照样绿，
  评审用内存变异证实。
- **判不出就别判，把盲点写在明处；表达不了判据时收窄被判对象。**「排空是否与
  子进程并发」静态证不了，那就改判「启动器一律不许开这个管道」，逃生口整个去掉。
  假装覆盖到了比不覆盖更坏；**一个语义错的精确值也比一个诚实的粗略值更坏**
  （`/proc/<pid>` 的 mtime 有纳秒，但它未必是进程启动那一刻）。
- **反证要先验落点。** 「拿掉修复看它红不红」有相当一部分「没红」是变异脚本自己
  没生效（没匹配上、或打在了同名串的更早一处）。顺序是：先断言目标串存在 →
  再断言变异落在预期位置 → 最后才看用例红不红，结论**用退出码判**。每写一条
  用例立刻变异一次，别攒到最后。

**判据与豁免都带着它成立的前提，而前提失效时没有任何机制会提醒你**——当时正确
的豁免会安静地变成盲区。本节自己就是例子：#59 让位给 #64 的理由写下时成立，
8 小时后 #64 未合并即关闭。所以把前提写在判据旁边，让下一个人判得出它还成不成立。

## 观测本身先成立（错题本 L-001 升级，2026-11-03）

- **轮询或读取得到 0 / 空时，先证明这次观测有效，再把它当证据或往下写。** 取值分三态——失败、空、
  非空；取不到就当「不知道」，继续等或停下，不当「没有」。新写的查询先拿一个已知非零的对象对照一次。
  读出来还要写回去时（`gh pr view … | 加工 > 文件` 再 `gh pr edit --body-file`），先判读取成功且文件
  非空（`set -o pipefail`、`test -s`）。
  为什么：gh 一次失败让「待跑检查 = 0」被读成全部跑完；空队列与查询失败、缩写 SHA 返回 0、取不到被
  并进终态都是同一形状（#130、#131、#142）；2026-11-02 `gh pr view` 偶发 GraphQL EOF，管道里的 sed
  照样产出 0 字节文件，`gh pr edit` 退出码 0 把 PR 正文清空，事后核字节数才发现（#1638）。
  2026-11-06 导出脚本核验同类再犯：像素比较回 `(None, "hot_rebuilt")` 表示热态基线丢失，却把无差异值当成通过；
  必须连比较状态一起核，缺失有效基线不交付（#1790）。同轮收件箱还记录网络抖动 / 旧 run 取消让 watch 提前退出，
  仍须按当前完整 head SHA 重取状态，查不到不算检查结束。
  2026-11-12 同日两次：盯 PR 的 Monitor 查询用了 gh 不存在的字段，报错被 `|| continue` 吞掉，30 分钟零事件；
  `tests/test_convert_output_content.py` 的 `_wait_idle` 把任何不带 `realigning` 的响应当成落定返回，Windows 腿拿到
  没有 `state` 的响应即 KeyError（无关 PR 的 CI）。轮询要连续失败 N 次就显式告警，等待函数只认带完整终态字段的响应。
- **报数或引用事实前，先确认集合边界没被截断（错题本 L-009 升级，2026-11-05）。** 看过 `head`、分页或折叠的
  输出，只能说「这几条」，不能说「全部」；清单念出来不等于逐项评估过。为什么：一轮四次数字错，三次是看了被
  截断的子集；只评了 e2e 腿，漏了唯一有攻击面的 Windows 后端腿（#189、#303）。

- **改变状态的命令执行后，用另一个查询核对状态（错题本 L-031 升级，2026-11-11）。** 命令的输出与退出码回答的是
  「我注意到」，不是「我做了」：入队、写密钥、发布之后用独立查询核目标状态，字段也要挑对（入队看 `mergeQueueEntry`）；
  首次用到的密钥要有长度级诊断。脚本里的 `ssh` 默认读 stdin，放在 heredoc 或管道里会吞掉后面的行，一律加 `-n`。
  为什么：合并队列仓库里 `gh pr merge --squash --auto` 只打一行「!」就返回、根本没入队（#177）；2026-11-03 无终端时
  `wrangler secret put` 把空串存成密钥并报 Success，OAuth 回调一直被拒；2026-11-09 一次数据发布脚本里 `ssh` 吞掉了
  heredoc 余下的行，同步与提交都没执行、退出码 0，服务器上前几次发布留下的空暂存目录说明踩过不止一次。

## 改共享判据，同一次改动扫完所有消费点（错题本 L-017 升级，2026-11-11）

判据或它依赖的原语收敛在一处、消费点散在各处：改它时列全调用点逐个问「它的答案变了，这里还对吗」，能做成机械看护
就做，夹具要选得出差别（`tests/test_axes_traversal_authority.py`）。为什么：同一判据连着三次只改一处，残留处往往更坏
（色条照旧宣称生效）；2026-10-30 三份用户反馈：「素材等于磁盘文件」漏改 `/api/ai/run`，续跑路径没有正常路径的修正，
两个入口对同一脚本结论相反（#1504、#1509、#1514）；2026-11-10 worker 全局包了 `os.stat` 按改指表作答，产品自己的
相对读回退也用 `os.stat` 判「沙盒里有没有」，被骗成「有」而跳过了脚本旁的原文件，评审报 P1（#1821）。

## 反方向越界时它也要响（错题本 L-020 升级，2026-11-05）

写完断言问一句：越过另一条边时它响吗？计数只防多不防少；根取小则闭包算小，假绿；最低版本常量只防调太高、
不防留太低；升级路径只有降级有人管。修完缺陷再问一句「它暴露了哪条判据只有一半」，把另一半补上。
为什么：判据只钉一条边时一声不吭，四个不同日子（2026-08-28 至 09-05，迁入时未留 PR 号）都是这个形状。

## 夹具要能分出选错了谁（错题本 L-033 升级，2026-11-05）

写判据先问缺陷在哪个维度显形，夹具要有相邻碰撞与恢复后的时刻。单项目、单会话、队列只有一条的夹具里两个主语
必然重合，「选错对象」量不到。为什么：「记住过就自动批准」判的是刚到的 B，动作却批准了队首 A，绕过了
`tavotto run` 的确认屏，而用例队列里只有一条（#192、#193、#307、#186）。

## 规则常被违反时先查范围（错题本 L-038 升级，2026-11-05）

一条规则总被违反，先查它的范围是否宽过要守的事；判据窄过所守之事则会假红。写豁免时并排念「看见的」与
「写下的」，并钉反例。为什么：四个并行 PR 全落在「一次只开一个」的冲突域里，因为域范围混入了耦合差一个数量级
的脚本（#189、#192、#193、#194）。
