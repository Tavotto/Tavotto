- **反空门禁纪律**：新增的核心不变式测试，提交前必须手工反证一次——把修复
  拿掉，确认它真的红，并把结论写进 PR。「读的人会以为它在挡什么，而它什么
  都没挡」比没有更坏。豁免表要写得出理由，并区分「豁免」（本来就不画）与
  「使能」（画在一个关着的通道上，开了就必须变）。反证是**事后**那一半；
  事前那一半（写判据之前先说出主语：谁的、哪个进程、哪个时刻、哪个维度）
  的唯一出处是根 `AGENTS.md` 的「判据的主语」一节。
- **空转的门禁比没有门禁更坏**：nightly 曾对早已退役删除的 `packaging/tavotto.iss`
  报平安；macOS 冒烟曾借 worker-env 让「runtime 没打进去」全绿。判「最近
  跑过没有」要数**有结论的 run**。
- 每个「只在别人电脑上发生」的 bug 先变成 `tests/test_windows_regressions.py`
  的用例再谈修（cp936 编码、文件占用、盘符/反斜杠/中文路径、端口占用、
  CLI 只有 .cmd、解释器探测）。
- **做变异反证的手法（错题本 L-005 升级，2026-11-03）**：变异前工作区必须干净——先把修复提交；
  变异按锚点替换，锚点对不上就报错退出，不用 sed 地址范围；跑用例加 `python -B`（不读旧 `.pyc`），
  结论只认退出码；还原只动被变异的那个文件（修复已提交，还原才不会连带抹掉它），跑完 `git status`
  核工作区与变异前一致。
  为什么：用 `git checkout` 还原变异，把未提交的修复一起抹掉，累计十余次；变异没应用上时的红绿
  也曾被当成门禁有效的证据（#128、#162、#181、#189、#457、#550、#561、#1095、#1118、#1157）。
  2026-11-16 再犯：变异期间开着的本地后端不受 `-B` 管，写下了改坏那份的 `.pyc`；还原在同一秒、字节数相同，
  按 mtime + size 判没过期，后续测试与截图仍跑改坏的代码。会 import 被变异模块的每个进程都设
  `PYTHONDONTWRITEBYTECODE=1`，每项还原后清 `__pycache__`（会话记录，无编号）。2026-11-19 再犯：反证前没提交修复，
  用 `git checkout <文件>` 还原，修复一起被抹掉、提交里只剩新用例，还原后也没再跑一遍修复版，CI 上才红（#2043）。2026-11-27 再犯：反证把切片挪到另一行、字节数不变，用 `cp` 在同一秒还原，没设 `PYTHONDONTWRITEBYTECODE=1`，之后一直跑变异版 `.pyc`，正常代码被误判成红（#2311）。看护：只靠人记。
- **变异后不管绿还是红，都核「该跑的路径真跑了、红的是目标路径」（错题本 L-030 升级，2026-11-05）。** 绿有多种
  成因：分支从没被夹具执行、选择器缩到一条而判据在别的用例里、变异本身是语义 no-op（`set() or 推导式` 仍求值到
  后者）。先排除这些，再谈判据弱，免得去加强本来就好的判据（#181、#187、#189）。看护：只靠人记。
- **推送前跑仓库级扫描用例，不只跑自己改到的那几份（错题本 L-108 升级，2026-11-03）。** 改了
  `scripts/`、新增 subprocess 调用或用例、动了 workflow 时，`grep -l '<改到的文件名>' tests/*.py`
  找出读同一文件的结构判据一起跑，`src/tavotto/` 新增 subprocess 另跑 `tests/test_windows_regressions.py`
  （按结构判，只在 macOS 执行的那行也算）；叠栈 PR 不跑 CI，更要本地跑全。派子代理建这类文件时
  把这几条写进提示。为什么：入口脚本编码扫描、下载步骤闭集、subprocess 未钉 encoding / creationflags
  在五个不同日子各到 CI 才红，各多耗一轮（#1135、#1139、#1280、#1635、#1639、#1641）。
  升级后再犯：#1671、#1702（subprocess 没钉 encoding，只跑了相关用例）。2026-11-25 新测试文件里 `subprocess.run(..., text=True)`
  没给 `encoding`，本地只跑了功能相关的几组，`tests/test_source_hygiene.py` 在 backend-fast 三个版本上红（#2229）。
- **变异杀不死、或抽掉修复不红时，先查夹具，别急着改判据（错题本 L-019 升级，2026-11-05）。** 依次查三处：
  夹具缺维度；对象复用（`mockResolvedValue` 只求值一次，两次响应是同一引用，「不换对象」的断言恒真）；
  同一保证有两份实现（fallback 的两个出处填了同值，判据分辨不出走的是哪条）。造区分性数据要选现实中真会不同的值。
  为什么：四个不同日子（2026-08-21 至 09-04，迁入时未留 PR 号）都是判据没问题、夹具量不到。看护：只靠人记。
- **读 CI 结论按 workflow 最新一轮列全 job，裸名状态不算结论（错题本 L-099 升级，2026-11-05）。** 每一项 SKIPPED 或
  CANCELLED 各写出可验证的理由，别把清单念出来当评估；PR 显示 BLOCKED 时先确认现役那轮跑完，跑完还 BLOCKED 再查原因，别推空提交
  换 head。为什么：裸名状态常来自矩阵父占位或被挤掉的旧 run，两个方向都会骗人（#303、#314、#315、#317、#299、#296、#302）；
  补打 full-ci 让同一 sha 起两轮，被取消那轮留下一批 1 至 2 分钟的红项，曾被误读成卡住（2026-11-04，#1739）。看护：只靠人记。
- **偶发红或无关红先读一层根因，别加等待、标 flaky 或直接重跑（错题本 L-100 升级，2026-11-05）。** 重新入队或重跑前
  写得出「它为什么红」；读不出就记 issue，不能一句「无关」放过。为什么：「偶发」常是断言与缺陷在赛跑——Radix 关闭浮层
  归还焦点又把气泡打开，鼠标点开必现、键盘打开不现，加个 await 能让用例绿，缺陷原样留在产品里（#311、#315）；
  2026-11-02 合并组红在与本 PR 无关的桌面壳握手超时用例（实为 spawn 失败），一分钟内重新入队、没记 issue（#1603）。
  2026-11-11 合并组除两个 Gate 外全是 cancelled，被当成机器故障连排两次；
  快速失败下先红的腿自己也显示 cancelled，Gate summary 的 `root_failures` 早已点名 posix-e2e 里一条钉旧行为的用例，check-run 注解里也有「本腿失败」（#1828）；同日另一 PR 的 summary `root_failures` 为空、被踢四次，要按 completedAt 找最早结束的非 success 腿、看它注解里有没有「本腿失败，merge_group 快速失败」（#1846）。2026-11-16 合并组 backend-fast / backend-platforms / windows-exe-smoke 全显示 cancelled，被判成队列侧取消；真红的是一条腿 pytest 步骤（step 结论 failure、job 结论被覆写成 cancelled），聚合判定 JSON 的 `root_failures` 早已点名（#1940）。2026-11-18 至 19 日，`windows-exe-smoke (1)` 的 `coding-agents.spec.ts` 一天踢出合并队列 8 次以上，各 PR 重排即过、前一晚复盘记为「待查，未归因」；读出根因（能力接口 1 秒内刷新多次、重挂载视图把「高级」收回）后一个测试侧 PR 就止住了（#2059）。2026-11-24 合并组几十个 job 同秒 cancelled、只有两个聚合门红，被当成 GitHub 侧整轮取消原样重排；真红藏在 Windows 分片一个 cancelled job 的 pytest 步骤里（golden 浮点末位跨平台不同），同一个 PR 又被踢一次（#2140）。
- **并发、进度与「正忙」用例用栅栏或事件摆出时序，别断言墙钟上限、别靠 sleep 或后台线程采样（错题本 L-177 升级，2026-11-27）。**
  顺序用 `threading.Barrier` / `Event` / hold 放行或假时钟钉住；往下走之前等前提显式成立（真进了 build、拿到锁、请求在途）；
  工作线程里的异常带回主线程断言为空；超时只作防挂死且放宽；采样断言改读服务端记下的阶段序列；测某一道限额时把别的限额调开。
  为什么：「两个探测并发跑完 < 单次 × 1.7」在负载高的 3.10 分片量到 2 倍、大表进度用例靠后台线程轮询没采到 render 阶段，各踢掉一个无关 PR（#2079、#2096）；
  2026-11-25 夜慢 runner 上五条同类用例（固定延迟造「正忙」、没等试运行进 build 就放取消、线程异常被吞成「少了几条」「200≠409」）
  在合并组随机红，连坐踢掉别人的 PR 五次（#2237、#2243、#2245、#2250、#2251）。2026-11-26 又五条：墙钟 2 秒、4 秒量「马上」（Windows 异步回收锁、迁移），
  读 rAF 还没画完的中间值，没等第一次渲染回来就定起点，项目指纹算进注册表原子写的临时文件（#2260、#2281、#2262、#2258、#2284）——「马上 / 不超过 N 秒」改等可观察信号。看护：只靠人记。
- **入队前验按队列次序累积 merge 出的树，不只是自己的分支（错题本 L-113 升级，2026-11-27）。** 改过回退顺序、夹具默认值、golden 或共享文档体积的 PR，
  把已在队列里、碰同一批 spec / golden / 文件的 PR 依次 merge 后本地跑那几条。为什么：并行 PR 的 hunk 原样插进重排后的文件，两两验过不等于组合验过（#175、#177、#186）；
  11-22 两个 PR 各给根 AGENTS.md 加一段，叠加后超体积上限（#2105）；2026-11-25 分支基点没跟上改了夹具元素框缺省的 PR，preflight golden 过期，三条腿红（#2195）；
  2026-11-26 新加的脚本方案卡与刚合入的「连接不适用就落回改脚本」e2e 组合冲突，各自 CI 都绿（#2202 与 #2240）。看护：只靠人记。
