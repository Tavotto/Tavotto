Chinese, Japanese and Korean text in figures stops rendering as empty
boxes, the Codex plugin now installs from a release channel instead of a
source checkout, and scripts that read data files by relative path can be
told to run in their own directory. Around those, a four-round UI/UX audit
reworked navigation, settings and the explanatory text throughout the app,
and the build no longer asks you whether a slow script is stuck.

## Added

**CJK text in figures.** `plt.title("中文标题")` and friends drew every
Chinese, Japanese or Korean character as an identical empty box.
Symptom: the title looks like `□□□□`, the PDF has no searchable text for
it, and the only warning (`Glyph 20013 … missing from font(s) DejaVu
Sans.`) went to a log you never see. Trigger: any non-Latin label — the
default font stack ships no CJK coverage. Tavotto now appends a
platform-probed CJK fallback chain (PingFang / Hiragino on macOS,
Microsoft YaHei / SimHei on Windows, Noto CJK / WenQuanYi on Linux; only
faces actually installed enter the chain — no fonts are bundled). The
element panel reports which face drew the characters, the PDF text layer
reads the characters back, and the problem panel stops calling correctly
drawn CJK a violation. Machines with no CJK face installed keep the old
per-character "missing glyph" report. (#295, ADR 0045)

**EPS and TIFF export.** Both formats join the export dialog and the CLI
alongside PDF/PNG/SVG. (#295, ADR 0046)

**Codex plugin installs from a release channel.** The marketplace entry
now points at the `plugin-stable` branch, which carries a complete,
built plugin — the embedded canvas included. Previously the entry pointed
at a source checkout, so installing required a build step users had no
reason to run. Upgrade with `codex plugin marketplace upgrade tavotto`
and reload Codex. (#289, #290, #292, #293, ADR 0043)

**"Run in the script's directory".** A project-level switch in
Settings → Rendering environment, also offered directly from the "script
produced no figures" error. With it on, your script runs with its own
directory as the working directory, so data it opens by relative path
(`os.path.exists`, `glob`, C++ readers such as ovito) resolves the same
way it does in your terminal. (#301, ADR 0047)

**Interpreter repair candidates.** When the bundled runtime is missing a
package and the project has no virtualenv, Tavotto now lists the Python
interpreters already installed on your machine as repair candidates
instead of leaving you to find one. (#294, ADR 0044)

**Scatter selection outlines every marker.** Selecting a scatter series
drew one big rectangle around the whole collection; now each point is
outlined, including marker-only `Line2D` series. (#295)

## Changed

**UI/UX audit, four rounds.** The top bar is down to Projects and
Documents, with a stable "← back to canvas / figure name / current
object" context strip above the canvas, and switching modes restores your
viewport instead of resetting it. Settings gained an update page and a
privacy page, the asset library's "Open" split into "Edit source figure"
and "Add to canvas", the problem panel groups by rule, and a dedicated
pass rewrote the explanatory text across the app. Icons are unified to a
single lucide size scale. (#296, #299)

**A long build is no longer killed for being slow.** Symptom: a script
that takes a while on its first render was killed at a flat 900 seconds,
and the only knob was a per-script field asking you to predict how many
minutes it would need — before you had ever run it. Trigger: any
cold-start build of a script that is genuinely slow rather than stuck.
The timeout now asks "is it still producing output?" instead of "how long
has it been running": 20 minutes with not a single byte of new output is
declared hung, with a four-hour hard limit behind it, and the message
tells you which of the two happened. The per-script cost field stays as
documentation and no longer affects any timeout. (#305, ADR 0050)

## Fixed

**"Stem does not exist" when a script drew nothing.** Symptom: you open a
figure the registry knows about and get a bare "stem does not exist".
Trigger: the script ran to completion but captured zero figures — a
missing data file, an early return. Tavotto now reports
`no_figures_captured` and puts the tail of the script's own output in the
error block, so `[ERROR] file not found` is right there. (#298)

**CJK text was attributed to the wrong font on Linux.** Symptom: the
problem panel reports "the CJK text is drawn by *Noto Sans CJK JP*, which
is not an accepted Chinese face" for a figure that looks perfect, and the
element panel names a font you never chose. Trigger: matplotlib 3.11+
with a font *collection* installed (`NotoSansCJK-Regular.ttc` holds the
JP/SC/TC/HK/KR faces in one file) — Tavotto opened the file but not the
face inside it, so every entry reported the collection's first face.

**Legend entries stopped following their source on matplotlib 3.8 and
3.9.** Symptom: changing a line's colour, style, width or marker did not
reach its legend entry, and detaching/re-following did nothing. Trigger:
running Tavotto against the lower bound of the declared matplotlib range
— an API keyword that only exists from 3.10 was used unconditionally, and
the resulting error was swallowed as "this candidate has no legend
handle". The bundled desktop runtime (3.11.x) was never affected.

**Chinese messages vanished on Windows.** Symptom: a script or tool run
by Tavotto printed nothing where it should have printed a Chinese
diagnostic. Trigger: 25 subprocess entry points under `scripts/` did not
pin their output encoding; on a Windows code page other than UTF-8 the
text was dropped silently. All of them now pin it, and an enumerating
gate keeps new entry points from regressing. (#317)

**A batch of smaller bugs.** Error copy that told you to click something
that does not exist; the MCP diagnostics table missing a cell; the
version history being written back in full instead of incrementally; two
tutorial interactions (canvas double-click into in-figure editing, and
"select a figure first" when one was already selected on the canvas).
(#295, #314)
