# Tavotto 0.17.0

## Before you upgrade

**Tavotto now renders and exports with RenderCore; PyMuPDF is gone.**
Reading, writing and rasterising PDFs — asset previews, exports and
write-back — now go through the new backend that shipped as a candidate in
0.16.0. What you may notice:

- **Text you add on the canvas** (text boxes, labels such as "(a)" — not
  the text inside a matplotlib figure) is now drawn with Liberation Serif /
  Sans / Mono and Noto Sans SC instead of Times / Helvetica / Courier.
  Advance widths are the same, so line breaks, positions and box sizes do
  not change and no document is rewritten; the baseline sits slightly
  higher (about 1.8 pt at 12 pt). There is no fallback face any more:
  characters outside those fonts — Hangul, Arabic, Devanagari, Hebrew, the
  mathematical alphanumerics (`𝛼`), emoji — export as a box, the text layer
  still carries the original character, and the Problems panel lists each one
  (`glyph-missing`) instead of silently switching fonts. `×10⁵` and `H₂O`
  now keep their superscripts and subscripts in the text layer instead of
  being flattened to `×105` / `H2O`. Text inside your figures is unaffected.
- **Mirrored or semi-transparent panels stay vector.** They used to be
  embedded as bitmaps with unselectable text; the inspector warning about
  that is gone because it no longer happens.
- **PNG exports of vector sources record their real resolution** instead of
  a fixed 96 dpi.
- **`pip install tavotto` installs pikepdf, fonttools, uharfbuzz, pypdfium2
  and Pillow instead of PyMuPDF.** Setting `TAVOTTO_RENDER_BACKEND=pymupdf`
  is now an explicit `backend_retired` error rather than a silent fallback.
  (ADR 0072, 0073; #539)

**Minimum macOS for the desktop app is now 14 on Apple Silicon and 15 on
Intel Macs**, up from 11. The bundled PDF libraries require it. If your Mac
runs an older macOS, stay on 0.16.0 and do not install the 0.17.0 update.
Linux and Windows requirements are unchanged. (#539)

**There is now a desktop app for Intel Macs.** This is the first release
with one dmg per architecture (ADR 0076, #505):

| Mac | Download | Requires |
| --- | --- | --- |
| Apple Silicon (M1 and later) | `Tavotto-0.17.0-macOS.dmg` | macOS 14 or later |
| Intel | `Tavotto-0.17.0-macOS-Intel.dmg` | macOS 15 or later |

The Apple Silicon file keeps its old name, and the in-app updater tracks
each architecture separately.

Also check before you open existing documents: the legend font size now
scales the whole legend box (under **Changed**), style values and inspector
sizes are now page sizes (under **Changed**), and edits whose target curve
can no longer be identified are no longer applied (under **Changed**).

## Added

**A Style tab in the left rail, and canvases that follow a style.** The tab
shows the fonts and on-page sizes of the current figure's titles, axis
labels, tick labels, legends and canvas labels, and its data-line, frame
and tick settings. Each can be edited in place. A value that breaks the
publication profile is outlined, and its marker jumps to that issue in the
Problems panel. At the bottom, the Style picker binds the current canvas to a
style from your library: the whole style is applied to every figure on the
canvas in one undo step. From then on, changing that style — from the tab
or by saving it in Settings — updates the figures on the canvas, and a
figure added later is aligned once when it first renders. Only the items
that changed are rewritten, so edits you made to other items in the
inspector are kept. Editing a built-in style saves a copy and binds
the canvas to the copy. Undoing a style edit reverts this canvas only; the
canvas then stops following the style until you pick it again. "Restore
original" returns every figure on the canvas to its script's look and
unbinds the style. The Paper styles page in Settings now only manages the library; its
"Apply to the current figure…" button became "Use for this canvas".
(ADR 0081, #547)

**TIFF files show up in the asset library.**
Trigger: a project folder contains `.tif` / `.tiff` figures (a common journal
submission format). Before: they were silently left out of the asset library —
and a script that saved only a TIFF made its figure disappear from the library
altogether. Now they are listed, previewed, placed on the canvas and exported
like PNG / JPEG. Supported: 8-bit and 16-bit (reduced to 8-bit, no automatic
contrast stretch) grayscale / RGB with or without alpha, 8-bit palette and
1-bit black-and-white images; uncompressed, LZW, Deflate, PackBits, JPEG and
CCITT G3/G4 compression. Multi-page TIFFs use the first page, as multi-page
PDFs do. Floating-point or signed pixels, CMYK / Lab, 32-bit samples, other
compressions (ZSTD, WebP, JPEG 2000), BigTIFF and planar TIFFs are not
supported: they are listed under "These files can’t be used" with the reason
and how to re-save them, instead of being drawn wrong. Writing edits back into
the original file still works only for PDF / PNG figures; for a JPEG or TIFF
figure it now says so instead of reporting success without changing the file.

**A missing package can be picked up from a Python you already have.**
Trigger: a script imports a package the rendering interpreter lacks, while
a Conda environment, a pyenv version, the `python` your terminal uses, or
an interpreter your project points at (`.vscode/settings.json`,
`.python-version`, `environment.yml`, the script's shebang) already has
it. Before: Tavotto only offered to install into its own environment, and
switching interpreters meant typing a path into a setting that was hard to
find. Now Tavotto checks those interpreters, switches to the best one that
has everything the script needs, and says so in a notice with a "Revert"
button. It asks to install packages only when none of them is complete.
Choices you made yourself are never overridden: an interpreter pinned
globally or for this project, having chosen the default chain (including
clicking "Revert"), or a project's own venv. In those cases a complete
environment is offered, preselected, in the dependency dialog. This also
covers imports Tavotto cannot map to a package name (a lab's own library,
for example), as long as they really fail to import in the current
interpreter. Adopting an environment from the dialog re-checks it first and
refuses one that is still missing packages. (ADR 0079; #522, #562, #609)

**A left-rail Workspace drawer: current project, favourites and recent
projects.** Favourites can be reordered by dragging, or with Move up / Move
down in the "…" menu; recent entries are not truncated, entries with the
same name can be told apart, and missing folders can be removed in one go.
"Open folder…" and "New project…" sit at the bottom. The project name in
the top bar now opens and closes this drawer instead of its own six-item
menu. (#550)

**Dragging inside a figure snaps, and legends resize from their corners.**
Trigger: dragging text, an axis label, a legend or a subplot inside a
figure. Before: nothing snapped — only canvas objects did — so lining up
"Vacuum" with "Superconductor" or two axis labels was done by eye, and a
legend could only be resized one font-size / spacing field at a time in the
inspector. Now in-figure drags snap to other elements' left / centre / right
and top / middle / bottom edges and to the figure's centre lines, with the
same guides as canvas objects; hold ⌘ or Ctrl to drag without snapping. A selected legend has four corner handles: drag one to scale the
whole legend with the opposite corner fixed and a live preview; one drag is
one undo step. Moving the main plot together with a colorbar (⇧-click to
multi-select) now carries labels you had moved, such as "(a)", the same way
dragging the plot alone already did. (#575)

**Flowchart boxes carry their contents, and bare annotation arrows can be
dragged.** Dragging a box moves the text and nested boxes inside it; an
arrow attached to the box follows with that end (an arrow whose other end
is on another box is stretched), and an arrow with both ends inside moves
whole. Dragging an outer dashed frame moves the whole module. Hold ⌘ /
Ctrl to drag only the box. Arrows drawn with `ax.annotate("", xy=…,
xytext=…, arrowprops=…)` can now be selected, dragged whole or by either
end, like arrows added with `add_patch`; before, they snapped back on the
next draw. This works when both ends use coordinates Tavotto can convert
back (`data`, `axes` / `figure` fraction, points or pixels, and `offset …`
for the tail). (#552, #553)

**Settings → Diagnostics → Performance records where drag stutter comes from.**
Trigger: dragging figure sub-elements or canvas objects feels choppy on a
particular Mac. Before: there was no way to show *where* the time went on that
machine — the developer's Mac could not reproduce it. Now "Start" opens a small
probe panel on the canvas: drag as usual, optionally run the auto test (two
synthetic 3-second drags on an object you click, always cancelled, so the
document and undo history are untouched), then "Finish and save". The report
is a numbers-only JSON (frame times split into input handling / rendering /
unattributed, render counts, SVG size, Mac model, power and thermal state — no
file names, figure text or paths), saved to `perf-reports/` in the Tavotto data
folder and shown in Finder. Nothing is uploaded. Developers read it with
`python scripts/perf_report.py report.json --html out.html`. (ADR 0075)

**Tavotto's MCP server can be set up in hosts other than Codex.** The full
package now contains `integrations/configure.py`, which checks that the
bundled launcher starts and prints a configuration snippet for Cursor,
ZCode, DSH, WorkBuddy, Claude Code, Claude Desktop, Trae or VS Code
(Copilot Agent); it writes no files. The project directory must be given
with `--project-root`; the filesystem root, your home directory and its
parents are refused. Hosts without a native skill entry can generate
equivalent instructions with `--emit instructions`. `tavotto_health` now
reports which package copy is running. On Windows, `--health` /
`--provision` output is always UTF-8, which fixes a health report that was
lost when the path contained Chinese characters (this affected
`tavotto codex install` too). Setup steps are in the README.
(#559, #560, #588)

**On a server over SSH, a second `tavotto --no-browser` prints a fresh
login address.** Trigger: Tavotto is already running on the port and your
browser lost its session (another browser, cleared cookies, another
computer). Before: the only way to log in again was to kill the server.
Now running the same command again prints a new one-time `#dnonce=` address
next to "already running". The README has a new "On a remote server, over
SSH" section (forward the same port number, use `127.0.0.1`, not
`localhost`). (#594)

**The Windows installer asks where to install on a first install.** The
default (`%LOCALAPPDATA%\Tavotto`, or the previous location if Tavotto was
installed before) is filled in, so clicking Install behaves as before.
Upgrades, in-app updates and passive installs still do not ask. (#521)

**Scripts that `import pypdf` or `import PyPDF2` get the one-click install
when the package is missing**, instead of only "missing pypdf". (#510)

**Export jobs carry a bounded phase trace that names the failing step.**
Trigger: any export (`POST /api/export`, or `tavotto_export` over MCP)
whose status you read back. Symptom before: a `partial` or `failed` job
told you *that* it failed and, at best, the error code of one output;
where in the pipeline it broke (source, compile, compose, raster,
inspect, publish, report) was not recorded. Now the job status has a
`trace`: one event per phase (phase, elapsed ms, outcome, error code),
capped at 64 events (the middle is dropped, head and tail are kept and
`truncated` says so), and `failed_phase` / `failed_code` point at the
*first* failure — later knock-on failures do not overwrite it. A job whose
figures all succeeded but whose style-check report could not be written is
`partial` with `failed_phase = "report"`. Existing keys are unchanged. (ADR
0071)

**Preparation results carry a complete execution receipt, and a plan that
no longer matches the world is refused with a named reason.** Trigger:
opening or re-preparing a figure through the preparation API (`POST
/api/engine/preparation`). Symptom before: the receipt described the
interpreter Tavotto *intended* to use; a health-check or probe result could
be mistaken for the report of the process that actually ran the script;
and a plan made before the working-directory grant, the interpreter choice
or the script's data changed was still executed. Now the receipt's runtime
section is accepted only from the process that ran the script
(`report_origin = build`, and its pid — or, on Windows where a virtual
environment's `python.exe` is a launcher, the launcher's child — matches
the one the control plane started; anything else is recorded as
`runtime_rejected` and the receipt is `partial`), it lists the project
files the script opened through Python (`inputs`, always `partial`: native
readers such as h5py are named as unobserved, never guessed), and
`binding_check` compares them with the data the plan was made against.
Before a session is started the plan is re-checked against the grant, the
interpreter decision and the data binding; any mismatch is
`preparation_plan_stale` with a `reason`, and nothing runs. A live session
whose data changed after it ran keeps showing the figure it made, marked
as an old snapshot (`binding_check.matched = false`) until you rebuild;
your edits are kept. (ADR 0070, 0071)

## Changed

**A legend's font size now scales the whole legend box, as
`ax.legend(fontsize=…)` does in matplotlib.** Trigger: setting a legend's
font size in the inspector, dragging a legend corner, or applying a paper
style / publication profile that sets legend font size (the built-in style
does, for every legend). Before: only the entry text changed size; the
padding, row spacing, handle length, handle–text gap, column spacing and
minimum row height stayed at the script's size, so the box did not scale
with its text and corner-dragging overshot or undershot. Now all of those
follow the font size. Border padding, label spacing, handle length, handle
text padding and column spacing can still be set on their own in the legend's
layout details, on top of the new size. The legend title keeps its own size
(`title_fontsize`), as in matplotlib. **Migration:** documents saved with a
legend font size override — set by hand, or by applying a style or profile —
redraw that legend with a proportionally larger or smaller box when opened
(for example a 10 pt legend set to 7 pt: 97 × 42 px → 82 × 33 px at 100 dpi).
Text size is unchanged; the right and top edges of a dragged legend move.
Adjust the spacing fields if you need the old look. (#579, ADR 0034)

**Font sizes and line widths are shown and entered at their size on the
page.** Trigger: a figure placed on the canvas at other than 100 % — for
example at 60 % of its native width. Before: the inspector showed the
script's 9 pt while the Style tab showed 5.4 pt and the Problems panel said
"5.40 pt", and a style applied 9 pt to the script, which readers saw as
5.4 pt. Now the inspector (including the floating element bar and the
right-click quick edit), the Style tab and the Problems panel show the same
on-page number, with two decimals; typing 8.5 gives 8.5 pt on the page, and
Tavotto writes the corresponding script value (14.17 at 60 %). Scatter
marker area (pt²) still shows the script value. At scales above 100 % some
two-decimal page values cannot be represented exactly and show one step off
(typing 8 at 133 % shows 8.01). Documents are unchanged: overrides still
store script values. (ADR 0082, #557)

**Styles use on-page sizes, and the built-in default style keeps the type
hierarchy.** Before: the default style set every text to 9 pt, set every
data line to the thinnest 0.5 pt, and changed the font of titles and axis
labels only — tick labels and legend entries kept theirs. Now it follows
the default publication profile with tick and legend text a step below the
axis labels, leaves data line widths alone, and sets the font on tick
labels and legend entries too. **Migration:** a style saved before this
version keeps its numbers as script values until you first edit it; on
that edit it is converted to page sizes (its existing numbers are kept and
now mean points on the page), and the figures on the current canvas are
realigned in the same undo step. The status bar says when this happens.
A style still cannot change a legend title's font; that is reported
rather than skipped silently. (#547)

**"Fix" and "Fix all" in the Problems panel check the result before changing
anything.** Before: fixes were written one by one without looking at the
result — tick labels could end up larger than the axis title, enlarged text
could push an axis title further out of the figure, fonts were never fixed,
and "Fix all" also applied the suggestions. Now the backend computes the
smallest change from the sizes readers see on the page, renders it, and
checks every issue again; only if that passes is the change committed, as
one undo step. Otherwise the document is untouched and the status bar says
why. Font sizes are raised by level, fonts are fixed (a font the profile
requires but this machine lacks is reported by name), elements outside the
figure are brought in by adjusting the margins, and "Fix all" leaves
suggestions alone. Figures opened with `tavotto run` cannot be fixed
automatically. (ADR 0080, #549)

**An edit whose target can no longer be identified is not applied.**
Trigger: you restyled a curve that has an explicit `label=…` and then
changed the script's structure (reordered, inserted or deleted curves, or
added a subplot in front). Before: the edit silently moved to whichever
curve now sat in that position, and writing back to the original file
applied it there. Now such an edit is skipped with a warning, "Clear stale
edits" in the inspector lists it, and write-back is blocked while it is
there. Curves without an explicit label, the axes themselves and text are
still matched by position. Edits made before this version carry no
identity and are matched by position as before. (ADR 0083, #602)

**The Codex plugin starts its server through a bundled launcher, and an
outdated engine is reinstalled in the background.** The plugin's
`.mcp.json` now runs `./mcp/launch.cmd` instead of a bare `python3`. On
macOS and Linux it simply runs `python3`. On Windows it tries, in order,
`TAVOTTO_MCP_PYTHON`, Tavotto's managed environment, `py -3`, `python` /
`python3` on `PATH` and `%LOCALAPPDATA%\Programs\Python`, skips the
Microsoft Store alias and interpreters older than 3.8, and hands over to
the first one that really runs. This is aimed at Windows installs where the
plugin showed as enabled but offered no tools (#266); it has been checked
with the Codex CLI on Linux but not yet on a Windows machine with Codex
Desktop, so #266 stays open — if the tools are still missing, run
`tavotto codex install`. Separately, after a plugin upgrade that left an
older engine in the managed environment, the launcher now says so
(`managed_runtime_stale`), starts a reinstall in the background and asks
you to open a new session, instead of silently running without its full
tool set (#487). Set `TAVOTTO_MCP_NO_AUTO_PROVISION=1` to turn the
background reinstall off. (#548)

**Codex: a folder confirmation that Codex declined on your behalf is no
longer reported as your refusal.** Trigger: Codex Desktop's full-access
permission mode (approval policy `never`) or `codex exec`, where Codex answers Tavotto's confirmation request
itself without showing a dialog. Before: Tavotto said you had declined and
asked you to confirm again, with no dialog to confirm in. Now this is
`workspace_confirmation_auto_declined`, and the message points at the two
ways out: switch Codex to a permission mode that asks for approval, or set
`TAVOTTO_MCP_ROOTS`.
Access is still refused in that case. (#633)

**An aliased import that the script never uses no longer blocks the
figure.** Trigger: `import sympy as smp` where `smp` is never used, and the
rendering environment has no sympy. Before: Tavotto asked you to install
sympy first, and without it the script failed on that line. Now the figure
renders. Only `import X as Y` counts, and only when neither name appears
anywhere else in the script (a script using `globals()`, `eval`, `exec` and
the like is never judged); a plain `import X` is always treated as needed,
because it is often there for a side effect such as registering styles or
colour maps. `tavotto run` is unaffected. (ADR 0061, #555)

**Codex and other MCP hosts: an editing session survives a restart of the
server process.** Trigger: the host restarts Tavotto's MCP server (a
configuration change in Codex, or WorkBuddy recycling its agent between
turns). Before: the canvas's next call failed because the `session_id` was
unknown. Now open sessions are saved and restored by `session_id` after the
project is checked against the current connection's roots; closed or
evicted sessions are not revived. The embedded canvas also no longer treats
a host's plain-text interception as success — it shows the host's message
and keeps the previous image. (ADR 0078, #511)

**Original-size exports are no longer blocked by canvas-placement rules.**
Trigger: a figure wider than the canvas page (or overlapping another
object) exported at original size. Before: the export dialog listed "Out
of page" as a blocking issue and asked you to acknowledge it, although the
canvas page is not part of that export. Now the placement rules
(out-of-page, outside-margin, overlap) do not apply to original-size
exports, and the style-check report uses the figure's own size as its page.
Canvas exports are unchanged. (#596)

**Reverting an AI edit refuses if the script changed after it.** Trigger:
the drawing assistant edited a script, and the script was then edited by
hand, by another assistant session, or deleted. Before: "Revert" wrote the
snapshot back over the later changes and reported success. Now it is
refused (`ai_revert_conflict`) with the script untouched, and the reason is
shown; before, a failed revert showed nothing. (#597)

**Environment problems are reported as what they are.** An interpreter set
in Settings that was deleted while Tavotto was running is reported as
unusable instead of an internal error with a stale path. A project `.venv`
recreated at the same path is checked again instead of being trusted from
before. A missing submodule inside an installed package (for example
`numpy.core._multiarray_umath`) is shown as the script's own error rather
than as a missing package with an install button that could not fix it.
A worker killed between requests is reported one way — how it exited, and
where its log is. (#598)

**Diagnostic bundles keep your project's location, names and error text
out.** The project root is replaced by `<project:hash>` before your home
folder is, so cloud-drive folder names, account e-mails and personal
folder names in the path no longer appear. The bundle's `app.log`,
`recent_errors` and "Copy diagnostics" now come from a separate log written
without argument values: the messages your script raised, file names and
request query strings are reduced to types and short hashes when they are
logged. E-mail addresses are removed in international and punycode forms
as well. The bundle schema is now 3. (#524, #536, #580, #601)

## Fixed

**A legend placed with a preset location no longer jumps the first time it
is dragged.** Trigger: a legend anchored with `loc="upper right"` and the
like, dragged for the first time. Before: it landed a few pixels away from
where you let go (about 6 px for a 6.9 pt legend), because Tavotto measured
text on a 100 dpi bitmap renderer while the canvas draws vector SVG. Now
text is measured the way the canvas draws it, so the legend stays where you
drop it and selection boxes, hit areas and snap guides of in-figure text
line up with the glyphs. Bitmap preview and PNG export still lay out for
pixels. (#576, #579)

**Letting go of a drag no longer flashes "Rendering…".** Trigger: releasing
a drag of a figure element. Before: the "Rendering…" badge lit up on every
release and the figure could blur for a moment while the new version's
embedded images decoded. Now the badge appears only when an ordinary
re-render takes longer than 700 ms (a cold start still says so at once), and
the previous picture — at the dragged position — stays while the new one's
images decode, for at most 250 ms; after that the new picture is shown
anyway. (#575)

**A dragged element no longer jumps back to where it started before
landing.** Trigger: releasing a drag of an element inside a figure. Before:
about 200 ms after release the element snapped back to its old position and
only reached the new one when the next render arrived. (#525)

**Releasing a drag is faster on figures with large embedded images and
long element lists.** On a three-panel figure with a 2340 × 1920 image,
release-to-new-image went from about 260 ms to about 105 ms; React work on
release and when the new image arrives was roughly halved. (#518, #526,
#528, #530)

**Dragging behaves predictably in more cases.**
- Moving a subplot together with its own title (multi-selected) moved the
  title twice as far in the preview and then jumped back; it now moves
  once.
- Dragging something away and back to where it was no longer writes an
  edit, adds an undo step or pins titles out of the automatic layout.
- Undo while the render of a just-finished drag is still on its way now
  removes the preview offset immediately.
- Esc during a drag first cancels the drag without changing the document.
- Zooming the view (⌘= / ⌘− or pinch) during a drag no longer makes the
  element jump.
- Annotation text placed with `textcoords="axes fraction"`,
  `"offset points"` or `"figure fraction"` lands where it is dropped (it
  was off by up to a third of the figure); annotations in coordinates that
  cannot be converted back are no longer offered as draggable.
- In figures using `layout="constrained"` or `"tight"`, dragging a title,
  axis label or annotation now keeps its vertical position, and dragging a
  text no longer moves the subplots.
- Writing a value that is already set no longer triggers a re-render.
(#587, #591, #593)

**The Problems panel no longer reports false font-size and line-width
problems after a figure is resized.** Trigger: a figure saved with
`bbox_inches="tight"` (so the file is smaller than the script's figsize),
or undoing / redoing a resize after the figure's native size changed.
Before: the scale was silently wrong, the Problems panel reported compliant
text and lines as too small, and "Fix all" enlarged them. (#543, #551)

**Objects in figures are recognised correctly.** Subplots with the axis
turned off no longer produce invisible, selectable tick labels and spines.
`pcolormesh` / `contourf` grids that fill a subplot can be used to drag it.
An RGB image next to a stand-alone colour bar is recoloured when you
change that colour bar's colour map or limits, and moves with its subplot;
a colour bar created with `ax=` only claims images in that subplot.
(#527, #538)

**Legends with custom handlers survive editing.** Trigger: a legend entry
drawn by a `handler_map` handler (for example a colour-ramp swatch).
Before: changing the legend's padding, spacing, columns, order or hiding
any entry collapsed that swatch into a flat pale block. Also, a proxy
line's custom dash pattern was replaced by the plotted line's after the
first edit. Both are now kept. (#544)

**Changing an error bar's colour also changes its caps**, unless the
script set the marker edge or face colour explicitly. (#556)

**`np.loadtxt("data.txt")` and `np.genfromtxt` find data next to the
script.** Before: they failed with `FileNotFoundError` in the default
sandboxed mode, although `open()` and `pd.read_csv` worked. (#545)

**Rendering with your own Python no longer breaks the macOS app's code
signature.** Trigger: rendering, health-checking or analysing with a
project `.venv`, a system Python, a configured interpreter or
`TAVOTTO_WORKER_PYTHON`. Before: `.pyc` files were written inside
`Tavotto.app`, after which `codesign --verify` and Gatekeeper checks failed.
Your own modules are still cached as usual. Also: restarting browser mode
on the same port right after closing it no longer moves to the next port
(which lost the "last document" kept by the browser). (#592)

**Writing back to the original file fails cleanly when the disk is full.**
Before: if backing up the second target (the PNG after the PDF) failed, the
PDF was already replaced, a `.updating` file was left behind and the
request ended in a 500. Now all targets are backed up before any is
replaced, and the request ends in 409 `write_back_backup_failed` with the
originals untouched. A worker crash during the verification step is now
a 409 as well, and temporary files left by an interrupted autosave are
cleaned up later. Replacing an original is now flushed to disk first. (#580,
#595)

**Switching projects no longer carries state across.** Render results,
missing-package plans and install progress, the asset list and its "can't be
used" list, and the drawing assistant's conversation from the previous
project no longer appear in the next one, and late replies from the old
project are dropped. Package installs keep running and report back when you
return. Two projects can now rebuild their managed environments at the
same time, each with its own progress; if a rebuild request fails on the
network after the backend already started, the progress is still shown.
(#597, #605, #607, #621, #634)

**Preparing a figure reports the same error as rendering it.** A figure
that the script never produced was reported as ready by the preparation
API and failed only when rendered. Files inside a project's own `.venv`
(libraries, fonts, style files) are no longer listed as the script's data
inputs, where they could crowd out real data. A session left over from a
failed build now asks for folder confirmation again when the evidence
changed, instead of re-running in the old sandbox. (#599)

**`tavotto run`: a figure whose undone edits could not be restored is
locked.** Before: such a figure silently differed from the document. Now
re-rendering the same edits (which retries the restore) is allowed; other
edits, exports, history previews and continue / detach are refused until
it is consistent again, and the canvas says to re-run the original command.
(#626)

**`tavotto run`: Ctrl-C no longer ends with a Tavotto error.** A reset
connection after the parent went away is treated like a normal
disconnect, and a script waiting in `plt.show()` finishes with its own exit
code instead of raising `ConnectionResetError`. (#647)

**Starting Tavotto while another instance is running is quiet and
race-free.** A second `tavotto --port N` that finds Tavotto already on
that port hands over and exits without loading the PDF backend or marking
the running instance's AI sessions as interrupted; that path could crash
on Linux. Two instances started at the same moment no longer both pick the
same free port. On Windows the listening port is now held exclusively.
(#644, #651)

**Four fixes carried over from user reports.** The drawing assistant
started with `FileNotFoundError` for scripts registered in a subdirectory
(#502). The Codex plugin did not find a pipx-installed Tavotto whose path
contained a space (#486). "Building figure…" stayed forever when a render
failed with an unexpected error (#478). The macOS desktop app found no CA
certificates for HTTPS, so update checks and telemetry could not connect;
it now uses the system bundle `/etc/ssl/cert.pem` (#439). (#541)

**Smaller fixes.**
- The tutorial's hint card no longer sweeps across the asset card, where
  the second click of a double-click could land on "Skip this step"
  (#581, #654), and restoring an autosave no longer overwrites the tutorial
  document you just opened (#643).
- Cancelling a drag in the canvas list no longer lets a later drop from
  Finder reorder canvases (#584).
- A 0-byte panel source is reported as `source_unreadable` instead of
  failing the whole export (#517, #580).
- With nothing selected, Tab into the element tree lands on the first row
  (#531).

## Under the hood

- **Export performance.** RenderCore's size probing, PDF writing, preview
  cache and PNG / TIFF encoding were tuned before it became the default,
  and very large exports (for example A4 at 1200 ppi) are rendered in bands
  so memory use does not grow with page size. Measurements, including
  against the previous backend, are in `docs/perf-baseline.md`.
  (ADR 0077; #506, #509, #513)
