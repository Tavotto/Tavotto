# Tavotto 0.21.3

You can now share a figure or layout with a link and collect comments on the
picture, drag leader lines, tables and hand-drawn legend markers on the canvas,
and let your AI repair a script by writing a small launcher or filling in its run
arguments. More of your edits reach the exported `.py`, and journal checks use
newer guideline data. This release also fixes several script, export, font and
startup problems that left figures empty, rotated or stopped with an unhelpful
error.

## Before you upgrade

**Text in canvas text boxes now sits centred in its line, and tall formulas make
their own line taller.** The preview and the exported file now agree; before, the
export placed text about 0.1 em higher than the preview. Existing horizontal text
exports about 0.1 em lower than before, sideways text in vertical text boxes about
0.1 em further left, and boxes that contain a tall formula (a fraction, a sum with
limits) grow to fit it.

**Scripts that set their style inside `if __name__ == "__main__":` now open with
that style.** Before, Tavotto called `main()` directly, so a `plt.style.use(...)`,
`plt.rcParams[...]`, theme or random seed set in that block never ran and the
figure opened with default colours, line widths and fonts. Tavotto now runs such
scripts the way `python script.py` does, so a figure you had already opened may
look different (it now matches the script). Scripts whose block only calls
`main()` are unchanged.

**Phone photos are exported upright.** PDF, PNG, TIFF and SVG export used to
ignore the rotation recorded in the photo, so a portrait photo came out turned 90°
and squeezed. Layouts that already contain such a photo will export it correctly
now. JPEG photos are still embedded in PDFs unchanged.

**Journal checks may show new notes.** For journals whose guideline states a
minimum line width, data lines thinner than that are now flagged. Journals with
newer guideline data are also checked for minimum bitmap resolution and accepted
fonts. Projects already set to such a journal pick this up when you open them.
Requirements that depend on a condition are listed in a collapsed "Needs your
check" group and are not counted as problems.

**Dropping a script now shows only that script's figures.** Dragging a `.py` (or a
notebook, R or MATLAB script) onto Tavotto used to fill the asset panel with every
image in the script's folder. It now lists only the figures that script, and any
script you run afterwards, produces.

**The Chinese label of the right panel's assistant tab is now 助手.** It was
改图助手. The shorter name keeps the tabs on one line at narrow widths now that a
*Review* tab can appear. The feature is still called 改图助手 everywhere else.

## Share a figure for review

**Share a figure or layout with a link.** Press *Share for review* next to
*Export* to turn the figure or layout you are looking at into a link. Whoever
opens it can comment on the picture in a browser (click an element, drag a box,
or leave a general note) without installing Tavotto or signing in. Their comments
show up in a new *Review* tab in the right panel, where you can reply and mark
them done. After you change the figure, *Update this link* adds a new version to
the same link.

- Only the rendered picture and the positions of its elements are uploaded, never
  your scripts, data or file paths, and nothing is sent until you press *Create
  link* or *Update this link*.
- Each device can create one new link per day; updating an existing link is not
  limited.
- Links expire 30 days after the last update, and *Stop sharing* deletes them
  right away.
- Set `TAVOTTO_NO_REVIEW_SHARE=1` to remove the feature and all of its network
  requests.

**Reviewers can pick a single curve, tick label or text.** Clicking a curve on the
review page used to select a large box around the whole plot, and tick labels
could not be picked at all. The review page now picks elements the way the canvas
does: a curve highlights along its own path, a tick label on its own. A comment
shows its pin where the reviewer clicked, and the pin follows the element when you
move it.

**Reviewers can click axis lines, gridlines and tick marks.** Each subplot's axis
lines, gridlines and tick marks can be picked as their own targets, for example
"Left axis line", "X gridlines" and "X tick marks", and a comment on one of them
shows its pin right on it in Tavotto.

## Canvas, layout and editing

**Leader lines can be dragged and reshaped.** A line added with
`transform=ax.transAxes` (for example a dashed leader line from a map point to its
label) used to be treated as a data curve: you could restyle it but not move it.
Lines in axes, figure or inch coordinates now drag like shapes, and the move can
be undone.

- Pressing on one segment drags just that segment: its two ends move together and
  the neighbouring segments stretch, so the line stays connected.
- Selecting the line shows a small square at each bend; drag one to move only that
  point.
- Double-click a segment to add a bend, double-click a bend to remove it. Hold
  Shift to keep a move horizontal or vertical.
- Data curves, `axhline` / `axvline`, lines offset from data coordinates and lines
  with more than 64 points still move only as a whole, or not at all.

**Hand-drawn legend markers and images in axes coordinates can be dragged.**
Markers drawn with `ax.scatter(..., transform=ax.transAxes)`, line and shape
collections in axes or figure coordinates, and images placed with
`imshow(..., transform=ax.transAxes)` could be restyled but not moved, and
clicking anywhere in their subplot also selected them. They now drag and undo like
shapes, and their selection box is just the drawn element. Data scatter plots,
data line collections and ordinary `imshow` images stay put.

**Tables added with `ax.table` can be dragged.** Before, dragging a table only
said it was not supported. It now drags like a shape, cells and text together, and
the move can be undone. Tables placed below a subplot (`loc="bottom"`) can be moved
without pushing the other subplots around.

**Font sizes can go up to 200 pt.** The size boxes stopped at 24 pt for tick
labels, legends and colorbar ticks, 36 pt for other figure text, 96 pt for canvas
text boxes and 72 pt in style presets. Because the panel shows sizes as they appear
on the page, the limit shrank with the figure: in a figure scaled to about 72%,
typing 20 pt for tick labels snapped back to 17.36. All of them now go up to
200 pt.

**Axes aspect, logit scale and colorbar axes.**

- Choosing "Equal" for an axes' aspect no longer switches to "Custom 1.0" after the
  redraw.
- The axis scale menu lists "logit" only when the data or limits fit inside (0, 1);
  before, picking it outside that range made the render fail.
- The axes that holds a colorbar no longer shows subplot properties (scale,
  inversion, grid, spines, face colour) that had no effect or did not undo
  cleanly. It keeps position and visibility, and the colorbar element carries the
  rest. Preflight and style presets no longer treat a colorbar as a subplot whose
  spines need completing.

**Undoing tick-label visibility or arrow colour restores the exact state.** On a
colorbar or a twin axis, hiding the tick labels did nothing because those labels
sit on the right side, and undoing it turned on an extra row of labels on the left
that stayed until a fresh run. Hiding now hides both sides, and undo puts back
exactly the sides the script showed. Undoing a colour change on an arrow whose fill
differs from its edge used to repaint the fill in the edge colour; undo now
restores the edge colour and the fill separately.

**Groups skip objects from a newer Tavotto.** Clicking or marquee-selecting a
group that contains objects written by a newer version no longer selects or moves
those objects.

**Layouts saved by a newer Tavotto open safely.** Upcoming versions add new kinds
of canvas objects, starting with free vector paths. In this version such an object
is kept as it is: the layer list shows it as "Newer object", the canvas draws a
dashed placeholder you cannot select or move, and saving keeps it unchanged.
Export is blocked with a line saying how many objects come from a newer version,
so a figure is never exported with a piece silently missing.

**Opening a layout made by a newer Tavotto no longer shows a blank canvas.** It
used to open empty, and saving then overwrote the original file. The layout is now
left closed and untouched with a note that it came from a newer Tavotto; the
desktop app offers **Check for updates** and the browser version offers **Send
feedback**. A project package from a newer Tavotto says so too, instead of "the
layout in this package is neither schema 2 nor schema 3", for both Import project
package and dropping a package onto the canvas.

**Projects edited in a newer Tavotto open cleanly.** When a project was saved by a
newer version that added a new kind of edit (for example dragging individual
segments of a leader line), this version used to show "property not supported"
warnings. Edits it doesn't recognise are now skipped quietly: the figure opens
normally, everything else applies, and those edits stay saved in the project so a
newer version still shows them. Writing back to the original file is refused with
a plain explanation instead, because the written file would be missing those
edits; update Tavotto, then write back.

**Undoing an axis range change restores the range your script set.** On plots
whose script sets an explicit axis range while leaving autoscaling on (seaborn's
categorical plots, such as bar and violin plots, do this), undoing a change to the
x or y range recomputed the range with matplotlib's default margins. The bars or
violins came back slightly wider, and writing back to the original file could then
be refused because the figure no longer matched a clean replay. Undo now restores
the exact range the script set; if you switched the axis to a log scale in
between, the range is recomputed for the new scale as before.

**Tool hints no longer hide behind notices.** When a notice is showing at the
bottom of the canvas, the hint for the current tool moves up above it.

**Refined workspace surfaces.** Light and dark themes use new surface colours and
page shadows and a 28 px control height. In the export dialog, progress and
completion notices now sit in the right-hand column as plain file cards with
project-relative folder paths instead of spanning the preview. Notices shown
before a dialog opens stay beneath its backdrop. In single-figure editing, the
Canvas tab no longer shows the page settings (preset, size, orientation); they
appear once a second figure turns the canvas into a layout.

## Export

**The exported `_edited.py` carries many more of your edits.** When you tick **PY**
on export, these edits are now written into the script, so running it without
Tavotto draws the same figure. Before, they were left out and the script drew the
element as it originally did. The export says how many edits were left out.

- **Colorbar:** label, colormap, value range, tick size and colour, outline on/off
  and width, and showing or hiding it. Horizontal flip, end arrows (extend), and
  the colormap and range of a colorbar built from a bare `ScalarMappable` cannot
  be expressed in plain matplotlib and are not written.
- **Grid and frame:** grid colour, line style, width and transparency, which sides
  show tick marks, the colour and width of all four frame lines at once, and the
  grid switch on 3D axes.
- **Legend:** title and title size, number of columns, padding and spacing,
  rounded frame, anchor point, and the colour, line style, width and marker of each
  key. Reordering or hiding entries, and restyling keys of error-bar or stem
  entries, are not written.
- **Error bars, stems, bars and scatter:** colour, width, cap size, transparency
  and visibility of error bars; colour, line style, markers and visibility of
  stems; fill, outline, hatch and visibility of a single bar, and a bar series'
  hatch width, hatch colour, bar width and name; scatter size, marker, line style,
  hatch and colour map; curve and series names.
- **Text effects and arrows:** text outline, background box and line spacing
  (including labels in a legend), the axis-label distance on 3D plots, arrow style,
  colour, width, dash style, head size, visibility and layer, dragging an arrow's
  end points, and showing, hiding or re-layering a text box or table you added. A
  dashed arrow still dashes only the shaft and keeps a solid head.
- **Ticks:** fixed tick values or a fixed step, minor ticks and their step, tick
  label format (including scientific notation), tick label visibility, major and
  minor tick width and length, and edited single tick labels. On 3D axes, tick
  width and single tick labels are still left out, and when the export also
  changes the figure or axes size, tick edits that depend on where the ticks fall
  are left out too.

**The export preview can show the figure on a journal page.** The preview pane has
a **Figure | In-page** switcher (原图预览 | 版面预览). In-page places your figure at
true 1:1 millimetre scale on a two-column journal page matching the journal
profile's column widths, with serif body text, equations and a `Fig. 1` caption,
so you can judge font sizes against real print. A **Position** button (换位置)
moves the figure between common placements: top, middle or bottom of a column for
single-column figures, and top, middle or bottom of the page for full-width
figures. Wheel zoom and pan still work. The surrounding text is sample copy for
scale only; exporting still saves just the figure.

**Contour plots whose labels use a formatting function export as editable SVG.** A
figure that labels contour lines with a function, such as
`ax.clabel(cs, fmt=lambda v: f"{v:.1f}")`, used to fail every export with "SVG
pairing is unavailable for custom code in the figure (custom instance attribute
QuadContourSet.labelFmt)". Matplotlib calls that function only while creating the
label text, so Tavotto no longer blocks the PDF + SVG pair for it. Other custom
code on the same contour object is still blocked.

## Scripts and AI repair

**AI repair tries a fix before calling something a Tavotto bug.** When a script
only needed something from your side, such as arguments, an environment variable,
an answer to a prompt or a moved data file, repairing with your AI sometimes
offered to send a bug report instead of trying a fix. It now has to try the
matching fix first, and gets a reminder to act once half its time is used instead
of exploring until it runs out.

**AI repair can add a small launcher instead of giving up.** Some scripts are fine
but never produce a figure when run on their own: their drawing functions are only
defined, or they need data loaded or a setting made first. The AI can now write a
few lines of glue that call your own code, saved in Tavotto's folder inside the
project. Tavotto then runs your script through it and the figure appears in the
same panel as before. Your script and your code folders are not changed, and the
launcher can be undone.

**AI repair fills in a script's run arguments itself.** When a script needs
command-line arguments (for example a required `--data` option), repairing with
your AI used to work out the values and ask you to type them in, or suggest editing
the script. It now sets the arguments and checks that the figure appears. They
show up in the script's run-arguments box afterwards so you can change them. Your
script is not modified.

**Scripts that unpack their arguments in one line ask for them.** A script such as
`data, work, out = sys.argv[1:4]` stopped with "not enough values to unpack
(expected 3, got 0)" when run without arguments, and Tavotto offered an AI fix
that could not supply them. Tavotto now opens the run-arguments entry, the same as
for scripts that read `sys.argv[1]` directly. Other unpacking errors are reported
as before.

**Scripts that report missing data through their argument parser ask for the
file.** Some scripts give every option a default and, when the data file is not
there, exit with their own `parser.error("cannot find data.xlsx, use --input …")`.
Tavotto used to send you to fill in run arguments, which did not help. When the
message names a data file the script just looked for and did not find, Tavotto
shows the missing-data dialog: point it at the file once and the script runs,
without editing it. Errors argparse raises while parsing (a missing required
option, an invalid value) still ask for run arguments.

**Scripts that check a data file's size or date first can be relinked.** When a
script builds a data path and checks it before reading (`path.stat()`,
`os.path.getsize`, `os.path.getmtime`, or `os.listdir` on a folder) and the file
or folder is gone, Tavotto reports the data as missing instead of a generic script
error. You can point it at the right file once, and the AI repair assistant can
link the file you chose; before, the link was refused with "not a path this script
was found to be missing".

**Pasting a command with Windows paths keeps the backslashes.** Pasting
`python plot.py --input F:\data\t1\a.xlsx` into the script arguments box on
Windows used to drop the backslashes (the path became `F:datat1a.xlsx`). Quoted
paths with spaces and `"C:\dir\\"` style trailing backslashes work too. macOS and
Linux are unchanged.

**Running a file that only defines plotting functions points you to the script
that calls them.** If you opened and ran a helper module from a larger codebase,
Tavotto installed its dependencies, ran it, and then said no figure was produced,
offering an AI fix that could only invent data. Tavotto now recognises such a file
before running it, without installing anything, and looks through the project and
the code repository it belongs to for a script that imports it. The card names that
script and offers "Run it" (or "Open and run" when it lives outside the project,
which opens that repository folder first). "Run anyway" stays available. When no
calling script is found, the card says the file only defines plotting functions.

**Figures drawn by a function come out when Tavotto switches to your own Python.**
Some scripts only define drawing functions such as `make_map()` and never call
them. When such a function saved a figure and then read the file back, the safe run
stopped, Tavotto switched to your own Python, and that run ended with "no figure"
because nothing called the function. The switched run now calls the same function.
If the function is no longer in the script, Tavotto skips the pointless second run
and shows the original card.

**Scripts that import a helper from a parent folder run right away.** If a script
adds a parent folder to `sys.path` and imports a helper from it (for example a
shared `figure_style.py`), Tavotto could stop with "1 library's source can't be
determined yet" and wait for you to click Run anyway every time, when your own
Python had certain add-on hooks installed. It now runs these scripts first and asks
only if the module really can't be found.

**Scripts that ask for a desktop plotting window now run.** A script starting with
`matplotlib.use("TkAgg")` or `"Qt5Agg"` used to fail when the Python in use had no
desktop window toolkit, and switching Python did not help. Tavotto never opens
windows, so it now keeps a non-interactive backend in that case, in safe mode or in
your own Python. Scripts that choose a file-based backend such as `pdf` or `svg`
are left as they are.

**A picture saved under the wrong extension says so.** If a script fails to read an
image because its contents don't match its extension (for example a JPEG saved as
`.png`), the failure card says exactly that in one sentence, and the AI repair
assistant gets the same fact. Neither your script nor your image is changed.

**Scripts using pygal world maps install in one click.** A script importing
`pygal_maps_world` got "Tavotto doesn't recognise it", and typing the package name
`pygal` installed fine but still could not be imported, because world maps are a
separate package. Tavotto now recognises both and installs the right one.

**Missing packages can go into the Python you chose for the project.** If you
picked your own Python and Tavotto's managed environment installed a missing
package but still failed its final "environment can't run" check, the one-click fix
kept offering the same install and you waited 30–50 seconds each time for the same
failure. Tavotto now offers to install the package into the Python you chose (it
asks first, since this changes your own environment, and never does it
automatically). If you have no such Python, the card no longer offers the doomed
install as its main button and points you to choosing another Python.

**Figures from an ended run say so and offer "Run again".** A figure made by
running a script with your own Python can only be edited while that run is alive.
After reopening Tavotto, clicking one showed "Render failed". It now shows "Run
ended" with a "Run again" button that runs the script the way "Open and run" does.

**Figures that use macOS Helvetica at small sizes open under your own Python
too.** The fix for "failed to load glyph" at 5 to 7 pt only covered safe mode. It
now also applies when the script runs with your own Python (for example scripts
that save a picture and read it back), and a failure now reports the real reason
instead of just "no figure was drawn".

**A converted script's candidate no longer flickers out of view.** When "ask the AI
to align once more" produces nothing better, Tavotto puts the previous candidate
back. During that restore the card could briefly report the candidate as missing or
not ready; it now stays in place and readable.

**The figure list no longer fails when a file disappears during a refresh.** If a
script was rewriting its output while Tavotto refreshed the project, a figure file
could vanish between being listed and being read, and the whole list failed to
load. That file is now skipped and the rest loads.

**Dropping a script shows that script's figures, and one figure is one card.**

- R and MATLAB scripts count the same way as Python: Tavotto reads (never runs) the
  file names they save to (`ggsave`, `pdf()`, `png()`, `file.path(...)`, `saveas`,
  `exportgraphics`, `print -dpng`) plus a same-named `.R` / `.m` next to the figure,
  so dropping `plot.R` shows the figures `plot.R` saved.
- Figures already used in the layout always stay visible. Opening the folder itself
  (folder drop, folder picker, new project) still shows everything, and reopening
  from the recent list keeps whichever view you had.
- The same figure saved as PDF, SVG and PNG (also in `pdf/`, `png/`, `svg/`
  subfolders) is one card. The canvas uses the PDF when there is one, otherwise the
  largest bitmap; an unedited SVG is used only when it is the only file.
- Whether a figure can be edited no longer depends on which format you placed: an
  untouched PNG of a script-made figure that also has a PDF/SVG enters element
  editing through that vector file instead of failing the pixel-exact PNG check.

**Scripts inside a package that use relative imports now run.** If a script lives
in a package (a folder with `__init__.py`) and imports its neighbours with
`from .helpers import tidy`, running it as a plain file always failed with
"attempted relative import with no known parent package". Tavotto now recognises
this shape and runs the script the way `python -m plots.fig` would, in both the
safe and the real-Python modes, while keeping the figure under the same script
name as before. Scripts that already run, and the `tavotto run` terminal command,
are unchanged.

## AI connections

**A connection that stops working says why and offers the one fix that helps.**
When an AI connection fails, the connection list and the failed-task card say what
went wrong in a few words (the key is wrong, the quota is used up, the model does
not exist, or the address cannot be reached) and offer the matching action:
re-enter the key, switch to another AI, change the model, or check again. Custom
addresses you added now appear in the "Connect an AI" list with the same status and
button, and saving one no longer asks which protocol it uses.

**Custom AI addresses: the protocol is detected when you save.** Custom connections
that could list models but never completed a task now work in more cases. When you
save an address, Tavotto sends one very short test message to find out which
protocol it speaks, and relays that only offer OpenAI Chat Completions are now
supported. If nothing works, the connection is still saved and shows the reason.

**Custom addresses without a model list no longer show as broken.** Relays with no
model list endpoint were shown as "connection error" right after saving even though
the test message had gone through. They now show as ready, and the extra model
names you enter are kept.

**Relays that reject an optional field no longer stop the AI on the first
request.** When a third-party endpoint (for example a one-api or new-api relay)
rejects the first request because of an optional field such as `include` or the
reply length limit, the built-in assistant retries once without that field (or with
the other name for the length limit) and keeps that choice for the rest of the
task. Endpoints that reject the key or are out of quota still stop at once with the
same message as before.

## Journal standards

**Journal checks use newer guideline data, with the original text on source
cards.** For journals that have newer guideline data, Tavotto also checks the
plain requirements it can judge and, when old and new data state the same item,
uses the newer one. Source cards show a screenshot of the guideline text with the
sentence highlighted. Requirements that depend on a condition, or that Tavotto
cannot check yet, are listed in a collapsed "Needs your check" group at the end of
the problem list. If the newer data cannot be loaded, checks work as before.

**Journals that only have newer guideline data can be picked.** The journal list
now includes them. Picking one checks the plain requirements it can judge and
lists the rest under "Needs your check"; items the guideline does not state are
left unchecked.

**Journal checks flag data lines that are too thin.** For journals whose guideline
states a minimum line width with no conditions (for example "at least 2 pt"), data
lines thinner than that are flagged, measured at the final size on the page. Only
data lines are checked (curves, bars with a visible outline); axes, ticks, grid
lines and legend frames are not.

**Requirements show whether a rule is required or recommended.** When the catalog
marks it, the requirements list and the source card show a small grey "Required" or
"Recommended" next to the value. Preflight checks and their severity are unchanged.

**Outside mainland China, journal catalog updates use the overseas server
directly.** The old overseas address answered with a redirect that Tavotto
deliberately does not follow, so every update attempt failed once before falling
back to the China server. Tavotto now uses the address that answers directly.
Mainland China users and the update contents are unchanged.

## AI agents (MCP)

**Opening Tavotto from the Codex desktop app on Windows works again.** On some
Windows machines, asking Codex to open Tavotto failed with an error about a
missing `ai_catalog.json`, even though Tavotto opened fine on its own. This
happened when Tavotto had once been installed or updated from inside Codex, which
leaves an incomplete copy in Codex's private folder. Tavotto now notices when it is
started from such a copy and switches to your real installation instead.

**`tavotto_make_journal_ready` delivers a journal-ready figure in one call.** Give
it a figure and a journal and it opens the figure, fixes it to that journal's
rules, runs the pre-export checks and exports the files, then reports what changed,
what is left and where the files are. If a step fails it stops there without
exporting and says what to do next; if the checks still need your confirmation it
asks you instead of exporting anyway. The session stays open afterwards. It appears
whenever the built-in journal library is switched on.

**Edits an agent made but did not export are kept as a draft.** Before, closing a
figure session (or closing it to make room for another) threw the edits away. Now
they are kept as a draft and opening the same figure again brings them back; edits
that no longer fit because the script changed are skipped and listed. Your original
script is never touched, and the draft is cleared as soon as the figure is
exported. Open the figure with `discard_draft` to start from the script as it is.
Closing a session that still has unexported changes now says plainly that they were
dropped, and the one-step journal fix reminds the agent to export before closing.

**Agents no longer need to close and reopen a figure after editing its script.**
When an agent edits the plotting script, its next call (open, preflight, export and
so on) reruns the same session with the new script and keeps the edits it already
made; any edit that no longer fits is skipped and listed. Before, the session kept
running the old script, so agents reopened figures more than four times each on
average in our evaluation.

**Failed tool calls tell the agent what to do next.** Failed results now carry a
short `next` step: the exact tool call to make, a note that the script itself has
to change, or a question to put to you with the choices filled in. When "make this
figure meet the journal's rules" cannot finish, it names the rule, the element and
the two requirements that clash, and the property involved when there is one. Error
codes are unchanged. `tavotto_fix_to_journal` also says which step got stuck and
which elements were in the way (for example an inset that would be pushed out of
the figure at the new width), and for the figure-size step tells the agent to change
`figsize` in the script rather than force the size with overrides.

**Agents can open scripts that read back the figure they just saved.** When a
script saves a figure and reads that file back (`savefig("fig.png")` then
`Image.open("fig.png")`), `tavotto_open_figure` used to stop with
`safe_file_operation_blocked`. It now runs the script once more in a real Python,
as the desktop app already did, and the result says `execution: "native"`. Files
the script writes then go to disk for real and are not limited to the authorized
folders. Choosing "safe mode only" in the project, or setting
`TAVOTTO_EXECUTION_FALLBACK=0`, turns this off.

**Agents can start without the usual warm-up calls.** The first figure an agent
opens now reports the Tavotto version and any available update, and the tool
descriptions state the rules directly, so no health check or usage guide is needed
first. A journal can be given by name (for example "Nature" or "Nat Commun",
ignoring case and punctuation): a single match is used and reported back, several
matches are returned as candidates, and an unknown name returns the closest
suggestions.

**Agents can read journal requirements with their sources.** When a verified facts
catalog is available, the agent can read versioned requirements together with their
sources, submission stages and conditions; requirements for different kinds of
figures stay distinct. Existing preflight keeps using its current rules and the new
facts are not applied automatically.

## Data to figure (experimental, off by default)

These changes sit behind the `ai.taf.enabled` experiment switch, which is off by
default. Nothing changes while it is off.

**Draw a figure straight from a data file.** The home screen offers a second way in
for people who have data but no figure yet: pick a folder of data and Tavotto lists
the tables it found in a "Data" section of the left rail. Click a data file and a
temporary tab opens next to your figures. Tavotto proposes a few ways to draw it,
shows their names right away and fills in the thumbnails one by one from your real
data. The side panel shows which columns were used (X axis, Y axis, grouping, and
what happens to cells that are not numbers) so you can change them, and the data
sits in a strip underneath. Click one candidate and the tab turns into the real
figure, with a new script written next to your data in `tavotto_figures/`. Your
data files are never changed, and the temporary tab is not part of your project.

**It starts from sensible defaults.** Candidates are listed straight away with the
recommended one first, and each preview appears as soon as it is drawn. The flow no
longer stops to ask which column to use or what to do with text cells inside a
number column: it takes the last numeric column as the measured value, leaves text
cells out and uses the detected header row, and tells you which columns it used. A
preview that cannot be drawn is left out.

**Plot several files at once.** Once there are at least two plottable data files, a
"Select" button appears in the "Data" title row. Pick files by clicking them
(Cmd/Ctrl+click and Shift+click for a range also work). The panel has two buttons.
"Plot each" makes one figure per file using the recommended way to plot it; waiting
files say "Queued", the current one spins and finished ones say "Done"; "Stop"
finishes the current file and leaves the rest. The new figures appear as cards in
the asset library and none is opened for you. A file that can't be plotted is marked
"Failed" (hover for the reason, click to open it on its own), and the panel offers
"View assets" and "Retry". "Plot combined" puts up to 8 picked files with the same
columns in one figure, one group per file, and opens the usual choice of ways to
plot it in a temporary tab; if the columns don't match it says so and offers "Plot
each" instead. The new script is created next to the data files in
`tavotto_figures`, and reads the original files each time it runs.

**Preview a data file before drawing.** A text table or one sheet of an Excel
workbook can be previewed: column names and types, the number of rows and columns,
the first rows as written, and any description lines skipped above the header. When
the header row was not recognised, picking a different row re-reads the table right
away. The list of Excel sheets reports each sheet's row and column counts. Scripts
Tavotto generated from a data file now say which file (and sheet) they came from,
so a figure can be grouped under its data.

**More kinds of data files.**

- Plain-text tables (`.txt`, `.dat`, `.asc`): Tavotto works out the separator
  (comma, tab, semicolon or runs of spaces), skips the description lines many
  instruments write at the top and finds the row that names the columns. When it
  cannot tell which row that is, it says so and lets you pick. Files that are not
  tables are reported as unreadable.
- Thousands separators such as `1,000` are read as numbers. In semicolon-separated
  files a number containing a comma is never converted automatically, because
  `1,234` there usually means 1.234; you are asked what to do with it.
- Instrument exports with a title, a note line such as `operator: lab`, the column
  names and a units line (`nm  a.u.`): the column names now come from the line next
  to the units and the units line is no longer read as data. Before, the note line
  was picked as the header and only histograms were offered.
- GROMACS / Grace `.xvg` files: column names come from the axis labels and legends,
  and common Grace markup (superscripts, subscripts, Greek letters) becomes plain
  text. If a file holds several data sets separated by `&`, only the first is drawn.
- Text tables saved as GBK / GB2312 / GB18030, or as UTF-8 / UTF-16 with BOM, are
  read correctly, including Chinese column names and group values. Tavotto decides
  the encoding once (BOM first, then strict UTF-8, then strict GB18030) and the
  generated script uses the same one; other encodings are reported as unreadable
  rather than guessed. The overview and file list show the encoding used.
- Pasted tables, CSV data and numeric grids use the same cell rules: `1_000` is
  read as 1000, `NaN` is a missing value (so a column containing it is no longer
  offered as a category column), and `Infinity` or overflowing literals such as
  `1e999` are reported as non-finite values. Tables over 100,000 rows or 64 columns
  are rejected as a whole, never read partially.

**No automatic footnote under the plot.** The generated figure no longer prints a
note such as "n non-numeric cells ignored", the definition of a summary ("mean ±
SD") or fitted line, or the sample size. The plot itself is unchanged, the space
reserved for the note is gone, and the details are in the side panel. When groups
have different sample sizes, n still appears in the tick labels.

**Smaller fixes.** If the data folder can't be written to (read-only folder or
drive, no permission, full disk), creating the figure now fails with a specific
message and nothing is left behind. When a data file already has dozens of figures
drawn from it, drawing another no longer runs out of names, and if a name ever
cannot be found the failure shows only its explanation without a "try again"
button. The list of data files reads the disk at most once more after a burst of
file changes. The candidate tiles in light theme use the same warm tint as the
rest of the workspace.

## Failures, startup and diagnostics

**Three more dead-end messages now have a button.** When a figure handed over from
your editor has not been run yet, the message has a "Run" button that runs the
script and puts the figure on the canvas. When the figure you are editing loses its
script, it offers "Relink script", which opens the project status page on that
figure. When a project fails to open or be created, the message names the project:
if the folder cannot be found, "Choose folder again" opens the folder picker (the
project stays in your recent list, so an unplugged drive is not forgotten); a failed
creation says so and offers "Try again", as does any other open failure, followed by
"Send problem report" if it fails a second time. The "copy" button on that message
copies the sentence plus the original error text. Message pills at the bottom of the
window now grow with their sentence (up to 560 px) instead of cutting it off at
360 px.

**A broken last project no longer stops the desktop app from starting.** If the
project Tavotto reopens at launch had a damaged settings or state file, the
background service could quit before the window appeared and "Restart" led to the
same error every time. Tavotto now opens the project picker so you can choose or
recreate the project. When the service does quit during startup, the minimal
startup report sent from the error page also records which startup step it reached
(the same fixed list used for startup timeouts; no log text).

**When antivirus software removes or locks Tavotto's files, the error page offers
to reinstall.** Windows used to show an English "Unhandled exception in script" box,
and the app then sat for a minute before an error page whose "Restart" could not
fix it. Tavotto now quits that failed start straight away and checks whether its
installed files are all present and readable. If some are missing or blocked,
"Reinstall Tavotto" becomes the main button, with the existing advice to add Tavotto
to your antivirus trust list. The startup diagnostics record only the result of the
check (intact, missing, unreadable or unknown), never file names.

**Projects with more than three script figures no longer re-run scripts you just
opened.** On machines with enough memory Tavotto keeps up to eight script figures
ready, but its background process still closed every figure beyond the third. In a
project with four or more script figures, switching back to a figure you had just
opened often re-ran its script, and saving or exporting could lose the export-ready
copy ("The existing Figure session expired; SVG capture cannot rerun it" in the
log), so an SVG export could fail. Figures Tavotto keeps ready now stay ready.

**Fonts with punctuation in their names are kept as written, and write-back never
overwrites an outside edit.** Installed fonts whose family name contains Fontconfig
punctuation (a hyphen as in `DFYanKaiW7-B5`, or a colon) are passed to Matplotlib as
literal names instead of being replaced by a fallback or used to select a file.
Math text keeps the chosen weight and style, including in exported `.py` scripts.
While an edit is written back to a script, the source file's content is checked
before the backup and before each replacement. If it changed in the meantime, even
with the same length and modification time, the write-back stops and reports that
the original changed, leaving the other version untouched. If the source cannot be
read while preparing, it stops and reports that the original could not be verified
instead of skipping the check. Verification reads the whole file each time, so
write-back of very large files takes longer. Thanks to kingside33 for the font fix.

**Feedback bundles include more of what is needed to trace a problem.**

- When the selected figure came from a script run with your own Python, the
  "render environment" section used to contain only an internal error. It now
  records that interpreter and its environment.
- If a script adds a shared code folder to `sys.path` and imports a helper from
  there, ticking "script source" now also includes the local Python modules the
  script really loaded from outside the project folder the last time it ran, even
  if you restarted Tavotto before sending the report. Third-party packages and
  Python's own modules are never included, and nothing changes when "script source"
  is not ticked.
- When installing missing packages into a Tavotto-managed environment finishes but
  the final self-test fails, the bundle records which step failed (could not start,
  timed out, returned an error, or exited without replying), the exit code, the
  stable error code, the exception type and frame categories, and the Tavotto
  engine source line. Error text, paths and file names are left out, and the README
  in the bundle says so. Bundle schema is now 16.

## For developers

These pieces are not switched on for users yet.

- **Static SVG foundation.** The proposed SVG layer records stable nodes, physical
  dimensions and nested transforms, and translates supported paths, text, images,
  references, clips and opacity into the existing RenderCore representation.
  Unsupported expressions produce explicit errors. CJK fallback uses the resolved
  font family and weight.
- **Explicit SVG chart bindings.** A closed chart model associates axes, series,
  data and legends explicitly. Matplotlib calculates the bound region and the
  compositor preserves unbound annotations and decoration. Fixed chart requests use
  the existing worker pool, v1 envelopes, shared capacity accounting and sandbox
  guards, and Python and workerd apply the same payload budgets and lifecycle;
  older supervisors fall back to the Python pool. Charts rendered with
  `native-manifest/2` publish their display frame only inside
  `manifest.render_frame`, and new frame fields require `native-manifest/3`. Older
  builds reject `/2` with `chart_model_unsupported` and keep the previous render.
