Magplot is now **Tavotto**. Same tool, same figures, new name — another
company was already using the old one. This is a clean break rather than a
compatibility layer, so two things need a hand from you: the desktop app
will not update itself into this release, and the `magplotfile/` folder
inside each of your projects needs renaming. One step each, both at the
bottom under Upgrading.

Beyond the name: the interface now speaks English, you can edit a figure
without leaving Codex, exports are checked against a journal's publication
standards before they are written, the macOS app brings its own rendering
runtime so a fresh Mac needs no Python at all, and clicking something inside
a figure now follows the shape that was actually drawn instead of the box
around it.

## Renamed to Tavotto

**The name follows everywhere.** The package on PyPI is `tavotto`, the
command is `tavotto`, the app is Tavotto, project packages are `.tavotto`,
and settings, caches and layouts live in a `Tavotto` folder in your user
data directory.

**Two things carry over on their own**, because they are files and settings
on your disk that we have no business rewriting behind your back. The script
registry in a figure library is still read as `mm_registry.json` and written
back as `tavotto_registry.json` the first time it is merged, and
`MM_WORKER_PYTHON` is still honoured alongside its new name
`TAVOTTO_WORKER_PYTHON`.

**Everything else stops at 0.7.0.** `.magplot` project packages, the
`magplotfile/` folder inside a project, the old user data directory and the
browser-side state saved under the old name are not read. There is no shim
for any of them: a version that recognises some of the old names but not
the others is harder to explain — and to trust — than one that recognises
none. Nothing is deleted, so a copy of 0.7.0 can still open what it wrote.

## Added

**The interface speaks English.** Every screen, menu, dialog and error
message exists in English and Simplified Chinese, including the desktop
app's native menu bar. The default is still Simplified Chinese; a language
you pick yourself wins over your system's, and the choice is stored per
machine rather than inside a document, so sharing a figure never drags your
interface language along with it. What is deliberately not translated: your
own content — project, canvas and file names, text inside figures, anything
matplotlib prints — and diagnostic material like tracebacks and logs, which
are only useful verbatim.

**Edit a figure without leaving Codex.** The Codex plugin now ships an MCP
server and an embedded canvas, so a figure Codex just wrote can be opened,
adjusted and exported in the conversation. The canvas is the same code the
app uses — the same dragging, hit-testing, snapping, undo and patch
handling — not a reduced second implementation that would drift. Note one
honest gap: the protocol and the canvas both have automated coverage, but
rendering the canvas inside Codex Desktop itself has not been verified on
real hardware yet.

**Exports are checked against publication standards.** Before a figure is
written, it is checked against a versioned profile: font sizes, page widths,
raster resolution and a set of data-presentation suggestions. Font size is
judged at its **final physical size** — a panel scaled to 60% is measured at
what a reader would actually put a ruler against, not at what the script
declared. Findings come in four levels: errors block the export until you
explicitly confirm, warnings are always shown, *cannot be verified* covers
things no checker can see (text baked into a bitmap, say) and also asks for
confirmation, and suggestions are never decided for you. Whatever you
confirmed is recorded in the proof file written alongside the figure. A
journal's own numbers can override the defaults.

**The macOS app brings its own rendering runtime.** Like the Windows
installer since 0.3.0, the macOS app now contains a private Python with the
scientific stack already in it: install, open a figure, render — no Python
of your own, and no download on first use. If you have set your own
interpreter it still wins; the bundled one is only used when nothing you
chose is available. Apple silicon only for now — there is no Intel build,
and the app says so rather than failing at the first render.

**Selecting follows the shape that was drawn.** Curves, `fill_between`
regions, `ax.fill()` polygons and patches now report the path matplotlib
actually drew, and clicking, marquee selection and the selection outline all
use it. A diagonal line is selected by its line, not by the mostly-empty
rectangle around it, and dragging a marquee circles ink rather than poking
into a box. Scatter points and marker-only lines still fall back to their
bounding box; that gap is known and recorded rather than papered over.

**Ticks, spines and colourbars became editable.** How many ticks there are,
where they fall and how they are written now goes through matplotlib's
locators and formatters instead of the text objects it regenerates on every
draw — so the change survives a redraw, an undo, a write-back and a reopen.
Minor ticks can be turned on with or without numbers, and a single tick
label can be retyped. Frame lines can be set all at once or one side at a
time, and undoing one side falls back to whatever the level above says
rather than freezing today's value. Colourbars can be flipped between
vertical and horizontal and given end-extension triangles, in place, landing
exactly where matplotlib would have put them had the script asked for it in
the first place.

**Handing a figure over works when only the desktop app is installed.** The
desktop build now also ships `tavotto-cli`, a console executable beside the
app, and the Codex plugin knows to look for it. Previously the plugin could
only find a pip or pipx install, so on a machine with just the app it
reported that Tavotto was not installed.

## Fixed

**macOS never received in-app updates.** The update manifest was assembled
from whichever build finished first, and only the Windows half ever made it
in. The macOS app therefore reported "up to date" indefinitely — with a
green build, which is why it went unnoticed for a release. The manifest is
now built after both platforms finish, and refuses to publish a half one.

**Two drags in a row, and the first one vanished.** Dragging an element
inside a figure, then dragging it again before the first render came back,
silently discarded the first move: the second gesture was measured from an
anchor that predated it. Nothing reported an error and nothing looked
wrong — the element simply ended up somewhere other than where you had put
it. The heavier the script, the wider the window in which it happened.

**Canvas housekeeping was not saved.** Renaming, deleting, duplicating or
reordering a canvas never marked the document as changed, so autosave did
not run. If you did any of it and closed the app without touching the active
canvas afterwards, the work was gone.

**Opening a document rewrote it.** A second after a document was restored
from disk, autosave mistook the load for an edit and wrote the file back
with a fresh timestamp. Harmless on its own, but with the same document open
in another tab it was enough to trigger a stale-write conflict.

**A failed canvas export left the figure in the wrong state.** Composite
export applies each panel's own overrides to a live figure and restores them
afterwards. The restore was only guaranteed around the final save step, not
around the two steps that actually fail — an unwritable target folder, a
path too long, a file held open on Windows — so one failure meant every
panel after it drew with someone else's settings.

**Windows: `tavotto open` died on Chinese text.** The lightweight entry
point dispatched `open` and `doctor` before standard output was switched to
UTF-8, so the first path or message containing Chinese characters killed the
command with an encoding error. The caller saw a crash instead of the
message explaining what to do.

**A hand-edited registry could take the CLI down with it.** A
`tavotto_registry.json` that was valid JSON but the wrong shape raised
straight through the error contract, so `tavotto open --json` printed a
traceback where its caller expected one line of JSON. It now reports a
proper error code. Relatedly, the registry is written atomically — killed
mid-write it used to leave invalid JSON in your figure library, which
reinstalling the app would not fix.

## Upgrading

**Desktop.** Uninstall Magplot first, then install Tavotto from this
release. The application identifier changed with the name, so this one
release cannot install over its predecessor; from 0.8.0 onward in-app
updates resume as normal. Your projects and figures are untouched by the
uninstall.

**pip / pipx.** The package name changed, so `pip install -U magplot` will
never find this release:

```bash
pip uninstall magplot
pip install "tavotto[worker]"
```

**Codex plugin.** The marketplace moved with the repository:

```bash
codex plugin marketplace add Tavotto/Tavotto && codex plugin add tavotto@tavotto
```

**In each project**, rename the folder holding your named canvases, exports
and version history:

```bash
mv <project>/magplotfile <project>/tavottofile
```

**Settings, recent projects and layouts** kept in your user data directory
are not migrated. The old folder is still there if you need something out of
it — `~/Library/Application Support/Magplot` on macOS,
`%LOCALAPPDATA%\Magplot` on Windows, `~/.local/share/magplot` on Linux —
with `Magplot` replaced by `Tavotto` for the new one.
