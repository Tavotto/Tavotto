# Tavotto 0.21.2

Tavotto now follows the journal you picked through Settings, export, styling and
the AI assistant. Failure messages end with a button that does the next step,
animated hint cards teach gestures that are easy to miss, and you can drop
images, notebooks and files onto the canvas or into the AI assistant. This
release also fixes several script, export and Windows problems that left figures
empty or stopped with an unhelpful error.

## Before you upgrade

**Dragging an uncropped figure's edge inward in a layout now resizes it.**
Previously it cropped the figure and stopped at the content edge. The figure now
re-renders at the smaller size with the same text size, like dragging outward. If
the text no longer fits, a notice offers to scale the text down just enough to
fit the frame. Hold ⌥ (Alt) while dragging an edge to crop instead.

**Export starts from the journal's requirements when the project is checked
against a journal.** Resolution starts at the journal's highest stated value (for
example 1000 dpi for Elsevier line art) unless your own default is higher, and a
format the journal does not list is swapped for one it does (PDF + PNG becomes
PDF + TIFF). Formats the journal does not list stay selectable and show a small
dot; hovering explains why.

**Switching away from a journal now asks first.** This applies to the "Spec"
dropdown under Checks and to the spec library in Settings. Before, the journal
could be dropped silently.

**A script that finds its data next to itself is now run again in the script's
folder without asking.** This happens only in projects where you have not picked
a working folder yet. If you chose "Sandbox" in Settings, Tavotto leaves it alone
and shows the "Run in the script folder" button as before. The script runs twice
that first time and once afterwards. You can switch back to Sandbox in Settings
at any time, and files are protected exactly as when you click the button
yourself.

**Opening the same layout in a second window now asks which window edits it.**
The second window shows a card in the middle of the canvas instead of letting
both windows overwrite each other. "Save as..." now really makes a new layout,
leaving the original untouched.

**Animated hint cards appear in the bottom-right corner of the window.** Each
shows at most twice and never again once you have used the gesture or closed the
card. Turn them all off under Settings › General › Action hints.

**Dropping or pasting an image onto the canvas copies it into your project
folder.** It is added as a normal figure and never overwrites a file that is
already there; a same-named file with different content gets a "(2)" name.

**EPS export asks first when an annotation is semi-transparent.** Nothing
changes when nothing is semi-transparent.

**Background updates in mainland China can use one more download server.** The
update is still verified with the signature built into the app. Checking for
updates and downloads you start yourself behave as before; users outside
mainland China are not affected.

**Plots you already moved inside a subfigure may sit in a slightly different
place.** Dragging a plot inside `fig.subfigures(...)` now moves it the full
distance. In projects saved earlier where you had already moved such a plot, that
plot will show in a slightly different place when reopened; drag it back once and
save.

## Journal standards across Tavotto

**Export follows the journal you picked.** When a project is checked against a
journal, the export dialog starts from that journal's requirements (resolution
and formats, as described above). The "Spec" dropdown under Checks now shows the
journal's name instead of being blank.

**Adjust a figure's style to the journal in one step.** When the figures on the
canvas use font sizes, fonts or line widths the journal does not allow, the Style
panel shows a line such as "4 not matching Nature Chemistry" with an "Adjust to
journal" button. Hovering lists each change (for example "Ticks size 8 → 7 pt").
One click raises sizes below the journal's minimum, lowers sizes above its
maximum, thickens lines below its minimum width and switches to a font the
journal accepts when one is installed. If the canvas follows a style, that style
is updated; otherwise a new style named after the journal is created and
followed. One undo reverts it.

**The spec page no longer shows default numbers under a journal.** Settings ›
Journal spec used to show the journal's column widths at the top but the default
spec's 80 / 150 mm further down, so it looked like two sets of rules were in
force. The spec library now opens on the journal itself and lists the values the
project is actually checked against; anything the journal does not specify reads
"Not specified" followed by the value used instead. "Duplicate to edit" copies
the journal's rules into a spec you can change.

**See which journal a layout is checked against.** The journal's name appears as
a small chip next to the layout name in the top bar. Clicking it opens Settings ›
Journal spec. Narrow windows show only the icon.

**The figure assistant knows the journal you picked.** Requests to the assistant
now include that journal's figure requirements (font size range, accepted fonts,
minimum line width, figure widths, minimum resolution), so "make this meet the
submission requirements" works from the journal's actual numbers instead of
guesses. Projects without a journal send the same request as before.

**The page-width check now covers journals that only state a maximum width.**
Some journals (for example JACS) give only a maximum width for each column, and
the pre-submission check used to skip the page-width rule for them: a 228.6 mm
wide figure passed without a word. The check now flags a page wider than the
journal's largest stated maximum ("the page width 228.6 mm is over the profile's
maximum width, 177.8 mm"). Journals with exact column widths are checked exactly
as before; when a journal states both, either one is enough to pass. For a
journal that only states a maximum width, the problems panel also offers a
one-click change to that maximum column width.

## Canvas, layout and gestures

**Animated hint cards teach hidden gestures when you need them.** Tavotto shows a
small animated card when it sees you doing something the slow way:

- The canvas has drifted mostly out of view: double-click empty space to
  recenter.
- You just resized a figure by its edge: hold ⌥ (Alt) to crop instead.
- You moved objects several times in a row without any guides: drag alignment
  guides out of the rulers.
- You change a figure's text from the sidebar: double-click the text itself.
- You draw an almost-square rectangle or an almost-level line: hold ⇧.
- You pan a zoomed-in canvas one wheel notch at a time: hold Space and drag.
- You change the same style property on one element after another: ⇧-click to
  select them all first.
- After a couple of days of use, four modifier gestures are covered too. Dragging
  in an almost perfectly straight line suggests ⇧ to lock the axis; a tiny
  correction right after an object snapped suggests ⌘ (Ctrl) to skip snapping;
  three tiny drags in a row suggest the arrow keys (⇧ for big steps, ⌥/Alt for
  fine ones); stopping a rotation just short of a 15° step suggests ⇧ to snap.
- Once you have picked up five gestures, a last card points to the full shortcut
  list (press ?).

**Drag or paste images onto the canvas.** Drop a PNG, JPG, TIFF, PDF or SVG file
onto the canvas, or paste a screenshot with Cmd/Ctrl+V. Dropping several files
handles each one by type and ends with one summary line. Project packages
dropped on the canvas open like "Import project package", and a script that is
outside the current project now offers "Open its project" instead of asking you
to go back to the home screen. Anything that cannot be added says so in one
sentence with a button to send feedback.

**Open a Jupyter notebook like a script.** A `.ipynb` file no longer dead-ends.
Drop one on the home screen or on the canvas, or press the new "Turn into a
script and run" button on a notebook listed under "Jupyter notebooks" in the
script list, and Tavotto turns the notebook's code into a plain `.py` next to it
and runs that.

- Markdown cells are kept as comments, and notebook-only commands such as
  `%matplotlib inline` or `!pip install ...` are commented out with their
  original text kept.
- Notebooks that call `display(...)` or `get_ipython()`, or import from IPython,
  still run when IPython is not installed (quiet stand-ins are added to the
  generated script only when needed).
- Nothing is executed during the conversion and nothing leaves your machine. Your
  notebook is never changed, and a `.py` of the same name that you wrote or
  edited is never overwritten (the new copy gets "(notebook)" in its name
  instead).
- If a notebook cannot be converted (very old format, no code, something Tavotto
  cannot read), it says why in one sentence with a button to send feedback.

**One layout, one window at a time.** If you open the same layout in a second
window, that window shows a card: "Edit here" takes over (the other window saves
first and steps aside), or "Save a copy" makes a separate layout. The window that
was taken over shows the same card with "Take it back". Anything you tried to do
before choosing is remembered and carried out afterwards. When a save finds that
another window saved a newer version, the message offers "Save a copy" so neither
version is lost.

**More stroke options for shapes and arrows.** Rectangles, ellipses, triangles,
diamonds and polygons can now have no outline: turn the stroke off in the
Appearance panel and the fill covers the whole shape on the canvas and in every
export format. Shapes and arrows also gained stroke opacity, three more dash
styles (long dash, dash-dot, long dash-dot), round-dot, diamond and stealth
arrowheads with small, medium and large sizes, and line cap and corner style
options. The less common ones are under "More" in the Appearance panel. Existing
projects look and export exactly as before; the new settings only appear once you
change them. Stroke opacity below 100% cannot be written to EPS (the same limit
as fill opacity), so that format reports it and the other formats export
normally.

**Dashed arrows keep a solid head.** Changing an arrow's line style to dashed (or
dotted) used to dash the arrowhead too, so `->` heads broke into fragments and
filled `-|>` heads got a broken outline. Now only the shaft is dashed and the
head stays solid. Arrows your script itself draws dashed are left exactly as
matplotlib draws them. Styles whose shaft and head are one outline (`simple`,
`fancy`, `wedge`) are dashed as a whole, as before.

**Removing a project from the home page is easier to find.** The "⋯" on each
recent-project card is now always shown instead of appearing only on hover, and
right-clicking a card opens the same menu. "Remove from list" takes the project
off the list; the files on your computer are not touched.

**Reopening a project no longer drops what you just did when the last layout
can't be opened.** Dragging a figure onto the canvas, pasting, or double-clicking
a figure in the library used to do nothing except show "Your last layout isn't
open yet." Now the action is kept and carried out. When the last layout is gone
and there is nothing else to continue from, Tavotto quietly starts a new layout
and puts the figure in it. When the layout is only temporarily unreadable, it
tries once more on its own. When there are other layouts you could continue from,
the empty canvas shows the choice right in the middle, and whatever you pick,
your figure lands there. Figures handed over from an AI editor follow the same
rules. Your older layout files are never changed, and Tavotto still never opens
an older layout in place of the missing one without asking.

**Shapes, lines and text placed directly on the figure can be selected and
edited.** If your script draws on the figure itself instead of inside a subplot,
for example with `fig.add_artist(Polygon(..., transform=fig.transFigure))` to
connect two panels, those elements could not be clicked or edited before. This
also affected lines, text, line collections and arrows added with
`fig.add_artist`, `ConnectionPatch`, images added with `fig.figimage`, and the
titles, text, legends and shapes inside `fig.subfigures(...)`. All of them now
show up in the element list, can be selected, and can have their style changed.
Shapes, lines and text can also be dragged. Legends inside a subfigure used to
move only half as far as you dragged them; they now land where you drop them.

**Plots inside subfigures move the full distance.** Dragging a plot that lives in
a matplotlib subfigure (`fig.subfigures(...)`) used to move it only part of the
way, and its size readout in the properties panel was off. It now lands exactly
where you drop it.

## Failures now end with a button

Every failure now ends one of three ways: it is fixed quietly, it gives one
sentence and one button that does what you were trying to do, or it offers "Send
it to us".

**Failed script cards always offer a way forward.**

- If your AI isn't connected, the main button is now "Send it to us"; "Fix it
  with your AI" is still there as the second button.
- "Can't run yet" now says why, and no longer offers a "Check again" that would
  fail again.
- A script that finishes without a figure because it couldn't find its data now
  lets you point to the data, instead of only saying nothing was drawn.
- For figure-name conflicts, the main button stays "Open Connections", and the AI
  fixer is no longer offered where it can't help.
- Folder permission problems, scripts that call `sys.exit()`, and rendering that
  was interrupted now say what happened in plain words instead of showing a raw
  error or process details.

**Export, save and write-back failures.**

- When a folder can't be written to, the export failure offers "Export to another
  folder": pick a folder and the export runs again right there.
- When a bitmap export is over the size limit, it offers "Export at N dpi" with
  the highest resolution that fits, and exports at that setting when clicked.
- A save that fails because the file was changed elsewhere after you switched
  layouts no longer points you to a dialog that never opens.
- A write-back that fails its safety check gives one plain sentence and a "Send
  feedback" button (the internal details are folded away), and a write-back
  blocked because the script changed has a "Re-render" button.
- A layout from a newer version has a "Check for updates" button in the desktop
  app.

**Save failures.** A failed save (Cmd/Ctrl+S, autosave, or saving into the
project) offers "Retry save". If another window or an outside edit got there
first, it offers "Reload", which brings back the newer version and keeps your
edits as a recovery copy. A style change that could not be saved offers "Try
again" with the value you just typed.

**More failure messages have a button.** A failed project package export or open,
an AI edit whose project refresh did not go through, an example project that
would not open, and a PNG that could not be redrawn from its script each offer
"Try again" (or "Refresh project"). If the second attempt fails too, the button
becomes "Send problem report" instead of offering the same retry again. If you
have moved to another project or layout in the meantime, the button just
dismisses the message and does not redo anything there. When a layout in the
recent list was made by a newer version, the desktop app offers "Check for
updates" (the browser version offers "Send problem report"). When its copy is
gone from this computer, the row is now removed from the list and the message
says so, instead of showing a red error. A few errors that cannot be fixed by
retrying (a saved figure marker that no longer matches, or rebuilding a figure
that is not allowed to be written back) now offer "Send problem report".

**When a figure in the layout can't be found, export says which one and lets you
find it.** If an image used in a layout was moved, renamed or deleted, exporting
used to fail with an internal error message and a "Try again" button that could
only fail again. Export now says, in one sentence, which figure can't be found,
and offers "Find this figure": it opens the relink dialog for just that figure (a
file with the same name elsewhere in the project is matched automatically), and
once it is relinked the export runs again by itself. Single-figure exports no
longer show a raw "404 Not Found" message in this case. In two-line notices, the
action button and "Details" are now centered vertically.

## Export

**Greyed-out formats explain why on hover.** In the export dialog, hovering a
greyed-out format such as PY or EPS showed nothing when the pointer was on the
checkbox itself. The reason now appears in a tooltip, for example that .py needs
"Each figure separately" when exporting a whole layout.

**EPS can't do transparency: you are asked before exporting.** PostScript has no
transparency, so an EPS export of a figure with semi-transparent annotations used
to fail afterwards with a message. Now, when EPS is ticked and an annotation on
the figure is semi-transparent, clicking Export first asks what you want: export
a PDF instead (EPS is swapped for PDF), export the EPS with those annotations
fully opaque (colours unchanged; PDF, SVG and PNG keep the transparency), or
cancel.

**Exporting the edited .py works again after moving text on a tightly cropped
figure.** If your script saves its figure with `bbox_inches="tight"` and you moved
a text label, axis label, title or legend in Tavotto, exporting the edited `.py`
failed with "the edited script doesn't reproduce the figure". The edited script
placed the moved items relative to the uncropped figure instead of the cropped
page you see in Tavotto, so everything moved by the width of the cropped margin.
Moved items now land exactly where they are in Tavotto, and the edited script is
exported.

**Figures whose script names elements in Chinese now export.** If your script
gave plot elements names with Chinese characters or spaces (for example
`ax.set_gid("面板 A")`), exporting the figure from the canvas could fail for
every format. Tavotto now renames those ids inside the exported SVG and keeps
every reference pointing at the same element. Your script is not changed, and
figures without such names export exactly as before.

## Scripts that couldn't find their data or run safely

**Scripts that look for their data next to themselves now draw on the first
try.** A script that finds its data with a relative path, for example
`glob("data/*.csv")` or `pd.read_parquet("data.parquet")`, used to come back with
no figure, an empty plot, or an error such as "x and y must have same first
dimension", and you had to click "Run in the script folder". Now, if the data
turns out to be in the script's folder, Tavotto switches the project to run there
and runs the script once more, without asking (see "Before you upgrade" for when
this applies).

**Link moved data for scripts that check or list it first.** When a script checks
for its data before reading it (`os.path.exists`, `isfile`, `isdir`, `getsize`,
`os.stat`, `Path.exists` and similar), lists a data folder (`os.listdir`,
`os.walk`, `Path.iterdir`) or collects files with `glob`, pointing Tavotto at the
moved file or folder now makes the script run normally, without editing it. You
can do this from the missing-data dialog, or let the AI fixer do it after you
confirm. This also covers scripts that build the path from their own location and
raise their own `FileNotFoundError` naming it, which previously showed up as a
generic script error that could not be linked. Data read by native readers such
as ovito `import_file` or h5py still needs the file put back where the script
expects it, or the confirmed script rewrite.

**Copy your confirmed data to where a script reads it.** When a script run
directly on your computer cannot read an absolute path and you have already
pointed Tavotto at that data, the card now offers to copy your file to the path
the script expects, then run again. It copies a regular file only, never
overwrites, and keeps your original untouched. If the folder is not writable, you
can approve a one-time copy with the system prompt (on macOS protected folders
such as Desktop, open System Settings instead). If copying is not possible you
can still change the path in the script after reviewing every line, or ask your
AI to fix it.

**Review a missing input path after native execution.** When desktop native
execution confirms that a Python read failed because an absolute input path is
missing, Tavotto can offer a preview of an editable path in the unchanged script.
You choose whether to apply the backed-up change. Paths that cannot be matched
safely remain ordinary script errors.

**Correcting a linked data folder.** When a script constructs its input filename
dynamically, the repair assistant can now help you correct an existing linked
data folder even if the original filename is no longer in the run report. It asks
before changing the folder and explains that the link can affect multiple missing
inputs. Data links apply during safe execution; native execution still uses the
original paths.

**Scripts that read missing command-line arguments.** When a Python script
directly reads a missing command-line argument, Tavotto can now offer the existing
run-arguments recovery instead of reporting a generic script error. Other index
errors continue to show their original diagnostics.

**Scripts that write a temporary file and replace it no longer fall back.** A
script that writes a file inside the project (for example a temporary file that it
then renames over an existing cache) and reads the result back now runs in safe
mode and draws its figure, instead of stopping with "safe mode did not really
perform a file operation" and retrying natively. The changes live in a per-run
scratch layer that is discarded when the run ends, so your project files stay
byte-for-byte unchanged. Scripts that inspect those paths in ways the scratch
layer cannot reproduce (for example `os.stat`) are still reported and run
natively, as before.

**Clearer message for scripts that only copy existing images.** Some scripts
don't draw anything: they just copy ready-made PDF or PNG files into place, for
example a submission package that re-exports finished figures. Tavotto used to
say it produced no figure, guess that a data file was missing, and offer the AI
fixer, which had nothing to fix. It now says the script only wrote out image
files. The button opens the output images in the asset library, and the AI fixer
isn't offered.

**Scripts written by ChatGPT that import `artifact_tool` no longer fail to
install dependencies.** Scripts generated in ChatGPT sometimes import
`artifact_tool`, `ace_tools` or `caas_jupyter_tools`. These modules only exist
inside ChatGPT's web sandbox, so installing dependencies failed for the whole
batch with "the package isn't in the index". Tavotto now installs the other
packages, explains in one sentence that the module only exists in ChatGPT, and
offers a button that copies a note asking the AI to regenerate the script without
it. Your script is not changed.

## Converting R and MATLAB scripts

**Conversion checks the tables and logs the source writes.** For R and MATLAB
sources, Tavotto now checks that the converted script writes the files the source
plainly writes (a literal file name in an ordinary top-level statement). If some
are missing it asks the AI once to add them; if they are still missing you can
point at a file of your own or skip them, and still adopt the result.

When the project already holds an earlier result for a file, the new one is
compared with it (CSV, TSV and XLSX cell by cell, text and log files line by
line) and marked same, different or can't compare, with the reason. If something
differs you can ask the AI to check once more. Dynamic paths and unsupported
formats cannot be checked and stay marked as such.

**Review possible outputs before adopting a conversion.** The conversion
comparison now shows filenames mentioned by the source and redirected write
attempts seen during validation. These are partial clues, not proof that every
table, log, or other output was preserved; filenames can include inputs and a
write attempt may not have completed.

**Intermediate files during script conversion.** When a converted script writes
an intermediate file and then checks it with `pathlib`, conversion validation can
now see the temporary file and continue. Validation still keeps the original
project files unchanged.

## AI assistant and connections

**Attach files in the AI assistant.** The assistant's input box now takes files:
click the paperclip, paste a screenshot, or drop files in (up to 6, any format).
Pictures are shown to the AI you connected, so you can say "match the colors of
this figure"; data files such as CSV or XLSX are handed over for it to read.
Large or unusual images are shrunk or converted automatically, and if the current
model can't see images Tavotto says so and offers one that can. Attached files
stay on your computer and go only to your own AI; the task history only remembers
how many you attached.

**Claude Fable 5.2 in the built-in AI connection.** When you connect Claude
through your own Anthropic API key, Claude Fable 5.2 is now a suggested model.
Choosing it shows an estimated cost in the run trace. Before, the cost field was
blank for this model.

**OpenCode Go keys connect.** Adding an OpenCode Go connection with a valid key no
longer fails with "can't connect". The key check now identifies itself as Tavotto
instead of a generic Python client, which OpenCode's network edge was blocking,
and AI fixes that run through the built-in assistant now send the per-conversation
session id OpenCode Go requires.

**`tavotto mcp` now works from a pip install.** If you installed Tavotto with
pip, pipx or uvx, `tavotto mcp` now starts the MCP server directly. Before, it
only worked from the desktop app or the plugin. On a headless machine you can run
`uvx --from "tavotto[worker]" tavotto mcp`. Nothing changes if you never run that
command.

**pip, pipx and uvx installs no longer report a broken canvas.** When Tavotto is
installed with pip, pipx or uvx, the `tavotto_health` check no longer reports the
missing canvas or plugin package as a fault or tells you to reinstall the plugin.
It now says this install has no canvas by design, and "Connect to AI editors" also
works from that install.

**One-step "fix to journal" for AI editors.** Tell your AI editor which journal
you are submitting to and it can now bring the open figure into line in one go:
`tavotto_fix_to_journal` picks the column width, resizes the page, raises and
swaps fonts, snaps line widths and tidies ticks, legend frames and borders,
checking every step against a real render and rolling everything back if the fix
would introduce a new problem. If the figure could be single or double column it
asks you first instead of guessing. It shows before and after previews, and
`dry_run` lets you see what would change without touching anything. Your script
is never edited, and nothing is exported unless you ask for it. The preflight
report now also tells the AI, for each problem, whether Tavotto can fix it or the
script has to change.

## Windows, macOS and diagnostics

**Figures that use macOS Helvetica at small sizes open again.** A script that
sets the font to the system Helvetica on a Mac at 5 to 7 pt (the usual Nature
setup) failed to open with "failed to load glyph" or "division by zero", even
though the same script ran fine from the terminal. Tavotto now falls back to
unhinted text only for the few sizes where the font file cannot be loaded, and
your figure opens, previews and exports as usual.

**Recover incomplete Matplotlib font indexes.** When Matplotlib's cached font
list omits its default font even though the font is installed, safe rendering can
now recover the font inventory without changing the existing cache. Previously,
figures using the default font could fail to open for editing.

**Clear expired diagnostics when Windows files are temporarily in use.** Expired
environment diagnostics are now retried when a Windows reader temporarily prevents
the cache file from being replaced. If the file remains locked, Tavotto tries
again when that project's diagnostics are next accessed.

**Clearer diagnostics when a fallback run also fails.** When a protected file
operation blocks one run and its fallback also fails, the diagnostic report can
retain the observed operation categories and the uncaught exception category for
their respective attempts, when available. These facts contain no file paths or
exception text and do not determine whether a missing file was an input or an
output.
