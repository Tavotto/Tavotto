# Tavotto 0.20.0

A release about a calmer, more legible workspace and about problems reported
from real installs. The timeline gets a version strip you can scrub, the
interface text and icons are larger and sharper, and menus and dialogs were
tidied after a full UI review. Connecting an AI with an API key works again
in the desktop app, converting R or MATLAB scripts with Codex works on
Windows, and data left behind by starting Tavotto from the Codex or Claude
desktop app is brought back. Failure cards now name what went wrong and offer
the fix — switch Python, supply run arguments, or revert an AI edit that broke
the script.

## Before you upgrade

**The Windows installer is still not code signed.** Expect a SmartScreen
prompt on first run; update packages remain minisign-signed. macOS builds
are signed and notarized as usual.

**If you started Tavotto from the Codex or Claude desktop app on Windows.**
Tavotto now always runs outside the desktop app's Microsoft Store package, so
it uses the same data as when started from the Start menu. If an earlier
version was started from such an app, your recent projects, project settings,
AI connections, AI edit history, original-image backups and managed Python
environments were kept in that app's private folder
(`%LOCALAPPDATA%\Packages\...\LocalCache`), so Tavotto opened from the Start
menu looked empty. The first start of 0.20.0 outside such an app copies back
whatever is missing, silently. Existing files are never overwritten and the
originals stay where they were; where both places have a settings file, only
the missing recent projects, projects and AI connections are added. Large
managed environments and downloaded AI command-line tools are brought over the
first time they are needed; rebuildable caches are not copied. (#1576, #1603)

## New

**Timeline version strip.** The Timeline tab has a strip of ticks at the top,
one per saved version. Hovering shows that version's stored thumbnail
(nothing is re-rendered, so it keeps up with the mouse); clicking opens the
compare card. ←/→/Home/End and Enter work from the keyboard. (#1573)
- Thumbnails are taken of the area that has content, not the whole page, and
  every thumbnail in the timeline is centred on that content. Versions saved
  by earlier builds are cropped from their sketch the same way.
- The scope filter and the "Named" toggle are one row: "This figure / All
  figures" when a single figure is open, "This layout / All figures" in a
  multi-figure layout.
- Restoring a version that would change which figures are on the canvas now
  always asks first and says how many figures it will become.
- Opening a project, leaving it or restoring a version no longer adds an
  entry when nothing changed since the previous key moment or named version,
  so reopening a project no longer leaves a run of identical "Project opened"
  entries. After an ordinary auto-save they are still recorded, so "Before
  restore" can always be found. Exports, saves, write-backs and named
  versions are always recorded; identical entries from earlier versions are
  hidden, not deleted. (#1575)

**Sharper icons that respond to you.** Interface icons are drawn with a
thinner stroke aligned to the screen's pixel grid, so edges no longer look
soft on Retina displays, and small icons next to text are 16 px instead of
14 px. (#1560) Icons in buttons, the left rail, the toolbar, menus and the
command palette play a short one-shot motion on hover, click or keyboard
highlight, and status icons animate once when they appear. Every motion is
under 0.75 s; with the system's "Reduce motion" setting on, icons do not
move. (#1548) The smallest icons (expand and dropdown arrows, tab close
buttons, warning and status marks) are drawn separately for 12 px on whole
pixels, so they stay sharp on standard displays too; status marks are now
solid shapes with the symbol cut out. (#1589) The Outline rail icon shows the
solid selected form like the other rail items. (#1610)

**A tidier workspace after a full UI review.**
- The properties panel text goes from 12 to 13 px with a wider label column.
  In the element tree the content rows read darker than the group rows, the
  style panel adapts to the panel width, and an empty canvas offers cards to
  pick a figure to edit. (#1552)
- The top-bar "…" menu is grouped into File / View / Help; the command
  palette shows an icon for every command and plain grey shortcut keys;
  Settings wording is clearer ("Reset interface layout"); the welcome page
  and tutorial are simpler and say what is left to do on a disabled "Next".
  (#1556)
- The export dialog shows only the figure name and size under the title, the
  save location reads "project / relative path", "Strict verification" and
  "Style check report" moved into a collapsed "Advanced" section, and only
  figures that need changing get a red dot. The Contact dialog puts "Your
  message" first and uses an "Add screenshot/file" button. (#1555)
- The left rail is now Project / Assets / Outline / In-figure / Style /
  Problems / Settings, where Outline combines the canvas list and layers. On
  windows 1280 px wide or more the left panel is pinned by default, so adding
  figures no longer collapses the asset drawer; below 1280 px the properties
  panel slides over the canvas instead of taking space, and below 1180 px the
  rail shows icons only. With exactly one editable figure and nothing
  selected, the AI assistant targets it automatically. (#1554)
- A figure added without a drop position now always lands in free space
  (scaled down by at most 40% to fit a gap) instead of almost exactly on top
  of the first one. Hints no longer float over dialog backdrops, several
  hints appear only when they apply, and after mouse use, pressing Enter or
  closing a menu no longer draws the thick keyboard focus ring. (#1557)

**The AI assistant tells you when it has gone quiet.** If the connected AI
tool prints nothing for 2 minutes, the status line says so and offers Cancel
and Retry; Tavotto does not stop the task on its own, and the overall
15-minute limit is unchanged. In Task History, a revert refused because the
script changed after the AI edit now offers "View changes", and failed tasks
show a plain sentence instead of an internal code such as `agent_quota`.
(#1599)

## Fixed

**Converting R or MATLAB scripts with Codex on Windows works.** On Windows,
Codex's sandbox refused every command, so a conversion through a Codex
subscription could never write the new script. This is fixed. Converting a
long script also no longer runs out of time (the limit now grows with the
script's length, up to 30 minutes), a refused write is reported as "The AI
couldn't write to the conversion workspace" with a Retry button, and while
the AI is writing a long file the progress line says "Writing a long file…"
instead of looking stuck. (#1604)

**"Connect with an API key" AI never ran in the desktop app.** In the
0.19.0–0.19.2 desktop installers, the built-in AI used when you connect a
provider with an API key (instead of a Codex / Claude Code subscription)
failed about a tenth of a second after every request, without contacting the
provider. The installer was missing the module that starts it. Connections
through Codex or Claude Code were not affected. The desktop smoke test now
starts the built-in AI from the installed app. (#1570) Relatedly, when the
AI could not run at all, the assistant no longer says "The change did not
pass the pre-write check"; it names what actually went wrong. (#1592)

**A run that breaks right after an AI edit offers to revert that edit.** If a
script ran fine, the AI changed it, and the changed script then fails with its
own error, the failure card says so and its main button is **Revert the AI's
change**, which restores the version before that edit and runs it again. It
is only offered when the script on disk is still exactly what the AI left; if
you edited it afterwards, nothing is overwritten. The fix assistant now also
knows the script was just edited by the AI. (#1608)

**Codex / Claude Code sign-in, quota and connection failures are named.** If
a run through the Codex or Claude Code command line failed because you were
signed out, hit a usage or rate limit, or the service could not be reached,
the card now says which, from the error codes the command line reports, and
its main button is "Check connection" instead of a "Retry" that could not
succeed. Failures a retry can fix (timeouts, step or budget limits) still
offer "Retry". (#1598)

**Scripts no longer fail as a "script error" when your Python can't write
to Tavotto's cache.** Some Python environments (for example a virtual
environment built from another app's bundled Python) can read Tavotto's cache
folder but cannot create folders in it, so every run stopped before your
script ran while the card blamed the script. The card now says what happened
and its button switches back to Tavotto's built-in Python and runs again;
only the setting that picked that Python is cleared. (#1595) Such an
environment is now also turned down when you choose it, with the same
one-sentence reason. (#1614)

**Missing packages and wrong Python versions get a concrete fix.** If a script
needs a package Tavotto can't install for you (a private library, a local
module, something only in a conda environment), the card's main button is now
"Use my own Python"; "Fix with your AI" is still there as a secondary button.
If the Python version doesn't fit and Tavotto already found a checked
environment that does, the main button reads "Switch to <environment name>".
An environment you picked yourself for a project is no longer replaced
automatically. (#1600)

**Scripts that check their own arguments get the "Run arguments" editor.** A
script that counts `sys.argv` itself and exits with a usage message (for
example `if len(sys.argv) < 11: raise SystemExit("Usage: …")`) used to be
reported as "remove that sys.exit". It is now treated like an `argparse`
script that is missing arguments, and the failure details offer **Run
arguments**. (#1605)

**Legend size in the properties panel resizes the whole legend.** Changing a
legend's size in the panel used to change only the entries' text, while the
legend box and the floating toolbar kept the old size. The panel now changes
the legend's own font size, so both places agree. In projects where an earlier
version set the entries' sizes from the panel, the field shows mixed values
until you type a size, and **Reset** clears both in one undo step. (#1609)

**Scripts whose file name contains a dot now run.** A script such as
`4-51.slope_ratio.py` or `fig.v2.py` failed with `ModuleNotFoundError: No
module named '4-51'` when run through its entry function. Such scripts now
load from their file directly, the same way `python script.py` runs them.
(#1590)

**Clearer package download failures.** When installing a package fails
because the network is unreachable, the card says whether neither the
official index nor the mirror could be reached, or whether the download
source you configured is unreachable (Tavotto does not switch a source you
set). Looking up a package's versions now tries the mirror once when the
official PyPI is unreachable, and on Windows pip output from Tavotto's own
environments is read as UTF-8, so non-English system languages no longer
garble the install log. (#1601)

**Scripts that load a private package folder built for another Python
version.** If a script puts its own `pip install --target` folder at the
front of `sys.path` (for example a `.kegg_python` folder whose matplotlib was
built for Python 3.12) and Tavotto runs it with a different Python, the run
used to fail with an `ImportError` and the fix assistant kept trying to
switch Python versions. Tavotto now offers **Skip this folder and rerun**:
for that project, imports no longer come from that folder. Your script and
the folder are left untouched. (#1564)

**A rewritten script no longer fails with a missing entry function.** If you
rewrote a registered script to draw at the top level after the project was
opened, every run failed with `AttributeError: module has no attribute ...`.
Before a registered script runs, Tavotto now checks the registered entry
against the script as it is now and re-detects it when the function is gone,
updating only the `entry` field of that registry line. If an entry still
cannot be found, the card says so (`script_entry_missing`), and the AI repair
has a `fix_entry` tool that does the same. (#1565)

**First run on a fresh machine no longer fails with "session s-1 does not
exist".** When the very first run on a machine was still starting (matplotlib
builds its font cache) and a second try-run of the same script started, for
example from the AI repair button, the second one closed the session the
first one had just opened. A try-run now shares that session instead. The
repair assistant's environment list also starts with the environment the
project is actually running in, marked as current, so its "run the script to
verify" step is no longer refused. (#1572)

**Missing helper modules are no longer offered as packages to install.** If
a script stores its own folder in a variable and then adds a subfolder to
`sys.path` (for example `ROOT / "source"`) and that subfolder is missing,
Tavotto used to pre-fill same-named PyPI packages for the script's own helper
modules. These are now reported as missing local modules: nothing is
pre-filled and nothing is sent to pip. (#1582)

**Figures removed by a run no longer come back in the project file.** When a
run with different arguments no longer produced a figure the previous run
had, Tavotto reported it as unlinked but the script registry could quietly
add it back a moment later, mostly on slower Windows machines. The registry
now keeps exactly the figures the run reported. (#1585)

**Scripts that call `sys.stdout.reconfigure(...)` draw again.** Scripts whose
first line is `sys.stdout.reconfigure(encoding="utf-8")`, or that wrap
`sys.stdout.buffer` or call `sys.stdout.detach()`, failed with an
`AttributeError` and produced no figure. (#1541)

**"Restart" after a startup timeout no longer gets stuck the same way.** When
the desktop app gave up waiting for its engine to start, **Restart** reopened
the same project and could time out again. It now goes straight to the
project picker (your recent projects are kept). (#1550)

**Exports and previews**
- When the canvas held a single figure, text, arrows and shapes added on the
  canvas were missing from the export preview and the exported files. They
  are now drawn into PDF, PNG, TIFF, SVG and EPS, clipped to the figure
  frame, with their stacking preserved; exports without annotations are
  byte-for-byte unchanged. An annotation with transparency fails only the EPS
  item, with a stated reason. (#1551)
- If an export stopped at the "file already exists" confirmation and you
  then changed the file name, format, scope or folder, Overwrite replaced a
  different file than the one listed. Changing any of these now starts over
  with a fresh conflict check. (#1549)
- For script-run figures, undoing an edit and then saving could make the
  reopened canvas and the export preview show the state from before the
  undo. Projects saved by earlier versions may show the "approximate
  preview" badge on such figures until they are rendered once. (#1547)
- The large export preview of an edited figure no longer switches to a
  sharper copy of the pre-edit render. (#1583)

**Editing on the canvas**
- Typing into a text box and then clicking empty canvas space, without
  pressing Enter, discarded the typed text; typing in the inspector and
  clicking away merged the next action into the same undo step. Text is now
  committed whenever the editor closes. (#1546)
- Dragging a legend again while the previous drag was still rendering could
  move the whole figure instead; changing the shared font size or the figure
  size while rendering could apply to the wrong target. These now apply each
  step in order. (#1532)
- "Rebuild as editable figure" on a PNG could jump to another canvas and open
  an older figure with the same file name. The rebuilt figure is now added
  next to the PNG on the canvas you started from. (#1545)

## Diagnostics

- When an AI edit or conversion fails, the session's log line records the
  exit code, the built-in runner's failure reason and which verification
  checks were unmet, so a diagnostic bundle can explain a run that failed
  instantly. Only fixed codes are written, never paths, prompts or keys.
  (#1571)
- For each Codex CLI run, the bundle records how many events and commands
  it produced, how many failed or were declined, how many files it changed
  and whether it touched the target file, the longest silent gap, and whether
  it used the official login or a relay — counts and fixed labels only, never
  commands, paths, prompts or output. (#1587)
- Diagnostic bundles say whether the app was running with a Windows package
  identity and whether its data folders are under `Packages`. (#1576)
- After a startup timeout, the minimal diagnostic bundle records which
  startup step the app was waiting on. (#1550)
- The "Send feedback" confirmation lists the execution trace file under its
  own description (steps and timings of recent tasks, no prompts, scripts,
  file names or paths). (#1543)
