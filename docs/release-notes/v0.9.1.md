This release is about breadth and trust. Far more of what matplotlib draws is
now something you can click and change — the coloured grid of a
`pcolormesh`, the wedges of a pie, the lines of a contour, the band left by
`axhspan`. You can try the whole editor in a browser without installing
anything. The local server asks for a credential in every mode, not just on
the desktop. And the installers, the wheel and the sdist can be verified
back to the commit they were built from.

The other half of the work does not show up as a feature. A benchmark that
compares Tavotto against plain matplotlib on 149 real scripts found nine
defects that had been there since long before this release, one of them
serious enough to write a wrong colour into your original PDF with nothing
said. Reading matplotlib's own source turned up several more. They are all
in **Fixed**.

## Added

**Try it in a browser, install nothing.** [tavotto.com/try](https://tavotto.com/try)
runs the real editor — the same canvas, the same element tree, the same undo
stack — with Python itself running in the page through Pyodide. Drop in a
`.py` file or start from one of the examples. Your script never leaves the
browser: nothing is uploaded, nothing is stored, and the page tells you the
sha256 of the file it actually executed so "unchanged" is a claim you can
check rather than one you have to take on faith.

**Much more of a figure is editable.** We read matplotlib's artist model
end to end and stopped recognising things one class name at a time. What is
newly selectable: the coloured grid from `pcolormesh`, `hist2d` and
`sns.heatmap`; contour lines; the event lines from `eventplot`; the stems
from `stem`; the wedges of `ax.pie`; the bands from `axhspan` and `axvspan`;
circles, ellipses and other shapes added with `add_patch`; line collections;
and inset and secondary axes. Patches and collections also gained two
properties they never had: **hatch**, for telling same-coloured regions
apart in black-and-white print, and **line style**. Because recognition now
works by family rather than by name, a class you wrote yourself —
`class MyPatch(Rectangle)` — is editable with no work on our side, and so is
whatever seaborn or pandas draws on top of matplotlib.

**Coming from Magplot 0.7 is now a command.** `tavotto doctor --migrate`
moves your settings, canvas layouts, version history, autosaves, styles,
write-back baselines and assistant history across. Settings are merged with
yours winning, nothing in the old location is deleted, `--dry-run` shows the
plan without writing a byte, running it twice does nothing the second time,
and `--rollback-migration` removes exactly the files the migration created.
Plain `tavotto doctor` notices the old data and points at the command, so
you never need to know the folder names. One folder it deliberately leaves
alone is the `magplotfile/` inside each of your own projects, because only
you know where those are — see Upgrading. Details in
`docs/migration-magplot.md`.

**The interface starts in English outside Chinese-language systems.** A
system set to Japanese, French or German now opens in English rather than
Simplified Chinese, and that includes the desktop app's native menu bar and
splash screen on the very first launch, before the window has loaded. A
language you pick yourself still wins over your system's.

**Optional anonymous usage statistics.** Asked once, on first launch, with
both answers equally easy to give; off unless you say yes, and no identifier
is even generated before then. What can be sent is restricted by shape, not
by discipline: no property accepts free text, so file names, paths, scripts,
prompts and the text inside your figures cannot be transmitted even by
mistake. There is a switch in **Settings → Privacy, diagnostics and About**,
and `TAVOTTO_NO_TELEMETRY=1` overrides everything. The full event list is in
`docs/analytics/telemetry-events.md`; the promise is in `docs/privacy.md`.

**Release files can be verified.** The Windows and macOS installers, the
wheel and the sdist each carry a build provenance attestation, the wheel
ships an SPDX SBOM, and `SHA256SUMS.txt` covers the wheel and the sdist. To
confirm a download really came from this repository:

```bash
gh attestation verify tavotto-0.9.1-py3-none-any.whl -R Tavotto/Tavotto
```

Not every attachment is attested. The SBOM, `SHA256SUMS.txt` itself, the
Codex plugin manifest and zip, and the desktop updater manifest
(`latest.json`) carry no attestation, so `gh attestation verify` on one of
those will tell you it found none. For those files that is the expected
answer today, not evidence of tampering.

**A support matrix you can read.** `docs/support-matrix.json` states what is
actually supported rather than what sounds good. Desktop builds exist for
Windows x64 and macOS Apple Silicon and nothing else: there is no desktop
build for macOS Intel or Windows ARM, and Linux is pip-only, in beta. A test
compares the file against what the build pipeline really produces, so the
promise cannot drift away from the fact.

## Changed

**Browser mode now requires authentication, like the desktop always has.**
Started from `pip`, Tavotto used to be an unauthenticated local web app that
could browse directories, open projects, write layouts, overwrite your
original figures and invoke AI CLIs — reachable by any page your browser
happened to load. Both modes now share one boundary: a one-time nonce, an
HttpOnly cookie, a strict same-origin check, and 401 for everything else.
Launching normally is unaffected; the browser opens with the credential in
the landing URL. **If you drive the API from scripts or `curl`**, see
Upgrading below.

**Value-mapped artists now show the colour controls that actually work.**
`scatter(c=z)`, `pcolor` and `hexbin` used to offer a fill-colour picker.
That picker never did anything — matplotlib recomputes those colours from
the data array on every draw, so the interface reported a change the figure
never made. They now expose **colormap**, **vmin** and **vmax** instead.

**Several keyboard and screen-reader problems are fixed.** With a panel
selected, pressing Enter on a toolbar button used to run the canvas shortcut
instead of the button — focus on *Export*, press Enter, and figure editing
opened. Closing a dialog with Escape dropped focus to the top of the page
rather than returning it. The panel resize handles, format badges, tab lists
and number fields were unusable or unreadable with assistive technology.
Automated checks now run on Chromium, WebKit and an English locale.

**Error messages no longer fall back to Chinese.** Roughly thirty backend
failures used to reach an English interface as Chinese text, because they
carried no stable identifier for the front end to translate. Every error
response now carries one, and a check refuses to build if a code exists
without wording in both languages.

**pip no longer installs on Python 3.14.** The supported range is
`>=3.10,<3.14`: what pip permits should equal what we have actually tested.

## Fixed

Everything below was already broken in 0.8.0. Regressions introduced and
resolved inside this cycle are left out — you never saw them.

**A wrong colour could be written into your original figure with no
warning.** Changing a property that applies to a whole series — bar fill
colour is the clearest case — and then undoing it did not return the artist
to what the script drew. Write-back compares the replayed figure against the
live one and blocks anything that disagrees, but colour does not move
geometry, so the comparison found nothing to object to and the incorrect
colour was baked into your PDF silently. Overlapping properties now restore
in an order that gets back to the original.

**A figure with per-point transparency would not open at all.**
`scatter(..., alpha=<array>)` and `imshow(..., alpha=<array>)` hand back an
array where a single number was expected, and the whole element tree failed
to build — a perfectly ordinary figure simply refused to open. When alpha is
an array those artists now offer no transparency control, because matplotlib
refuses to set one on them at all; a scalar alpha is unaffected.

**A script that never calls `savefig` produced no panels at all.**
`plt.plot(...)` followed by `plt.show()` — the shape AI assistants write most
often — left you with an empty library and no error explaining why. Figures
still open in memory when the script ends are now picked up.

**Reading a data file next to your script failed.** `pd.read_csv("data.csv")`
raised `FileNotFoundError` even though the file was right there, because
rendering runs in a sandbox with a different working directory. Relative
reads now fall back to the script's own folder — reads only; writes, renames
and deletions never leave the sandbox. Relatedly, `open("x")` worked while
`Path("x").read_text()` did not, an inconsistency that was very hard to
explain to yourself while looking at it.

**A script that draws at the top level was invisible.** Code not wrapped in
a function was judged not to be a plotting script by the scanner, so it
never appeared in the library at all.

**Shapes were missing from the element tree.** The band from `axhspan`, the
wedges from `pie`, circles and ellipses were drawn but not listed, so there
was nothing to click. Separately, `pcolor` and `hexbin` were registered
correctly and then silently dropped, because most collections report an
infinite bounding box that happened to look like an empty one.

**On matplotlib 3.8, filled areas never appeared.** The whole filled region
from `fill_between` and `stackplot` was missing from the element tree — and
3.8 is the lowest version the package claims to support.

**Undo crashed on legend font size** with a `TypeError`, and **undo could
not restore a dashed line** to its original pattern.

**A non-finite axis transform broke rendering and looked like a protocol
error.** `secondary_xaxis` with a function such as `1000/v` produces infinity
at zero; the resulting bounding box was rejected wholesale by the Rust
renderer, which restarted the session and reported something entirely
unrelated to the cause.

## A note on 0.9.0

You may see a `v0.9.0` tag in the repository with no release attached. Nothing
was ever published under it — no wheel, no installer, no PyPI upload. Its
release gate ran for the first time in this project's history and found four
things wrong with the gate's own tooling. Fixing those meant changing files
that the gate loads from the tag itself, and tags here are immutable, so the
work landed on a new one. **0.9.1 is the release; 0.9.0 is a tag that never
shipped.** If you are upgrading from 0.8.0, this page is the only one you
need.

## Upgrading

**Desktop.** The in-app updater handles this one; nothing to do.

**pip / pipx.**

```bash
pip install -U "tavotto[worker]"
```

**Codex plugin.**

```bash
codex plugin marketplace upgrade tavotto
```

Then reload Codex — an open session does not pick up new tools.

**If you call the API from scripts.** Requests now need a credential. Read
the secret from the session file Tavotto writes in its data directory and
send it as a header:

```bash
curl -X POST http://127.0.0.1:5089/api/engine/render \
  -H "X-Tavotto-Auth: $(python3 -c 'import json,sys;print(json.load(open(sys.argv[1]))["secret"])' \
      "<data dir>/session/port-5089.json")" \
  -d '{"id":"Fig1.pdf","patches":[]}'
```

For a development proxy or a one-off experiment, `--insecure-no-auth` (or
`TAVOTTO_INSECURE_NO_AUTH=1`) turns the boundary off and prints a warning
while it is on. The full model is in
`docs/adr/0008-unified-local-session-auth.md`.

**Coming from Magplot 0.7.** Install Tavotto, then run
`tavotto doctor --migrate` for your settings and layouts. One thing the tool
deliberately does not touch, because it lives in your own project folders
rather than in application data, is the `magplotfile/` in each project. Move
that one yourself — but **not** with `mv magplotfile tavottofile`. If you
have opened the project in Tavotto even once, `tavottofile/` already exists,
and `mv` onto an existing directory moves the source *inside* it: you end up
with `tavottofile/magplotfile/`, buried deeper than before, still invisible
to Tavotto, and `mv` exits successfully without a word. Copy instead, which
is right whether or not the destination exists and never overwrites a file
you already have:

```bash
mkdir -p <project>/tavottofile
cp -R -n <project>/magplotfile/. <project>/tavottofile/
```

Then see what was held back:

```bash
diff -rq <project>/magplotfile <project>/tavottofile
```

A `... differ` line is a name that exists on both sides with different
contents: **your current file was kept**, the 0.7 one is still in
`magplotfile/`, and you decide which you want. `Only in ...tavottofile` is
something you made in Tavotto, not a conflict. The old folder is left
untouched, so delete it yourself once you are satisfied. (When `cp -n` skips
a file, macOS returns 1 and prints nothing while GNU returns 0 — read the
`diff`, not the exit code.)

Your figure libraries need nothing: an `mm_registry.json` is still read, and
rewritten under the new name the next time it changes.
