The product-experience and reliability overhaul lands in one release:
twenty-three rounds that rebuild how a document is saved, how a figure
finds its script, how you edit a single figure without first learning
page layout, and how it leaves as a file. Around it, `tavotto run` lets a
script keep its own Python while Tavotto only draws, a missing dependency
stops being a dead end, and figures large enough to freeze the editor no
longer do.

**If you have documents with rotated text, shapes or arrows, read the
first note at the bottom before you re-export them** — the export
direction was wrong, it is fixed, and documents where you compensated for
it will now export the other way.

## Added

**`tavotto run` — your script, your Python, Tavotto only draws (Beta).**
`tavotto run -- python fig.py` runs your script the way your shell would:
stdio, working directory, environment, `argv` and Ctrl+C are passed
through untouched, and you do not install Tavotto into that environment or
change a line of the script. The figures it draws are handed to the
desktop app for editing. Nothing runs until you confirm: the desktop shows
a confirmation screen, a session card with live/offline state, and marks
which panels came from a live session. (#189, #192 — ADR 0021)

**Missing dependencies are no longer a dead end.** Opening a project whose
script needs a package you do not have used to stop there. Tavotto now
finds and adopts the project's own `.venv`, and offers a controlled
one-click repair for what is still missing. (#177 — ADR 0018, ADR 0019)

**Saving is a real state machine.** A document now has an explicit save
state (`clean` / `dirty` / `saving` / `saved` / `save_error` / `conflict`)
instead of a line of text guessed from context. `⌘S` saves and waits for
the disk; a failed write is no longer a toast that disappears after 4.5
seconds. Editing a `tavottofile/*.json` outside the editor is detected as
an external change with three honest exits — reload, deliberately
overwrite, or save as — and while a conflict is unresolved Tavotto does
not touch a byte on disk. Crash recovery no longer overwrites your main
document at startup: the recovered copy waits in a slot for you to decide.
(#201 — ADR 0023, ADR 0024, ADR 0025)

**Figures reconnect to their scripts while you work.** Add a script to a
figure that is already on the canvas, from outside the editor, and it
becomes editable on the spot — no deleting and re-adding. The project
watcher now tracks the whole project directory rather than walking a list
of registered scripts, so new files, deletions, renames and atomic
replacements are all seen. (#206 — ADR 0026)

**"Why can't I edit this figure?" has an answer and a next step.** The
script registry is now a project connection status page: one figure, one
of six mutually exclusive states, a sentence in plain language and the
action that follows from it. A summary line at the top says how many
figures are editable, waiting to be connected, or layout-only; asset cards
carry a badge instead of just going quiet; and the canvas toolbar has a
"why can't I edit this?" link that opens the page scrolled to that figure —
without changing your selection or running anything. Conflicting
candidates are listed and never auto-chosen. (#207 — ADR 0027)

**Quick edit: open one figure, change it, export it at its original
spec.** Editing inside a figure used to require putting it on the canvas
first, which meant understanding millimetre pages, column widths and
multi-panel layout before you could touch anything. Opening a figure now
goes straight to a single-figure workspace — the same panel object seen a
different way, so going to the canvas and back cannot lose your position
or size. Exporting at the original spec reads the source image's real
physical density (PNG `pHYs`, JPEG JFIF/Exif) instead of guessing, and
says out loud when it is assuming. (#208 — ADR 0028)

**Style, Spec and Export are three separate things.** Global profiles live
in your user data directory behind a single atomic store, and a project
now records both the profile it is bound to and a full snapshot of the
rules as they were then — so changing a global standard does not silently
re-judge a figure you signed off last month. When the bound profile has
changed, Tavotto offers to sync and you confirm. (#209 — ADR 0029)

**A standing Problems panel.** "Does this figure have problems?" used to
be answerable only by opening the export dialog. There is now a left-hand
Problems panel where each issue navigates to the real canvas, object and
property field it is about — including problems on your second canvas,
which previously were not listed at all. (#214 — ADR 0030)

**One export pipeline, one export panel.** "What should this export
contain?" was answered in four places with four sets of defaults, so the
same figure and the same settings could produce two different files
depending on which entry point you used. Original-spec and canvas export
are now two scopes of one request. Exports are written to a temporary
directory and published atomically, so a crash or a full disk never leaves
half a PDF; a job that produces PDF and PNG together reports `partial`
rather than claiming success or throwing away the file it did produce;
overwriting is an explicit `ask` / `replace` / `rename` choice; and files
exported through the new panel are named what you typed, without the
`_MMDD_HHMMSS` suffix. Filenames are validated against the strictest
platform's rules as you type them. The export panel drops a screenful of
noise and is reordered around the three questions you actually answer.
(#214 — ADR 0031; the Codex/MCP export path joins the same pipeline in
#272)

**Very large figures stay editable.** A figure with hundreds of thousands
of elements could freeze the editor while it was being previewed. Preview
now prices a figure by artist family before the giant SVG is ever
produced, rasterizes heavy data layers at `savefig` time only, enforces a
byte budget and a DOM-node budget on what reaches the browser, and
downgrades an over-budget preview to a bitmap before anything tries to
read it — with diagnostics that distinguish the five states this can be
in. (#193, #199, #200, #202, #204, #205 — ADR 0022)

**The editing surface, rebuilt across the board.** Eleven rounds of
consistent property editing: one typography capability layer used by every
text control including annotations; scientific text with real glyph
coverage and font fallback; legend entries bound to the artists they
describe; direct manipulation of axis spines and a four-sided tick model;
a floating context bar for multi-selection with shared alignment
references; a QuickEdit right-click menu with rebuild and batch actions; a
reorganised settings shell with managed environment package management and
diagnostics on their own page; an offline tutorial project that ships with
the app; and interactive onboarding whose steps complete on what you
actually did, not on a timer. (#228 — ADR 0032 through ADR 0041)

**Open every figure a script draws, in one call.** A script that draws
four independent figures used to take four `tavotto_open_figure` calls and
four session ids to manage. `tavotto_open_figure` now accepts `stems[]` or
`discover_stems`, opens them through the same path a single figure takes,
and reports `done` / `partial` / `failed` so one bad figure neither hides
the three that opened nor makes you throw them away. (#271, closes #174)

**Parasite axes are no longer invisible.** Twin axes created through
`mpl_toolkits.axes_grid1.host_subplot(...).twinx()` hang off
`host.parasites` and appear in neither `fig.axes` nor `ax.child_axes` — so
the second data series, its label and its whole tick set were missing from
the manifest, silently, with no warning. They are now traversed and
editable, with `position` and `visible` honestly reported as unsupported
because the host recomputes both on every draw. Existing element ids are
unchanged: the new axes are appended, never inserted. (#258)

**`tavotto codex install / doctor / uninstall`.** Installing, checking and
removing the Codex integration from the CLI, instead of editing config by
hand. (#169, closes #117 — ADR 0012)

**Unsupported properties explain themselves.** A control that Tavotto
cannot honour — the orientation switch on a multi-host colorbar, subplot
position under a persistent tight layout — stays where it is, greyed out,
with one sentence saying why, instead of disappearing without explanation.
(#160 closes #76; #161 closes #140)

## Fixed

**AI rollback could truncate the `.py` you wrote yourself.** Reverting an
AI edit restored the snapshot with `shutil.copy2`, which opens your source
file for writing — emptying it — and then streams the old content back. A
full disk, a killed process or an I/O error part way through left a
truncated script, and the good copy was already gone. Measured, not
inferred: injecting `ENOSPC` turned a 220-byte script into 32768 bytes of
nothing. Rollback now writes atomically. (#254)

**Rotated text, shapes and arrows exported in the wrong direction.** An
annotation rotated to 90° came out of the PDF mirrored, at 270°. The
export now matches the canvas. **This changes what existing documents
export** — see the first note below. (#215)

**Previews ignored your edits, and twin axes and log scales came back
wrong.** Three defects found in real use by another lab: the preview was
rendered without your overrides, so what you were looking at was not what
you had changed; secondary axes and logarithmic scales were mishandled;
and the rotation defect above. (#215)

**Double-clicking a figure card could lock you out of in-figure editing
permanently.** Whether double-clicking opens in-figure editing was decided
once, from a snapshot of the panel taken when it was created. If you
double-clicked before the figure's script association arrived, that
decision was "no" — and nothing ever asked again, even after the button to
enter in-figure editing appeared in the property panel. (#279, closes
#267)

**The font dropdown listed fonts this runtime cannot draw.** Choosing
Times New Roman, Arial or Helvetica in the browser playground changed
nothing while the interface reported "1 override": the list came from a
hard-coded table that never asked what was actually installed. The
dropdown now lists only fonts the running interpreter can render. (#155,
closes #110)

**Superscripts and Greek letters were missing from the exported PDF's text
layer.** matplotlib's default `pdf.fonttype=3` draws anything beyond
U+00FF as an XObject: the pixels were right, but `10⁵` came out of a text
extraction as `105`, and `μ`, `α`, `Δ`, `≤` were not there at all.
PDF, PS and EPS export now embed TrueType (Type 42). (#228)

**Every time you opened a figure through Codex, the same preflight advice
was printed again.** `tavotto_open_figure` returned all seven preflight
fields unconditionally, repeating item-by-item advice on every open and
crowding out the manifest summary. It now returns counts and blocking
items by default — blocking items still listed, because they will stop an
export — and the full detail on request. (#171, part of #102)

**`tavotto run --help` wrote to stderr**, so `tavotto run --help | less`
and `> help.txt` were empty. The rule that Tavotto's own output goes to
stderr exists because stdout belongs to your program — which is true only
once there is a program; `--help` returns before anything is spawned.
(#233, closes #198)

**Cancelling a load in the browser playground really cancels it.**
Pressing cancel killed the worker and then, about 400 ms later, an idle
timer started a new one that carried on downloading Pyodide in the
background. (#156, closes #111)

**Keyboard users could get trapped in Safari and other WebKit browsers**
when focus fell back to `<body>`. (#164, closes #138)

**Codex could report "you declined" when you were never asked.** If the
host declared support for a permission prompt and then never showed one,
Tavotto reported `workspace_confirmation_declined` and asked you to
approve again — with no dialog to approve. Transport failure, host error,
a real decline and "we do not know" are now four separate outcomes, each
with the recovery that actually applies. (#242, closes #173)

**The render cache could serve a stale image** when a rewrite happened in
the same tick at the same size. (#152, closes #143)

**A narrow window permanently switched off your sidebar.** The sidebar
giving way on a small screen was written to local storage as if you had
chosen it, so it stayed off when you went back to a large screen — and
back off again after a restart. Preference and current state are now
recorded separately. (#207)

**First-run guidance pointed at a control you had collapsed.** (#157,
closes #112)

**Opening a figure got slower with every axis it had.** Building the
manifest asked matplotlib for tick labels three times per tick
pseudo-element, and each call re-ran the locator and formatter. The tick
model is now computed once per build. (#273, closes #220)

**A rejected `tavotto run` attach no longer burns the handoff
credential.** The one-time credential was consumed before the attach was
attempted, so a failure that was entirely recoverable — including your own
cancellation — left nothing to retry with. Separately, a worker error on a
native endpoint no longer comes back as HTTP 200. (#237, closes #190 and
#191)

## Notes

**Rotated text, shapes and arrows now export in the direction the canvas
shows them — check documents where you worked around the old behaviour.**
Symptom: an annotation you rotated to 90° came out of the PDF export
mirrored, at 270°, so the way to get the angle you wanted was to type the
opposite one. That is fixed — the exported PDF now matches the canvas.
Trigger: any document saved before this release that contains a rotated
text box, shape or arrow whose angle was chosen to compensate; re-exporting
it now produces the mirrored angle. Tavotto does not correct those angles
for you: a 270° that was a workaround and a 270° you actually wanted are
identical in the file, and guessing would silently rewrite your work.
What to do: open the document and look at the rotated annotations on the
canvas — the canvas has always shown the angle you typed, so an angle that
looks wrong there is the old workaround. Set each one to the angle you
actually want. What you see on the canvas is now what the export produces.
(#244, follows #215)

- **`tavotto run` is Beta.** The contract between the CLI and the desktop
  is settled (ADR 0021), the product surface is new.
- **The built-in minimum font size fallback is 8 pt.** The separate
  8.5 pt hard floor is gone — it was stricter than the standard it was
  enforcing, which itself specifies 8 pt legends and tick labels. Figures
  flagged only by that floor now pass; profiles that set their own minimum
  are unaffected. (#209)
- **Old export requests are unchanged.** A request without `filename`
  (the `stem` + `dpi` form, or the older `items[]` + `texts[]` form) still
  produces timestamped names, the same receipt shape and the same
  `_proof.json`. Existing tabs, CI scripts and the Codex plugin need no
  changes. (#214)
- Upgrading from 0.7.0 or earlier on desktop still requires uninstalling
  the old version first (the app identifier changed in 0.8.0).
