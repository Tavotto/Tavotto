Fixes four issues that make figures fail to open. **If you installed v0.1.0, please upgrade** — two of these break ordinary figure libraries outright.

## Fixed

**Figure libraries without a `paper_style.py` failed to open at all.**
`paper_style` is a private convention of the author's own figure library, not an
engine dependency, but the worker imported it unconditionally — so any other
library started with `ModuleNotFoundError` and rendered nothing. Figure capture
already had a general fallback and never needed that module.

**Scripts calling `plt.close(fig)` produced an empty figure on matplotlib ≥ 3.11.**
Symptom: double-clicking a panel does nothing, or the element tree comes up empty.
Trigger: your script closes the figure after saving — the normal pattern when one
script produces several panels:

```python
def save_panel(fig, stem):
    fig.savefig(OUT / f"{stem}.pdf")
    plt.close(fig)          # ← from matplotlib 3.11 on, this detached the canvas
```

matplotlib 3.11 changed `plt.close()` to reset the figure's canvas, which removed
the renderer the engine needs to measure element bounding boxes. Magplot no longer
depends on what state the script leaves the figure in. **If you are on matplotlib
3.10 or older this never affected you** — but it would have hit the moment you
upgraded.

**Hidden directories were scanned into the asset browser.** `.venv`, `.git`,
`.rendered` and similar were listed as panels, and the scan descended into
virtualenvs. Hidden entries are now pruned as the directory tree is walked.

**Scripts whose output filenames are computed were silently skipped** when drafting
the script registry — for example `fig.savefig(OUT / f"{stem}.pdf")`, where the name
is only known at run time. You got an empty `mm_registry.json` with no indication of
why panels had no ⚡ marker. Those scripts are now reported as `dynamic_names` with a
prompt to register them by hand.

## Install

```sh
pipx install "magplot[worker] @ https://github.com/erwanjun/magplot/releases/download/v0.1.1/magplot-0.1.1-py3-none-any.whl"
```

Already on v0.1.0? Use **Settings → Check for updates**, or re-run the command above
with `pipx install --force`.
