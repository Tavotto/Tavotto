Python 3.14 installs the current version instead of a two-year-old one,
the Codex plugin can normalize a figure you already have without redrawing
it, and Tavotto tells you when a new version is out. Around those, the
whole interface went through a consolidation pass — one design
constitution, a hand-drawn icon set, shorter copy, and a long list of
small fixes users reported from real projects — and the desktop app no
longer waits half a minute to start on machines whose reverse DNS never
answers.

## Added

**Python 3.14.** `pip install tavotto` (and `pipx install
"tavotto[worker]"`) on Python 3.14 used to install **0.8.0** silently:
every release after 0.8.0 declared `requires-python <3.14`, so a 3.14
interpreter — now the default `python3` from Homebrew and the default for
pipx on those machines — could only resolve the one old version without
that upper bound. The Codex plugin then reported `engine_too_old`, and
`pipx upgrade tavotto` resolved to 0.8.0 again. This release accepts
Python 3.14 (`requires-python >=3.10,<3.15`), so 3.14 installs the
current version. The CI backend suite now runs on 3.14 alongside 3.10 and
3.13, and the wheel is installed into a clean 3.14 environment and
started as part of the package smoke. The desktop builds still bundle
their own 3.13 runtime; nothing changes there. Project environments on
3.14 are now accepted by the environment check instead of being refused
as unsupported. (#351)

**Codex: normalize an existing figure without redrawing it.** When a
figure already exists and only needs a new width, font, or a font-size
floor, the Codex skill now routes the request to a new MCP tool,
`tavotto_normalize_figure`. It records a baseline, changes only the named
targets (width alone keeps the original aspect ratio; `min_font_pt` lifts
only text below the floor), detects clipping, overlapping text, and
legends covering data on the real render, makes bounded margin / legend
adjustments only when measurements require them, exports, and verifies
the delivered file itself (PDF page size and embedded fonts, PNG pixels
and dpi). If the constraints cannot be met, the session returns to its
baseline and no file is written; the response names the conflict and the
smallest constraint to relax. A requested font that is not installed is
reported as `font_unavailable` instead of being silently substituted.
Tick labels gained a `fontfamily` override, and every text element in the
manifest now reports the face that actually draws it (`face`, and
`math_face` for mathtext such as log-axis `10^4`). The plugin's minimum
engine version moves to 0.15.0 accordingly: an older Tavotto with the
new plugin is told to upgrade instead of failing at import. (#341,
ADR 0051)

**"A new version is available" on startup.** Symptom: you ran an old
version for weeks because the only hint of an update was a 6 px dot on
the "⋯" button. Trigger: the startup update check found a newer release.
Tavotto now shows the release once — current version, release notes,
"Later" / "Update now". On the desktop that downloads the update with
progress and offers to restart; a pip / pipx install runs pip and tells
you the running process is still the old version until restart; a source
checkout is shown the `git pull` to run. "Later", ×, and Esc all dismiss
that version only; the next version asks again. The dialog waits for the
first-run telemetry consent and the `tavotto run` handoff confirmation
before it appears. (#331)

**Colorbars can be resized.** Clicking a colorbar now gives it the same
eight handles as a panel; `fig.colorbar(im, ax=ax)` colorbars with a
fixed `box_aspect` release that constraint while you drag instead of
snapping back after one frame, and undo restores it. (#340)

**Every installed font family in the font list.** The font drop-down
used to offer three generic families and a handful of named candidates;
it now lists every TrueType / OpenType family matplotlib's font manager
knows about on your machine (400+ on a typical desktop), after the
preferred ones. Two related bugs went with it: a script that set an
installed font was flagged "not installed", and hyphenated font names
were parsed as fontconfig patterns. (#340)

**Custom colormaps show as "Custom".** A `ListedColormap([...])` built
in the script showed up as `from_list`, and choosing that entry wrote an
override matplotlib rejected with `ValueError` ("apply failed"). The
entry now reads "Custom", the gradient preview is drawn from the
script's own colours (discrete maps as hard-edged blocks), and after
switching to another colormap a "Script original" entry at the top of
the list takes you back. (#340)

**Selecting a bar series outlines every bar.** Selecting an `ax.bar()`
series drew one rectangle around the whole run, gaps included; each bar
now gets its own outline, hit-testing lands on the bar body, and marquee
selection intersects per bar. (#340)

**Desktop installers and the GitHub Release now carry the project
LICENSE.** The Windows installer and the macOS app ship the project
licence (AGPL-3.0 full text) alongside the application: on Windows it
lands in the installation directory next to `Tavotto.exe`, on macOS in
`Tavotto.app/Contents/Resources/`. Every GitHub Release also attaches
`LICENSE` as a separate asset next to `SHA256SUMS.txt`, so the licence
can be read without opening the source archive. Nothing changes in the
installer flow: there is still no licence page to click through. (#347)

## Changed

**One design system, applied everywhere.** A design constitution
(`docs/ux/DESIGN_CONSTITUTION.md`) now governs the interface, and every
surface was brought under it in three passes — a visual consolidation of
the settings shell and its eleven pages, a five-batch Apple-style review
(shared primitives, editable fields, inspector pages, export / settings /
assistant), and a component-by-component polish (primitives, left panel,
inspector, canvas, dialogs). What you will notice: translucent surfaces
instead of solid hairlines, one row grammar in the inspector (88 px label
column, two folding levels, two numeric widths), one blue on the canvas,
at most two notifications at a time, the inspector's "n changed" badge
doubling as the restore menu, a 360 / 320 px overflow gate on the
property panel, and a lot of repeated explanatory text removed. (#330,
#332, #335, #350–#355, #358–#367, #370, #371, #387)

**A hand-drawn icon set replaces lucide.** All 141 interface icons were
redrawn to one specification (2 / 24 stroke, solid dots, ≤ 3 elements),
and 28 toggle-style icons gained a filled "on" state. Names are unchanged
one-for-one. (#357, ADR 0052)

**Shorter, calmer copy.** 1,321 interface strings (Chinese and English)
plus the desktop shell's own were rewritten: one thing per sentence, no
"why" clauses, no filler, no apologising. Error and hint text is visibly
shorter; English uses natural contractions and drops "please". (#344)

**Interface audit, P0 and P1.** From a 66-screenshot maturity audit:
"fit to canvas" is now a mode that re-fits when the window or sidebars
change size until you pan or zoom yourself; the empty-canvas hint stays
on screen; the tutorial coachmark keeps a fixed two-line footer and shows
a step's own instruction only once its precondition holds; the export
dialog no longer offers "current canvas" and "pick a figure first" at the
same time; the tutorial sample figures are clean under the default
profile. Segmented controls are real segmented selectors (tabs are tabs);
a pinned right panel shows the canvas page instead of "nothing selected";
panel property pages have a fixed order; the subplot page leads with
geometry; the paper-style dialog is two columns grouped by role. The left
panel is "Layers" with one "editable figure" icon everywhere, the element
tree expands to the semantic cluster level by default, the problem panel's
scope tabs carry counts and unverifiable groups sit apart, curves split
into "Line" and "Data points", mathtext in object headers is shown as
readable text (`min⁻¹`), legend entries and tick labels get proper
breadcrumbs, and the project / profiles / agents settings pages are
restructured. (#337, #339, #342)

**The figure-editing assistant.** Streamed replies fade in word by word,
the status line has a light band, send and stop share one button, the
conversation follows the bottom while content or the composer grows, and
the command palette keeps its highlight on the same item by identity
while you type (multi-word queries match in any order). (#356, #370,
#387)

**Preflight `palette-line-markers`.** No longer fires for a solid line
plus a dashed one; it now requires that no series has markers *and* a
line style repeats. (#337)

**Codex plugin icon.** The plugin list and composer showed the old blue
square; the icon is now generated from the brand assets with the rest.
(#336)

## Fixed

**Startup waited 30–60 seconds on machines with no reverse DNS.**
Symptom: the desktop app, the browser, or `tavotto open` sat on
"starting" for half a minute, then everything worked. Trigger: the
standard library's HTTP server calls `socket.getfqdn()` between `bind`
and `listen`; on a machine whose reverse-DNS lookup never answers (some
macOS networks, some CI runners) that call blocks while the port is
bound but not yet listening, so every readiness probe times out. Tavotto
now serves through its own `LocalWSGIServer` that never performs the
lookup; on a GitHub macOS runner the server took 35.8 s to become ready
before this change. (#380)

**Clicking a spine band while a child element is selected now selects
the axes.** Clicking the inner or outer band of an axes spine toggles
that side's inward / outward ticks and moves the selection to the axes so
the tick card appears. When a scatter series, legend, or text belonging
to that axes was selected, the ticks toggled but the selection stayed on
the child element: the tick card did not appear and the child's outline
remained on the overlay. The selection now stays put only when the axes
itself or that side's tick group is already selected. (#349, issue #343)

**Package job progress no longer bleeds across projects.** Starting an
install, update, or uninstall in one project and then switching to
another showed the first project's progress bar and cancel button on the
second project's Packages page (the backend rejects a cancel from another
project, so the button acted on a job that page could not see), and the
job's completion refreshed the second project's package list and
environment state. Progress is now stored per owning project: the other
project shows nothing, switching back shows the job again with a working
cancel button, and completion side effects run only when the owning
project is the one open. (#349, issue #309)

**Export status could say "done" before it had a duration.** Symptom:
`/api/export/state` (and the export dialog polling it) briefly reported
`status: done` with `elapsed_ms: null`. Trigger: the job wrote its final
status before its timing fields, and on Windows the gap — deleting the
temporary directory — was wide enough to poll into. Terminal fields are
now written before the terminal status. (#389, issue #381)

**Changing the figure size with an aspect-constrained axes drifted from
a fresh render.** Symptom: after resizing a figure that has an
`aspect="equal"` subplot or a `box_aspect` colorbar, the live view and a
clean re-render of the same document disagreed (a colorbar's height went
0.77 → 0.34 in one case). The script-original position is now recorded
as matplotlib's `original` position rather than the active one. (#340)

**The tutorial canvas kept the previous copy's layout after an asset
upgrade.** When the bundled tutorial assets were upgraded and re-copied,
the tutorial canvas's autosave slot still described the old copy's
layout, putting the new figure back at 1.19× and turning every line-width
and font-size check red. The slot is now invalidated when the copy is
created. (#337)

**Codex plugin `hero.svg` could be corrupted by the brand generator.**
The rewrite anchor also matched a comment that mentioned it, leaving an
unclosed comment and an invalid SVG. (#336)

## Under the hood

This release also carries the maintainability and CI work from a
2026-09-17 audit. None of it changes behaviour, but it changes what you
will find when you read the code: the engine's override table is split
into artist-family modules (`spinemodel`, `tickmodel`, `colorbarmodel`,
`legendmodel`; `overrides.py` 5,793 → 3,263 lines) with a gate that keeps
each family from importing a later one; the two runtime import cycles
(Python `manifest ↔ overrides`, frontend `actions ↔ useEngineSync`) are
gone and an import-graph guard with a debt baseline keeps new ones out;
the document store's write-back baseline and disk-writer coordination
moved into their own modules behind injected ports; `AGENTS.md` at every
level is a quick sheet pointing at `docs/rules/`. On the CI side, the
merge-queue path was measured and cut roughly in half (median 57 → 25–28
min), pytest and Playwright run in self-verifying shards, package smoke
tests are isolated per instance, the lab runner moved to a private
repository with the release chain split into two segments around it, and
randomized operation-sequence harnesses now exercise both the frontend
document store and the engine's override replay. (#372–#379, #382–#384,
#386, #388, #392, #396–#410, #415, #417, #418)

## Known issues

The new engine sequence harness found three narrow cases where the live
session and a clean replay of the same document disagree. None of them
corrupts the document; the symptom is that reopening it looks slightly
different from what you saw while editing:

- removing or switching off `bbox_visible` on a text while other `bbox_*`
  overrides remain hides the box live but shows it after replay (#412);
- a preview rendered while a legend's text box is later hidden leaves
  that preview's geometry in the hidden box (#413);
- a legend entry explicitly bound as `custom` keeps its frozen look only
  for the session; if the source series changes afterwards, replay does
  not reproduce it (#414).

They are pinned as expected failures in the test suite and will be fixed
in a following release.
