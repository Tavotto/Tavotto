# Tavotto 0.16.0

## Added

**Tavotto asks once, before the first render, which directory a script's
data paths are relative to.** Trigger: a script reads data by a relative
path (`pd.read_csv("data.csv")`, `np.loadtxt("runs/2024/a.dat")`, …) and
that path resolves differently under the script's own directory and under
the project root — or resolves in both places to different files. Symptom
before: the first render either failed with "file not found" or silently
read the wrong copy, and the only remedy was a setting nobody knew to look
for. Now the render stops with a choice — project root, script directory,
or keep the sandbox — listing which files each option would find; the
recommended option is preselected only when the evidence is unambiguous.
The answer is remembered for the project. Codex users answer the same
question through `tavotto_open_figure(workdir=…)`. (ADR 0057)

**Missing packages are prepared before the first run, all at once.**
Trigger: a script imports third-party modules the rendering interpreter
does not have, or the project declares them (`requirements.txt`,
`pyproject.toml`, PEP 723 script metadata). Symptom before: each missing
module surfaced one render at a time, and installing one could leave the
next still missing. Now Tavotto scans the script's unconditional imports
together with the project's declarations, shows one plan (what will be
installed, which imports it could not classify, and the target — Tavotto's
managed environment or the project's own venv), and a single confirmation
installs everything in one `pip` run, verifies the result, and only then
switches the environment over. Preparation can be cancelled until that
switch; "Skip" runs the script as-is. Managed environments are now kept
as generations: a failed or cancelled install never replaces a working one.
Codex users pass `prepare_dependencies=tavotto_managed|project_venv|skip`.
`packaging` is now a runtime dependency. (ADR 0061)

**Standalone shapes can be dragged on the canvas.** Trigger: shapes added
with `ax.add_patch(...)` — flowchart boxes drawn with `FancyBboxPatch`,
`Circle`, `Polygon`, the `Rectangle` behind `axhspan`, pie wedges. Symptom
before: they were listed but reported `draggable: false`, so a flowchart
made of 45 boxes could not be rearranged. A dragged shape moves as a
whole; text placed inside it with `ax.text` is a separate element and
moves only with a multi-selection. Bars are data and stay put. (#472)

**Codex: a session's complete state is available on demand.** The new
tool `tavotto_session_state { session_id }` returns the current manifest,
image, applied patches and preflight for an open figure without
re-rendering. It exists for the embedded canvas (below) but is callable by
the model as well.

## Changed

**Colour-bar changes reach every image sharing that colour scale.**
Trigger: several `pcolormesh` / `imshow` / scatter objects created with the
same `norm` instance and one colour bar attached to one of them — the
usual layout for panels (b) and (c) sharing a scale. Symptom: changing the
colour map or limits from the colour bar changed only the image the bar
was attached to; its siblings kept the old map. Now the colour bar writes
to every registered object sharing that norm; undo returns each to its own
original; the inspector shows "shares the colour scale" on the siblings.
Only object identity of the `norm` counts — equal-looking norms created
separately are not linked. The manifest gains an optional `scale_gids`
field on colour bars. (#474)

**Selecting a `pcolormesh` grid outlines what is drawn, not the whole
grid.** Trigger: a grid whose data extends past the axes limits, or one
drawn with `shading="nearest"`. Symptom: the selection frame stood taller
than the subplot. The outline is now the grid's real perimeter clipped to
the axes; the bounding box used for alignment and snapping is unchanged.
(#473)

**A project whose script the host Python cannot parse no longer
disappears from the list.** Trigger: syntax that the project's own
interpreter accepts but the interpreter running Tavotto does not (a newer
minor version). The script is now analysed inside the project interpreter
(parse only — nothing is imported or executed) and listed with the same
stem and entry rules. Other reasons a script is not listed — unreadable,
undecodable, a genuine syntax error, or "not a plotting script" — are now
reported separately in the discovery report.

**A project's own virtual environment is discovered, checked and adopted
before the first render.** Trigger: the project directory contains a venv
with matplotlib. Symptom before: the first render ran with the built-in
interpreter and failed on a missing package, and only then was the venv
found. The check (Python version range, matplotlib, Tavotto's worker
imports) runs once per project per session. An interpreter that was chosen
explicitly but no longer works is reported as such (`explicit_python_
unusable`) rather than silently replaced.

**Colour fields in the manifest report `none` for a colour that does not
draw.** Trigger: any colour field (`color`, `facecolor`, `edgecolor`,
`markerfacecolor`, `markeredgecolor`, `handle_color`, `grid_color`, …)
whose value has alpha 0, for example a patch drawn with `edgecolor="none"`
or a line whose markers have `markerfacecolor="none"`. Symptom: the field
read `#000000`, so the inspector showed a black swatch for an edge that was
not there, and a script or agent reading the manifest could not tell
"black" from "none".
The field now reads the string `none`; it is accepted back as a value in
overrides, and the inspector draws it as an empty swatch labelled "None".
A filled shape's `facecolor` keeps reporting the colour that would draw
while `fill` is off, as it did before. Anything that parses these fields
as a hex string must accept `none` as well. (#427)

**Choosing a rendering interpreter in Settings runs the full health check.**
Trigger: Settings → Rendering environment → pointing Tavotto at your own
Python. Symptom: the setting was accepted as long as `import matplotlib`
worked, so an interpreter with an unsupported Python version, or one whose
Pillow / numpy DLLs are broken, was stored — and the first render failed
with "crashed" (#435). The check is now the same one used for project
environments (Python version range, matplotlib, and Tavotto's own worker
imports), and refuses with a specific reason: unsupported Python version,
no matplotlib, worker cannot start (with the failing import), or the
interpreter cannot start. An environment already stored before this
version is not re-checked until you pick it again.

## Fixed

**The embedded canvas in Codex Desktop no longer waits forever on a large
figure.** Trigger: opening a figure with roughly 200 or more elements
(≈ four axes with a couple of hundred labels and arrow annotations was
enough) from the Tavotto plugin. Symptom: the model saw the figure and could edit it, `tavotto_
preflight` was fine, but the canvas panel stayed on "waiting for
tavotto_open_figure". Codex Desktop caps the copy of every tool result it
hands to the panel at 1 MiB and blanks the structured payload above that;
Tavotto's open result for such figures was 1.3–2.7 MB. Now the open result
keeps itself under budget by leaving out the parts the panel can fetch
itself (SVG first, then the manifest), marks what it left out in
`structuredContent.elided`, and the canvas fetches the full state through
`tavotto_session_state`. Small figures still arrive whole. If the panel
still receives an empty shell it says so instead of waiting. (#457,
ADR 0069)

**Dependency repair no longer offers to install into an environment that
will not be used.** Trigger: Settings → Rendering environment points at a
specific interpreter, or `TAVOTTO_WORKER_PYTHON` is set. Symptom: "Install
pandas into Tavotto's environment" succeeded, the render still lacked
pandas (the pinned interpreter wins), and the second click answered
"installation not confirmed, start over". The card now says which
interpreter is pinned and where the pin comes from, offers "restore
automatic detection", and installs nothing. "Already tried this round" and
"the environment already has it" are reported as such instead of
"not confirmed", and a `pip` run that failed or was cancelled can be
retried. (#465, #466)

**The Codex plugin's `--provision` no longer reports "0.15.0 is not
published" on a Mac whose `python3` is Apple's 3.9.** Trigger: running
`--provision` where `python3` resolves to the Xcode command-line-tools
interpreter (3.9.6). Symptom: the venv inherited 3.9, whose bundled `pip`
hides releases that require a newer Python, so it said "No matching
distribution found" and Codex read that as an unpublished release. The
base interpreter is now checked before the venv is created and the
message names the interpreter that was tried. (#453)

**Tavotto's own engine modules can no longer be shadowed by files in your
project.** Trigger: a project containing `manifest.py`, `overrides.py` or
another file named like one of Tavotto's modules. Symptom: the safe worker
imported the project's file instead of the engine's and failed in
unrelated places. The worker now loads the engine from a private package;
your files always win the name in your own script. (#447)

**Legend entries unlinked in an older document look different after
reopening.** Trigger: a document saved with 0.15.0 or earlier in which a
legend entry was unlinked from its plot object ("Unlink" on the legend
card, or `binding = custom` written by hand), and whose plot object was
edited *after* the unlink. Symptom: the handle kept the look it had at the
moment of unlinking, but only for that session. The document recorded just
"custom", so reopening it derived the handle from the plot object's
*current* state again, and a live session and a replay of the same
document drew two different figures (#414). Now the document decides:
"Unlink" writes the handle's colour, line width, line style, marker and
marker size into the document together with the binding (bars, fills and
scatter handles have only the colour), and an unlinked handle always draws
as *the script's original handle plus those overrides*. "Relink" removes
all six fields and is the exact inverse. Entries unlinked before this
version carry no such styles, so they now show the script's original
handle instead of the look they had when they were unlinked; that look was
never stored and cannot be recovered. To freeze the current look, press
"Unlink" again. (#414, ADR 0034)

**A render process that dies now says how it died, instead of "crashed
(unresponsive)".** Trigger: the rendering worker exits during the first
build or a later render — most reports came from people rendering with
their own Conda or venv interpreter on Windows. Symptom: every attempt ended
in the same sentence, "渲染进程崩溃（无响应），会话需要重建", and the
diagnostics report listed bare `Traceback (most recent call last):` lines
with nothing after them (#435). Now the message states the exit status
(`sys.exit()`, a Python fatal error, an access violation, a missing DLL, a
signal, or "closed the pipe but kept running") and says explicitly when the
worker left no output at all; the worker runs with `faulthandler` enabled,
so a hard crash leaves its Python stack in `worker.log`; and the
diagnostics report carries the last lines of evidence from recent
`worker.log` files (error and frame lines only — nothing your script
printed and no source lines) plus the exception line of each traceback.
Two related changes: a script that calls `sys.exit()` no longer kills the
worker — `sys.exit(0)` / `exit()` at the end is a normal ending, a script
that parses command-line arguments with argparse (or click, typer, docopt)
and exits because Tavotto passed none is reported as "the script requires
command-line arguments" together with its `usage:` text (give the arguments
defaults, or use `tavotto run -- python script.py args…`), and any other
non-zero exit is reported as the script's own exit; and non-UTF-8 bytes on
the worker's protocol pipe are reported as garbage on the pipe rather than
as a crash. The `SyntaxWarning: invalid escape sequence '\o'` line that a
full Python printed at the top of `worker.log` (from `manifest.py`) is gone.

**A text's background box no longer comes back after replay when it was
switched off.** Trigger: a text with `bbox_visible` turned off (or the
override removed) while other `bbox_*` overrides — colour, padding, edge —
remain. Symptom: the box was hidden in the live session but drawn again
after reopening the document. Visibility is now decided by `bbox_visible`
alone; a box created by an override starts hidden, and styling never
toggles it. (#412)

**A hidden legend's text geometry no longer depends on the last preview or
export.** Trigger: rendering a preview or exporting at a different dpi
while a legend is hidden. Symptom: the manifest's bounding boxes for that
legend's text kept the geometry of that other draw, so a live session and
a replay of the document disagreed. The hidden legend is now laid out once
at the document's dpi. (#413)

## Under the hood

- **RenderCore** — a new PDF/PNG/TIFF rendering path (render IR, font
  policy, vector composition of imported pages, raster buffer) landed
  behind a candidate switch; the shipped default is still the previous
  backend. (ADR 0059, 0060, 0065, 0066, 0067)
- **Private Python** — a provisioner for a self-contained CPython runtime
  landed with every target disabled in the lock file; nothing is
  downloaded unless a target is enabled. (ADR 0063, 0064)

## Known issues

The dependency-repair toast that appears when a package is missing points
at "Settings → Rendering environment"; the card it means lives at the
bottom of System → Diagnostics → Technical details, and the toast text is
the backend's Chinese original (#468). Both are cosmetic and will be fixed
in a following release.
