# Tavotto 0.21.0

A release about editing more of the figure directly on the canvas and about
getting out of your way when connecting things. Text labels can be rotated, set
vertically, use the fonts on your computer, and be copied out of a figure;
dragging a figure's edges now adds margin or crops instead of stretching;
gradient-filled peaks can be selected and recoloured; and journals can be
picked in Settings to check a figure against that journal's artwork rules.
Connecting an AI editor takes one click and no folder, updates download in the
background, and a long list of problems reported from real installs (Windows
conversions, long paths, hangs, wrong hints) is fixed.

## Before you upgrade

**The Windows installer is still not code signed.** Expect a SmartScreen
prompt on first run; update packages remain minisign-signed. macOS builds
are signed and notarized as usual.

**You will be asked about anonymous usage sharing again.** The usage-statistics
consent version went from 3 to 4 because the set of counted events grew: the
journal-list tool that connected AI editors call is now counted (only the fact
that it was called, never the search text, which journal, or any result). Until
you answer, nothing is sent, even if you agreed before. The question itself is
easier to read now (see below); "Not now" is remembered and not asked again.

**AI editors you connected earlier are updated automatically.** The next time
you open Settings, editors connected with an earlier version are rewritten to
the new folder-less setup (the old config is backed up first). Start a new
chat in the editor afterwards. If you relied on an editor being limited to one
folder, run `tavotto hosts connect <editor> --project-root <folder>` to keep
that limit.

**Annotations now follow their figure.** In a multi-figure layout, text labels,
arrows and shapes that lie entirely inside a figure move and scale with it.
The "With annotations" button in the floating bar is gone because this is now
automatic. Annotations that lie outside a figure or cross its edge still stay
where they are.

**The macOS app and the Windows installer change size.** The macOS app is about
20 MB smaller (duplicate libraries are now stored once). The installer grows by
roughly 10 MB because it now carries a serif Chinese font (Noto Serif SC).

## New

**Pick a journal and check your figure against its requirements.** Settings >
Specifications has a new "Journal" row: choose one and the problem panel checks
against that journal's artwork rules, and the page width follows one of its
columns. Each requirement has a "Source" button that shows the sentence it came
from, highlighted on the journal's own page; anything the journal doesn't state
is shown as not specified instead of being filled in.
- Journals that ship with the app work offline. Tavotto can also look up
  further journals one at a time when you pick them (up to 20 a day per
  computer, shared with connected AI editors), verified against a signature
  built into the app, and kept on your computer afterwards. The online catalog
  is switched on separately from this release; until then Tavotto quietly keeps
  using the built-in list and shows no error. Set `TAVOTTO_NO_JOURNAL_SYNC=1` to
  rule out these requests entirely.

**AI editors know about journals and the newer desktop features.** Asking
Codex, Claude Code, Cursor or another connected AI editor to "make this ready
for Nature" now makes it look the journal up in the same library the desktop
app uses, check and export against it, and tell you which journal and guideline
version it used. If a journal isn't in the library it says so and asks for the
guideline text instead of making numbers up. When a journal's guidelines could
not be fetched, it says why (the download limit is used up and about how long
to wait, you need to be online, or the data failed verification and was
discarded) instead of retrying around the limit or filling in numbers from
memory.
- Existing Pillow / plotly / R / MATLAB scripts are no longer refused. The agent
  leaves the original untouched and writes a new `<name>_matplotlib.py` next to
  it, the same rule as the desktop app's "Generate editable version".
- When Tavotto tools are missing in an AI editor, the agent first points
  desktop users to Settings > Figure assistants > Connect AI editors
  (including Google Antigravity) and only falls back to terminal commands when
  that is not available.
- The skill lists rotated and vertical canvas text, copying figure text as
  annotations, edge drag to pad or crop, the version timeline and two-colour
  gradient peaks, so the agent hands these to the desktop window instead of
  saying they can't be done.

**Connecting an AI editor no longer asks for a folder.** Settings > Connect AI
editors > Connect is one click on every editor. Before, the first connection
opened a folder picker and the editor was then limited to that folder, so in
Claude Code, VS Code or WorkBuddy, opening a figure from another project failed
with "path out of scope".
- Claude Code, VS Code and WorkBuddy use the project the editor itself is
  working in, so switching projects just works.
- Editors that do not report a project (Claude desktop, TRAE, Cursor, ZCode,
  Antigravity) can open figures anywhere on this computer, on any drive and in
  any folder. Only credential files stay blocked: `.env` files, private keys,
  SSH and cloud credentials, browser login data and Tavotto's own key file (the
  same list the fix assistant uses).

**Text on the canvas.**
- Text annotations can be rotated to any angle: drag the round handle above the
  frame (hold Shift to snap to 15 degrees) or type an angle in the Properties
  panel. Alignment, snapping and the multi-selection frame follow the rotated
  outline, and exports draw the text where the canvas shows it.
- Text labels can be set vertically with the new "Direction" control in the
  Properties panel and the floating text toolbar. Vertical text runs top to
  bottom with columns from right to left; Chinese characters stay upright,
  English letters and digits lie on their side, and full-width punctuation uses
  its vertical forms. The box height is the column length (text wraps into a new
  column at that point), and Left / Center / Right becomes Top / Middle / Bottom.
  Vertical text can be rotated too, and exported PDF, SVG and images match the
  canvas.
- The font menu for text annotations lists every font on this computer that can
  be embedded, and English and Chinese can use different fonts (for example
  Times New Roman with SimSun). The export embeds the fonts you see on the
  canvas. On a computer without one of them the name is kept, a warning appears,
  and the text falls back to the closest built-in font.
- A text annotation can carry the exact font Matplotlib used for a piece of text
  in the figure; the canvas and exports then draw it in that same font file
  instead of the nearest built-in family. Only the font's name and a fingerprint
  of the file are stored in your layout, never the font itself. If the font is
  missing or forbids embedding, the closest built-in font is used and the
  properties panel marks it as missing.
- The Font row of a figure's text is now one row with two dropdowns, English on
  the left and Chinese on the right. When the English font you picked already
  draws Chinese, the Chinese dropdown is greyed out and says why. Either font can
  be restored on its own; with both changed, the restore button opens a small
  menu (English, Chinese or both, one undo step). Nothing about how fonts are
  saved changed.
- The text box in Quick Edit and the properties panel is a plain input at rest,
  with a small "TeX" tag at its right edge that switches between plain text and
  LaTeX source. While you edit, a floating bar with bold, italic, superscript,
  subscript, line break and case appears above it (Tab reaches the bar, Esc comes
  back). The Quick Edit header shows only the kind of element, such as "Title".
- The properties panel no longer shows the "Figure > Subplot" trail at the top;
  to go up a level, click the parent in the Figure elements tree. The "n changes"
  button now sits on the name line.

**Copy text from inside a figure as a text annotation.** While editing a
figure's contents, select a piece of text (title, axis label, tick number,
legend entry or text added by the script), then press Cmd/Ctrl+C or right-click
and choose *Copy as annotation*, and paste with Cmd/Ctrl+V or *Paste as
annotation*. You get a text annotation on the page on top of the original,
offset 4 mm to the lower right like a duplicate, with the same wording (formulas
included), size, colour, bold or italic, alignment, rotation and font. A y-axis
label comes out rotated, and stays rotated correctly when the figure is rotated
or flipped. Curves, filled areas and other non-text things show "... can't be
copied yet" in the top bar.

**Dragging a figure's edges adds margin or crops, instead of stretching.**
- In single-figure editing, edges change the canvas around the figure instead of
  the figure size: drag outward to add white margin (for example for labels, or
  to reach a journal column width, which it snaps to), drag inward to remove it.
  Inward dragging stops at the figure edge and again at the edge of the plotted
  content ("tight"); hold Alt (Option on macOS) to crop into the content. Drag a
  corner to resize the figure itself proportionally (hold Shift for a free aspect
  ratio); text keeps its pt size and the figure re-renders when you let go. A
  capsule next to the canvas explains each drag, and **Fit to content** /
  **Remove margin** appear when the figure is selected. Exports use the figure
  plus its margin. Margins live in your layout only and are not written back to
  the script.
- In a multi-figure layout, the four side handles crop that side: the figure
  stays where it is at the same scale, the handle stops at the figure edge and
  again at the edge of the plotted content, and Alt cuts into the content.
  Corner handles still scale the whole figure proportionally, with a capsule
  showing the scale and the resulting text size in pt (amber when it falls below
  your journal's minimum). Crops already in your layouts are unchanged; **Reset
  crop** puts a figure back to its full size.

**Gradient-filled peaks (XPS / spectroscopy fitting).** Some scripts draw a
peak's gradient as many thin colour stripes clipped to the peak outline.
- Each peak highlights and responds to clicks only where it is actually drawn.
  Before, its selection box was a band across the whole subplot, clicking one
  peak often selected another above it, and on figures with many peaks the later
  subplots' peaks lost their outlines and could only be picked by a large
  rectangle.
- Selecting such a peak shows a "Gradient" row with the top and bottom colours
  (left and right for a horizontal gradient) and a preview bar. Changing a colour
  recolours the peak and keeps the gradient's light-to-dark profile; before, it
  flattened the gradient into one solid colour. Reset brings back the script's
  colours.
- If the script draws its own legend as small gradient swatches, the matching
  swatch in the same subplot is recoloured too. When several swatches have the
  same colours, Tavotto doesn't guess and the properties panel lists them so you
  can pick. Undo or Reset returns both to the script's colours. The script is
  never changed.

**Updates download in the background and install when you quit.** When Tavotto
finds a new version at startup it quietly downloads and verifies it, and a small
"Update ready" pill appears in the top bar. Click it to restart into the new
version, or ignore it: the update installs when you quit. Your running session
is never swapped out. Turn off **Settings > Updates > Download updates in the
background** to be asked first, as before. A failed background download stays
silent, and you can still download manually from Settings. Download progress no
longer makes the interface sluggish on slow connections.
- A slow update tries the other source. Updates come from the Tavotto mirror or
  GitHub. Before, Tavotto switched only when a download stopped completely, so a
  trickle of a few dozen KB/s on a 150-200 MB package could take very long. Now,
  when more than about three minutes would remain, it probes the other source
  for a few seconds; if that is clearly faster it takes over (the progress bar
  restarts from that source), otherwise it keeps the first download. This happens
  at most once per update, and the installer's signature is verified the same
  way either way.

**Codex inside Tavotto.**
- Picking a model your Codex is too old for now tells you to update it. When the
  Codex desktop app updates first, newer models appear in the model list while
  the Codex command Tavotto runs may reject them, which failed with a 404.
  Tavotto now compares the versions: the last row of the ChatGPT model menu reads
  "Update Codex", and a 404 failure card offers the same button. Updating
  switches to a newer Codex already on your computer (such as the desktop app's)
  or installs one inside Tavotto. When neither is possible, the row is greyed out
  and says how to update, and the failure card offers to switch back to your
  default model, with the command under "Details".
- Codex failures from an expired sign-in or an exhausted quota now say so and
  offer "Check connection" instead of only "Failed".
- The one-click Codex install is now version 0.166.0 (was 0.165.0) so the newer
  models work. The download comes from the official npm registry, falling back to
  the npmmirror copy of the same file, instead of from GitHub. On a machine in
  mainland China, npmmirror is tried first (the same region check used for app
  updates and Contact the author), because the official source ran at around
  2 MB/s there without being slow enough to switch; if the mirror is slow it
  still switches back.

**The assistant shows what it is doing with small animated dot orbs.** The line
that says what the AI is doing starts with a small dot orb instead of a static
icon, with a different shape while it thinks, runs your script, reads or edits
it, and between sending your request and the first reply. Finished steps keep a
dimmer, slower orb. The empty assistant panel shows a larger orb. Orbs stop
drawing when scrolled out of view and stay still with "Reduce motion" on.

**Progress bars are drawn as dot grids.** Installing packages, preparing a
project, downloading an update or Python, exporting and sending a report now show
a row of small dots: sparse for what remains, packed closer for what is done.
When progress is unknown, a short stretch of dense dots slides back and forth.
The dots sit on whole screen pixels, so they stay sharp on Windows at 125% and
175% scaling. In the desktop app they are sized from the display's physical
pixel density, so a 27-inch 4K screen at 150% or 175% no longer shows dots twice
as large as on a Mac; where the display reports no size (some projectors, TVs,
remote desktops, virtual machines) and in the browser version they follow the
scaling setting. Reduce motion stops the animation.

**On Windows, dropping a script on the home page opens it directly.** Dragging a
`.py` file (or an R / MATLAB script, or a folder) onto the home page used to open
a file picker and make you find the same script again. It now opens the script's
folder and runs the script, as on macOS; dropping a script on a canvas in the
editor works the same way. WebView2 runtimes older than 1.0.1518 (2023) still
fall back to the picker.

**Contact the maker and problem reports.**
- Any file type can be attached (CSV, MAT, HDF5, ZIP ...), up to 5 files and
  50 MiB in total (was 20 MiB; only images, PDF, Word, Excel and PowerPoint were
  accepted).
- "Attach diagnostic info" can include script source, crash reports and damaged
  sessions, three unticked checkboxes shared with Send a problem report. Ticking
  "Script source" no longer shows a privacy warning under it; the other two still
  do.
- Settings > Help & diagnostics > "Send a problem report" opens the
  problem-report dialog with those checkboxes again (it used to open the Contact
  dialog, whose bundle never included them).
- When you send a problem report with *Contact the maker* on, the app keeps a
  small record so the maker's reply appears under *Contact the maker > My
  letters*, tagged "Report" with the report ID. The dialog says so. A report that
  gets no reply is forgotten locally after 30 days; nothing changes if *Contact
  the maker* is off (`TAVOTTO_NO_CONTACT=1`).

**The first-launch usage-sharing question is easier to read.** It no longer opens
with two bullet lists. It opens with an illustration and two plain sentences
(only anonymous usage records are sent; your figures, scripts, data and file
names are never sent), and the full lists are one click away under "What exactly
is sent". "Not now" and "Share anonymously" are still two same-sized buttons on
one row.

**Smaller conveniences.**
- Windows without long-path support: "Make editable version" no longer fails
  straight away when the project sits in deeply nested or long-named folders; if
  a path still can't be used, the card says a file path in the project is too
  long and the conversion did not start.
- Option+Tab wraps inside dialogs on Safari and the macOS app, so keyboard users
  are no longer stuck on the Close button (Shift+Option+Tab goes the other way).
- "Min resolution" and every other resolution value now say "dpi" (the canvas
  panel's export summary, export and profile settings, journal rules, export
  check notes). Only the wording changed; checks, saved settings and exported
  files are the same.
- In Settings > Packages, the package name field and the "Search PyPI" and
  "Install" buttons sit directly under the "User-installed" heading instead of
  inside a grey card.
- The "Recent layouts" list asks "Open anyway" or Cancel before opening another
  project's layout, instead of opening it and then failing to find its script
  figures.
- Reopening the same layout file from the project keeps its named timeline
  versions, so you no longer need to look for them under "This project's
  layouts on this computer".
- On small screens or at high scaling, the window is no longer larger than the
  screen and the bottom buttons are no longer cut off.
- Interface icon animations no longer pass through themselves (the folder sheet,
  group squares, envelope flap, image-icon sun, sparkles). Each starts from the
  state before the action and ends at the resting icon; lock and unlock move by
  the same distance, disconnect pulls the plug out (and "Disconnect" plays it),
  distribute slides one block to even spacing. The disconnect, save and unlock
  icons were redrawn.
- The editing reference for AI editors now says that `annotate()` arrows with
  empty text whose endpoint coordinates can be converted back can be dragged
  whole or by either end; only arrows with text or non-convertible coordinates
  stay style-only.

## Fixed

**Converting scripts with Codex on Windows.**
- With Codex signed in to an official OpenAI model, "Make editable version" could
  read your script and data and then stop with "the AI was not allowed to write
  the new file", because Codex's file-writing tool fails inside its Windows
  sandbox. Tavotto now writes the new Matplotlib script itself on Codex's behalf
  (only that file, inside Tavotto's own working folder). Your original script and
  project folder are never touched.
- If that still stops on a PC where Codex's sandbox cannot run at all, Settings >
  Figure assistants > Advanced has **Let the AI run without a sandbox when
  converting** (Windows only, off by default; other AI tasks are unaffected). A
  conversion blocked by the sandbox also offers to turn it on and retry in one
  click. The diagnostic bundle records whether it was on.

**The desktop app's AI repair can run protected commands again.** On the desktop
app, when the AI repaired a script it could not run commands in its protected
mode and always answered that the sandbox was unavailable, and its trial runs
silently lost their operating-system sandbox. The sandbox test asked the app to
run a one-line Python command, which the packaged app does not understand; it now
uses the built-in Python (or a plain system program when that isn't installed
yet). Nothing changes when you run Tavotto from source.

**Installing a missing package no longer leaves the figure missing another one.**
When a script stopped on a package the built-in Python lacks (for example
scikit-learn), installing it created a fresh project environment that could lack
packages the script had used all along from the built-in one, such as pandas, so
the next run stopped again, one package per round. This happened mostly when the
script imports its own helper module from a folder it adds to `sys.path`
(including `Path(__file__).parents[1]`). Tavotto now reads helper modules in
those folders when planning the install (a few levels above the project at most,
never your home folder or above). When it still can't see all imports, the new
environment also gets the built-in packages (pandas, SciPy, seaborn, Pillow).
The confirmation lists every package before anything is installed.

**Scripts that `import pymupdf` can install it in one click.** PyMuPDF's current
documentation uses `import pymupdf` instead of `import fitz`; Tavotto only knew
the old name, so a script written the new way got a "missing pymupdf" card with
no install button and an empty "Specify package..." box. Both names now lead to
the same install into an environment Tavotto manages.

**A copied script that saves figures with the same names gets its own figures.**
If you copied a script to rerun on new data and it saves figures under the same
file names (for example into a different output folder), preparing the copy used
to stop with "these figure names already belong to other scripts", and the only
way out took the figures away from the original. Tavotto now links the copy's
figures separately; the asset panel still shows the original file names, and the
first time you open the copy's figures it runs once more. Only when both scripts
write the very same file in the project folder is it still reported as a clash,
and then the card offers sending feedback (not "Use your AI to fix it", which
couldn't change anything because the clash isn't in the script) and still says
where to choose which script a figure belongs to. Your scripts are never changed.

**Scripts that write their SVG by hand get "Make editable version".** A script
that uses no plotting library and builds SVG text itself used to end with "no
figure was produced, the data file was probably not found". The card now says the
figure was drawn as SVG and offers **Make editable version**, which writes a
separate Matplotlib script for you to compare and accept. The original is never
changed.

**The fix assistant can correct a data file you linked by mistake.** If a script
couldn't find its data and you pointed Tavotto at the wrong file, the next run
failed with a reading error (for example `JSONDecodeError`) and the assistant
could find the right file but not replace your earlier choice. It now sees which
file each data link points to and can re-point a wrong link after you confirm.
Choosing a different file for the same path in the missing-data dialog also
always takes effect now. Your script and data are never changed.

**The fix assistant waits for a running install before switching Python.** When it
tried to create a new environment while a package installation for the same
project was still running, it failed immediately with "dependency install busy"
and often gave up. It now waits, however long a slow network or large packages
take (the card says "Waiting for another installation to finish..." and Stop still
works). Only if the installation shows no progress for 10 minutes is the
assistant told the problem is temporary and can try again. A script still running
in the environment still has to be stopped by you first.

**Scripts that start another script which prints text no longer fail with a
protocol error.** If your script ran a second Python script with
`subprocess.run(...)` (or used a library that writes straight to the console) and
that program printed anything, the run failed with `protocol_mismatch` and no
figure was captured. That output now goes to Tavotto's render log like the rest
of your script's output, and the run completes.

**Figures a script only saves into an in-memory buffer are no longer missing.**
If a script saved a figure only into a `BytesIO` (for example to convert it to
TIFF with Pillow) and then closed it, Tavotto did not show that figure at all.
With several figures, one could quietly go missing while the others appeared.
Such figures now appear, sized to match what the script produced when it saved
with `bbox_inches="tight"`, and the desktop app and the browser version list the
same figures. If a script has more of them than fit, the extra ones are counted
in the "not shown" notice instead of disappearing silently.

**Rendering no longer gets slower as more figures are open.** With four or more
scripted figures on the canvas, editing one could re-render the others in the
background one after another, but Tavotto kept only three render sessions alive,
so each re-render restarted a script from scratch (about 15 times slower than a
warm render, 20 to 40 seconds on some Windows machines). Tavotto now keeps up to
eight sessions when your computer has the free memory (three otherwise), and
background re-renders of neighbouring figures no longer push out the figure you
are editing. A neighbouring figure that would need a fresh start while sessions
are full keeps its previous picture.

**The first render after opening a project is faster.** On a slow disk or a
Microsoft Store Python, the first render could take 20 to 40 seconds because the
render session had to start at that moment. Tavotto now quietly starts the
session for the first script-backed figure once the project has settled, and
checks each interpreter once instead of once per concurrent task. Nothing is run,
drawn or written in the background, failures are ignored, and your scripts and
files are never touched. The first render after launch also runs its independent
Python-environment probes side by side, trimming a fraction of a second; Tavotto
still never picks a different Python on its own.

**The rewrite preview after pointing at missing data could hang on Windows.**
After choosing the real data file in the "data file not found" dialog, the first
step could sit on "processing" for minutes with "Later" greyed out and Esc doing
nothing, so the only way out was quitting. The preview's Git status check could
be blocked by Git or a helper it started. It now runs with no inherited input,
never prompts or takes repository locks, and gives up after 3 seconds (the
preview then omits the Git note). The preview request has its own 30-second
limit, and "Later" or Esc cancels it while pending. Nothing is written to your
script until you confirm.

**Preparing the environment on Windows no longer fails once at random.** The
first attempt to prepare the private Python for a single-package fix could stop
with a "write failed" error when antivirus software or a search indexer briefly
held the freshly unpacked files, and only a second click worked. Tavotto now
retries that step for a few seconds, and when it still fails the log records the
step and the Windows error code.

**AI history from the old Microsoft Store install is no longer lost on first
start.** When Tavotto moved data out of the old Store (MSIX) package's private
folder, the AI history could end up empty if two parts of the app opened it at the
same moment on first start. The second now waits for the first to bring the old
history over.

**Export and preview**
- The full-layout export preview draws arrows and shapes the way they are
  exported. Arrows used to follow the corner-to-corner diagonal of their box (an
  up-right arrow showed as down-right, horizontal reversible-reaction arrows
  turned slanted, arrowheads were missing), filled rectangles and ellipses were
  grey outlines, dashed lines looked solid, and the scale bar's line cut through
  its label. The preview now uses each object's real endpoints, arrowheads, fill,
  stroke, dash, rotation and stacking order. The exported PDF and PNG files were
  already correct.
- Text boxes, arrows and shapes added over a single figure keep their relative
  size when exported. When the figure was shown scaled down on the canvas (a
  large Matplotlib figure fitted into the page), a label matched to the figure's
  text ended up about half as large in the file, inside a box too big for it.
  Export now scales font size, line width, padding, border and corner radius by
  the figure's ratio. The figure's own text is unchanged, and nothing changes when
  the figure was shown at its original size.
- The export receipt lists only the files this export wrote. After exporting every
  figure separately right after an earlier export, it could list files from the
  earlier one, leave out a figure's files, and make "Show in folder" look for a
  file that does not exist; a single export after a per-figure batch also showed
  the batch's old list. A failed figure with no error detail now shows a plain
  "export failed" line instead of a raw `{{error}}` placeholder.
- Multi-page PDF merge: when a script wrote several figures into one `PdfPages`
  file and you ran it through the default "Prepare and run", the export window
  offered no "merge into one multi-page PDF" choice under "Export each figure
  separately" and produced one single-page PDF per figure. It now appears after
  either entry point.
- Reopening a saved layout no longer shows a restored draft's figure. After
  restoring a draft and opening the saved layout of the same name with the same
  script figure, the canvas and whole-sheet preview kept showing the draft's
  version (for example its title) while the export used the saved one. Both now
  read the preview matching the layout's own settings, and the "approximate
  preview" badge appears when none exists.
- An SVG whose text was converted to paths says so. When a figure is exported to
  SVG without its source script, text falls back to outlines; the result row now
  adds one line that it can no longer be edited as text in Illustrator and
  similar tools (only shown when text was actually outlined).
- Overwriting an export without the style-check report no longer leaves the old
  `<name>_style-check.json` next to the new figure. Only the file Tavotto wrote is
  removed; other files are never touched.
- Serif canvas labels with Chinese now export that Chinese in a serif (Song) face
  (Noto Serif SC), matching the canvas; before, it came out in a sans-serif (Hei)
  face. Sans-serif and monospace labels keep Noto Sans SC.
- A serif label's degree and unit symbols keep the label's font in the export: it
  showed a serif face on the canvas but a sans-serif face in PDF, SVG and images
  for the celsius and fahrenheit signs, the Kelvin sign and the Angstrom sign.
  They are now drawn as °C, °F, K and Å in the label's own font in both places.
  What you typed stays unchanged in the saved project, and copying text from the
  exported PDF still gives the original symbols (the SVG text layer reads °C, as
  it already did for composed superscripts).

**Write back to the original file**
- Write back re-checks the source images right before backing up and replacing
  them. Writing an edited figure back replays the script first, which can take
  minutes; if another program replaced the original during that replay, Tavotto
  could back up the newer version and then overwrite it. It now re-verifies every
  target (modification time and size as you first saw them) before the backup and
  before each replace, and if anything changed it stops with the usual "source
  changed" message, leaves your files untouched (rolling back any sibling already
  replaced) and keeps no temporary files. The verification replay no longer
  touches your original images: if the script saves a PNG through an open file
  handle into the project, that write goes to a throwaway copy.
- The "Write back to original file" dialog remembers the original's modification
  time from the moment it opens. If another program replaces the file while the
  dialog is open, confirming is refused with the usual "changed outside this tool"
  message and the file is left untouched; close and reopen the dialog to write
  back against the new version. Restoring from the write-back records uses the
  same check.
- The result dialog no longer reads "No figure edits to write back yet" above the
  list of updated files after a successful write-back.
- Restoring from the write-back records names the backup folder actually used,
  instead of always saying `cache/original_backups` when the project has a custom
  backup folder.

**Editing on the canvas**
- One undo reverts a resize together with the automatic re-layout. Before, when
  you resized one picture in a layout group and the others moved aside, a single
  undo moved the others back but left the picture at its new size, so the two
  overlapped (and could be saved or exported that way). Resize and re-layout are
  now one undo step, and redo restores both.
- Typing a title or axis label one character at a time into the properties panel
  of an adopted PNG (the "edit based on the redrawn version" path) no longer
  keeps only the last character. The panel now keeps showing the previous
  version's fields until the new one arrives, so the box stays put. Geometry
  edits still wait for the exact redraw.
- Pasting a runtime figure within the same project no longer opens the relink
  dialog for a supposedly missing source, and the figure's edits come along.
- The log-axis range no longer accepts 0 or negative numbers: a lower limit of 0
  or less on a logarithmic axis reverts to the previous value in the properties
  box, and layouts that already hold such a limit now show the same picture on
  the canvas, in exports and after reopening.

**Hints that now match what the app actually does**
- The close-window prompt says "Don't save" keeps your local draft, which is
  offered for recovery on the next start, instead of reading like the edits are
  thrown away.
- For a script that reads stdin without a prompt (`sys.stdin.readline()`,
  `sys.stdin.read()`) after an earlier `input("Your name? ")`, the prepare card
  labels the earlier text "Output so far" instead of showing it as if the same
  question were asked again.
- A missing figure script is no longer reported as "script updated". After a
  rename or deletion and a failed "Rebuild", the properties panel says the source
  script is missing.
- A script that fails for lack of LaTeX (`text.usetex` with no `latex` on PATH, or
  a missing TeX package) shows the explanation that this is a system TeX tool,
  not a Python package.
- A Python pinned in Settings that lacks packages the script imports lists them on
  one line.
- "Project status" no longer says there are no figures when runtime-captured
  figures exist; it says how many.
- The first click on "Edit figure content" for an original PNG that cannot be
  safely adopted shows the real reason, with the "Rebuild as editable figure"
  button, instead of a generic "couldn't render" message and the button only on
  the second click.
- Renaming a figure script and renaming it back clears the canvas "script is
  gone" badge, and the script no longer stays listed as "to prepare":
  refreshing rechecks the project and drops paths that no longer exist, and a
  card you dismissed stays dismissed if nothing changed.
- A script that reads standard input in Tavotto and calls `readline(size)`, `read(size)` or
  `readlines(hint)` on standard input now gets what Python gives: at most `size`
  characters with the rest kept for the next read or `input()`, and `readlines`
  stops only after the total exceeds `hint` (both while preparing a script and in
  the desktop app).
- In the safe run mode, runs are no longer reported as fully successful after a
  blocked operation when threads were involved. If a script (or a library it
  uses) checked for files from several threads, or created folders with
  `os.makedirs(..., exist_ok=True)` / `Path.mkdir(exist_ok=True)` from several
  threads while Tavotto was blocking a deletion, some collisions or checks were
  missed and the run could be reported as complete. Every thread is now judged on
  its own.

## Diagnostics and privacy

- When a script runs an external program (for example `rsvg-convert` through
  `subprocess`) that can't be found, the feedback bundle's report now has a short
  `project.missing_commands` entry: the command name (well-known tools as is,
  anything else hashed), whether it is on the render process's PATH, whether it
  exists in a few common install locations (named, never as paths), whether a
  Homebrew install is present but unlinked, and how many PATH entries there were.
  No paths and no text from your script; nothing is sent unless you send the
  bundle yourself.
- The first-run setup log (creating the rendering environment, installing
  matplotlib) is redacted before it is kept: credentials and query strings in
  package-index URLs, personal paths and other secrets are removed, and the data
  folder appears as `<data>`. If a step fails, the log ends with one line naming
  the step (environment, install or import check) and whether it timed out or
  exited with an error; a timed-out install keeps what pip printed before it was
  stopped. Thanks to @mvanhorn for this contribution (#807).
- Journal downloads, when available, send the journal id, a random anonymous
  device token (not the usage-statistics identifier), the catalog version and a
  client type, never your project, files, script, paths or figure content. See
  `docs/privacy.md`, "Journal standards catalog".
