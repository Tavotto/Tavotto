# Tavotto 0.18.0

## Before you upgrade

**Save now writes the layout into your project.** ⌘S / Ctrl-S updates its
bound file in `tavottofile/`; an older layout that exists only in local
recovery storage asks for a filename once. Autosave remains local crash
recovery, and saving without an open project remains local. If another
program changed the project file, Tavotto asks you to resolve the conflict
instead of silently overwriting it. (#674)

**A project using your existing Python may now run from the script's
folder.** This applies to project-level system, Conda or pyenv interpreters,
including an eligible interpreter adopted after a missing import. Ordinary
relative outputs therefore land beside the script, as they do when you run
it there in a terminal. An explicit working-directory choice is kept.
Bundled and managed runtimes, project venvs and globally pinned interpreters
retain their sandbox default. Explicit interpreter choices are never
silently replaced. (ADR 0107, #713)

**A figure's `savefig` frame is now its editing frame.** New tight-cropped
figures keep their saved labels and margins when opened, edited or
exported. Existing layouts retain their earlier frame until you choose
“Use the original figure's frame”; that change preserves placement and can
be undone. An old crop that does not intersect the new frame is refused
with an explanation instead of making the whole layout unexportable.
(ADR 0098, #678, #698)

**MCP authorization must name a project, not your whole home folder.**
Start your host in the project, or set `TAVOTTO_MCP_ROOTS` to that project.
Home directories and their ancestors are now rejected. If you switch from
a generated Claude Code, DSH or WorkBuddy configuration to the new plugin
or bundle, remove the old Tavotto entry to avoid loading two servers.
(#712)

Desktop system requirements are unchanged: macOS 14 or later on Apple
Silicon, macOS 15 or later on Intel, and Windows x64. Choose the dmg for
your Mac's architecture. Linux continues to use the PyPI browser mode.

## Added

**A layout timeline with named checkpoints and visual comparison.** Open
it beside the save status or with ⇧⌘H / Ctrl-Shift-H. Preview earlier
layouts, compare them side by side or overlaid, and restore one in a single
undo step. Named checkpoints are never automatically pruned; automatic
snapshots follow pauses, and successful saves, exports, writebacks and
project changes create key moments. Naming a checkpoint now lives in this
timeline, with ⌥⌘S / Ctrl-Alt-S as the direct shortcut. Reaching the named
checkpoint limit stops new names without deleting the ones already there.
(ADR 0101, #679, #776)

**Missing data can be located once and remembered for the project.** When
a script cannot open an input file, choose its new file or folder in the
dialog. Tavotto retries using a read-only relocation rule, and related
missing inputs can be repaired together. A file that still exists at its
original location always wins; output destinations are not redirected.
(ADR 0106, #716)

**Input paths that need a script change get a reviewable repair.** Checks
such as `exists`, `glob`, directory scans and supported native readers
cannot always use read-only relocation. For proven input-path constants,
Tavotto shows a line-by-line diff and requires an explicit confirmation
before replacing them. Backups are kept in both the project and Tavotto's
local data folder; recovery can restore the original or undo only those
substitutions when possible. Computed paths and ambiguous read/write uses
are excluded. This repairs input paths; it does not write arbitrary visual
figure edits back into Python. (ADR 0110, #730)

**Scripts can ask questions in the interface.** `input()` and supported
stdin reads show the prompt and recent script output. Ordinary answers can
be remembered and changed later; unanswered questions time out after ten
minutes. With no interface available, Tavotto asks you to run the script
once in its window instead of waiting forever. `tavotto run` continues to
use the terminal. **Remembered answers live in
`tavottofile/_script_inputs.json` and travel with a copied or synced project
folder; project packages exclude them. `getpass` answers are not remembered,
but the current dialog displays them as plain text, so do not enter secrets
there.** (ADR 0099, #680, #701)

**One-click environment repair works without a preinstalled Python.**
Tavotto can prepare its private Python and install the script's required
packages together. The dialog shows download and install progress, keeps
cancel and retry available, and resumes editing or running after a
successful repair. Desktop installers carry the Python archive; installing
additional scientific packages can still need a network connection.
Clicking a figure or running a script that lacks an environment opens the
repair dialog directly. Target-specific acceptance limits are listed under
Known issues below. (#682, #709, #740, #742, #743, #760, #774, #793)

**Arrow keys nudge elements inside a figure.** Supported titles, legends,
annotations, shapes, arrows, subplots and groups follow the same movement
rules as a mouse drag. The step is 0.5 mm on the page, Shift makes it 5 mm,
and Option / Alt makes it 0.1 mm. A continuous sequence is one undo step;
editing inside a figure no longer moves the entire canvas panel instead.
(ADR 0093, #671)

**Multiple selections get quick formatting and alignment.** Compatible
text selections inside figures and canvas text selections have a floating
typography bar. Eligible figure elements also have alignment controls;
one group edit remains one undo step. (#666)

**Shared colorbars form real groups in the element tree.** Subplots
explicitly named as owners and their colorbar can be selected, moved and
resized together. Moving just one owner leaves the shared colorbar with
the group. A single-owner colorbar appears under its subplot. This also
works for manual `cax=` layouts when `ax=ax` or `ax=[b, c]` explicitly
identifies the owner or owners. Ownership is never inferred from proximity
or matching colors. (ADR 0102, #691, #794)

**The desktop app can open a remote Tavotto engine in its own window.**
File → Connect remote instance opens an isolated window for an engine
reached through your SSH tunnel. Scripts, data and exports stay on the
server, while your local project remains open separately. Establish the
tunnel yourself and use matching port numbers; one remote window is
supported, and reopening it requires a fresh login URL. (ADR 0105, #702)

The following three installation channels activate when the verified
0.18.0 package is promoted to `plugin-stable`. A release-preparation commit
on `main` does not activate them; the README installation sections are
published only after that promotion is verified.

**Claude Code plugin (Beta).**
Tavotto now installs into Claude Code as a plugin:
`claude plugin marketplace add Tavotto/Tavotto --sparse .claude-plugin`, then
`claude plugin install tavotto@tavotto`. It is the same plugin as for Codex (same MCP server and
skill); Claude Code has no embedded canvas, so you edit through the tools. The folder Claude Code
was started in is the authorized project. If you had set Tavotto up in Claude Code with the config
generator, remove that `.mcp.json` entry after installing the plugin, or you will have two servers.
The release promotes this same package to the `plugin-stable` branch.

**DeepSeek Harness bundle (Beta).**
Tavotto now installs into DeepSeek Harness as a profile bundle:
`dsh plugin --profile web add "git+https://github.com/Tavotto/Tavotto.git#plugin-stable&path:/codex-plugin"`.
The MCP tools (`mcp__tavotto__*`) and the `tavotto-figure` skill come with it; no YAML to merge. The folder
you start `dsh` in is the authorized project. If you had merged the config generator's `cordis.patch.yml`
row for Tavotto, remove it after installing the bundle: two rows with the same `tavotto` server name make the
second one fail to load. The release promotes the bundle together with the plugin.

**WorkBuddy plugin (Beta), and more hosts.**
WorkBuddy installs the same plugin as Claude Code: in WorkBuddy's plugin marketplace choose **Add marketplace**,
enter `Tavotto/Tavotto`, then install `tavotto@tavotto`. The conversation's working folder is the authorized
project. If you had added Tavotto to WorkBuddy by hand with the config generator, remove that entry after
installing the plugin. It shares the same `plugin-stable` release channel.

The config generator gained `--host minimax-code` (a project `.mcp.json` for MiniMax Code), and for Trae it now
prints one-click install links (`trae://` for the international edition, `trae-cn://` for the China edition), puts
Trae's timeouts in `env`, and refuses a Python path with spaces, which Trae can't parse. Trae's skill now goes in
`.trae/skills/`. ZCode's generated config now carries `timeoutMs`, so long exports no longer time out after 30 s.

Tavotto no longer accepts your whole home folder (or a folder above it) as the authorized workspace, from any
source: `TAVOTTO_MCP_ROOTS`, the host's MCP roots, a confirmation prompt, or the folder the server was started in.
Before, a host that reported the home folder as its root let Tavotto open anything under it. Start the host in a
project folder, or set `TAVOTTO_MCP_ROOTS` to the project; the error now says so (`workspace_root_too_broad`).

In the plugin, Codex's MCP config is now `codex.mcp.json` instead of `.mcp.json`, because other hosts read a
plugin's `.mcp.json` on their own and tried to start Tavotto from the wrong folder. Codex users don't need to do
anything: plugin updates pick it up, and an already-installed older version still checks out as healthy.

## Changed

**A quieter editor, with canvas tools closer to the work.** The interface
uses a gray desktop and white work surfaces. Canvas tools move to a bottom
floating toolbar, zoom sits beside the canvas tabs, and writeback is the
first item in the overflow menu. Low-frequency inspector controls expand
from compact summary rows. The home screen and tutorial are shorter, the
command palette and shortcut guide show keycaps, and Settings consolidates
into nine pages, including Project and About & updates.
(#756, #761, #763, #764, #765, #770, #775, #778)

**Problems are grouped into cards you can act on.** Browse by subplot or
issue category and fix that exact group. A figure with one subplot opens
directly to its issues; changing figure or project no longer leaves an
empty result filtered by the previous context. (#690)

**Style controls agree across the left rail and the style library.** Each
text category has font, size, bold and italic controls; tick direction,
length and width are available too. Library entries distinguish “not set”
from an explicit normal or off value. (#662, #703)

**Writeback history is part of the writeback dialog.** “Sync edits to…”
moves to the context menu and uses the same writeback flow. (#777)

**Adding a figure avoids covering existing objects when space permits.**
New figures are placed to the right or on another row, with a centered
fallback when they will not fit. Large additions are scaled sensibly,
changing page size refits the view, and objects outside the page are dimmed.
An intentional drag-and-drop location is kept. (#706, #762)

**Desktop menus expose more of the editor.** Save, alignment,
distribution, view, window and help commands are available in the native
menu bar. The workspace context menu can reveal the project folder or
selected script in the system file manager. (#660, #661, #663)

**Environment downloads can recover from a slow official source.** When
you have not configured a package source yourself, an eligible failed or
stalled official PyPI installation can retry through TUNA within the same
total time budget. Private-Python archives can switch to npmmirror, still
checked against the locked hash. Existing pip configuration is respected;
the effective source is read through pip rather than guessed from one
configuration file. (#744, #745, #767)

## Fixed

**Inspector controls stay under the pointer when the first render finishes.**
Build and stale-script messages no longer move the controls below them as
their state changes, so a horizontal-flip click is preserved when saving a
named layout checkpoint. (#797)

**Diagnostics actions stay in place while checks finish.** Report and
developer controls now precede the changing health results, so a result
arriving during a click does not move its target. Failure details and
environment-repair guidance remain visible. The inspector's full-name
restore buttons also wrap within narrow sidebars. (#797)

**A selected PNG keeps its own frame when editing starts.** An eligible,
untouched full-size PNG no longer inherits a tightly cropped companion
PDF's frame or jumps on the canvas. Source identity survives undo, redo,
reopening and independent panels. An original-copy export keeps its pixels,
density and transparency. Existing edits, ambiguous histories and pending
style work are guarded rather than silently replaced. See the bounded
scope under Known issues. (#791, #793)

**Selected-source editing checks the actual file.** Recorded save
settings and destination must identify one matching PDF or PNG, and its
initial pixels and frame must agree. A changed source or ambiguous save
history is refused explicitly instead of attaching edits to another
artifact. Per-save evidence is bounded, and incomplete evidence is reported
as such. (ADR 0113, #783, #789)

**Selection geometry now matches the exact preview you see.** SVG and PNG
previews have geometry from their own draw, with PNG geometry becoming
active only when the matching image loads. This fixes displaced first
drags and bar labels whose hit area or drag position disagreed with the
visible text. (#779)

**Opening a supported tight-layout figure no longer rearranges it
again.** Standard single-save persistent tight layouts begin from the
original subplot state, so extra preview draws do not progressively change
margins and tick density. Resizing a cropped figure also reapplies edited
axes positions correctly and agrees with a clean replay. (#781, #782)

**Manual colorbar ownership is visible rather than guessed.** A manual
`cax` with an explicit owner is nested or grouped correctly. Without that
declaration, the inspector explains how to add `ax` while keeping the
existing `cax`. Colorbar axes no longer consume the displayed subplot
numbers; stored axes identities stay unchanged. (#794)

**More matplotlib objects select and drag where they are drawn.** Error
bars, stems, curved and filled patches, and annotation arrows use their
actual contours instead of large bounding boxes. Anchored boxes,
AnnotationBbox and eligible insets move correctly; locator-managed axes
and constrained or tight layouts keep edited positions without displacing
unrelated subplots. Unsupported movements explain why. (#670, #697, #681)

**Layouts and styles stay with the right project and canvas.** Pending
style changes no longer spill across canvas, figure or binding changes.
Restart recovery checks layout ownership, so opening one project cannot
restore another project's layout or timeline. The last-open layout and
export defaults are now stored by the backend and survive a change of the
desktop sidecar's port; the shell also tries to reuse its previous port.
(#700, #718, #719, #773)

**Chinese fonts are easier to choose and less likely to become boxes.**
Dropdowns show localized font names; a font with only a Chinese family
name can be selected and rendered. A Western font pinned by filename can
receive Chinese fallback when its exact original face can be preserved.
(#704, #707)

**Saving into an in-memory buffer works for image conversion.**
`savefig(BytesIO(...))` is allowed through so PIL can read the buffer and
convert it to formats such as TIFF. This does not promise capture of every
buffer-only figure that is closed before discovery. (#739)

**Codex plugin on Windows: MCP tools now appear.**
On Windows, plugin 0.17.0 loaded as enabled, with its skill, but with no Tavotto tools at all, even with the engine installed. Codex gave no error. The bundled launcher was one file serving as both a shell script and a batch file, and `cmd.exe` echoed its first line (`#!/bin/sh`) to stdout ahead of the MCP handshake, so Codex dropped the server. The launcher is now two files: `mcp/launch` for macOS and Linux, and `mcp/launch.cmd` for Windows, whose first line is `@echo off`. The Codex MCP config (`codex.mcp.json`) points at `./mcp/launch`, and on Windows Codex resolves that to `launch.cmd`. macOS and Linux behave exactly as before. After upgrading the plugin, start a new Codex session. Diagnostic lines the server writes to stderr are now UTF-8, so on Windows systems whose code page is not UTF-8 they show up in the Codex logs instead of being dropped. If you are still on plugin 0.17.0 on Windows, run `codex plugin marketplace upgrade tavotto`. With this engine, `tavotto codex install` also treats any stdout output besides the health JSON as a launcher that does not start, and pins a verified interpreter into the installed copy.

**Windows installation can use Codex Desktop's bundled CLI and work
without Git.** If `tavotto codex install` finds no runnable Git, it can
install from the verified stable-channel archive. That local-marketplace
route updates with `tavotto codex upgrade`. The figure assistant also
finds the CLI bundled with Codex Desktop. (#725, #727)

**An old pip or pipx engine is no longer reported as “desktop app only”.**
If the `tavotto` engine installed with pip or pipx was too old for the plugin, the plugin's health check could report `desktop_only` ("only the desktop app is installed") and suggest steps that did not fix it. This happened when the plugin could not state a minimum engine version (a plugin installed from a local marketplace or source checkout) or when the engine's CLI could not report its version. A common trigger is a pip mirror that has not synced the new release yet, so `pipx install "tavotto[worker]"` installs an older version. The health check now asks the engine's own Python environment for its version. It reports `engine_too_old` with both versions when it knows the minimum, and a new code, `engine_incompatible`, when it doesn't. Both give upgrade commands such as `pipx install --force "tavotto[worker]==<version>"`. If pip reports an effective package index that points to a mirror, the message says the mirror may lag and adds `--index-url https://pypi.org/simple` to each command. `tavotto codex doctor` reports the same code and text.

**Large model edit receipts no longer have to include the whole figure.**
New model calls explicitly request a bounded apply summary and retrieve
state separately. Canvas and programmatic callers keep their full atomic
response. Older callers that omit the summary option can still exceed a
host's message limit. (#788)

**Export and update failures remain visible and retryable.** Failed
status reads keep the export job and its inputs; requesting cancellation
is distinct from confirming it, and status can be retried. Failed update
setting saves keep the last confirmed setting, and a failed restart leaves
a visible retry path. (#784, #785)

**Environment checks leave fewer traces.** Probes avoid writing bytecode
into your Python installation, workers avoid project `.pyc` files, and
Tavotto-owned Python, plugin, matplotlib and Linux fontconfig caches stay
in their own locations while preserving your matplotlib configuration.
HTTPS checks use platform certificate trust, and certificate failures are
reported separately from general network errors. (#711, #714, #717, #735,
#752, #755, #780)

## Known issues

**Two release acceptance issues remain open for 0.18.0.** The maintainer
has explicitly accepted these gaps for this release; the exception does
not mark the checks as passed or close the issues:

- **Distribution and real upgrades (#35):** clean Windows 10/11
  SmartScreen behavior and complete macOS installation / real N-1 update
  and state-preservation acceptance are not fully recorded. Windows
  installer signing is disclosed in the generated signing section below.
  macOS release artifacts still require signing and notarization, and
  updater artifacts still require their signatures.
- **Windows Codex Desktop installation (#266):** the launcher has real
  Windows CLI evidence, but official-channel Desktop cold-start and
  post-upgrade restart acceptance, plus the remaining Linux real-host
  evidence, are incomplete. If no tools appear, run `tavotto codex install`
  and start a new session. A CLI or protocol pass does not verify the
  Desktop canvas.

**New host channels are Beta, not fully verified host integrations.**
Claude Code, DSH and WorkBuddy have local-development smoke evidence;
release-artifact verification across their real clients is incomplete.
WorkBuddy's GUI and embedded canvas have not been accepted. ZCode's
signed-in tool flow and MiniMax Code's authenticated agent flow remain
unverified and experimental.

**Private-Python repair on Intel Mac is enabled by a maintainer
exception.** Clean Intel target evidence is still missing. The recorded
Apple Silicon target exercise used a frozen sidecar with a browser
interface, rather than the Tauri window. This is separate from building
and smoke-testing the ordinary Intel desktop installer. (#774)

**Selected-PNG adoption is deliberately narrow.** Cropped PNGs, active
layouts, ambiguous save histories, existing or baked edits and pending
style work do not silently switch to a new source context. Selected-source
writeback, history writeback, synchronization and automatic fixes remain
unsupported. Tight-layout stabilization does not cover multiple saves,
native execution, custom layout engines or manually positioned axes.

**Some structural movements remain restricted.** Shared-colorbar groups
do not infer missing owners, merge overlapping groups or cross SubFigure
boundaries. Shared orientation changes and SubFigure-local transforms
retain their restrictions; tables and figure-level boxes are not newly
made draggable by this release.
