The macOS app is now **signed and notarised** — double-click to open, no security
warning. And when Magplot can't find a Python with matplotlib, it now offers to set
one up for you instead of just reporting the problem.

## Added

**Magplot can install a rendering environment for you.** ⚡ in-figure editing needs a
Python that can import what your scripts import. If none is found, the properties panel
and **Settings → Privacy, diagnostics and About** now offer a one-click install, or let
you point Magplot at an interpreter you already have.

The automatic install creates an **isolated environment inside Magplot's own data
directory** and installs matplotlib there. It never modifies your existing Python
environments — those are what you do research in. If you already have a scientific
stack, pointing Magplot at it is still the better option: your scripts often need
scipy or pandas too, and only your own environment has those.

On a machine with no Python at all, Magplot says so plainly and links to python.org
rather than pretending it can fix it.

## Fixed

**macOS: the app is signed and notarised.** Previous `.dmg` builds carried only an
ad-hoc signature, so first launch required right-click → Open.

**Rebuilding the frontend no longer blanks a running instance.** The build replaced the
served directory in place, leaving a few hundred milliseconds where every asset 404'd.
It now stages the new build and swaps it atomically. Affects anyone running from a
source checkout while rebuilding.

**Windows and macOS installer filenames are now consistent** — both use the plain
version number, matching the wheel.
