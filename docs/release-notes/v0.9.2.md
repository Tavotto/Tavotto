A small release. One thing changed in the editor; the rest is the machinery
that builds and ships Tavotto, rewritten so that a release can be rehearsed
end to end before a version number is spent on it.

## Fixed

**A colorbar shared by several subplots no longer offers an orientation
switch.** Flipping one was never safe: the placement maths reads the
colorbar's current rectangle to work out its thickness and spacing, and with
more than one host that rectangle belongs to a layout Tavotto did not
compute. The switch appeared to work and then quietly moved the colorbar
somewhere wrong.

Rather than fix the placement — that is a real piece of architecture and it
is scheduled for v1.1 — this release stops claiming the capability. The
orientation control is not offered for a multi-host colorbar, and the
element reports why instead of failing silently. Single-host colorbars,
which is nearly all of them, are unaffected.

## Changed (release engineering — nothing you interact with)

**One workflow now runs a release from end to end.** Previously a tag push
started two workflows that had to find each other: the desktop chain built
its installers and then polled `gh release view` in a `sleep` loop, waiting
for the other workflow to create the Release it needed to attach to. If the
qualification gate ran long — it takes thirty to sixty minutes — the poll
gave up first and the installers went nowhere. Two version tags were spent
discovering this, and tags in this repository are immutable.

The chain is now a single orchestration: trust → build → desktop →
qualification → validate → publish, with the desktop workflow called
directly and handed an already-verified commit SHA. There is no polling
anywhere in it.

**A release can be rehearsed.** `release.yml` accepts a manual dispatch with
`publish=false`, which builds everything, runs the full qualification, and
produces the SBOM, checksums and provenance — but creates no Release, no
PyPI upload and no tag. A formal tag no longer has to be the first time the
publishing path executes.

**Downstream steps read an artifact manifest instead of guessing filenames.**
Every build leg writes what it produced — role, path, size, SHA-256 — and
the publishing steps look files up by role. A glob that matched both the
wheel and a desktop update bundle is the kind of mistake this removes by
construction.

**A repository-wide setting can no longer weaken the release gate.**
`LAB_VISUAL_GATE=false` exists so that a drifting visual baseline does not
keep the nightly run red. When the two qualification definitions were merged
into one, that switch silently gained the power to let a build with visual
regressions publish. It is now scoped to non-release runs.

## Notes

Desktop 0.7.0 and earlier will not upgrade in place — the bundle identifier
changed to `com.tavotto.tavotto` in 0.8.0. Uninstall the old version first.
