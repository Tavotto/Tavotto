This release is about the half-second between doing something and seeing it.
Dragging a label used to mean waiting for matplotlib; now the figure moves
under your cursor and Python runs once, when you let go. Panels, drawers and
the viewport stopped teleporting. The desktop app updates itself instead of
sending you to a download page. And a figure you just made somewhere else —
in a terminal, or by asking Codex — is one command away from being on the page.

## Added

**Editing is instant.** Dragging an element inside a figure, or dialling a
font size, colour or line width, now changes what you see immediately —
frame by frame, at pointer speed. matplotlib runs **once**, when the gesture
ends, to produce the authoritative render. Everything you could edit before
you can still edit; what changed is that you no longer wait between the input
and the picture. The preview lives only in the browser: it never enters the
undo history and never reaches your files, so one gesture is still exactly
one undo step, and the figure you export is always the one Python drew. A
few properties are honestly excluded and fall back to the old round trip —
panel opacity, error bars, bar series, ticks and tick labels — because they
have no faithful preview to give.

**Motion, where standing still was confusing.** Menus, dialogs, popovers and
tooltips now leave the way they arrive instead of vanishing. A panel getting
a fresh render cross-fades rather than snapping. Zoom, fit-to-canvas, zoom
presets and "locate this object" all ease to their destination, so you don't
have to re-find yourself after every click. Side drawers open and close.
Canvas tabs, the layer tree and layout-group reflow slide from where they
were instead of jumping. Direct manipulation — the scroll wheel, pinch zoom,
dragging an object — stays instant on purpose, and everything respects
`prefers-reduced-motion`.

**The desktop app updates itself.** Check, download, install, restart —
without leaving Magplot. Update packages are signed, and the app verifies the
signature before installing. Browser, pip and pipx installs keep using the
existing updater and its `pip install --upgrade` path; the two never both
answer. Note that this is the first release *with* the in-app updater, so
0.6.0 users need one manual install to get here; from 0.7.0 onward the app
does it.

**Send a figure in from anywhere.** Just ran a script and got a PDF?

```bash
magplot open figures/Fig1_kinetics.pdf   # the output
magplot open figures/fig1_kinetics.py    # or the script
magplot open figures/                    # or the whole library
```

It finds the figure's library, registers anything missing in the script
registry, and hands the figure to the desktop window — the one already open,
if there is one. There is also a **Codex plugin**, so figures Codex writes
come out in a shape Magplot can take over and arrive automatically:

```bash
codex plugin marketplace add erwanjun/magplot && codex plugin add magplot@magplot
```

**A toolbar for in-figure text.** Font and size on one row; bold, italic,
colour, background, outline, layout and layering as icons on the next, with
the details behind each one. The right-click popover and the properties panel
now show the same controls and behave identically, and the controls offered
are exactly the ones the renderer reports for that element — not a list the
interface maintains separately.

## Changed

**The properties panel stays open.** It is what you look at while editing, so
waiting for a selection to summon it cost a click every time. It is now
docked by default on wide windows; on narrow ones, where it overlays the
canvas, it still starts out of the way and appears when you widen the window.

**Page-size presets are drawn to scale.** Single column, double column, full
page and square were four same-width words; they are now four thumbnails
sharing one mm-to-pixel scale and a common baseline, so the difference is
visible instead of read.

**The Windows installer is two pages.** First-run installation goes progress
→ done. Nothing was removed but pages: the install directory, Start Menu
folder and desktop shortcut all behave as they did, and silent and passive
installs are unchanged.

**Project files are collected in `magplotfile/`.** Exports land in
`magplotfile/export/`, named canvas files beside them, version history in
`magplotfile/versions/` — one folder inside your project instead of several
places. This actually shipped in 0.6.0 and went undocumented; files written
by earlier versions remain readable where they are.

## Fixed

**Dragging a subplot left parts of it behind.** A regression introduced in
0.6.0: after 0.6.0 began replaying figure-anchored positions (so that what
you write back matches what you get on reopen), any title, axis label or
legend you had *moved yourself* was pinned to its old figure coordinates. You
dragged the subplot and those elements stayed put. Colourbar axes and `twinx`
twins never followed at all, since matplotlib considers them separate axes.
Now the stored anchor values move with the subplot in the same commit, so hot
editing and a clean replay still agree to the pixel and it remains one undo
step. Which elements follow is decided by the renderer, which is the only
side that can see matplotlib's sharing relationships — `sharex=True` alone is
not enough to count, or dragging one subplot would drag its whole column.
Turn it off under Settings → Canvas and editing → drag subplots with their
elements.

**A drag interrupted by the system became a real edit.** If the operating
system cancelled a pointer gesture mid-drag — a notification stealing focus,
a palm touch, a lost pointer capture — the interrupted drag was silently
committed at wherever the pointer had got to. Cancellation now restores the
element and writes nothing: no override, no history entry, no render.

**Windows: handing a figure over failed with a Chinese path or message.**
When Codex ran the plugin's handoff script its output was a pipe, so Python
fell back to the system code page (cp1252 / cp936) and the very first line of
JSON — which can contain Chinese text — killed the process with
`UnicodeEncodeError`. The caller saw "the script crashed" instead of the
message explaining what to do. Both the script's own streams and every
subprocess it reads are now pinned to UTF-8, with regression tests that run
under a cp1252 stdout.
