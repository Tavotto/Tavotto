Annotations you draw now behave like a real vector editor — arrows preview
live while you drag, Shift constrains angles and proportions, and the two
"my shape vanished" bugs are gone. Inside figures, three long-standing gaps
close: standalone arrows and gradient-filled peaks are finally editable, and
changing a text's font now carries its sub/superscripts along. The AI
assistant no longer trusts a broken Windows Store codex alias, and can
install the CLI for you with one click.

## Added

**In-figure arrows are editable.** Arrows drawn by your script — both
standalone `FancyArrowPatch` objects and the arrows attached to `annotate()`
(including text-less `annotate("")` arrows) — now appear as first-class
elements in in-figure editing: colour, line width, head size, opacity,
z-order and visibility. Positions stay with the script on purpose: an
arrow's endpoints are semantic data coordinates (they point at a peak), and
dragging them in a layout tool would only detach the annotation from the
fact.

**Gradient fills can change colour.** The common "imshow gradient clipped by
a path" idiom — light-to-dark component fills in XPS/spectroscopy figures —
is now recognised as a single-hue gradient, and exposes its base colour as a
colour field. Recolouring re-derives every pixel's white-blend factor from
the original array, so the gradient's shape and transparency are preserved
exactly; undo restores the original pixels. Real photographic images fail
the consistency check and are left alone.

**Sub/superscripts follow font changes.** Changing a figure text's font
family used to leave `$…$` mathtext (the `cm⁻¹`-style scripts) in the old
font — two typefaces inside one label. The math font family now switches
with the text, and undo restores both.

**Marquee selection inside figures.** In in-figure editing you can now drag
from empty space to band-select multiple elements; Shift adds to the
selection. Containers (subplots) only join when fully enclosed, so a marquee
inside a plot doesn't constantly grab the host axes.

**Live arrow preview and Shift constraints on canvas.** Drawing an arrow or
line shows the actual line (head included) while you drag — what you see is
what lands, snapping and angle locks folded in. Illustrator-style Shift:
constrain moves to 0/45/90°, force proportional resize (edge handles too),
draw perfect squares/circles, lock arrows and lines to 15° steps. Selected
arrows and lines are outlined along the line itself instead of a bounding
rectangle.

**One-click CLI install.** If codex or claude isn't installed, Settings → AI
tools now offers "install via npm" — a background `npm install -g` with
progress, followed by a real launch check. Without npm on the machine it
points you at Node.js LTS instead of failing silently.

## Fixed

**Vertical arrows and dotted shapes no longer vanish.** Perfectly vertical
or horizontal arrows/lines have a sub-pixel bounding box, and Chrome skips
painting sub-pixel SVG viewports entirely; the viewport is now clamped while
geometry stays exact. Dotted strokes on closed shapes were invisible because
their dots are drawn purely by round line caps, which the shape stroke never
set — display and PDF export fixed together, from the same formula.

**Desktop drag-and-drop works again.** The Tauri shell's default drag-drop
handler swallows HTML5 drag events inside the window, which silently broke
dragging assets onto the canvas in the desktop app (browser mode was never
affected). Magplot doesn't consume OS file drops, so the handler is now
disabled and drag-and-drop belongs to the page again.

**Windows Store codex aliases can't fake an install.** CLI detection now
launch-verifies each candidate (`--version`) and falls through to the next
one — a stale `WindowsApps` execution alias that cannot be spawned no longer
reports codex as installed while every run fails. When nothing works, the
settings page names the broken path it skipped.

**Assistant prompts pin the toolchain.** The prompt sent to codex/claude now
states hard requirements up front — figures must be produced with matplotlib
via `savefig` (anything else is uneditable afterwards), stems and output
counts unchanged — and only mentions `paper_style.py` when the library
actually has one, instead of hard-coding one project's private style guide.

**Small workspace fixes.** The text-content row's four actions (newline,
sub/superscript, case) sit in one row under the input instead of a tall
stack beside it; the empty-canvas hint centres on the page instead of the
window; "layout file" is now called "canvas file" throughout the UI (naming
only — files and APIs unchanged).

## Upgrading

Desktop: download the new installer from this release and install over your
existing copy. pip/pipx: `pip install -U magplot` (or let "Check for
updates" do it). Projects, layouts and settings live in your user data
directory and are not affected.
