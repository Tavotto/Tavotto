# 验收、滚动切换和退出条件

## 1. 两个完成状态

**ci_hosted_ready**：在现有可用hosted资源上已完成合理的DAG、分片/隔离、Gate和事件验证；合并前覆盖不缩小；有真实前后样本或透明说明样本不足；可开始统一计划U00。

**runner_pool_ready**：额外执行池真实部署并通过多job隔离、准确路由、并行容量、网络、掉线回退与信任边界验证。未部署就是not_run，不借源码脚本正确声称服务器就绪。

不要求无限优化到2分钟才开始RenderCore。CI05列出已消除的主要瓶颈和剩余瓶颈；若无法达目标，保留实测和合理决定，而不是无休止扩大前置范围。

## 2. 逐级迁移

1. 现有required继续生效，新增计时/报告先观察。
2. 基于固定样本影子运行新切分集合，核对旧完整集合和新分片并集。
3. 一个领域一次切换，带上其正反测试、needs/required/事件测试和可逆路由变更。
4. 同时验证新PRpush取消、ready后新push、full-ci、merge_group和发行无误杀。
5. 完成关键代表样本的hosted对照，再试点一个私有执行槽；证明收益和隔离后扩槽，不把全部job一次迁过去。
6. 固定回退到旧路由/旧分片配置，重新运行同一候选；不得降低required来恢复绿色。

未实现的FirstOpenBench仍遵守统一计划planned/observing/enforced政策。它的JSON目录不是本前置要求马上跑完的测试全集。

## 3. 必须证明能拒绝的错误

- 缺少一个pytest/Playwright shard，或者重复一份报告充数。
- 构建artifact来自另一个SHA、target、recipe或被篡改。
- 真类型错误却使用空tsc命令报绿。
- 多job同时用同端口/目录造成串图，cleanup误杀另一job。
- 分片使需要真实资源的测试全部skip。
- PR运行要求可信lab标签，或者PR模板带入长期发布凭据。
- PR新push取消了merge/main/release，或旧pending挤掉必须保留的候选。
- 字体、科学栈或浏览器版本漂移被当产品回归；需识别环境并拒绝虚假比较。
- 新gate缺输入/错状态/错误事件组合却返回成功。

以对应负例证明判据有效，不要求为每个纯函数做全平台变异。对隔离、安全、漏测和身份的确定错误不能以性能提升抵消。

## 4. 必需与可选证据

每个变更最小交付为实际SHA、命令与exit code、测试实例/集合身份、结构化结果、构建输入与输出身份（如有）。大图trace/视频是失败诊断，若主要结构化证据已完整，单个可选截图上传失败不等价于产品错误；若必要报告缺失则资格不完整。

新的计时阈值初期观察，不能因为比预期多30秒无限重跑。证明实际取消可控、资源上限有效、并发无串扰是正确性；证明更快是测量结论。两者分别报告。

## 5. 运维需要外部权限时

只读清点和仓库代码可以先交付；注册/删除runner、创建VM、ACL、防火墙、systemd配置等生成管理员操作表，写清作用对象、资源、回退和验收命令。不在脚本中内置token，不从对话搜集密钥。

外部步骤未执行时维持hosted有效路由。不要创建一个没有对应runner的required job等24小时，再把等待误诊成测试卡死。CI基础设施错误归因明确但不能伪造资格通过。

## 6. 最终报告

输出：旧新DAG、覆盖迁移表、分片完整性与负例、真实耗时原始数据、资源配置实际值、已完成/待管理员事项、hosted_ready/pool_ready、仍未测平台、回退演练和U00入口。源测试通过、服务器部署完成、代码合并和产品发布是四种不同状态；本任务不自动完成后三种写操作。
