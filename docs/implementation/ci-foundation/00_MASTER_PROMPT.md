# 总实施提示词：实际整理 Tavotto CI，作为 U00–U11 的前置

你在 Tavotto 仓库工作。请交付真实可运行的 CI 改动、测试隔离、分片/聚合、构建复用和运维交接，不止输出另一份建议。参考 SHA 为 `8b95256c0d08a14bfcfc4c81358894ef01168933`；先检查实际 HEAD/status、根与目标目录 AGENTS/CLAUDE。当前代码优先，旧注释和本文时间不是当前机器的实测。

不覆盖用户未提交改动，不自动 reset/checkout、不 push/合并/发布，不修改 ruleset、runner 注册、防火墙、hypervisor 或凭据。外部运维步骤生成最小管理员交接，只有明确授权并具备访问条件时才执行。用户有更多计算资源，不等于已授权删除现有虚拟机或将 lab 接到公网 PR。

## 目标

把反馈耗时拆成可解释部分：workflow 触发/重复、DAG 等待、runner 分配、环境准备、测试执行、构建、产物传输与判定。先修最长串行路径与测试重复，再扩容量。目标是更快正确反馈和更高吞吐，不是最少 job 数、最低测试数或新平台复杂度。

沿用统一计划的四个问题：小改动合并、新能力启用、旧依赖删除、精确安装包发行分别验收。此阶段只改 CI 基础设施；不得开始替换 PyMuPDF、改变科学运行语义、修改根许可证、收费逻辑或批量启用尚未实现的 FO/RC 场景。

## 必须保留

- 三个 required context：`CI fast gate`、`CI integration gate`、`CodeQL gate`；CLA、安全、跨语言协议、当前平台/版本承诺和发布签名隔离继续成立。
- `aggregate_gate.py` 对 required failure/cancelled/skipped/missing/unknown 的拒绝。普通 PR 的重资格可以按既有合同整体 deferred；merge_group/full-ci 不可以。
- 最终组合在合并前验证。不能把当前 required 测试简单搬到 nightly/main 再宣称等价加速。
- 现有 `CompatBench`、四路等价、不变量、候选插件真实消费、安装冒烟仍有明确执行位置；不同判据不能互相替代。
- 新功能仍按 planned/observing/enforced/later 逐级纳入；本前置不要求立刻兑现统一计划全部来源条目。
- 精确 SHA、工具/锁/产物身份、真实测试实例集合与证据。不能从“最近一次绿”借结果。
- 公开 PR 与现有可信 lab 安全边界；标签和代码里的 if 不是保护长期主机的充分访问控制。
- 生成 canvas.html 等发行物不回写源码分支；不更改 plugin-stable 通道。

## 实施方法

1. CI00 建立任务图和覆盖映射，采集可获得的最近相关 run，包含成功、失败、取消与尝试次数。单个成功样本只能定位线索，不能编 p95 或 2× 提升。
2. 优先拆“判定等待边”，保留“真实数据依赖边”：打包不需要 pytest 产物时可与 pytest 并行；使用已构建前端/插件的消费者必须等待并核验对应生产者。最终聚合仍要求所有本次必需结果成功。
3. 第一轮保持覆盖集合，先分片和并行。需要把长全量测试从每次 PR 移入完整合并资格时，先逐项映射其新执行位置、代表性 PR 守护和支持矩阵，再显式批准，不悄悄删覆盖。
4. CI02 的构建生产者与单元测试分离；不能让一个名为 build 的 producer 仍先跑 35 分钟全套测试。保留真实 `tsc -b`，不要用根项目不检查 references 的空 `tsc --noEmit` 代替。
5. CI03 先证端口、目录、进程与全局状态隔离，再提升并行。优先 2 个独立 job 分片；测得收益与稳定性后才扩 3/4 个。同机总内存与子进程数受限。
6. CI04 优先保留 GitHub-hosted 默认路由，单独试点可销毁 VM。现有 lab VM 不改为 PR runner。不得以 ARC/Kubernetes/自研集群调度器作为开工前提。
7. CI05 对照同类变更、相同工具/硬件与冷暖状态，记录墙钟时间、资源分钟、失败率和取消行为。性能可先观察；错误数据、漏测试、越权和错产物立即阻断。

## 每个小 PR 的输出

本次事实 → 所改依赖/执行位置 → 实际命令与退出码 → 覆盖无遗漏说明 → 性能原始样本 → 风险/回退 → 未运行和下一步。脚本命令必须在当前仓库真实存在后才提供为可执行命令。不要造一个永远返回成功的 placeholder 来满足 YAML。

新选择器/聚合器必须验证自身，至少拒绝空集合、遗漏 shard、重复测试 ID、旧 SHA、错误产物和缺必要证据。新代码带相关负例即可，不为每个纯函数强行跑完整虚拟机。复杂性必须与真实节省相称。

## 范围上限

这不是重写产品引擎，也不是新的基础设施产品。优先复用脚本、GitHub artifacts、标准测试分片和现有 gates。不建立通用分布式缓存、所有语言测试调度服务、全套自动伸缩平台、跨 OS 虚拟化平台、任意增量测试依赖推导器。后台观测 runner 的建设不能无限推迟 U00。
