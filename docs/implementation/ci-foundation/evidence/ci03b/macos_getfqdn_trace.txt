## 读法

- 桩的追踪停在「socket 已 bind（还没 listen）；getfqdn 前」，之后 15 秒内没有下一行——卡在 HTTPServer.server_bind 的 socket.getfqdn(host)（bind 之后、listen 之前）。
- 脚本的轮询序列：第 0.03 s 一次 refused（桩还没 bind）→ 从 3.4 s 起连续 5 次 connect timed out（每次 3 s 的 connect 超时）——macOS 上「已 bind 未 listen」的端口对 SYN 不回 RST（本机实测：bound-not-listening → TimeoutError 3.01 s；nothing bound → ConnectionRefusedError 0.00 s）。
- 通过的用例（healthy / slow-ready / index-500 / no-version-field，--timeout 60）说明反查最终会回来，只是超过 15 s、少于 60 s。
- 真产品同一条路：#376 首跑 package (macos-latest, 3.13) 的 ready_seconds = 35.78 s（Linux 0 / Windows 2）；CI00 基线里旧写法（sleep 8 + curl）这一步 macOS 48 s vs 其它腿 13 s。werkzeug 3.1.8 的 BaseWSGIServer 继承 http.server.HTTPServer.server_bind，没有覆写。
