# 关窗询问闸真机验收（issue #223）

这份验收只回答一件事：**在真实的 Windows / macOS 桌面产物里，有未保存修改时点
窗口关闭按钮，用户是否被问了一句、三个出口是否各自兑现。**

**pytest、`cargo test`、vitest 都不能代替它。** 三层单测各自只能证明自己那一侧
自洽：Rust 侧证明闸的状态机对，Python 侧证明两侧词汇表同源，vitest 证明六个保存
状态各答什么。真正没人验过的是**壳与 WebView 之间那一跳**——`CloseRequested`
在 WKWebView / WebView2 上到底怎么派发。issue #223 的第 ① 项要的正是这一跳。

顺带把 issue 的第 ① 问也答掉：**改造前**（本 PR 之前的构建）dirty 关窗到底有没有
提示。两个平台各跑一遍 §0，答案写进 issue。

## 前置条件

1. 记录待验 commit：`git rev-parse HEAD`；工作树没有未说明的改动。
2. 用发行链构建真产物，**不要用 `pnpm dev` 或浏览器模式**：
   `python scripts/build_desktop.py`（Windows 出 NSIS，macOS 出 .app/dmg）。
   浏览器里点标签页关闭走的是 `beforeunload`，那一层本来就是绿的，测它等于没测。
3. 装好后从**开始菜单 / 启动台**打开（不是从终端跑 dev server）。
4. 每个场景之间**重开应用**：闸有「已确认」这一位，一次关闭之后它就不再拦了。

## 0. 基线：改造前有没有提示（每个平台一次）

**基线必须从本 PR 的 merge-base 构建，不要用 v0.12.0 官方安装包。**
v0.12.0（2026-08-27）早于 ADR 0024（2026-08-29）——那份包里根本没有保存状态机，
拿它测出来的「没提示」回答的是另一个版本的问题。

```sh
git worktree add /tmp/tavotto-baseline "$(git merge-base origin/main HEAD)"
cd /tmp/tavotto-baseline && python scripts/build_desktop.py
```

**怎么可靠地停在「有未保存修改」上**：自动保存的防抖只有 1 秒，手速去抢它会
得到一个假的「没坏」（那一刻状态已经回到 `saved`，**本来就不该**拦）。用一个
不会自己恢复的状态：

1. 打开任意项目，随便加一个文本对象，等状态栏显示**已保存**。
2. 到项目目录里用别的编辑器/脚本改一下 `tavottofile/*.json`（改个对象坐标即可）。
3. 回到应用，界面应出现**「文件已被外部修改」**（`conflict`）。这一档
   `flushAutosave` 根本不写磁盘，所以它**不会自己变回 clean**，可以从容操作。
4. 再随手改一个对象（确保 `dirty`），然后**点窗口右上角的关闭按钮**（不是 ⌘Q，
   不是应用菜单里的退出——那两条走另一条路，本 PR 不覆盖）。

**看什么**（三选一，照抄进 issue）：

- A：窗口**直接关掉**，没有任何提示 → 这正是 #223 判断的现状，本 PR 修的就是它。
- B：弹出**系统/WebView 自带**的「离开此网站？」样式提示（`beforeunload` 真的
  被派发了）→ 记下截图与原文，说明该平台上那一层是活的。
- C：弹出 Tavotto 自己的对话框 → 不可能（改造前没有这段代码）；出现了说明你装的
  不是基线包，重来。

平台各记一次（Windows / macOS 可能不同——这正是 #223 要问的）。结果回填 issue #223
第 ① 项，**连同产物版本号与 commit**。

## 1. 有未保存修改 → 弹三选一（两个平台各一遍）

1. 打开任意项目，编辑一个对象，趁状态栏显示「未保存 / 保存中」时点关闭按钮。
2. **看**：窗口没关，出现「有未保存的修改」对话框，三个按钮齐全
   （取消 / 不保存 / 保存并关闭）。
3. 按 `Esc`、点对话框外面——**都不该关掉它**（必须做出选择）。

失败签名：
- 窗口直接关掉 → 壳没拦（`CloseRequested` 没接上，或 `arm_close_guard` 被 ACL 拒）。
- 点了没反应、约 2 秒后窗口自己关掉 → **事件到不了前端**（ACL 少一处、事件名漂了、
  监听器没注册）。这是最容易发生的坏法，也是本次判据反复盯的那一位。

## 2. 三个出口各自兑现（两个平台各一遍）

| 点 | 该发生什么 | 怎么确认 |
| --- | --- | --- |
| 取消 | 对话框关掉，**窗口还在**，编辑还在 | 继续编辑，不再弹 |
| 不保存 | 窗口关掉；重开后文档停在**上一次自动保存**那份 | 重开看对象数 |
| 保存并关闭 | 按钮转圈 → 窗口关掉；重开后**这次的编辑在** | 重开看对象数 |

「不保存」那一格还要确认：**下次启动会弹崩溃恢复横幅**（本机副本还在），
选「丢弃」之后不再弹。

## 3. 没有未保存修改 → 不该问（两个平台各一遍）

等状态栏显示「已保存」，点关闭。**必须立刻关掉，不弹任何框。**
弹了就是回归——一个每次都出现的空提示会训练用户无脑点确定，那时候真该拦的
那一次也拦不住了。

## 4. 保存失败时不许关（至少一个平台）

制造写盘失败最省事的办法：关掉 sidecar 之外的磁盘写入权限不现实，改用
**冲突**这一档——用另一个编辑器/脚本改一下 `tavottofile/*.json`，让界面进入
「文件已被外部修改」，然后编辑 → 关闭 → 点「保存并关闭」。

**看**：窗口**不关**，对话框里多出一行说明（「没能保存成功，窗口先留着…」）。
这一位关系到「保存」这个词是不是谎话，别跳过。

## 5. 兜底：webview 没人应答时窗口仍关得掉（至少一个平台）

打开开发者工具（若该构建允许）执行一段死循环，或在 splash 阶段（sidecar 还在
启动、界面还没出来）点关闭按钮。

**看**：splash 阶段**立刻**关掉（闸还没 arm）；界面卡死时最多约 2 秒后关掉，
并在壳日志里出现 `[close-guard] 前端未在 … 内应答，放行关闭`。

**永远不该出现的是关不掉的窗口。** 出现了就是 P1：回退本 PR 比留着它更好。
