# Tavotto Beta 0.18.1b2（首跑体验预览版）安装与使用

这是一个**测试版**，用来试「把一个只有脚本的项目第一次跑出图」这条新流程。它和你电脑上的正式版
Tavotto 是两个独立的应用，可以同时装着，互不覆盖。**beta 与正式版的设置、最近项目和数据目录不共享**：
beta 用自己的 `Tavotto Beta` 目录（Mac：`~/Library/Application Support/Tavotto Beta`；
Windows：`%APPDATA%\Tavotto Beta` 与 `%LOCALAPPDATA%\Tavotto Beta`），第一次打开是干净状态，
测试不会改动正式版的设置。

只有一点要知道：项目文件夹本身是同一份。beta 会把脚本里 `input()` 的回答记在项目的
`tavottofile/_script_inputs.json`，并把这个文件升到新格式（version 2）；之后再用正式版 0.18.0
打开这个项目，正式版仍能读它（按旧方式回填回答），但不认得新加的那部分信息。

本版 = 正式版 **0.18.0** + 「首跑体验收敛」T01～T13b 这一批还没合进正式版的改动
（代码 = 分支 `feat/onboarding-convergence` @ `3476f2e7a`，其上只叠了 beta 打包类提交）。

## 能不能用

**Mac**
- 需要 **Apple 芯片的 Mac**（M1 / M2 / M3 / M4 …）。Intel 芯片的 Mac 打不开这个包。
  看法：左上角  → 关于本机 →「芯片」一行。
- **macOS 14（Sonoma）或更新**。

**Windows**
- **64 位 Windows 10 / 11**，不需要事先装 Python。安装包见下面「Windows 安装包」。

**Linux**：这一版没有提供。

## 安装（Mac）

1. 双击 `Tavotto-Beta-0.18.1b2-arm64.dmg`，把 **Tavotto Beta** 拖进「应用程序」。
2. 第一次打开会被系统拦下（这个测试版只有临时签名，没有经过 Apple 公证）。任选一种放行：
   - **方法 A**：打开「系统设置 → 隐私与安全性」，往下翻，看到「已阻止使用 Tavotto Beta」，
     点 **仍要打开**，输入开机密码。
   - **方法 B**（如果提示「已损坏，无法打开」）：打开「终端」，粘贴下面这一行后回车，然后再双击打开：

     ```
     xattr -dr com.apple.quarantine "/Applications/Tavotto Beta.app"
     ```

   只需要放行这一次。
3. 它**不会自动更新**。测完直接拖进废纸篓。

## Windows 安装包

Windows 版由仓库里的 beta 工作流（`.github/workflows/beta-windows.yml`）在**同一个 beta 分支**上打出，
和 Mac 版是同一份代码；安装包在那次工作流运行的产物（artifact）里，附带 `SHA256SUMS.txt`
和记录源码提交的 `BUILD.txt`。

1. 双击 `Tavotto Beta_…_x64-setup.exe`。
2. 这个测试版**没有代码签名**，SmartScreen 会弹「Windows 已保护你的电脑」：点 **更多信息** →
   **仍要运行**。
3. 按向导装完即可，不需要管理员权限（装在你自己的用户目录下）。开始菜单里叫 **Tavotto Beta**。
   卸载：设置 → 应用 → 已安装的应用 → Tavotto Beta → 卸载。
4. 和 Mac 一样：与正式版并排安装、不自动更新；设置、最近项目和数据目录与正式版分开。

## 这一版多了什么（请帮忙试）

**怎么试**：打开一个只有绘图脚本、还没出过图的项目文件夹。

1. **右下角的新手引导卡**：画布右下会弹出一张卡「发现绘图脚本 xxx.py」（每个项目只自动弹一次），
   点「开始准备」。页面顶部不再出现检查条。打开项目时只读地看一遍有哪些脚本，**不会运行**你的脚本。
2. **一步一步问**：卡会依次问——在哪个目录运行（推荐项已选好）→ 还差几个参数（只填必填的；
   其他参数和「原样参数 / 粘贴命令」收在折叠里）→ 要不要安装缺少的组件（点「安装」）→「运行」。
3. **不用选 Python 环境**：用哪一套运行由程序自动挑，不用选；都不能用时卡片只让你点「安装」
   （装进 Tavotto 自己管理的环境，**不改你自己的 Python**）。
4. **运行中**：可以「放到后台」，卡缩成右下角标；脚本里 `input()` 要你回答时卡会自己展开
   （`getpass` 的输入是遮住的，不保存、不写日志）。回答按「这个脚本 + 这组参数」记住，之后重放 / 导出不再重复问。
5. **画好之后**：点「进入编辑」，卡自动收起。填的参数会跟着这张图走：之后编辑、重开、导出都用同一组参数，
   同一个脚本用两组参数跑出来的同名图是两张，不会互相覆盖。
6. **收起与再打开**：「稍后」= 缩成角标，角标上的 × 才彻底收起；素材库脚本行的 ▶ 随时打开同一张卡。
7. **出错时**：点「详情」看错误原文和「下载这一次的诊断」（脱敏，之后成功重试也不会覆盖它）。
8. **Codex / MCP 插件**：插件和桌面应用用同一份参数与环境；只有脚本、还没跑过的项目，插件会提示你
   回到桌面应用里完成第一次运行（插件本身不做首跑）。

## 已知问题

- **验证范围**：新流程只在 macOS 上的浏览器自动测试里验证过（Chromium 中 / 英文、WebKit）；
  打包后的桌面应用、Windows、Linux 上**没有实际点过**。
- 没装 Python 的电脑上点「安装」（装私有 Python）没有实测过；真实联网安装、私有 pip 源、云盘占位文件也没测过。
- 窗口 / 画布较窄（约 800 像素以下）时，引导卡会盖住底部居中提示条的右半边。
- 脚本跑完却没出图时，「详情」里看不到脚本自己的打印输出。
- 「每个项目只自动弹一次」记在浏览器存储里：清掉站点数据后会再弹一次。
- 环境自动检测第一次准备时会多花几秒，期间点「停止」不会打断检测。
- 打开项目时仍会在项目里写一份 `tavotto_registry.json`（记录静态图名），这是原有行为。
- 插件 / MCP 不做「只有脚本的项目第一次运行」，会给出待办引导回桌面应用。
- 多值类参数（`append`、`*`、`+`）在表单里只读，要改请用「粘贴命令」；没有文件 / 列内容预览。
- 「已存在的输出文件会被覆盖」目前在界面上没有专门的提示。
- 应用重启后，进行到一半的准备不会自动续跑，需要再点一次。
