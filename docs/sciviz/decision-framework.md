# B. 可视化决策框架

本框架用于从数据和研究目的出发，选出画法并说明理由。整体是 **[推导]**，依据主要来自 VAD 第 2–7、10、12、13 章，以及 FDV。

使用方：
- 数据出图（ADR 0178）；
- Tavotto Agent 选图与改图；
- 需求评审。

现有的闭集配方（`engine/ai_data_recipe.py` 的 `FAMILIES` / `MARK_RULES` / `REJECTIONS`）已经实现了第 4–5 步。本框架补上另外三处：第 1 步的「统计身份」、第 3 步的「丢掉了什么」、第 6 步的理由分档。**不推倒重写。**

## 1. 数据抽象（What）

每列一行。所有推断出来的字段都标 `inferred`，用户可以改。

| 字段 | 取值 | 依据 / 注意 |
| --- | --- | --- |
| 类型 | categorical / ordinal / quantitative / time | VAD §2.5（p.31–34）[原文] |
| 方向 | sequential / diverging / cyclic | diverging 的**中点由语义确认**，不能看到负数就判（G-023） |
| key 候选 | 是 / 否 | 唯一性检验；数值列默认不当 key（VAD p.34）[原文]；key 与 value 可能就是分析目标（p.36） |
| 角色 | 沿用 `ai_data_roles.ROLES` | 时间是 key 还是 value 需要外部知识（VAD p.39）[原文] |
| 单位 | 列名后缀或用户填 | 数值轴的标题带单位（G-032） |
| **统计身份** | 原始观测 / 汇总值 / 误差量（SD、SEM、CI、unknown） | 新增。误差量类型拿不准就记 unknown，**不默认成 SD**（G-005、G-038） |
| 观测结构 | 独立 / 重复测量 / 配对 / unknown | 只认用户确认（GoG p.612 [原文]；现有 `ASK_FIRST`） |

## 2. 任务抽象（Why）

| 维度 | 取值（VAD 第 3 章 [原文]） |
| --- | --- |
| 目的 | present（投稿）/ discover（探索） |
| 查询 | identify / compare / summarize |
| 目标 | trend / distribution / correlation / outlier / extremes / part-to-whole |

任务作为输入或确认项交给推荐器，**不由推荐器自己定**（VAD p.78 [原文]）。用户说不清时，按「比较各组 / 看趋势 / 看关系 / 看分布」出选择题。

**Tavotto 的任务闭集**：与数据出图跑分用例（`tests/fixtures/data_figure_cases/recommend_cases.json`）用同一套词，对应到 VAD 的目标。

| Tavotto 任务 | VAD 目标 / 查询 | 典型画法 |
| --- | --- | --- |
| `compare_groups` | compare values | 原始点 + 汇总、箱线 + 点、柱（从 0 起） |
| `trend` | trend（有序 key） | 折线 + 点、汇总线 + 误差带 |
| `dose_response` | trend + dependency | 同上，常用对数横轴（G-054） |
| `relationship` | correlation / dependency（0 key、2 value） | 散点、散点 + 拟合 |
| `agreement` | similarity（两轴同一个量） | 等比例散点 + y = x（G-026） |
| `distribution` | distribution | 原始点、ECDF、小提琴 + 点、密度、箱线 + 点 |
| `part_whole` | part-to-whole | 归一化堆叠柱、饼（块少时） |
| `paired_change` | compare（重复测量） | 配对连线（个体经用户确认，G-038） |
| `ranking` | extremes / 排序 | 按数值排序的点图或柱（G-040） |
| `intervals` | value + 不确定性 | 点 + 误差线（类型写明，G-005） |
| `pattern_in_matrix` | 2 key、1 value | 热图 |
| `undetermined` | — | 出选择题，或走最保守的画法 |

`task_source` 的取值有三种：`from_hint`（用户的话）、`from_data`（从数据结构推出）、`needs_confirm`（要问用户）。按 P6，只有 `from_hint` 和用户点选过的结果，才算「用户确认过的目的」。

## 3. Derive（派生）

候选包括：差值、比值、归一化、log、分箱、聚合、排序、拟合。每个派生都要写明四件事：
1. 来源列与操作；
2. **丢掉了什么**（VAD §3.4.2.3、第 13 章 [原文]；Anscombe）；
3. 是否需要用户确认：归一化、比值、log 都需要（G-037）；
4. 结果写进脚本和配方，保证可追溯（P8）。

## 4. 编码候选

按（key 数，value 数，key 类型，任务）查表。下表依据 VAD 第 7 章 [原文]；里面的规模数字以约 1000×1000 像素的屏幕为前提，印刷图要重新标定。

| 结构 | 首选 | 依据与条件 |
| --- | --- | --- |
| 0 key，2 个数值 | 散点（可叠拟合线与置信带） | 点很多时改用密度或分箱（G-012） |
| 1 个类别 key，1 个数值 | 点图 / 原始点加汇总；柱（从 0 起） | 柱必须从 0 起（G-002）；数据量允许时露出原始点（G-012、G-050）；无序类别按数值排序（G-040） |
| 1 个有序 key，1 个数值 | 折线（看趋势）或点（看具体值） | 只有有序 key 才连线（G-018） |
| 2 个 key，1 个数值 | 热图；分组柱或小倍数 | 比较同一属性用小倍数，跨属性比较用分组（VAD §12.4 [原文]） |
| 分布 | 原始点加抖动；箱线加点；ECDF；直方图或密度 | 样本少不用小提琴（G-013）；bin 宽要说明（G-014） |
| 整体与部分 | 归一化堆叠柱、饼（块少时） | 各部分互斥、合计 100%（G-035）；优劣是品味（G-043） |

通道分配：最重要的量放在共同坐标轴的位置上（G-019）；有序数据用有序通道，类别用可区分的通道（G-020）。

## 5. 颜色、分面、聚合

- 类别色不超过约 8 种（G-021）。
- 有序数据用亮度单调的色图（G-022）。
- 发散色图的中点要有语义（G-023）。
- 冗余编码，照顾色觉缺陷（G-024）。
- 黑白下也要能读（G-025）。
- 叠加不超过 2–3 层，再多改用小倍数（G-029）；小倍数用相同的轴范围（G-027）。
- 有遮挡时聚合，并说明丢掉了什么（G-012）。

## 6. 理由三档（G-039）

1. **数据事实**，可核验。例：「横轴是有序的时间列，共 12 个取值」。
2. **感知依据**，指导性。例：「位置比面积准确（Munzner 的综合结论）」。
3. **用户确认过的目的**。例：「你要比较三组的均值」。

三档分开写，**不合成一个「推荐置信度」**，也不说「最优」。没确认的目的写成「假设你想……」，并给出改的入口。

## 7. 品味与默认值

遇到 `basis: taste` 的条目（G-042 至 G-051），先按用户或期刊；都没有时，可以用 Tavotto 出版规范的默认值。但**相反的做法不算问题，不要报告**。
